Example 1: SmartDevice: struct to class

Warm-up (level 1 of 3) From Tutorial 3.

Turn this struct and its functions into a class. Hide the data; keep the functions as the public interface. Add a constructor that takes the device ID and starts the device off, at 0 watts. Add getPower() so a test can read the power.

struct SmartDevice {
  std::string deviceID;
  bool isOn;
  double powerConsumption; // in Watts
};
void turnOn(SmartDevice& dev);
void turnOff(SmartDevice& dev);
void updatePower(SmartDevice& dev, double watts);
bool getStatus(const SmartDevice& dev);
FunctionKindAs a member
turnOn, turnOff, updatePowermutatorsdrop the SmartDevice& parameter
getStatusaccessorconst SmartDevice& becomes const behind the brackets

One function first: void turnOn(SmartDevice& dev) { dev.isOn = true; } becomes void SmartDevice::turnOn() { isOn = true; }. isOn now means the member of the object the function was called on.

Write this before you open the solution.

#include <iostream>
#include <string>

class SmartDevice {
 public:
  SmartDevice(std::string deviceID);
  void turnOn();
  void turnOff();
  void updatePower(double watts);
  bool getStatus() const;
  double getPower() const;

 private:
  std::string deviceID;
  bool isOn;
  double powerConsumption;
};

SmartDevice::SmartDevice(std::string deviceID)
    : deviceID(deviceID), isOn(false), powerConsumption(0) {}

void SmartDevice::turnOn() {
  isOn = true;
}

void SmartDevice::turnOff() {
  isOn = false;
}

void SmartDevice::updatePower(double watts) {
  powerConsumption = watts;
}

bool SmartDevice::getStatus() const {
  return isOn;
}

double SmartDevice::getPower() const {
  return powerConsumption;
}

int main() {
  SmartDevice lamp("lamp-01");
  lamp.turnOn();
  lamp.updatePower(9.5);
  std::cout << lamp.getStatus() << " " << lamp.getPower() << std::endl;
  lamp.turnOff();
  std::cout << lamp.getStatus() << std::endl;
  return 0;
}

It prints:

0

true prints as 1 and false as 0.

Read this after you have written your own answer.

Two common slips: leaving const off getStatus (then a const SmartDevice& cannot call it; see const), and keeping the SmartDevice& dev parameter, which makes the call lamp.turnOn(lamp).

Example 2: UserSession: header and .cpp file

Exam-typical (level 2 of 3) From Tutorial 3 (the UserSession class diagram).

The class diagram (Tutorial 3) has - username: string, - sessionDuration: int, - activeSessionCount: int (underlined: static), and + UserSession(username: string), + ~UserSession(), + getUsername(): string (an accessor), + getActiveSessionCount(): int and + updateDuration(sessionDuration: int): void. Write UserSession.h and UserSession.cpp. The constructor adds one to the count; the destructor takes one off.

Underlined means static. A parameter with the same name as a member hides the member (see The this pointer).

The include guard first: #ifndef USERSESSION_H, #define USERSESSION_H, ..., #endif. The header includes <string> because of the string members.

Write this before you open the solution.

#ifndef USERSESSION_H

Example 6: Schedule: a deep copy of a 2D array

Longer (level 3 of 3) An original example with a 2D dynamic array of dynamic objects.

A Schedule holds Activity*** mySchedule: timeslots rows, each a dynamic array of days pointers; each pointer is NULL or points at a dynamic Activity. The constructor and destructor are given. Write the deep copy constructor.

Schedule::Schedule(int days, int timeslots) : days(days), timeslots(timeslots) {
  mySchedule = new Activity**[timeslots];
  for (int r = 0; r < timeslots; r++) {
    mySchedule[r] = new Activity*[days];
    for (int c = 0; c < days; c++) {
      mySchedule[r][c] = NULL;
    }
  }
}
Schedule::~Schedule() {
  for (int r = 0; r < timeslots; r++) {
    for (int c = 0; c < days; c++) {
      delete mySchedule[r][c];
    }
    delete[] mySchedule[r];
  }
  delete[] mySchedule;
}

Three levels: mySchedule (array of rows), mySchedule[r] (a row: array of pointers), mySchedule[r][c] (one pointer). A deep copy makes a new array at each level and a new Activity for each non-NULL slot.

The copy must follow the constructor’s shape: one new Activity**[timeslots], then one new Activity*[days] per row.

Write this before you open the solution.

Schedule::Schedule(const Schedule& other) : days(other.days), timeslots(other.timeslots) {
  mySchedule = new Activity**[timeslots];
  for (int r = 0; r < timeslots; r++) {
    mySchedule[r] = new Activity*[days];
    for (int c = 0; c < days; c++) {
      if (other.mySchedule[r][c] == NULL) {
        mySchedule[r][c] = NULL;
      } else {
        mySchedule[r][c] = new Activity(*other.mySchedule[r][c]);
      }
    }
  }
}

Example 7: Garden: operator= with owned and shared parts

Longer (level 3 of 3) An original example in the shape of the Semester Test 1 and Class Test 2A flowchart questions.

A Garden owns its Plants (composition: Plant** plants, numPlants) and points at helper Gardeners it does not own (aggregation: Gardener** helpers, numHelpers). Write Garden& operator=(const Garden& other).

PartDelete the oldCopy from other
plants (owned)each Plant, then the arraya new array and a new Plant per slot
helpers (shared)only the arraya new array whose slots point at the same Gardeners

The four steps of the assignment operator stay the same. Only steps 2 and 3 change, per relationship.

Write this before you open the solution.

Garden& Garden::operator=(const Garden& other) {
  if (this == &other) {
    return *this;
  }
  for (int i = 0; i < numPlants; i++) {
    delete plants[i];
  }
  delete[] plants;
  delete[] helpers;
  numPlants = other.numPlants;
  plants = new Plant*[numPlants];
  for (int i = 0; i < numPlants; i++) {
    plants[i] = new Plant(*other.plants[i]);
  }
  numHelpers = other.numHelpers;
  helpers = NULL;
  if (numHelpers > 0) {
    helpers = new Gardener*[numHelpers];
    for (int i = 0; i < numHelpers; i++) {
      helpers[i] = other.helpers[i];
    }
  }
  return *this;
}

Example 8: Playlist: a constructor that checks its input

Exam-typical (level 2 of 3) Semester Test 1 Q15 and Q16 gave an object diagram and a constructor flowchart for a Playlist and asked for the class and the constructor. The recap gives the members and the check below.

Class Playlist has std::string title; int songCount; std::string* songs;. The constructor Playlist(std::string title, const std::string* source, int count) copies count songs from source. If source is NULL or count is negative, it keeps an empty playlist. Write the constructor and the destructor.

The recap notes that no initialisation list is used here, because nothing may be copied from invalid input. The safe defaults are set first, then the check, then the copy.

ConditionTrue meansFalse means
source == NULL || count < 0invalid input: stop; the playlist stays emptycopy the songs

Write this before you open the solution.

Playlist::Playlist(std::string title, const std::string* source, int count) {
  this->title = title;
  songCount = 0;
  songs = NULL;
  if (source == NULL || count < 0) {
    return;
  }
  songCount = count;
  songs = new std::string[songCount];
  for (int i = 0; i < songCount; i++) {
    songs[i] = source[i];
  }
}
Playlist::~Playlist() {
  delete[] songs;
}
int main() {
  std::string mix[3] = {"Ntsika", "Zama", "Imali"};
  Playlist good("Drive", mix, 3);
  Playlist bad("Empty", NULL, 2);
  Playlist neg("Neg", mix, -1);
  good.print();
  bad.print();
  neg.print();
  return 0;
}
