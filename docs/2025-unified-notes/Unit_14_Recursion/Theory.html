1. What is Recursion?

Recursion is when a function calls itself. Instead of using a loop to repeat something, you write a function that solves a small part of the problem and calls itself to solve the rest.

The Two Parts of Every Recursive Function

Every recursive function needs exactly two things:

  1. Base Case: The stopping condition. When do we stop calling the function?
  2. Recursive Case: The part where the function calls itself with a simpler input.

Without a base case, the function keeps calling itself forever (infinite recursion) and your program crashes with a stack overflow.

Simple Example: Countdown

Let's write a function that counts down from a number to 1: 

void countdown(int n) {
    if (n <= 0) {
        cout << "Done!" << endl;
        return;  // BASE CASE - stop here
    }

    cout << n << " ";
    countdown(n - 1);  // RECURSIVE CASE - call with smaller n
}

How this works:

  • if (n <= 0) - Base case: when n reaches 0 or below, stop
  • cout << n - Print the current number
  • countdown(n - 1) - Call the function again with a smaller number

If you call countdown(5), it prints: 5 4 3 2 1 Done!

Call stack for countdown(3):

countdown(3)  →  prints "3 ", calls countdown(2)
    countdown(2)  →  prints "2 ", calls countdown(1)
        countdown(1)  →  prints "1 ", calls countdown(0)
            countdown(0)  →  prints "Done!", returns
        countdown(1) returns
    countdown(2) returns
countdown(3) returns
Important: Without the base case if (n <= 0), the function would call itself forever and crash with a stack overflow error.

2. How Recursion Works: The Call Stack

When you call a function, C++ puts it on the call stack - a special area of memory that keeps track of active function calls. Each function call gets its own space (a "stack frame") with its own local variables.

Visualizing the Call Stack

Let's trace what happens when you call factorial(3): 

int factorial(int n) {
    if (n <= 1) {
        return 1;  // Base case
    }
    return n * factorial(n - 1);  // Recursive case
}
Call Stack Evolution for factorial(3):

Step 1: factorial(3) is called
┌──────────────────┐
│ factorial(3)     │  n = 3, waiting for factorial(2)
└──────────────────┘

Step 2: factorial(3) calls factorial(2)
┌──────────────────┐
│ factorial(2)     │  n = 2, waiting for factorial(1)
├──────────────────┤
│ factorial(3)     │  n = 3, waiting for factorial(2)
└──────────────────┘

Step 3: factorial(2) calls factorial(1)
┌──────────────────┐
│ factorial(1)     │  n = 1, BASE CASE! Returns 1
├──────────────────┤
│ factorial(2)     │  n = 2, waiting for factorial(1)
├──────────────────┤
│ factorial(3)     │  n = 3, waiting for factorial(2)
└──────────────────┘

Step 4: factorial(1) returns 1
┌──────────────────┐
│ factorial(2)     │  n = 2, gets 1, returns 2*1 = 2
├──────────────────┤
│ factorial(3)     │  n = 3, waiting for factorial(2)
└──────────────────┘

Step 5: factorial(2) returns 2
┌──────────────────┐
│ factorial(3)     │  n = 3, gets 2, returns 3*2 = 6
└──────────────────┘

Step 6: factorial(3) returns 6
(Stack is empty - all done!)

Final result: 6

Key points:

  • Each recursive call adds a new frame to the stack
  • Frames pile up until the base case is reached
  • Then they unwind (return) from top to bottom
  • Each frame has its own copy of the parameters
Stack Overflow: If recursion goes too deep (too many calls before hitting the base case), you run out of stack space and the program crashes. This is why the base case is so important.

3. Mathematical Recursion: Factorial and Fibonacci

Factorial

Factorial of n (written n!) is the product of all positive integers up to n:

  • 5! = 5 × 4 × 3 × 2 × 1 = 120
  • 3! = 3 × 2 × 1 = 6
  • 1! = 1
  • 0! = 1 (by definition)

Recursive definition:

  • n! = n × (n-1)! for n > 1
  • 1! = 1 (base case)
int factorial(int n) {
    if (n <= 1) {
        return 1;  // Base case: 0! = 1, 1! = 1
    }
    return n * factorial(n - 1);  // Recursive case
}

How this works:

  • factorial(5) = 5 × factorial(4)
  • factorial(4) = 4 × factorial(3)
  • factorial(3) = 3 × factorial(2)
  • factorial(2) = 2 × factorial(1)
  • factorial(1) = 1 (base case)
  • Now unwinding: 2×1=2, 3×2=6, 4×6=24, 5×24=120

Fibonacci Sequence

The Fibonacci sequence: 0, 1, 1, 2, 3, 5, 8, 13, 21...

Each number is the sum of the previous two numbers.

Recursive definition:

  • fib(0) = 0 (base case)
  • fib(1) = 1 (base case)
  • fib(n) = fib(n-1) + fib(n-2) for n > 1 (recursive case)
int fibonacci(int n) {
    if (n <= 0) {
        return 0;  // Base case 1
    }
    if (n == 1) {
        return 1;  // Base case 2
    }
    return fibonacci(n - 1) + fibonacci(n - 2);  // Recursive case
}

How this works for fibonacci(4):

Tree of recursive calls for fibonacci(4):

                    fib(4)
                   /      \
              fib(3)      fib(2)
             /     \      /     \
        fib(2)  fib(1) fib(1) fib(0)
        /    \
   fib(1) fib(0)

Returns:
fib(0) = 0, fib(1) = 1
fib(2) = fib(1) + fib(0) = 1 + 0 = 1
fib(3) = fib(2) + fib(1) = 1 + 1 = 2
fib(4) = fib(3) + fib(2) = 2 + 1 = 3
Swift Note: Notice how fibonacci(2) is calculated twice in the tree above. This is why the recursive Fibonacci is slow - it recalculates the same values over and over. We'll see better approaches later.

4. Recursion vs Iteration: When to Use Each

Many problems can be solved with either recursion or iteration (loops). How do you decide which to use?

The Same Problem, Two Ways

Let's calculate factorial using both approaches:

Recursive version:

int factorialRecursive(int n) {
    if (n <= 1) return 1;
    return n * factorialRecursive(n - 1);
}

Iterative version:

int factorialIterative(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}

Comparing the Approaches

Aspect Recursion Iteration
Code clarity Often clearer for naturally recursive problems Can be more straightforward for simple loops
Memory usage Uses call stack (one frame per call) Uses only a few variables
Speed Slower (function call overhead) Faster (no function calls)
Risk Can cause stack overflow if too deep No stack overflow risk
Best for Tree/graph traversal, divide-and-conquer Simple counting, array processing

When to Use Recursion

Recursion is better when:

  • The problem is naturally recursive - trees, graphs, divide-and-conquer algorithms
  • The code is much clearer - recursion expresses the solution more naturally
  • Depth is limited - you won't run out of stack space

When to Use Iteration

Iteration is better when:

  • Performance matters - iteration is faster and uses less memory
  • The problem is simple - counting, summing arrays, simple loops
  • Recursion might be too deep - risk of stack overflow
Rule of Thumb: If iteration is just as clear as recursion, use iteration. Use recursion when it makes the code significantly clearer or when the problem is naturally recursive (like tree traversal).
⚡ Swift Quiz
Quick Check: Why does recursive Fibonacci run slower than iterative Fibonacci?
Answer: Recursive Fibonacci recalculates the same values many times. For example, fib(5) calls fib(3) twice, fib(2) three times, etc. This leads to exponential time complexity. Iterative Fibonacci calculates each value only once, giving linear time complexity.

5. Recursion with Arrays

Recursion works well with arrays. Instead of looping through the array, we process one element and recursively handle the rest.

Sum of Array Elements

To sum an array recursively:

  • Base case: If the array is empty (size 0), return 0
  • Recursive case: Return first element + sum of the rest
int sumArray(int arr[], int size) {
    if (size == 0) {
        return 0;  // Base case: empty array
    }
    return arr[0] + sumArray(arr + 1, size - 1);  // First + sum of rest
}

// arr + 1 moves the pointer to the next element
// size - 1 reduces the size by 1

How this works for {5, 3, 8}:

sumArray({5, 3, 8}, 3)
  = 5 + sumArray({3, 8}, 2)
  = 5 + (3 + sumArray({8}, 1))
  = 5 + (3 + (8 + sumArray({}, 0)))
  = 5 + (3 + (8 + 0))
  = 5 + (3 + 8)
  = 5 + 11
  = 16

Check if Array is Sorted

To check if an array is sorted in ascending order:

  • Base case: If size <= 1, it's sorted (trivially true)
  • Recursive case: Check if first element <= second element AND rest is sorted
bool isSorted(int arr[], int size) {
    if (size <= 1) {
        return true;  // Base case: 0 or 1 element is always sorted
    }

    // Check if first two elements are in order AND rest is sorted
    return (arr[0] <= arr[1]) && isSorted(arr + 1, size - 1);
}

How this works:

  • Checks arr[0] <= arr[1]
  • If yes, recursively checks if the rest (starting from arr[1]) is sorted
  • If any pair is out of order, returns false

Find Maximum in Array

int findMax(int arr[], int size) {
    if (size == 1) {
        return arr[0];  // Base case: one element
    }

    int maxRest = findMax(arr + 1, size - 1);  // Max of the rest
    return (arr[0] > maxRest) ? arr[0] : maxRest;  // Compare first with max of rest
}

How this works:

  • Find the maximum of the rest of the array (recursive call)
  • Compare the first element with that maximum
  • Return whichever is larger

6. Recursion with Linked Lists

Linked lists are naturally recursive structures! A linked list is either:

  • Empty (NULL) - base case
  • A node followed by another linked list - recursive case

This makes recursion perfect for linked list operations.

Node Structure

struct Node {
    int data;
    Node* next;
};

Print Linked List Recursively

void printList(Node* head) {
    if (head == NULL) {
        cout << endl;  // Base case: end of list
        return;
    }

    cout << head->data << " ";  // Print current node
    printList(head->next);      // Recursively print rest
}

How this works:

  • If the list is empty (head == NULL), stop
  • Otherwise, print the current node's data
  • Recursively print the rest of the list (head->next)

Print Linked List in Reverse

This is beautiful with recursion - we print AFTER the recursive call instead of before: 

void printReverse(Node* head) {
    if (head == NULL) {
        return;  // Base case
    }

    printReverse(head->next);  // Recursively print rest FIRST
    cout << head->data << " "; // THEN print current node
}

Why this works:

For list: 1 -> 2 -> 3 -> NULL

printReverse(1)
    printReverse(2)
        printReverse(3)
            printReverse(NULL)  [returns immediately]
        prints 3
    prints 2
prints 1

Output: 3 2 1

The magic: we go all the way to the end first (recursion), then print on the way back (unwinding).

Count Nodes Recursively

int countNodes(Node* head) {
    if (head == NULL) {
        return 0;  // Base case: empty list has 0 nodes
    }
    return 1 + countNodes(head->next);  // 1 for current + count of rest
}

Search for Value Recursively

bool search(Node* head, int value) {
    if (head == NULL) {
        return false;  // Base case: not found
    }
    if (head->data == value) {
        return true;   // Found it!
    }
    return search(head->next, value);  // Search in rest
}
Swift Note: Swift's been watching Steins;Gate - a sci-fi thriller about a group of friends who discover they can send messages to the past, creating branching timelines. Think of each timeline as a linked list of events, where each event (node) points to the next event. Recursion lets us traverse these timelines forwards or backwards!

Experiment: Write a recursive function getMin(Node* head) that returns the minimum value in the list.

Solution:

int getMin(Node* head) {
    if (head->next == NULL) {
        return head->data;  // Base case: only one node
    }
    int minRest = getMin(head->next);  // Min of rest of list
    return (head->data < minRest) ? head->data : minRest;
}

How it works: Find the minimum of the rest of the list, then compare it with the current node's data. Return whichever is smaller.

Note: This assumes the list has at least one node (head != NULL).

7. Tree Recursion (Multiple Recursive Calls)

Some recursive functions make multiple recursive calls. This creates a tree of function calls instead of a linear chain.

Fibonacci is Tree Recursion

Remember Fibonacci? It makes TWO recursive calls: 

int fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);  // Two recursive calls!
}

This creates a tree of calls:

                    fib(5)
                   /      \
              fib(4)      fib(3)
             /     \      /     \
        fib(3)  fib(2) fib(2) fib(1)
        /    \   /  \   /  \
   fib(2) fib(1) ... ... ...
   /    \
fib(1) fib(0)

Counting Binary Strings

Here's another tree recursion example: counting binary strings of length n without consecutive 1s.

Examples:

  • Length 2: 00, 01, 10 (3 strings - "11" not allowed)
  • Length 3: 000, 001, 010, 100, 101 (5 strings)

Recursive insight:

  • If the string ends in 0, the previous part can be any valid string of length n-1
  • If the string ends in 1, the previous part must end in 0 (to avoid "11")
int countBinaryStrings(int n) {
    if (n == 1) {
        return 2;  // Base case: "0" and "1"
    }
    if (n == 2) {
        return 3;  // Base case: "00", "01", "10"
    }

    // Strings ending in 0 + strings ending in 01
    return countBinaryStrings(n - 1) + countBinaryStrings(n - 2);
}

// This is the Fibonacci sequence again!
Interesting: Many tree recursion problems reduce to Fibonacci or similar sequences!

8. Common Mistakes and How to Avoid Them

Mistake 1: Missing Base Case

// WRONG - no base case!
int factorial(int n) {
    return n * factorial(n - 1);  // Infinite recursion!
}

// CORRECT
int factorial(int n) {
    if (n <= 1) return 1;  // Base case
    return n * factorial(n - 1);
}

Result: Stack overflow - the function calls itself forever until the program crashes.

Mistake 2: Base Case Never Reached

// WRONG - base case is unreachable
int sumToZero(int n) {
    if (n == 0) return 0;  // Base case
    return n + sumToZero(n + 1);  // n gets BIGGER, never reaches 0!
}

// CORRECT - approach base case
int sumToZero(int n) {
    if (n == 0) return 0;
    return n + sumToZero(n - 1);  // n gets smaller, reaches 0
}

Result: Same as missing base case - infinite recursion and stack overflow.

Mistake 3: Not Making the Problem Smaller

// WRONG - recursive call doesn't reduce problem size
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n);  // Calling with same n - infinite!
}

// CORRECT - reduce n by 1
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);  // n - 1 is smaller
}

Mistake 4: Wrong Return Type

// WRONG - base case returns wrong type
int sumArray(int arr[], int size) {
    if (size == 0) {
        return;  // Should return 0, not void!
    }
    return arr[0] + sumArray(arr + 1, size - 1);
}

// CORRECT
int sumArray(int arr[], int size) {
    if (size == 0) {
        return 0;  // Correct return value
    }
    return arr[0] + sumArray(arr + 1, size - 1);
}

Mistake 5: Modifying the Wrong Parameter

// WRONG - modifying size in place doesn't help
void printArray(int arr[], int size) {
    if (size == 0) return;
    cout << arr[0] << " ";
    size--;  // This doesn't affect the recursive call!
    printArray(arr, size);  // Should be arr + 1, size - 1
}

// CORRECT
void printArray(int arr[], int size) {
    if (size == 0) return;
    cout << arr[0] << " ";
    printArray(arr + 1, size - 1);  // Move pointer AND reduce size
}
Debugging Tip: If your recursive function hangs or crashes, check:
  1. Do you have a base case?
  2. Will the base case ever be reached?
  3. Does each recursive call make the problem smaller?

9. When to Use Recursion

Perfect Use Cases for Recursion

1. Tree and Graph Traversal

Trees are naturally recursive. Each subtree is itself a tree, making recursion the natural choice.

2. Divide and Conquer Algorithms

  • Merge Sort - split array in half, recursively sort each half, merge
  • Quick Sort - partition array, recursively sort partitions
  • Binary Search - check middle, recursively search half

3. Backtracking Problems

  • Finding all permutations of a string
  • Solving mazes (try a path, backtrack if it fails)
  • N-Queens problem

4. Problems with Recursive Structure

  • Linked lists (a list is a node + a list)
  • Mathematical sequences (Fibonacci, factorial)
  • File system traversal (a directory contains files and directories)

When NOT to Use Recursion

1. Simple Iteration Works Better

// DON'T use recursion for simple loops
int sumArray(int arr[], int size) {
    // Better to just use a for loop here
    int sum = 0;
    for (int i = 0; i < size; i++) {
        sum += arr[i];
    }
    return sum;
}

2. Performance Critical Code

Recursion has overhead (function calls, stack frames). If performance matters and iteration works, use iteration.

3. Deep Recursion Risk

If recursion depth might be very large (thousands of calls), you risk stack overflow. Use iteration instead.

Tail Recursion

Tail recursion is when the recursive call is the very last thing the function does (no operations after it). 

// Tail recursive - nothing happens after recursive call
int factorialTail(int n, int accumulator) {
    if (n <= 1) {
        return accumulator;
    }
    return factorialTail(n - 1, n * accumulator);  // Last thing!
}

// Not tail recursive - multiplication happens after recursive call
int factorialNormal(int n) {
    if (n <= 1) return 1;
    return n * factorialNormal(n - 1);  // Multiply AFTER call returns
}

Some compilers can optimize tail recursion into iteration automatically (tail call optimization), making it as efficient as a loop.

Summary: Use recursion when it makes the code clearer or when the problem is naturally recursive. Use iteration when performance matters or when recursion doesn't add clarity.
⚡ Swift Quiz
Quick Check: What is tail recursion, and why is it potentially more efficient?
Answer: Tail recursion is when the recursive call is the absolute last operation in the function (nothing happens after it returns). It's more efficient because compilers can optimize it into a loop (tail call optimization), eliminating the function call overhead and using constant stack space instead of linear stack space.

10. Summary: Recursion at a Glance

Key Concepts

  • Recursion is a function calling itself
  • Every recursive function needs a base case (stopping condition) and a recursive case (function calls itself)
  • Recursive calls build up on the call stack, then unwind when the base case is reached
  • Tree recursion makes multiple recursive calls, creating a tree of function calls

Common Recursive Patterns

Pattern Example Base Case
Countdown countdown(n) n <= 0
Mathematical sequence factorial(n), fibonacci(n) n <= 1
Array processing sumArray(arr, size) size == 0
Linked list printList(head) head == NULL

Time and Space Complexity

Time Complexity:

  • Linear recursion (one recursive call): Usually O(n) - factorial, sum array, linked list traversal
  • Tree recursion (multiple calls): Can be exponential - naive Fibonacci is O(2^n)

Space Complexity:

  • Recursion uses O(depth) space on the call stack
  • Factorial: O(n) space for n recursive calls
  • Fibonacci: O(n) space (depth of tree), but makes exponential TIME calls

Common Mistakes to Avoid

  • ❌ Missing base case → infinite recursion
  • ❌ Base case never reached → infinite recursion
  • ❌ Not making problem smaller → infinite recursion
  • ❌ Wrong return type in base case → compilation error or wrong results

When to Use Recursion

✅ Use recursion when:

  • The problem is naturally recursive (trees, divide-and-conquer)
  • Recursion makes the code significantly clearer
  • Depth is limited (won't overflow the stack)

❌ Avoid recursion when:

  • Iteration is just as clear and simpler
  • Performance is important (recursion has overhead)
  • Recursion depth might be very large
