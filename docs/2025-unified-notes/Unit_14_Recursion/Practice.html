Problem 1: Power Function

Easy

Problem Description

Write a recursive function power(base, exponent) that calculates baseexponent.

Examples:

  • power(2, 3) = 23 = 8
  • power(5, 2) = 52 = 25
  • power(10, 0) = 100 = 1

Recursive Insight

Think about it this way:

  • Base case: When exponent is 0, return 1 (anything0 = 1)
  • Recursive case: baseexponent = base × baseexponent-1

Test Cases

power(2, 3) should return 8
power(5, 2) should return 25
power(10, 0) should return 1
power(3, 4) should return 81

Solution

int power(int base, int exponent) {
    if (exponent == 0) {
        return 1;  // Base case: anything^0 = 1
    }
    return base * power(base, exponent - 1);  // Recursive case
}

Explanation

How it works:

  • Base case: When exponent is 0, we return 1
  • Recursive case: We multiply base by the result of power(base, exponent - 1)

Example trace for power(2, 3):

  • power(2, 3) = 2 × power(2, 2)
  • power(2, 2) = 2 × power(2, 1)
  • power(2, 1) = 2 × power(2, 0)
  • power(2, 0) = 1 (base case)
  • Unwinding: 2 × (2 × (2 × 1)) = 8

Time Complexity: O(exponent) - we make exponent recursive calls

Space Complexity: O(exponent) - call stack depth

Problem 2: Student Grade Counter

Easy

Problem Description

Swift is helping students Refentse, Dian, and Kat prepare for their COS 110 exam. She has an array of their practice test scores and needs to count how many scores are above a certain threshold (passing grade).

Write a recursive function countAbove(arr, size, threshold) that counts how many elements in the array are greater than the threshold.

Example:

  • Array: {85, 62, 91, 74, 55, 88}
  • Threshold: 70
  • Result: 3 (scores 85, 91, and 88 are above 70)

Recursive Insight

  • Base case: If size is 0, return 0 (no elements to count)
  • Recursive case: Check if first element is above threshold, then add (1 or 0) to the count from the rest

Test Cases

int scores[] = {85, 62, 91, 74, 55, 88};
countAbove(scores, 6, 70) should return 3
countAbove(scores, 6, 60) should return 5
countAbove(scores, 6, 90) should return 1
Practice Playground 2

Write your recursive countAbove function.

Output:
Running...
Click "Run Code" to see the output...

Solution

int countAbove(int arr[], int size, int threshold) {
    if (size == 0) {
        return 0;  // Base case: no elements left
    }

    int countFirst = (arr[0] > threshold) ? 1 : 0;  // 1 if above threshold, 0 otherwise
    return countFirst + countAbove(arr + 1, size - 1, threshold);  // Add count from rest
}

Explanation

How it works:

  • Base case: When size is 0, no elements to check, return 0
  • Recursive case: Check if first element is above threshold (add 1 if yes, 0 if no), then add the count from the rest of the array
  • arr + 1 moves the pointer to the next element
  • size - 1 reduces the array size

Example trace for {85, 62, 91} with threshold 70:

  • countAbove({85, 62, 91}, 3, 70)
  • = 1 (85 > 70) + countAbove({62, 91}, 2, 70)
  • = 1 + 0 (62 ≤ 70) + countAbove({91}, 1, 70)
  • = 1 + 0 + 1 (91 > 70) + countAbove({}, 0, 70)
  • = 1 + 0 + 1 + 0 (base case)
  • = 2

Time Complexity: O(n) - we visit each element once

Space Complexity: O(n) - call stack depth equals array size

Problem 3: What's Wrong With This Code?

Intermediate

Problem Description

The following code is supposed to calculate the sum of all elements in an array recursively, but it has bugs. Can you find and fix them? 

int sumArray(int arr[], int size) {
    if (size == 0) {
        return 1;
    }
    return arr[size] + sumArray(arr, size - 1);
}

Test Cases

int arr[] = {1, 2, 3, 4, 5};
sumArray(arr, 5) should return 15 (1+2+3+4+5)

The Bugs

Bug 1: Base case returns 1 instead of 0

  • Problem: When summing, the identity element is 0 (adding 0 doesn't change the sum)
  • Fix: Return 0 when size is 0

Bug 2: Uses arr[size] instead of arr[size - 1]

  • Problem: Array indices go from 0 to size-1. arr[size] is out of bounds!
  • Fix: Use arr[size - 1] to access the last element

Corrected Code

int sumArray(int arr[], int size) {
    if (size == 0) {
        return 0;  // Fixed: Return 0 for empty array
    }
    return arr[size - 1] + sumArray(arr, size - 1);  // Fixed: Use arr[size - 1]
}

Why It Works Now

  • Base case correctly returns 0 (sum of empty array)
  • arr[size - 1] accesses the last element (valid index)
  • Recursively sum the last element with the sum of the rest

Alternative approach (using first element):

int sumArray(int arr[], int size) {
    if (size == 0) {
        return 0;
    }
    return arr[0] + sumArray(arr + 1, size - 1);  // First element + sum of rest
}

Problem 4: Recursive String Reverser

Intermediate

Problem Description

Swift wants to check if South African names are palindromes when reversed. Write a recursive function reverseString(str, start, end) that reverses a string in-place by swapping characters from both ends moving inward.

Example:

  • Input: "Refentse" → Output: "estnefe R" (not a palindrome!)
  • Input: "racecar" → Output: "racecar" (this is a palindrome!)

Recursive Insight

  • Base case: When start >= end, we've reversed the middle (stop)
  • Recursive case: Swap characters at start and end, then recurse with start+1 and end-1

Test Cases

reverseString("hello") → "olleh"
reverseString("Racecar") → "racecaR"
reverseString("a") → "a"
Practice Playground 4

Write a recursive function to reverse a string in-place.

Output:
Running...
Click "Run Code" to see the output...

Solution

void reverseString(string& str, int start, int end) {
    if (start >= end) {
        return;  // Base case: crossed in the middle or single character
    }

    // Swap characters at start and end
    char temp = str[start];
    str[start] = str[end];
    str[end] = temp;

    // Recurse with inner substring
    reverseString(str, start + 1, end - 1);
}

Explanation

How it works:

  • Base case: When start >= end, we've reached or passed the middle - stop
  • Recursive case:
    1. Swap the characters at positions start and end
    2. Move inward: start+1, end-1
    3. Recurse with the smaller substring

Example trace for "hello":

  • reverseString("hello", 0, 4) → swap 'h' and 'o' → "oellh"
  • reverseString("oellh", 1, 3) → swap 'e' and 'l' → "olleh"
  • reverseString("olleh", 2, 2) → start >= end, return (middle reached)
  • Result: "olleh"

Time Complexity: O(n/2) = O(n) - we swap n/2 pairs

Space Complexity: O(n) - call stack depth is n/2

Note: The & in string& str means we're passing by reference - changes to str modify the original string. Without it, we'd be working on a copy!

Problem 5: The Ackermann Function

Challenge

Problem Description

The Ackermann function is a classic example of a recursive function that grows incredibly fast. It's defined as:

  • A(0, n) = n + 1
  • A(m, 0) = A(m - 1, 1) when m > 0
  • A(m, n) = A(m - 1, A(m, n - 1)) when m > 0 and n > 0

This function makes multiple recursive calls and demonstrates how recursion depth can explode.

Warning: Don't try A(4, 2) or higher - it will take forever! Even A(3, 5) makes thousands of recursive calls.

Test Cases

A(0, 5) = 6
A(1, 3) = 5
A(2, 2) = 7
A(3, 2) = 29  // Gets slow here!
A(3, 3) = 61  // Very slow!

Implement the Ackermann function. Test with small values only!

Output:

Click "Run Code" to see the output...

Solution

int ackermann(int m, int n) {
    if (m == 0) {
        return n + 1;  // Base case 1: A(0, n) = n + 1
    }
    if (n == 0) {
        return ackermann(m - 1, 1);  // Base case 2: A(m, 0) = A(m-1, 1)
    }
    // Recursive case: A(m, n) = A(m-1, A(m, n-1))
    return ackermann(m - 1, ackermann(m, n - 1));
}

Explanation

The three cases:

  1. m = 0: Return n + 1 (simplest case)
  2. m > 0, n = 0: Recurse with A(m-1, 1)
  3. m > 0, n > 0: Double recursion! Calculate A(m, n-1) first, then use that result in A(m-1, ...)

Example trace for A(2, 1):

  • A(2, 1) = A(1, A(2, 0))
  • = A(1, A(1, 1)) [from A(2, 0) = A(1, 1)]
  • = A(1, A(0, A(1, 0))) [expanding A(1, 1)]
  • = A(1, A(0, A(0, 1))) [expanding A(1, 0)]
  • = A(1, A(0, 2)) [A(0, 1) = 2]
  • = A(1, 3) [A(0, 2) = 3]
  • = A(0, A(1, 2)) [expanding A(1, 3)]
  • ...eventually = 5

Why it's slow:

The double recursion creates an explosion of calls. A(4, 2) makes over 265536 calls - more than atoms in the universe!

Time Complexity: Beyond exponential - grows faster than any primitive recursive function!

Space Complexity: O(m + n) call stack depth

Historical Note: The Ackermann function was created to prove that not all computable functions can be defined using loops alone - some genuinely need recursion!

Problem 6: Count Nodes with Value Greater Than X

Challenge

Problem Description

Swift's been watching Re:Zero - an anime where the protagonist Subaru can return to a previous "checkpoint" when he dies, like loading a save file in a game. Each checkpoint is connected to the next in a timeline (like a linked list!).

Write a recursive function countAbove(head, threshold) that counts how many nodes in a linked list have a value greater than the threshold.

Re:Zero Context: Subaru experiences a timeline of events (checkpoints). We can model this as a linked list where each node represents a checkpoint with a "pain level" value. Let's count how many checkpoints had a pain level above a certain threshold!

Example

Linked list: 10 → 25 → 5 → 30 → 15

Threshold: 12

Result: 3 (nodes with values 25, 30, and 15)

Recursive Insight

  • Base case: If head is NULL, return 0 (no nodes to count)
  • Recursive case: If current node's value > threshold, add 1 to count from rest; otherwise add 0

Output:
Running...
Click "Run Code" to see the output...

Solution

int countAbove(Node* head, int threshold) {
    if (head == NULL) {
        return 0;  // Base case: empty list
    }

    int currentCount = (head->data > threshold) ? 1 : 0;  // Count current node
    return currentCount + countAbove(head->next, threshold);  // Add count from rest
}

Explanation

How it works:

  • Base case: If head is NULL (empty list), return 0
  • Recursive case:
    1. Check if current node's data > threshold
    2. If yes, currentCount = 1; otherwise currentCount = 0
    3. Recursively count nodes in the rest of the list (head->next)
    4. Return currentCount + count from rest

Example trace for list {10, 25, 5} with threshold 12:

  • countAbove(10→25→5, 12)
  • = 0 (10 ≤ 12) + countAbove(25→5, 12)
  • = 0 + 1 (25 > 12) + countAbove(5, 12)
  • = 0 + 1 + 0 (5 ≤ 12) + countAbove(NULL, 12)
  • = 0 + 1 + 0 + 0 (base case)
  • = 1

Alternative solution (cleaner):

int countAbove(Node* head, int threshold) {
    if (head == NULL) return 0;

    int restCount = countAbove(head->next, threshold);  // Count rest first
    return (head->data > threshold) ? (1 + restCount) : restCount;
}

Time Complexity: O(n) - we visit each node once

Space Complexity: O(n) - call stack depth equals number of nodes

Key Patterns You've Learned

  • Single recursion: One recursive call per function (power, countAbove)
  • Multiple recursion: Multiple calls in one function (Ackermann)
  • Array recursion: Process element + recurse on rest
  • Linked list recursion: Process current node + recurse on next
  • Two-pointer recursion: Work from both ends (string reverser)
