Example 1: Factorial with Call Stack Trace

Let's calculate 5! (5 factorial) and trace every step of how the recursion builds up and unwinds.

The Problem

Calculate 5! = 5 × 4 × 3 × 2 × 1 = 120 using recursion.

The Code

int factorial(int n) {
    if (n <= 1) {
        return 1;  // Base case
    }
    return n * factorial(n - 1);  // Recursive case
}

Step-by-Step Trace

Step 1: Initial Call - factorial(5)

• n = 5

• Check: Is n <= 1? No

• Execute: return 5 * factorial(4)

• Wait here until factorial(4) returns

Step 2: factorial(4) is called

• n = 4

• Check: Is n <= 1? No

• Execute: return 4 * factorial(3)

• Wait here until factorial(3) returns

Step 3: factorial(3) is called

• n = 3

• Check: Is n <= 1? No

• Execute: return 3 * factorial(2)

• Wait here until factorial(2) returns

Step 4: factorial(2) is called

• n = 2

• Check: Is n <= 1? No

• Execute: return 2 * factorial(1)

• Wait here until factorial(1) returns

Step 5: factorial(1) is called - BASE CASE!

• n = 1

• Check: Is n <= 1? YES!

• Execute: return 1

• Returns 1 immediately (no more recursion)

Call Stack at Maximum Depth (before unwinding):

┌──────────────────┐
│ factorial(1)     │ ← Returns 1 (base case)
├──────────────────┤
│ factorial(2)     │ ← Waiting for factorial(1)
├──────────────────┤
│ factorial(3)     │ ← Waiting for factorial(2)
├──────────────────┤
│ factorial(4)     │ ← Waiting for factorial(3)
├──────────────────┤
│ factorial(5)     │ ← Waiting for factorial(4)
└──────────────────┘

The Unwinding Phase

Step 6: factorial(2) completes

• Receives 1 from factorial(1)

• Calculates: 2 * 1 = 2

• Returns 2 to factorial(3)

Step 7: factorial(3) completes

• Receives 2 from factorial(2)

• Calculates: 3 * 2 = 6

• Returns 6 to factorial(4)

Step 8: factorial(4) completes

• Receives 6 from factorial(3)

• Calculates: 4 * 6 = 24

• Returns 24 to factorial(5)

Step 9: factorial(5) completes

• Receives 24 from factorial(4)

• Calculates: 5 * 24 = 120

• Returns 120 to main()

Final Result: 5! = 120

The call stack is now empty. All function calls have returned.

Complexity Analysis

Time: O(n) Space: O(n)

Time: We make n recursive calls (one for each value from n down to 1).
Space: The call stack grows to depth n (n stack frames at maximum depth).

Example 2: Fibonacci Sequence - The Problem with Naive Recursion

Let's calculate fibonacci(5) and see why the naive recursive approach is slow.

The Problem

Calculate the 5th Fibonacci number: 0, 1, 1, 2, 3, 5

The Code

int fibonacci(int n) {
    if (n <= 0) return 0;
    if (n == 1) return 1;
    return fibonacci(n - 1) + fibonacci(n - 2);
}

The Problem: Redundant Calculations

Here's the full tree of recursive calls for fibonacci(5): 

                        fib(5)
                       /      \
                  fib(4)      fib(3)
                 /     \      /     \
            fib(3)  fib(2) fib(2) fib(1)
            /    \   /  \   /  \
       fib(2) fib(1) f(1) f(0) f(1) f(0)
       /    \
   fib(1) fib(0)

Count the calls:
fib(5): 1 time
fib(4): 1 time
fib(3): 2 times  ← Calculated twice!
fib(2): 3 times  ← Calculated three times!
fib(1): 5 times  ← Calculated five times!
fib(0): 3 times  ← Calculated three times!

Total function calls: 15 calls to calculate fib(5)!

Manual Calculation

Working from the bottom up:

• fib(0) = 0 (base case)

• fib(1) = 1 (base case)

• fib(2) = fib(1) + fib(0) = 1 + 0 = 1

• fib(3) = fib(2) + fib(1) = 1 + 1 = 2

• fib(4) = fib(3) + fib(2) = 2 + 1 = 3

• fib(5) = fib(4) + fib(3) = 3 + 2 = 5

Result: fibonacci(5) = 5

Why Is This Slow?

Look at how many times we calculate fib(3): twice. For fib(2): three times. This redundancy grows exponentially.

The Problem: For fibonacci(40), we make over 330 million function calls! Most are redundant calculations.

The Better Approach: Iteration

Instead of recursion, use a loop to calculate Fibonacci numbers from the bottom up: 

int fibonacciIterative(int n) {
    if (n <= 0) return 0;
    if (n == 1) return 1;

    int prev = 0, curr = 1;
    for (int i = 2; i <= n; i++) {
        int next = prev + curr;
        prev = curr;
        curr = next;
    }
    return curr;
}

Iterative Trace for fibonacci(5):

• Start: prev = 0, curr = 1

• i = 2: next = 0 + 1 = 1, prev = 1, curr = 1

• i = 3: next = 1 + 1 = 2, prev = 1, curr = 2

• i = 4: next = 1 + 2 = 3, prev = 2, curr = 3

• i = 5: next = 2 + 3 = 5, prev = 3, curr = 5

• Return 5

Complexity Comparison

Approach Time Space Calls for fib(5)
Recursive O(2^n) O(n) 15 calls
Iterative O(n) O(1) 1 call (just the function), n-1 loop iterations
Lesson: Recursion isn't always the answer. When recursion creates redundant calculations (like Fibonacci), iteration is usually better. Use recursion when it makes the problem clearer, not when it makes it slower.

Example 3: Timeline Navigator - Recursive Linked List Traversal

Swift's been watching Link Click - a Chinese anime where characters can dive into photos to experience past events. Each photo links to the next moment in time, forming a timeline. Let's use recursion to navigate this photo timeline!

Link Click Context: The protagonists can "dive" into photographs to witness or change past events. Each photo captures a specific moment in time, and these moments are linked together chronologically - perfect for a linked list structure!

The Problem

Given a linked list of photo moments, we want to:

  1. Print all moments in order (forward traversal)
  2. Print all moments in reverse order (backward traversal)
  3. Find a specific moment by description

The Data Structure

struct PhotoMoment {
    string description;
    int timestamp;  // Seconds from start of timeline
    PhotoMoment* next;
};

Forward Traversal (Print in Order)

void printTimeline(PhotoMoment* current) {
    if (current == NULL) {
        return;  // Base case: end of timeline
    }

    // Print current moment
    cout << "[" << current->timestamp << "s] "
         << current->description << endl;

    // Recursively print rest of timeline
    printTimeline(current->next);
}

How it works:

• Base case: If current is NULL, we've reached the end - stop

• Recursive case: Print current moment, then recursively print the rest

• Because we print BEFORE recursing, moments appear in forward order

Reverse Traversal (Print Backwards)

void printTimelineReverse(PhotoMoment* current) {
    if (current == NULL) {
        return;  // Base case: end of timeline
    }

    // Recursively print rest of timeline FIRST
    printTimelineReverse(current->next);

    // THEN print current moment
    cout << "[" << current->timestamp << "s] "
         << current->description << endl;
}

How it works:

• Base case: Same as forward - NULL means stop

• Recursive case: Go to the end FIRST (recurse), then print on the way back

• Because we print AFTER recursing, moments appear in reverse order

Call Stack Visualization for Reverse

Given timeline: Moment1 → Moment2 → Moment3 → NULL

Going down (recursion):
printTimelineReverse(Moment1)
    printTimelineReverse(Moment2)
        printTimelineReverse(Moment3)
            printTimelineReverse(NULL)  ← Returns immediately

Coming back up (unwinding - THIS is when we print):
            [prints Moment3]  ← Printed first (last in, first out)
        [prints Moment2]      ← Printed second
    [prints Moment1]          ← Printed last

Output order: Moment3, Moment2, Moment1 (REVERSED!)

Search for a Specific Moment

PhotoMoment* findMoment(PhotoMoment* current, string target) {
    if (current == NULL) {
        return NULL;  // Base case: not found
    }

    if (current->description == target) {
        return current;  // Found it!
    }

    // Search in rest of timeline
    return findMoment(current->next, target);
}

How it works:

• Base case 1: If current is NULL, we searched the whole timeline and didn't find it - return NULL

• Base case 2: If current moment matches target, we found it - return pointer to it

• Recursive case: Search the rest of the timeline

Example 4: Find the Bug - Missing Base Case

One of Swift's students, Kayana, wrote a recursive function to sum numbers from 1 to n. But when she runs it, the program crashes with a stack overflow. Can you spot the bug?

Kayana's Code

int sumToN(int n) {
    if (n == 1) {
        return 1;
    }
    return n + sumToN(n - 1);
}

int main() {
    cout << sumToN(5) << endl;   // Should print 15
    cout << sumToN(0) << endl;   // What happens here?
    return 0;
}
The Bug: When you call sumToN(0), the program crashes!

Why Does It Crash?

Trace sumToN(0):

• n = 0

• Is n == 1? No

• Call sumToN(-1)

Trace sumToN(-1):

• n = -1

• Is n == 1? No

• Call sumToN(-2)

Trace sumToN(-2):

• n = -2

• Is n == 1? No

• Call sumToN(-3)

...and so on, forever! The base case n == 1 is never reached when n starts at 0 or below. 

Call stack grows infinitely:

sumToN(0)
    sumToN(-1)
        sumToN(-2)
            sumToN(-3)
                sumToN(-4)
                    sumToN(-5)
                        ...
                        (Eventually: STACK OVERFLOW!)

The Fix

The base case should handle ALL stopping conditions, including n <= 0: 

int sumToN(int n) {
    if (n <= 1) {        // Changed from n == 1
        return (n == 1) ? 1 : 0;  // Return 0 for n <= 0
    }
    return n + sumToN(n - 1);
}

Or, more clearly:

int sumToN(int n) {
    if (n <= 0) {
        return 0;  // Base case for 0 or negative
    }
    if (n == 1) {
        return 1;  // Base case for 1
    }
    return n + sumToN(n - 1);
}

Testing the Fix

Now sumToN(0) works:

• n = 0

• Is n <= 0? YES

• Return 0 immediately (no recursion)

And sumToN(5) still works:

• sumToN(5) = 5 + sumToN(4)

• sumToN(4) = 4 + sumToN(3)

• sumToN(3) = 3 + sumToN(2)

• sumToN(2) = 2 + sumToN(1)

• sumToN(1) = 1 (base case)

• Result: 5 + 4 + 3 + 2 + 1 = 15 ✓

Lesson Learned: Always think about edge cases for your base case:
  • What if n is 0?
  • What if n is negative?
  • What if the list is empty (NULL)?

Your base case must handle ALL possible stopping conditions, not just the "normal" one.

Example 5: Finding Maximum in Array - Divide and Conquer

Let's find the maximum value in an array using a divide-and-conquer approach with recursion.

The Problem

Given array {15, 42, 8, 23, 67, 19}, find the maximum value (67).

The Approach

Instead of comparing every element, we:

  1. Split the problem in half
  2. Find the max of each half (recursively)
  3. Return the larger of the two maxes

The Code

int findMax(int arr[], int left, int right) {
    // Base case: only one element
    if (left == right) {
        return arr[left];
    }

    // Base case: two elements
    if (right - left == 1) {
        return (arr[left] > arr[right]) ? arr[left] : arr[right];
    }

    // Recursive case: divide and conquer
    int mid = (left + right) / 2;
    int leftMax = findMax(arr, left, mid);
    int rightMax = findMax(arr, mid + 1, right);

    return (leftMax > rightMax) ? leftMax : rightMax;
}

Step-by-Step Trace

For array: {15, 42, 8, 23, 67, 19} (indices 0-5)

findMax(arr, 0, 5)                           [15, 42, 8, 23, 67, 19]
    mid = 2
    leftMax = findMax(arr, 0, 2)             [15, 42, 8]
        mid = 1
        leftMax = findMax(arr, 0, 1)         [15, 42]
            Base case: max(15, 42) = 42
        rightMax = findMax(arr, 2, 2)        [8]
            Base case: return 8
        return max(42, 8) = 42

    rightMax = findMax(arr, 3, 5)            [23, 67, 19]
        mid = 4
        leftMax = findMax(arr, 3, 4)         [23, 67]
            Base case: max(23, 67) = 67
        rightMax = findMax(arr, 5, 5)        [19]
            Base case: return 19
        return max(67, 19) = 67

    return max(42, 67) = 67  ← Final answer!

Visual Tree Representation

                    [15,42,8,23,67,19]
                           |
                    max(42, 67) = 67
                     /              \
            [15,42,8]              [23,67,19]
                |                      |
            max(42,8)=42          max(67,19)=67
             /      \              /         \
        [15,42]    [8]        [23,67]       [19]
          |         |           |             |
         42         8          67            19

Why Use This Approach?

You might be thinking: "Why not just loop through the array?" Good question! Here's the comparison:

Approach Time Space Pros
Iterative loop O(n) O(1) Simple, uses minimal memory
Divide & conquer O(n) O(log n) Can be parallelized, foundation for more complex algorithms
When to use divide-and-conquer:
  • When the problem can be split into independent subproblems
  • When you can parallelize the work (each half can be processed separately)
  • As a foundation for more advanced algorithms (merge sort, quick sort)

For simple max-finding, a loop is better. But divide-and-conquer teaches a valuable problem-solving pattern!

Complexity Analysis

Time: O(n) Space: O(log n)

Time: We visit each element once (n comparisons total across all recursive calls).
Space: Call stack depth is O(log n) because we split the problem in half each time.

Summary

You've seen five complete examples of recursion in action:

  1. Factorial: Classic linear recursion with detailed call stack trace
  2. Fibonacci: Tree recursion showing the problem with redundant calculations
  3. Photo Timeline: Recursive linked list traversal (forward and reverse)
  4. Bug Hunting: Debugging a missing/incomplete base case
  5. Array Maximum: Divide-and-conquer approach

Key Takeaways

  • Always trace your recursion: Draw the call stack to understand what happens
  • Watch for redundant work: Tree recursion can recalculate the same values many times
  • Test edge cases: Make sure your base case handles 0, negative numbers, NULL, empty arrays, etc.
  • Consider alternatives: Sometimes iteration is clearer and faster
  • Recursion shines for: Trees, linked lists, divide-and-conquer, backtracking
