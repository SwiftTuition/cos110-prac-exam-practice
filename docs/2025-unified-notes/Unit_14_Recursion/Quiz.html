Q1 [1 mark]

What is a base case in a recursive function?

A) The first function call in the recursion
B) The condition that stops the recursion
C) The main function that calls the recursive function
D) The return statement in the recursive function
Correct Answer: B) The condition that stops the recursion

Explanation:

The base case is the terminating condition in a recursive function. Without a base case, the function would recurse infinitely, eventually causing a stack overflow.

Why B is correct:

The base case defines when recursion should stop. It's the condition where the function returns a value directly without making another recursive call.

int factorial(int n) {
    if (n <= 1)  // BASE CASE - stops recursion
        return 1;
    return n * factorial(n - 1);  // Recursive case
}

Why other options are wrong:

  • A: The first function call is just the initial invocation, not the base case. The base case is checked on every call.
  • C: The main function (or any calling function) is external to the recursion mechanism. The base case is inside the recursive function itself.
  • D: A return statement exists in both the base case AND recursive case. The base case specifically returns without recursing further.
Key Point: Every recursive function must have at least one base case to prevent infinite recursion.
Q2 [1 mark]

What happens if a recursive function does not have a base case?

A) The function will compile but never execute
B) The compiler will produce a syntax error
C) The function will cause a stack overflow
D) The function will automatically stop after 1000 calls
Correct Answer: C) The function will cause a stack overflow

Explanation:

Without a base case, a recursive function will continue calling itself indefinitely. Each call adds a new frame to the call stack, eventually exhausting available stack memory and causing a stack overflow error.

What happens in detail:

  1. Function calls itself: Each recursive call creates a new stack frame
  2. Stack grows: Memory is consumed with each frame (parameters, local variables, return address)
  3. Stack limit reached: When stack memory is exhausted, the program crashes
  4. Error message: "Stack overflow" or "Segmentation fault" depending on the system

Example of infinite recursion:

void infiniteRecursion(int n) {
    cout << n << endl;
    infiniteRecursion(n - 1);  // No base case - never stops!
}

Why other options are wrong:

  • A: The function will execute - it will just never terminate properly.
  • B: This is not a syntax error. The code is syntactically valid, just logically flawed.
  • D: C++ has no automatic recursion limit. The function continues until stack memory is exhausted (typically thousands of calls, varying by system).
Warning: Always ensure your recursive function progresses toward the base case on every call!
Q3 [1 mark]

What is the time complexity of calculating fibonacci(n) using naive recursion?

A) O(n)
B) O(n log n)
C) O(n²)
D) O(2ⁿ)
Correct Answer: D) O(2ⁿ)

Explanation:

Naive recursive Fibonacci has exponential time complexity because each call spawns two more calls, leading to massive redundant computation.

The naive recursive implementation:

int fibonacci(int n) {
    if (n <= 1)
        return n;
    return fibonacci(n-1) + fibonacci(n-2);
}

Why it's O(2ⁿ):

Each function call makes 2 more calls (except base cases). This creates an exponential call tree:

                    fib(5)
                   /      \
              fib(4)      fib(3)
              /    \       /    \
         fib(3)  fib(2) fib(2) fib(1)
         /   \    /  \    /  \
      fib(2) fib(1) ...  ...
       /  \
    fib(1) fib(0)

Total calls ≈ 2⁵ = 32 calls for fib(5)

The number of calls approximately doubles with each increment of n, giving O(2ⁿ) complexity. More precisely, it's O(φⁿ) where φ ≈ 1.618 (golden ratio), but we simplify to O(2ⁿ).

Why other options are wrong:

  • A) O(n): This would be the complexity of iterative Fibonacci or memoized recursion, not naive recursion.
  • B) O(n log n): This complexity is typical for divide-and-conquer algorithms like merge sort, not Fibonacci.
  • C) O(n²): This would mean nested loops over n. Fibonacci's tree structure is much worse.
Important: For n=40, naive Fibonacci makes over 2 billion calls! Use memoization or iteration for practical applications.
Q4 [1 mark]

What is tail recursion?

A) Recursion that operates on the tail of a linked list
B) Recursion where the recursive call is the last operation in the function
C) Recursion that returns the last element of an array
D) Recursion that has multiple base cases at the end
Correct Answer: B) Recursion where the recursive call is the last operation in the function

Explanation:

Tail recursion occurs when the recursive call is the very last thing the function does. No computation happens after the recursive call returns.

Tail Recursive Example:

// Tail recursive - recursive call is last operation
int factorial(int n, int accumulator = 1) {
    if (n <= 1)
        return accumulator;
    return factorial(n - 1, n * accumulator);  // Last operation
}

NOT Tail Recursive Example:

// NOT tail recursive - multiplication happens AFTER recursive call
int factorial(int n) {
    if (n <= 1)
        return 1;
    return n * factorial(n - 1);  // Multiplication after return
}

Why tail recursion matters:

Compilers can optimize tail recursion into a loop (tail call optimization), using constant stack space instead of growing the stack with each call. This makes it as efficient as iteration.

Why other options are wrong:

  • A: "Tail" refers to the position of the recursive call in the code, not data structure tails.
  • C: Returning the last element has nothing to do with tail recursion structure.
  • D: The number/position of base cases doesn't define tail recursion - it's about where the recursive call occurs.
Key Point: In tail recursion, the function's return value is directly the result of the recursive call, with no pending operations.
Q5 [1 mark]

How much space on the call stack does a recursive function use?

A) O(1) - constant space
B) O(n) - proportional to recursion depth
C) O(n²) - squared with input size
D) O(log n) - logarithmic space
Correct Answer: B) O(n) - proportional to recursion depth

Explanation:

Each recursive call adds a new frame to the call stack. The maximum stack space used equals the maximum recursion depth.

Example - factorial(5):

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

Call stack progression:

Call 1: factorial(5)   |  Stack: [factorial(5)]
Call 2: factorial(4)   |  Stack: [factorial(5), factorial(4)]
Call 3: factorial(3)   |  Stack: [factorial(5), factorial(4), factorial(3)]
Call 4: factorial(2)   |  Stack: [factorial(5), factorial(4), factorial(3), factorial(2)]
Call 5: factorial(1)   |  Stack: [factorial(5), factorial(4), factorial(3), factorial(2), factorial(1)]
                       |  Max depth = 5 frames = O(n)

For input n, the recursion goes n levels deep, so space complexity is O(n).

Why other options are wrong:

  • A) O(1): This would mean constant space regardless of input. Recursion grows the stack linearly with depth.
  • C) O(n²): This would require nested recursion or storing n elements at each of n levels. Linear recursion is O(n).
  • D) O(log n): This applies to divide-and-conquer algorithms that halve the problem each time (like binary search tree operations). Linear recursion like factorial is O(n).
Special Cases:
  • Tail recursion (optimized): O(1) - compiler converts to loop
  • Binary tree traversal: O(height) - could be O(log n) for balanced, O(n) for skewed
  • Divide-and-conquer (binary search): O(log n)
Q6 [1 mark]

Which of the following problems is BEST solved using recursion?

A) Finding the sum of elements in an array
B) Traversing a binary tree
C) Calculating the average of a list of numbers
D) Finding the largest element in an array
Correct Answer: B) Traversing a binary tree

Explanation:

Tree traversal is inherently recursive because trees are recursive data structures - each subtree is itself a tree. Recursion naturally mirrors this structure.

Why recursion fits trees perfectly:

void inorderTraversal(Node* root) {
    if (root == NULL)  // Base case
        return;

    inorderTraversal(root->left);    // Traverse left subtree
    cout << root->data << " ";       // Process node
    inorderTraversal(root->right);   // Traverse right subtree
}

Each node's subtrees are processed the same way, making recursion elegant and natural. The iterative version requires explicit stack management and is much more complex.

Why other options are wrong:

  • A) Sum of array elements: Simple loop is clearer and more efficient. Recursion adds unnecessary overhead. 
    // Iteration is better
int sum = 0;
for (int i = 0; i < size; i++)
    sum += arr[i];
  • C) Average of numbers: Straightforward calculation, no recursive structure. Iteration is natural.
  • D) Finding maximum: Single pass with a loop is simpler and more efficient than recursion.
When recursion shines: Tree/graph traversal, divide-and-conquer (merge sort, quick sort), backtracking (N-queens, sudoku), dynamic programming (when memoized).
Q7 [1 mark]

What is "tree recursion"?

A) Recursion used only for tree data structures
B) Recursion that makes multiple recursive calls in one function call
C) Recursion with more than one base case
D) Recursion that uses a tree to store intermediate results
Correct Answer: B) Recursion that makes multiple recursive calls in one function call

Explanation:

Tree recursion occurs when a function makes more than one recursive call. This creates a tree-shaped call structure rather than a linear chain.

Classic Example - Fibonacci:

int fibonacci(int n) {
    if (n <= 1) return n;

    // TWO recursive calls - creates tree structure
    return fibonacci(n-1) + fibonacci(n-2);
}

Call tree for fibonacci(4):

                    fib(4)
                   /      \
              fib(3)      fib(2)
              /    \       /    \
         fib(2) fib(1) fib(1) fib(0)
         /   \
    fib(1) fib(0)

This branching creates a TREE structure

Compare to Linear Recursion (factorial):

int factorial(int n) {
    if (n <= 1) return 1;

    // ONE recursive call - creates linear chain
    return n * factorial(n-1);
}

Call chain for factorial(4): fact(4) → fact(3) → fact(2) → fact(1) (linear, not tree)

Why other options are wrong:

  • A: Tree recursion can be used for problems that don't involve tree data structures (like Fibonacci, which works on integers).
  • C: Number of base cases doesn't define tree recursion - it's about multiple recursive calls.
  • D: Tree recursion describes the call structure, not data storage. (Though memoization might use a tree/map for caching.)
Performance Warning: Tree recursion often has exponential time complexity due to redundant calculations. Consider memoization!
Q8 [1 mark]

Which statement about recursion vs iteration is TRUE?

A) Recursive solutions always run faster than iterative solutions
B) Every recursive function can be converted to an iterative function
C) Iteration uses more memory than recursion
D) Recursion cannot solve problems that iteration can solve
Correct Answer: B) Every recursive function can be converted to an iterative function

Explanation:

This is a fundamental truth in computer science. Any problem solvable with recursion can also be solved iteratively using an explicit stack to manage state. They are computationally equivalent.

Example - Factorial Both Ways:

// Recursive version
int factorialRecursive(int n) {
    if (n <= 1) return 1;
    return n * factorialRecursive(n-1);
}

// Iterative version
int factorialIterative(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}

Even complex tree recursion can be converted using an explicit stack:

// Tree traversal iteratively using stack
void inorderIterative(Node* root) {
    stack<Node*> s;
    Node* current = root;

    while (current != NULL || !s.empty()) {
        while (current != NULL) {
            s.push(current);
            current = current->left;
        }
        current = s.top();
        s.pop();
        cout << current->data;
        current = current->right;
    }
}

Why other options are wrong:

  • A: FALSE - Recursion often has overhead from function calls. Iteration is typically faster or equal.
  • C: FALSE - Recursion uses MORE memory (call stack grows with depth). Iteration typically uses constant space.
  • D: FALSE - They're equivalent in power. Anything iteration can solve, recursion can too (and vice versa).
Choosing Between Them:
  • Use recursion when: Problem is naturally recursive (trees, divide-and-conquer), code clarity matters
  • Use iteration when: Performance critical, stack depth might be large, simpler logic
Q9 [1 mark]

What is the purpose of a helper function in recursion?

A) To provide a user-friendly interface while maintaining additional parameters for recursion
B) To make the recursive function run faster
C) To prevent stack overflow
D) To convert recursion into iteration
Correct Answer: A) To provide a user-friendly interface while maintaining additional parameters for recursion

Explanation:

Helper functions allow clean public interfaces while the private recursive implementation uses extra parameters (like accumulators, indices, or partial results) that users shouldn't need to provide.

Example - Summing a linked list:

// Public interface - user just calls this
int sumList(Node* head) {
    return sumListHelper(head, 0);  // Initialize accumulator to 0
}

// Private helper - does the recursion with accumulator
int sumListHelper(Node* current, int accumulator) {
    if (current == NULL)
        return accumulator;  // Base case - return total

    return sumListHelper(current->next,
                         accumulator + current->data);
}

User calls: int total = sumList(myList); - simple!
Without helper: int total = sumList(myList, 0); - user must know to pass 0

Example - Checking if array is sorted:

// Public - clean interface
bool isSorted(int arr[], int size) {
    return isSortedHelper(arr, size, 0);  // Start at index 0
}

// Helper - needs index parameter
bool isSortedHelper(int arr[], int size, int index) {
    if (index >= size - 1)  // Base case
        return true;

    if (arr[index] > arr[index + 1])
        return false;

    return isSortedHelper(arr, size, index + 1);
}

Why other options are wrong:

  • B: Helper functions don't improve performance - same recursive calls happen. They improve API design.
  • C: Helpers don't prevent stack overflow. The recursion depth is the same.
  • D: Helpers are still recursive. Converting to iteration requires different approach (explicit stack or loops).
Common Helper Parameters: Index (for arrays), accumulator (for tail recursion), previous value, partial results
Q10 [1 mark]

What are mutually recursive functions?

A) Functions that call each other recursively
B) Functions that share the same base case
C) Functions that recursively process mutual data
D) Functions that must be called together
Correct Answer: A) Functions that call each other recursively

Explanation:

Mutually recursive functions are two or more functions where function A calls function B, and function B calls function A (directly or indirectly). They define each other recursively.

Classic Example - Even/Odd Check:

bool isEven(int n);  // Forward declaration needed
bool isOdd(int n);

bool isEven(int n) {
    if (n == 0)
        return true;
    else
        return isOdd(n - 1);  // Calls isOdd
}

bool isOdd(int n) {
                if (n == 0)
        return false;
    else
        return isEven(n - 1);  // Calls isEven
}

Call chain for isEven(4):

isEven(4) → isOdd(3) → isEven(2) → isOdd(1) → isEven(0) → true
                                                           ↑
                                                      Base case

Example - Hofstadter Female/Male Sequences:

Source: Adapted from EO3 2018, Question 3.2

int F(int n) {  // Female sequence
    if (n == 0) return 1;
    return n - M(F(n - 1));  // Calls M
}

int M(int n) {  // Male sequence
    if (n == 0) return 0;
    return n - F(M(n - 1));  // Calls F
}

Why other options are wrong:

  • B: Sharing a base case isn't the defining feature. Many separate recursive functions can have similar base cases (e.g., if (n == 0)).
  • C: "Mutual data" is vague. The key is mutual CALLING, not shared data structures.
  • D: They don't need to be called together by the user. One function starts, which then calls the other as needed.
Important: Forward declarations are required when functions mutually call each other, since each needs to know about the other before definition.

Q11 [2 marks]

True or False: Every recursive function must have exactly one base case.

Justify your answer with an example.

Answer: FALSE

Justification:

A recursive function can have multiple base cases. Each base case handles a different terminating condition. Having multiple base cases is common and often necessary.

Example 1 - Fibonacci (2 base cases):

int fibonacci(int n) {
    if (n == 0)  // Base case 1
        return 0;
    if (n == 1)  // Base case 2
        return 1;

    return fibonacci(n-1) + fibonacci(n-2);
}

Both n == 0 and n == 1 are base cases. Without both, you'd get incorrect results or infinite recursion for n=0.

Example 2 - Recursive GCD (Greatest Common Divisor):

int gcd(int a, int b) {
    if (b == 0)  // Base case 1
        return a;
    if (a == 0)  // Base case 2
        return b;

    return gcd(b, a % b);
}

Two base cases handle the cases where either number becomes 0.

Example 3 - Ackermann function (3 base cases):

int ackermann(int m, int n) {
    if (m == 0)  // Base case 1
        return n + 1;
    if (n == 0)  // Base case 2
        return ackermann(m - 1, 1);
    // Base case 3 is the general recursive case
    return ackermann(m - 1, ackermann(m, n - 1));
}

Key Points:

  • A function needs at least one base case to terminate
  • Multiple base cases are fine and often necessary
  • Each base case handles different terminating conditions
  • All base cases must eventually be reached to avoid infinite recursion
Rule of Thumb: You need enough base cases to cover all possible terminating conditions in your problem.
Q12 [2 marks]

True or False: With tail call optimization, tail recursive functions use O(1) space complexity instead of O(n).

Justify your answer and explain why.

Answer: TRUE

Justification:

When a compiler implements tail call optimization (TCO), it can reuse the same stack frame for each recursive call instead of creating new ones. This converts the recursion into iteration "behind the scenes," using constant O(1) space.

How Tail Call Optimization Works:

In tail recursion, the recursive call is the LAST operation. The function doesn't need to remember anything after the call returns - no pending operations. The compiler can:

  1. Replace the current stack frame's parameters with new values
  2. Jump back to the beginning of the function
  3. Effectively convert recursion into a loop

Example - Tail Recursive Factorial:

// With TCO: O(1) space
int factorial(int n, int acc = 1) {
    if (n <= 1)
        return acc;
    return factorial(n - 1, n * acc);  // Tail call - last operation
}

// Compiler optimizes to equivalent loop:
int factorial_optimized(int n, int acc = 1) {
    while (n > 1) {
        acc = n * acc;
        n = n - 1;
    }
    return acc;
}

Without TCO (normal recursion): O(n) space

// NOT tail recursive - O(n) space
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);  // Multiplication AFTER call
}

// Stack grows:
// factorial(5) waits for factorial(4)
// factorial(4) waits for factorial(3)
// ... all frames stay on stack until base case
// Space used: 5 frames = O(n)

Important Caveats:

  • C++: TCO is not guaranteed by the standard. Some compilers do it with optimization flags (-O2, -O3), some don't.
  • Functional languages: Scheme, Haskell guarantee TCO
  • Without TCO: Even tail recursive functions use O(n) space
Key Point: "With tail call optimization" is the key phrase. If the compiler performs TCO, space is O(1). Without it, space is still O(n) even for tail recursive code.
Q13 [2 marks]

True or False: Recursive solutions are always slower than iterative solutions for the same problem.

Justify your answer with reasoning.

Answer: FALSE

Justification:

While recursion often has overhead from function calls, this is not ALWAYS the case. Performance depends on optimization, problem structure, and implementation.

Cases Where Performance is Equal or Better:

1. Tail Call Optimization:

With TCO enabled, tail recursive functions are transformed into loops by the compiler, giving identical performance to iteration.

// With TCO, this is AS FAST as iteration
int factorial(int n, int acc = 1) {
    if (n <= 1) return acc;
    return factorial(n - 1, n * acc);
}

2. Compiler Inline Optimization:

For small recursive functions, modern compilers can inline them, eliminating call overhead entirely.

3. Problem-Dependent Complexity:

For divide-and-conquer algorithms, both recursion and iteration have the same asymptotic complexity. The constant factors may be negligible.

// Binary search: O(log n) both ways
// Iterative version
int binarySearchIterative(int arr[], int target, int size) {
    int left = 0, right = size - 1;
    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] == target) return mid;
        if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}

// Recursive version - with good compiler, similar performance
int binarySearchRecursive(int arr[], int target, int left, int right) {
    if (left > right) return -1;
    int mid = (left + right) / 2;
    if (arr[mid] == target) return mid;
    if (arr[mid] < target)
        return binarySearchRecursive(arr, target, mid + 1, right);
    return binarySearchRecursive(arr, target, left, mid - 1);
}

4. Cache Behavior:

Sometimes recursion has better cache locality than complex iterative solutions with explicit stacks.

When Recursion IS Slower:

  • Deep recursion without TCO (stack overflow risk)
  • Tree recursion without memoization (exponential redundancy)
  • Simple problems where iteration is straightforward (factorial, sum)
Bottom Line: With optimization and appropriate problems, recursion CAN match iteration's speed. The "always" in the statement makes it FALSE.
Q14 [2 marks]

True or False: Any iterative algorithm can be converted to a recursive algorithm.

Justify your answer.

Answer: TRUE

Justification:

Iteration and recursion are computationally equivalent - any problem solvable by iteration can also be solved by recursion, and vice versa. This is a fundamental principle in computer science.

How to Convert Iteration to Recursion:

The general pattern:

  1. Loop variable(s) become function parameter(s)
  2. Loop condition becomes base case (inverted)
  3. Loop body becomes recursive call with updated parameters

Example 1 - Simple Sum:

// Iterative
int sumIterative(int n) {
    int total = 0;
    for (int i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

// Converted to Recursive
int sumRecursive(int n, int total = 0) {
    if (n == 0)  // Loop condition inverted
        return total;
    return sumRecursive(n - 1, total + n);  // i-- becomes n-1, total+=i becomes total+n
}

Example 2 - Array Processing:

// Iterative
int findMax(int arr[], int size) {
    int max = arr[0];
    for (int i = 1; i < size; i++) {
        if (arr[i] > max)
            max = arr[i];
    }
    return max;
}

// Converted to Recursive
int findMaxRecursive(int arr[], int size, int index = 0, int currentMax = INT_MIN) {
    if (index == size)  // Loop end condition
        return currentMax;

    int newMax = (arr[index] > currentMax) ? arr[index] : currentMax;
    return findMaxRecursive(arr, size, index + 1, newMax);
}

Example 3 - Even Complex Loops:

// Nested loops iteratively
void printPairs(int n) {
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            cout << "(" << i << "," << j << ") ";
        }
    }
}

// Recursive version
void printPairsHelper(int n, int i, int j) {
    if (i == n) return;  // Done with all rows

    cout << "(" << i << "," << j << ") ";

    if (j == n - 1)  // End of row, move to next
        printPairsHelper(n, i + 1, 0);
    else
        printPairsHelper(n, i, j + 1);
}

void printPairs(int n) {
    printPairsHelper(n, 0, 0);
}

Key Points:

  • Loop variables → function parameters
  • Loop updates → parameter changes in recursive call
  • Loop termination → base case
  • May need helper function for accumulator/index parameters
Theoretical Basis: Turing completeness - both iteration (Turing machine) and recursion (lambda calculus) can compute the same set of functions.
Q15 [2 marks]

True or False: For searching in a sorted array, a recursive binary search is more efficient than an iterative linear search.

Justify your answer with complexity analysis.

Answer: TRUE

Justification:

Recursive binary search has O(log n) time complexity, while iterative linear search has O(n). For large arrays, O(log n) is significantly more efficient than O(n).

Recursive Binary Search - O(log n):

int binarySearchRecursive(int arr[], int target, int left, int right) {
    if (left > right)  // Base case - not found
        return -1;

    int mid = (left + right) / 2;

    if (arr[mid] == target)  // Found
        return mid;

    if (arr[mid] < target)  // Search right half
        return binarySearchRecursive(arr, target, mid + 1, right);
    else  // Search left half
        return binarySearchRecursive(arr, target, left, mid - 1);
}

// Time: O(log n) - halves search space each call
// Space: O(log n) - recursion depth

Iterative Linear Search - O(n):

int linearSearch(int arr[], int size, int target) {
    for (int i = 0; i < size; i++) {
        if (arr[i] == target)
            return i;
    }
    return -1;  // Not found
}

// Time: O(n) - may check every element
// Space: O(1)

Complexity Comparison:

Array Size Linear Search (worst case) Binary Search (worst case)
10 10 comparisons 4 comparisons
100 100 comparisons 7 comparisons
1,000,000 1,000,000 comparisons 20 comparisons

Why Binary Search is More Efficient:

  • Divide and Conquer: Binary search halves the search space each iteration
  • Logarithmic Growth: log₂(1,000,000) = 20 vs linear 1,000,000
  • Sorted Array Required: Binary search ONLY works on sorted data (key assumption in question)

Important Note:

The question compares recursive binary search vs iterative linear search. The recursion vs iteration part is irrelevant - the algorithm choice (binary vs linear) is what matters. Binary search (recursive OR iterative) beats linear search for sorted arrays.

Key Takeaway: O(log n) << O(n) for large n. Binary search (recursive or not) is vastly superior for sorted arrays.

Q21 [5 marks]

The following recursive function is intended to calculate the sum of integers from 1 to n. However, it has a bug. Identify the bug, explain what's wrong, and provide the corrected code.

Source: Adapted from EO3 2018, Question 3.1

int sum(int n) {
    if (n == 0)
        return 0;
    return sum(n) + n;
}
Bug Location: Line 4 - return sum(n) + n;

What's Wrong:

The recursive call is sum(n) instead of sum(n - 1). This causes infinite recursion because the function keeps calling itself with the same value of n, never progressing toward the base case.

Why It's Wrong:

  1. No progression to base case: For recursion to terminate, each call must move closer to the base case. Here, n never decreases.
  2. Infinite loop: sum(5) calls sum(5), which calls sum(5), forever.
  3. Stack overflow: Each call adds a frame to the stack. Eventually, stack memory is exhausted, causing a crash.

Execution if we tried sum(3):

sum(3) → calls sum(3) → calls sum(3) → calls sum(3) → ...
   ↓        ↓              ↓              ↓
Never reaches base case (n == 0)
Stack grows infinitely until crash

Corrected Code:

int sum(int n) {
    if (n == 0)
        return 0;
    return sum(n - 1) + n;  // FIX: n-1 instead of n
}

Why the Fix Works:

Now each recursive call decrements n by 1, progressing toward the base case (n == 0):

sum(3) calls sum(2) calls sum(1) calls sum(0)
                                         ↓
                                    returns 0

Unwinding:
sum(0) = 0
sum(1) = sum(0) + 1 = 0 + 1 = 1
sum(2) = sum(1) + 2 = 1 + 2 = 3
sum(3) = sum(2) + 3 = 3 + 3 = 6  ✓

Verification:

sum(3) = 3 + 2 + 1 = 6 ✓

sum(5) = 5 + 4 + 3 + 2 + 1 = 15 ✓

Common Mistake Pattern: Forgetting to modify the recursive parameter is a classic error. Always ensure recursion progresses toward the base case by changing parameters (decrement, halve, move pointer, etc.).

Key Takeaway:

The recursive call MUST make the problem smaller. In this case, that means calling sum(n-1), not sum(n).

The following function is supposed to find the maximum value in an array recursively. It contains a bug. Find it, explain the problem, and fix it.

        return arr[0];

        return arr[size];
    else
        return maxRest;

Bug Location: Line 7 - if (arr[size] > maxRest) and Line 8 - return arr[size];

What's Wrong:

The function accesses arr[size], which is out of bounds. Array indices go from 0 to size-1. Index `size` doesn't exist.

Why It's Wrong:

  1. Index out of bounds: For an array of size n, valid indices are 0 to n-1. arr[size] accesses memory beyond the array.
  2. Undefined behavior: Reading arr[size] could return garbage data, crash the program, or appear to work by chance.
  3. Wrong comparison: We want to compare the last element (arr[size-1]) with the max of the rest.

Example - Why It Fails:

// Base case: size == 1 returns arr[0] = 5
// Recursive case checks arr[size] = arr[4] ← OUT OF BOUNDS!
Array:  [5, 2, 8, 1]
Index:   0  1  2  3   4 ← DOESN'T EXIST!
                      ↑
                 Bug tries to access this

Corrected Code:

int findMax(int arr[], int size) {
    if (size == 1)
        return arr[0];

    int maxRest = findMax(arr, size - 1);

    if (arr[size - 1] > maxRest)  // FIX: size-1 instead of size
        return arr[size - 1];      // FIX: size-1 instead of size
    else
        return maxRest;
}

Now we correctly compare arr[size-1] (the last element) with the maximum of the first size-1 elements.

      Compare arr[2] (8) vs 5 → max = 8
   Compare arr[3] (1) vs 8 → max = 8

Approach 2 - Pass index parameter:

    if (arr[index] > maxRest)
        return arr[index];

}

  • Array of size n has indices 0 to n-1

Q23 [3 marks]

Write a recursive function power(int base, int exp) that calculates baseexp (base raised to the power exp). Assume exp ≥ 0.

Example: power(2, 3) returns 8 (2³ = 8)

Solution: 
int power(int base, int exp) {
    // Base case: any number to power 0 is 1
    if (exp == 0)
        return 1;

    // Recursive case: base^exp = base × base^(exp-1)
    return base * power(base, exp - 1);
}

How It Works:

The function uses the mathematical property: baseexp = base × baseexp-1

Example Execution - power(2, 3):

power(2, 3)
= 2 × power(2, 2)
= 2 × (2 × power(2, 1))
= 2 × (2 × (2 × power(2, 0)))
= 2 × (2 × (2 × 1))
= 2 × (2 × 2)
= 2 × 4
= 8  ✓

Call Stack Trace:

  1. power(2, 3) → calls power(2, 2)
  2. power(2, 2) → calls power(2, 1)
  3. power(2, 1) → calls power(2, 0)
  4. power(2, 0) → returns 1 (base case)
  5. power(2, 1) → returns 2 × 1 = 2
  6. power(2, 2) → returns 2 × 2 = 4
  7. power(2, 3) → returns 2 × 4 = 8

Complexity Analysis:

  • Time Complexity: O(exp) - makes exp recursive calls
  • Space Complexity: O(exp) - call stack depth

Alternative - Optimized Version (O(log exp)):

int powerFast(int base, int exp) {
    if (exp == 0) return 1;
    if (exp == 1) return base;

    // If exp is even: base^exp = (base^(exp/2))^2
    if (exp % 2 == 0) {
        int half = powerFast(base, exp / 2);
        return half * half;
    }
    // If exp is odd: base^exp = base × base^(exp-1)
    return base * powerFast(base, exp - 1);
}
Key Pattern: Exponentiation by repeated multiplication. Each recursive call decreases the exponent by 1 until reaching 0.
Q24 [4 marks]

Write a recursive function bool isSorted(int arr[], int size) that returns true if the array is sorted in ascending order, false otherwise. Use a helper function if needed.

Test cases:

  • {1, 2, 3, 4} → true
  • {1, 3, 2, 4} → false
  • {5} → true (single element)

Source: Similar to EO3 2016, Question 3 patterns

Solution: 
// Helper function with index parameter
bool isSortedHelper(int arr[], int size, int index) {
    // Base case: reached second-to-last element
    // (or array has 1 element)
    if (index >= size - 1)
        return true;

    // Check if current element <= next element
    if (arr[index] > arr[index + 1])
        return false;  // Found out-of-order pair

    // Recurse to check rest of array
    return isSortedHelper(arr, size, index + 1);
}

// Public interface
bool isSorted(int arr[], int size) {
    return isSortedHelper(arr, size, 0);
}

How It Works:

  1. Start at index 0
  2. Compare arr[index] with arr[index+1]
  3. If arr[index] > arr[index+1], not sorted → return false
  4. If all pairs in order, continue to next index
  5. Base case: reached end of comparisons → return true

Example Trace - {1, 2, 3, 4}:

isSortedHelper({1,2,3,4}, 4, 0)
   → Check: arr[0] (1) <= arr[1] (2)? YES ✓
   → Call: isSortedHelper({1,2,3,4}, 4, 1)
      → Check: arr[1] (2) <= arr[2] (3)? YES ✓
      → Call: isSortedHelper({1,2,3,4}, 4, 2)
         → Check: arr[2] (3) <= arr[3] (4)? YES ✓
         → Call: isSortedHelper({1,2,3,4}, 4, 3)
            → Base case: index (3) >= size-1 (3)
            → Return: true

Final result: true  ✓

Example Trace - {1, 3, 2, 4}:

isSortedHelper({1,3,2,4}, 4, 0)
   → Check: arr[0] (1) <= arr[1] (3)? YES ✓
   → Call: isSortedHelper({1,3,2,4}, 4, 1)
      → Check: arr[1] (3) <= arr[2] (2)? NO ✗
      → Return: false

Final result: false  ✓

Alternative Solution (Without Helper):

bool isSorted(int arr[], int size) {
    // Base case: array with 0 or 1 element is sorted
    if (size <= 1)
        return true;

    // Check first two elements
    if (arr[0] > arr[1])
        return false;

    // Recursively check rest of array
    return isSorted(arr + 1, size - 1);
}

Note: arr + 1 creates a pointer to the second element, effectively "shifting" the array left.

Complexity Analysis:

  • Time Complexity: O(n) - checks each adjacent pair once
  • Space Complexity: O(n) - recursion depth equals array size in worst case
Key Insight: Array is sorted if every adjacent pair is in order. Recursion checks pairs one by one, short-circuiting on first failure.
Q25 [4 marks]

Write a recursive function to count the number of nodes in a singly linked list.

Assume the Node struct is defined as:

int countNodes(Node* head) {
    // Base case: empty list
    if (head == NULL)
        return 0;

    // Recursive case: 1 (current node) + count of rest
    return 1 + countNodes(head->next);
}

How It Works:

  1. If list is empty (head == NULL), count is 0
  2. Otherwise, count is 1 (for current node) + count of remaining list
  3. Recurse with head->next until reaching NULL

 head

= 1 + (1 + countNodes(head->next))  // Points to node with 30
= 1 + (1 + (1 + countNodes(NULL)))
= 1 + (1 + (1 + 0))
= 1 + (1 + 1)
= 1 + 2
= 3  ✓

1 Node(10) 1 + countNodes(next) 1 + 2 = 3

3 Node(30) 1 + countNodes(next) 1 + 0 = 1
4 NULL Base case 0

  • Empty list (NULL): Returns 0 ✓
  • Single node: Returns 1 + countNodes(NULL) = 1 + 0 = 1 ✓

= 2 + (arr[2] + sumArray({5,3,8,2}, 2))
= 2 + (8 + sumArray({5,3,8,2}, 2))
= 2 + (8 + (arr[1] + sumArray({5,3,8,2}, 1)))
= 2 + (8 + (3 + sumArray({5,3,8,2}, 1)))
= 2 + (8 + (3 + (arr[0] + sumArray({5,3,8,2}, 0))))
= 2 + (8 + (3 + (5 + 0)))
= 2 + (8 + (3 + 5))
= 2 + (8 + 8)
= 2 + 16
= 18  ✓

Conversion Pattern (Iteration → Recursion):

Iterative Element Recursive Equivalent
Loop variable i Function parameter index
Loop condition i < size Base case if (index == size)
Accumulator total Return value accumulation
Loop increment i++ Recursive call with index + 1
Loop body total += arr[i] Return statement return arr[index] + ...

Complexity Comparison:

  • Iterative: Time O(n), Space O(1)
  • Recursive: Time O(n), Space O(n) - due to call stack
Key Steps for Conversion:
  1. Loop variable becomes parameter (or track with size)
  2. Loop end condition becomes base case (inverted)
  3. Loop body becomes recursive call with updated parameter
  4. Accumulator (if needed) can be parameter or part of return
Q27 [4 marks]

Write a pair of mutually recursive functions isEven(int n) and isOdd(int n) that determine if a non-negative integer is even or odd. Assume n ≥ 0.

Hint: 0 is even. A number is even if n-1 is odd. A number is odd if n-1 is even.

Solution: 
// Forward declaration needed for mutual recursion
bool isOdd(int n);

bool isEven(int n) {
    // Base case: 0 is even
    if (n == 0)
        return true;

    // Recursive case: n is even if (n-1) is odd
    return isOdd(n - 1);
}

bool isOdd(int n) {
    // Base case: 0 is not odd
    if (n == 0)
        return false;

    // Recursive case: n is odd if (n-1) is even
    return isEven(n - 1);
}

How It Works:

The functions call each other alternately, decrementing n by 1 each time until reaching the base case (n = 0).

Example Trace - isEven(4):

isEven(4)
   → 4 != 0, so call isOdd(3)
   isOdd(3)
      → 3 != 0, so call isEven(2)
      isEven(2)
         → 2 != 0, so call isOdd(1)
         isOdd(1)
            → 1 != 0, so call isEven(0)
            isEven(0)
               → 0 == 0, return true  ← BASE CASE
            → isOdd(1) returns true
         → isEven(2) returns true
      → isOdd(3) returns true
   → isEven(4) returns true  ✓

4 alternations until base case

Example Trace - isOdd(5):

isOdd(5)
   → 5 != 0, so call isEven(4)
   isEven(4)
      → 4 != 0, so call isOdd(3)
      isOdd(3)
         → 3 != 0, so call isEven(2)
         isEven(2)
            → 2 != 0, so call isOdd(1)
            isOdd(1)
               → 1 != 0, so call isEven(0)
               isEven(0)
                  → 0 == 0, return true
               → isOdd(1) returns true
            → isEven(2) returns true
         → isOdd(3) returns true
      → isEven(4) returns true
   → isOdd(5) returns true  ✓

Call Pattern:

  • isEven(4): even → odd → even → odd → even(0) = TRUE
  • isOdd(5): odd → even → odd → even → odd → even(0) = TRUE
  • isEven(3): even → odd → even → odd(0) = FALSE

Why Mutual Recursion Works Here:

Numbers alternate between even and odd as you count down. Each decrement flips the parity:

  • If n is even, then n-1 is odd
  • If n is odd, then n-1 is even
  • Keep going until reaching 0 (which is even)

Complexity Analysis:

  • Time Complexity: O(n) - makes n function calls total
  • Space Complexity: O(n) - call stack depth of n frames
Not Practical! This is a teaching example. In reality, use n % 2 == 0 (O(1)). Mutual recursion is useful for more complex problems like grammar parsing or state machines.

Forward Declaration Required:

Since isEven calls isOdd, and isOdd is defined after isEven, we need a forward declaration:

bool isOdd(int n);  // Forward declaration

// Now isEven can call isOdd
bool isEven(int n) { ... }
Pattern: Mutually recursive functions define each other. Function A calls B, and B calls A. Both progress toward shared base case(s).
Q28 [4 marks]

Write a recursive function to find and return a pointer to the last node in a singly linked list.

Function signature: Node* getTail(Node* head)

If the list is empty, return NULL. Assume the Node struct is defined as:

struct Node {
    int data;
    Node* next;
};

Source: Adapted from EO3 2018, Question 4.1

Solution: 
Node* getTail(Node* head) {
    // Base case 1: empty list
    if (head == NULL)
        return NULL;

    // Base case 2: this is the last node (tail)
    if (head->next == NULL)
        return head;

    // Recursive case: tail is in the rest of the list
    return getTail(head->next);
}

How It Works:

  1. If list is empty, no tail exists → return NULL
  2. If current node's next is NULL, this IS the tail → return it
  3. Otherwise, the tail must be further down the list → recurse with next

Example - List: 10 → 20 → 30 → NULL:

List structure:
[10|*]--->[20|*]--->[30|NULL]  ← tail
 n1        n2        n3

Execution trace:
getTail(n1)
   → n1 != NULL? YES
   → n1->next == NULL? NO (points to n2)
   → Call: getTail(n1->next) = getTail(n2)

   getTail(n2)
      → n2 != NULL? YES
      → n2->next == NULL? NO (points to n3)
      → Call: getTail(n2->next) = getTail(n3)

      getTail(n3)
         → n3 != NULL? YES
         → n3->next == NULL? YES ✓ (BASE CASE)
         → Return: n3  ← This is the tail!

      → getTail(n2) returns n3
   → getTail(n1) returns n3

Final result: pointer to node with data=30  ✓

Call Stack Visualization:

Call Stack (going down):
━━━━━━━━━━━━━━━━━━━━━━━
getTail(n1) waits for getTail(n2)
getTail(n2) waits for getTail(n3)
getTail(n3) returns n3 (base case)
━━━━━━━━━━━━━━━━━━━━━━━

Unwinding:
━━━━━━━━━━━━━━━━━━━━━━━
getTail(n2) returns n3
getTail(n1) returns n3
━━━━━━━━━━━━━━━━━━━━━━━

Edge Cases:

Empty list:

getTail(NULL)
   → head == NULL? YES
   → Return: NULL  ✓

Single node:

getTail(n1)  // n1->next = NULL
   → head == NULL? NO
   → head->next == NULL? YES
   → Return: n1  ✓ (single node IS the tail)

Using the Result:

Node* tail = getTail(head);
if (tail != NULL) {
    cout << "Last value: " << tail->data << endl;
    // Can now add nodes after tail:
    tail->next = new Node{40, NULL};
}

Complexity Analysis:

  • Time Complexity: O(n) - visits every node
  • Space Complexity: O(n) - recursion depth equals list length

Iterative Comparison:

Node* getTailIterative(Node* head) {
    if (head == NULL) return NULL;

    while (head->next != NULL) {
        head = head->next;
    }
    return head;
}
// Space: O(1) - more efficient
Key Pattern: Traverse to end of list. Base case checks for NULL (empty) or next == NULL (found tail). Recursion follows the chain.
