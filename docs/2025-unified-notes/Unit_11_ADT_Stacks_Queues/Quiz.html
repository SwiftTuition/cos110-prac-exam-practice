Question 1 2 marks
Which of the following best describes the LIFO (Last In First Out) principle?
a) The first element added is the first one removed
b) The last element added is the first one removed
c) Elements are removed in random order
d) Elements can be removed from any position

✓ Correct Answer

b) The last element added is the first one removed

Explanation:

LIFO (Last In First Out) means that the most recently added element is the first one to be removed. This is the fundamental principle of a stack.

Think of a stack of plates: the last plate you put on top is the first one you take off.

Why other options are wrong:

  • a) This describes FIFO (First In First Out), which is the principle for queues
  • c) Random order removal is not a standard ADT principle
  • d) Arbitrary position removal would be more like an array or list, not a stack
Question 2 2 marks
In a queue implementation, what happens when you try to enqueue an element into a full array-based queue?
a) The oldest element is automatically removed
b) An overflow error/exception should occur
c) The new element replaces the front element
d) The queue automatically resizes

✓ Correct Answer

b) An overflow error/exception should occur

Explanation:

When using a fixed-size array to implement a queue, attempting to enqueue when the queue is full should result in an overflow error or throw an exception.

This is a safety mechanism to prevent writing beyond the array bounds, which would cause undefined behavior or memory corruption.

Why other options are wrong:

  • a) Automatically removing elements would violate queue semantics - the user should explicitly dequeue
  • c) Replacing elements would lose data without the user's knowledge
  • d) In a basic array implementation, automatic resizing is not standard behavior (though dynamic arrays could do this)
Question 3 1 mark
True or False: In a circular queue, when the rear pointer reaches the end of the array, it wraps around to the beginning.

✓ Correct Answer

True

Explanation:

This statement is true. A circular queue uses modulo arithmetic to wrap the rear (and front) pointers around to the beginning of the array when they reach the end.

This is typically implemented using: rear = (rear + 1) % capacity

This wrapping behavior allows the queue to reuse empty spaces at the beginning of the array after elements have been dequeued.

Question 4 2 marks
What is the time complexity of the push() operation for a linked-list-based stack implementation?
a) O(n) - linear time
b) O(log n) - logarithmic time
c) O(1) - constant time
d) O(n²) - quadratic time

✓ Correct Answer

c) O(1) - constant time

Explanation:

Pushing onto a linked-list-based stack is an O(1) operation because:

  1. Create a new node (constant time)
  2. Set the new node's next pointer to the current top (constant time)
  3. Update the top pointer to the new node (constant time)

The number of operations does not depend on the size of the stack - it's always the same 3 steps, regardless of whether the stack has 5 elements or 5 million elements.

This is one of the advantages of linked-list implementations: both push and pop are O(1), and there's no overflow issue (only limited by available memory).

Question 5 1 mark
True or False: You can implement a stack using queues, and you can implement a queue using stacks.

✓ Correct Answer

True

Explanation:

This statement is true. You can build:

  • A stack using two queues: Move elements between queues to reverse the order for LIFO behavior
  • A queue using two stacks: Use one stack for adding elements, another for removing them

But these aren't practical - some operations become O(n) instead of O(1). It's mainly a programming exercise to show these structures can simulate each other.

Question 8 3 marks
📄 ADAPTED FROM: COS 110 EO3 2018
Consider the following array-based stack implementation: 
class Stack {
private:
    int* arr;
    int top;
    int capacity;
public:
    Stack(int size) {
        arr = new int[size];
        capacity = size;
        top = -1;
    }
};
What is the purpose of initializing top to -1?
a) To indicate the stack is empty
b) To reserve the first array position
c) To prevent negative indices
d) To optimize memory usage

✓ Correct Answer

a) To indicate the stack is empty

Explanation:

Initializing top to -1 serves as a sentinel value indicating that the stack is empty.

How it works:

  • When the stack is empty, top = -1 (points to "before" the first element)
  • When we push the first element, we increment: top = 0, then store at arr[0]
  • To check if empty: return top == -1;
  • To check if full: return top == capacity - 1;

Alternative design: Some implementations start top = 0 and use a separate size variable, but the -1 approach is simpler and more common.

Question 11 3 marks
Identify and fix the bug in this stack push() implementation: 
void Stack::push(int value) {
    if (top == capacity) {
        cout << "Stack overflow!" << endl;
        return;
    }
    arr[top] = value;
    top++;
}

✓ Correct Answer

Bug: Should check top == capacity - 1, not top == capacity

The Problem:

The overflow check is wrong. When top == capacity, we've already gone out of bounds! Array indices range from 0 to capacity - 1.

Why this is dangerous:

  • If capacity = 5, valid indices are 0, 1, 2, 3, 4
  • When top = 4 and we push, we should check if full BEFORE incrementing
  • If we check top == capacity (i.e., top == 5), we've already written to arr[4] and incremented to 5
  • Next push would write to arr[5], which is out of bounds!

Corrected version:

void Stack::push(int value) {
    if (top == capacity - 1) {  // Fixed: check against capacity - 1
        cout << "Stack overflow!" << endl;
        return;
    }
    top++;           // Increment FIRST
    arr[top] = value;  // Then store
    // OR equivalently:
    // arr[++top] = value;
}

Note: There's also a second issue - the order. If top starts at -1, we should increment BEFORE storing, not after.

Question 12 4 marks
Complete the following isEmpty() and isFull() functions for a circular queue: 
class Queue {
private:
    int* arr;
    int front, rear, size, capacity;
public:
    bool isEmpty() {
        // Your code here
    }

    bool isFull() {
        // Your code here
    }
};

✓ Correct Answer

bool isEmpty() {
    return size == 0;
}

bool isFull() {
    return size == capacity;
}

Explanation:

When you have a size variable tracking the number of elements, checking empty/full is straightforward:

  • Empty: size == 0 means no elements in the queue
  • Full: size == capacity means all spaces are occupied

Alternative without size variable:

If you don't track size, it's trickier:

bool isEmpty() {
    return front == -1;  // Convention: front = -1 when empty
}

bool isFull() {
    return (rear + 1) % capacity == front;
}

However, this requires sacrificing one array slot to distinguish between full and empty states, or using an additional flag. The size-based approach is cleaner.

Question 13 3 marks
What is wrong with this linked-list stack destructor? 
Stack::~Stack() {
    delete top;
}

✓ Correct Answer

Bug: Only deletes the top node, causing memory leak for all other nodes

The Problem:

This destructor only deletes the top node, leaving all other nodes in the linked list still allocated in memory. This causes a memory leak.

Why this happens:

In a linked list, each node points to the next. Deleting only the top node doesn't automatically delete the rest - you need to traverse and delete each node.

Corrected version:

Stack::~Stack() {
    while (top != NULL) {
        Node* temp = top;
        top = top->next;
        delete temp;
    }
}

// Alternative version:
Stack::~Stack() {
    while (!isEmpty()) {
        pop();  // If pop() already handles deletion
    }
}

Key principle: In C++, you are responsible for deleting ALL dynamically allocated memory. If you allocated N nodes with new, you must delete each of those N nodes.

Question 14 5 marks
Implement the pop() function for a linked-list-based stack. The function should return the popped value and handle the empty stack case by throwing an exception. 
class Stack {
private:
    struct Node {
        int data;
        Node* next;
    };
    Node* top;
public:
    int pop() {
        // Your implementation here
    }
};

✓ Correct Answer

int pop() {
    if (top == NULL) {
        throw runtime_error("Stack underflow: cannot pop from empty stack");
    }

    Node* temp = top;
    int value = top->data;
    top = top->next;
    delete temp;

    return value;
}

Step-by-step breakdown:

  1. Check if empty: if (top == NULL) - throw exception if trying to pop from empty stack
  2. Save reference to current top: Node* temp = top; - we need this to delete it later
  3. Save the value: int value = top->data; - store before we lose access
  4. Move top pointer: top = top->next; - advance to next node (or NULL if this was last node)
  5. Free memory: delete temp; - clean up the old top node
  6. Return the value: return value;

Common mistakes to avoid:

  • ❌ Deleting before saving the value: delete top; return top->data; (accessing deleted memory!)
  • ❌ Not checking for empty stack (causes NULL pointer dereference)
  • ❌ Forgetting to delete temp; (memory leak)
  • ❌ Not updating top pointer (loses access to rest of stack)
Question 15 3 marks
Swift is playing Clash Royale and needs to track his elixir expenditure during a match. Elixir regenerates continuously, but Swift wants to know the order in which he spent elixir on cards to analyze his strategy. Which ADT is most appropriate?
a) Stack - to review plays in reverse chronological order
b) Queue - to review plays in chronological order
c) Array - for random access to any play

✓ Correct Answer

b) Queue - to review plays in chronological order

Explanation:

Since Swift wants to analyze plays in the order they happened, a queue (FIFO) is most appropriate. As he plays cards, they're enqueued. When reviewing, he dequeues them in the same order they were played.

Why this makes sense:

  • First card played → First one reviewed (FIFO)
  • Preserves chronological order for strategy analysis
  • Simple enqueue/dequeue operations

Why other options are less suitable:

  • a) Stack: Would give reverse chronological order (last play first), which is less intuitive for strategy review
  • c) Array: Overkill - we don't need random access, just sequential review
  • d) Linked list: More complex than necessary when queue operations suffice

Clash Royale context: In the game, you have 10 elixir max, cards cost 1-9 elixir, and elixir regenerates at ~1 per second. Tracking card plays helps you see if you're wasting elixir by staying at max capacity too long (called "elixir leak").

Question 16 4 marks
You're implementing a "browser back button" feature. When a user visits a new page, it's added to history. Clicking "back" should return to the previous page. Which ADT and which operation corresponds to "back"?
a) Queue - dequeue
b) Stack - pop
c) Queue - enqueue
d) Stack - push

✓ Correct Answer

b) Stack - pop

Explanation:

Browser history is a classic stack application. The most recently visited page is the first one you return to when clicking "back" - this is LIFO behavior.

How it works:

  • Visit new page: push(page) - add to history stack
  • Click "back": pop() - remove current page, return to previous
  • Current page: peek() - view without removing

Example trace:

  1. Visit Google → Stack: [Google]
  2. Visit YouTube → Stack: [Google, YouTube]
  3. Visit Reddit → Stack: [Google, YouTube, Reddit]
  4. Click Back → Pop Reddit → Stack: [Google, YouTube] (now on YouTube)
  5. Click Back → Pop YouTube → Stack: [Google] (now on Google)

Real implementation note: Browsers often use TWO stacks - one for back history, one for forward history. When you go back, the current page is pushed onto the "forward" stack.

Question 17 3 marks
A printer queue manages print jobs. Three jobs arrive in order: Job A (10 pages), Job B (2 pages), Job C (50 pages). If printed in FIFO order, which job prints second?
a) Job A
b) Job B
c) Job C
d) Depends on priority

✓ Correct Answer

b) Job B

Explanation:

In a FIFO (First In First Out) queue, jobs are processed in the order they arrive:

  1. First: Job A arrives → enqueued first → prints first
  2. Second: Job B arrives → enqueued second → prints second
  3. Third: Job C arrives → enqueued third → prints third

The number of pages is irrelevant in a basic FIFO queue - only the arrival order matters.

Why option (d) is wrong:

The question specifies "FIFO order", which means no priority consideration. A priority queue would be different - it might print Job B first (fewest pages) if that's the priority metric, but that's not what was asked.

Real-world note: Many modern printer systems DO use priority queues or allow job reordering, but the basic model is FIFO.

Question 18 5 marks
📄 INSPIRED BY: COS 110 EO2 2023
Write a function that uses a stack to reverse a string. The function signature is: 
string reverseString(string str);
For example: reverseString("hello") should return "olleh".

✓ Correct Answer

string reverseString(string str) {
    Stack s;

    // Push all characters onto stack
    for (int i = 0; i < str.length(); i++) {
        s.push(str[i]);
    }

    // Pop all characters and build reversed string
    string reversed = "";
    while (!s.isEmpty()) {
        reversed += s.pop();
    }

    return reversed;
}

How it works:

Step 1 - Push all characters:

For "hello":

  • Push 'h' → Stack: [h]
  • Push 'e' → Stack: [h, e]
  • Push 'l' → Stack: [h, e, l]
  • Push 'l' → Stack: [h, e, l, l]
  • Push 'o' → Stack: [h, e, l, l, o]

Step 2 - Pop all characters:

Because stacks are LIFO, popping gives us characters in reverse order:

  • Pop → 'o' → reversed = "o"
  • Pop → 'l' → reversed = "ol"
  • Pop → 'l' → reversed = "oll"
  • Pop → 'e' → reversed = "olle"
  • Pop → 'h' → reversed = "olleh"

Why stacks are perfect for this:

The LIFO property automatically reverses the order - the last character pushed (end of string) becomes the first character popped (start of reversed string).

Time complexity: O(n) where n is string length - we process each character exactly twice (once to push, once to pop).

Question 19 2 marks
Which of the following applications is LEAST suitable for a stack?
a) Function call management (call stack)
b) Undo/Redo operations in text editors
c) First-come-first-served customer service
d) Expression evaluation (postfix notation)

✓ Correct Answer

c) First-come-first-served customer service

Explanation:

First-come-first-served requires FIFO (First In First Out) behavior - exactly what a queue provides, not a stack.

Why the others ARE suitable for stacks:

  • a) Function call management: When function A calls B calls C, C must finish first (return), then B, then A. This is LIFO - perfect for stacks. This is literally called the "call stack"!
  • b) Undo/Redo: The most recent action is the first one to undo. Perfect LIFO behavior.
  • d) Expression evaluation: Postfix evaluation uses a stack to track operands. E.g., 3 4 + 5 * → push 3, push 4, pop both and push 7, push 5, pop both and push 35.

Why customer service needs a queue:

If you use a stack for customer service, the most recent customer would be served first - meaning early arrivals wait forever while new arrivals keep "cutting in line". That's unfair and not FCFS!

Question 21 3 marks
In a circular queue with capacity 8, if front = 6 and rear = 2, how many elements are in the queue?
a) 4 elements
b) 5 elements
c) Impossible to determine without size variable
d) The queue is empty

✓ Correct Answer

c) Impossible to determine without size variable

Explanation:

This is a tricky question that highlights a fundamental challenge with circular queues!

The problem:

With only front and rear pointers, we can't distinguish between:

  • Empty queue: front = 6, rear = 2 (never added any elements)
  • Wrapped queue: front = 6, rear = 2 (elements at indices 6, 7, 0, 1, 2)

Both scenarios produce the same pointer values!

Solutions to this problem:

  1. Track size separately (most common): 
    int size;  // Explicitly count elements
bool isEmpty() { return size == 0; }
bool isFull() { return size == capacity; }
  2. Sacrifice one slot: Keep one array position always empty. Full when (rear + 1) % capacity == front
  3. Use a flag: Add a boolean isEmpty flag

If we HAD a size variable: We could calculate: size = (rear - front + 1 + capacity) % capacity, but without it, we simply cannot know.

Question 22 4 marks
Compare array-based and linked-list-based stack implementations. Which statement is TRUE?
a) Array-based has better memory efficiency for small stacks
b) Linked-list-based has O(1) push/pop, array-based has O(n)
c) Array-based can grow indefinitely, linked-list has fixed size
d) Both have identical time and space complexity

✓ Correct Answer

a) Array-based has better memory efficiency for small stacks

Explanation:

For small stacks, array-based implementations use less memory because:

  • Array storage: Only stores the data values + a few integers (top, capacity)
  • Linked list storage: Stores data values + a pointer for each node (8 bytes on 64-bit systems) + potentially memory fragmentation overhead

Example: For a stack of 10 integers:

  • Array: 10 × 4 bytes (ints) + ~8 bytes (metadata) = ~48 bytes
  • Linked list: 10 × (4 bytes data + 8 bytes pointer + malloc overhead) ≈ 120+ bytes

Why other options are wrong:

  • b) BOTH have O(1) push/pop when not resizing
  • c) It's the OPPOSITE - linked lists can grow indefinitely (limited by RAM), arrays have fixed size (or need expensive resizing)
  • d) They have different tradeoffs as explained above

Complete comparison table:

Aspect Array-based Linked-list-based
Push/Pop time O(1) O(1)
Memory per element Lower (just data) Higher (data + pointer)
Size limit Fixed (overflow possible) Dynamic (limited by RAM)
Cache performance Better (contiguous) Worse (scattered)
Question 23 3 marks
What happens when you try to dequeue from an empty linked-list-based queue?
a) Returns NULL
b) Returns 0
c) Should throw an exception or return error
d) Automatically adds a default element first

✓ Correct Answer

c) Should throw an exception or return error

Explanation:

Trying to dequeue from an empty queue is an underflow error. The function should:

  • Throw an exception (best practice in modern C++)
  • OR return an error code/sentinel value and handle it elsewhere
  • OR print an error message and return a default value (less ideal)

Why this matters:

If head == NULL and you try to access head->data, your program will crash (segmentation fault). You MUST check if the queue is empty before accessing head.

Example implementation:

int dequeue() {
    if (head == NULL) {
        throw runtime_error("Queue underflow");
        // OR: return -1; with documented error handling
    }

    int value = head->data;
    Node* temp = head;
    head = head->next;
    if (head == NULL) tail = NULL;  // Queue is now empty
    delete temp;
    return value;
}

Why other options are wrong:

  • a) & b): Returning NULL or 0 doesn't tell the caller whether the queue actually contained NULL/0 or was empty
  • d): Automatically adding elements would change program behavior unexpectedly

Question 25 6 marks
You're implementing a two-ended queue (deque) that supports insertions and deletions at both ends. Which of the following is the BEST implementation choice and why?
a) Array-based with two pointers (front and rear)
b) Singly linked list
c) Doubly linked list
d) Two stacks

✓ Correct Answer

c) Doubly linked list

Explanation:

A doubly linked list is the best choice for a deque (double-ended queue) because it provides O(1) operations at both ends.

Operations needed for deque:

  • pushFront() - add to front
  • pushBack() - add to rear
  • popFront() - remove from front
  • popBack() - remove from rear

Why doubly linked list is best:

Operation Time Complexity How
pushFront() O(1) Insert at head
pushBack() O(1) Insert at tail
popFront() O(1) Remove head, update head pointer
popBack() O(1) Remove tail, use prev pointer to update tail

Why other options don't work as well:

  • a) Array with two pointers: Works well for regular deque, BUT if not circular, adding/removing at front requires shifting all elements (O(n)). Circular array works but is more complex.
  • b) Singly linked list: popBack() requires O(n) traversal to find second-to-last node to update tail pointer. No prev pointer!
  • d) Two stacks: Can simulate a deque but operations become O(n) in worst case when transferring between stacks

The important part: The prev pointer in doubly linked lists lets you delete from the rear in O(1) time - singly linked lists can't do this because you need to find the second-to-last node.

Structure:

struct Node {
    int data;
    Node* next;
    Node* prev;  // Key for O(1) popBack
};

class Deque {
    Node* head;
    Node* tail;
};
