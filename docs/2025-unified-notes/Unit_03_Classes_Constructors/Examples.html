Example 1: Building a Simple Class with Multiple Constructors

Problem Statement

Create a BankAccount class that stores an account holder's name, account number, and balance. The class should have:

  • A default constructor that sets name to "Unknown", account number to 0, and balance to 0.0
  • A parameterized constructor that accepts all three values
  • A display function to show account details
  • Deposit and withdrawal functions with validation

Solution Approach

Step 1: Design the Class Structure

We need private data members for name, account number, and balance. Public functions will allow controlled access to modify the balance.

Step 2: Write Constructors

Use initialization lists for efficiency. The default constructor provides safe default values. The parameterized constructor accepts specific values from the user.

Step 3: Implement Member Functions

The deposit function adds money (with validation to prevent negative deposits). The withdraw function checks if sufficient funds exist before deducting.

Experiments to Try

🔬 Experiment 1: Remove the default constructor. Can you still create acc1 without arguments?

What happens: Compilation error. Once you define a parameterized constructor, C++ no longer provides a default constructor automatically.

Error message: "no matching function for call to 'BankAccount::BankAccount()'"

Fix: Either keep the default constructor or create acc1 with parameters: BankAccount acc1("Unknown", 0, 0.0);

🔬 Experiment 2: Try calling acc2.balance = 10000.0; directly in main(). What happens?

What happens: Compilation error because balance is private.

Why this is important: Encapsulation protects data from unauthorized access. Users must use deposit() and withdraw(), which include validation.

Error message: "'double BankAccount::balance' is private within this context"

🔬 Experiment 3: Change the parameterized constructor to use assignment instead of an initialization list. Does it still work?

What happens: It works, but it's less efficient.

Assignment version:

BankAccount(string name, int accNum, double bal) {
    accountHolder = name;
    accountNumber = accNum;
    balance = bal;
}

Why initialization lists are better: They directly construct the members with the correct values, avoiding default construction followed by assignment.

🔬 Experiment 4: Remove the const keyword from the display() function. Does the code still compile?

What happens: Yes, it still compiles and runs fine in this example.

When it matters: If you pass a const BankAccount& to a function and try to call display(), it will fail if display() isn't marked const.

Example:

void printAccount(const BankAccount& acc) {
    acc.display();  // Only works if display() is const
}

🔬 Experiment 5: Add a getter function getBalance() that returns the balance. Should it be const?

Answer: Yes, it should be const because it doesn't modify the object.

Implementation:

double getBalance() const {
    return balance;
}

Why: Getters (accessors) should always be const. They only read data, never modify it.

Example 2: Deep Copy Constructor for Dynamic Arrays

Problem Statement

Create a Playlist class that stores a dynamic array of song titles. The class needs a proper copy constructor to perform deep copying so that each playlist object has its own independent array.

Why This Matters

Without a deep copy constructor, copying a Playlist object would create two objects pointing to the same array. When one object is destroyed, it deletes the array, leaving the other object with a dangling pointer (pointing to freed memory).

Shallow Copy (BAD):
playlist1:           playlist2:
+---------+          +---------+
| songs  --\         | songs  --\
| count=3 | \        | count=3 | |
+---------+  \       +---------+ |
              \_____________________/
                      |
                      v
              ["Song A", "Song B", "Song C"]

Problem: Both point to SAME array!
Deleting one breaks the other.


Deep Copy (GOOD):
playlist1:           playlist2:
+---------+          +---------+
| songs  --|         | songs  --|
| count=3 | |        | count=3 | |
+---------+ |        +---------+ |
            v                    v
   ["A","B","C"]          ["A","B","C"]

Each object has independent memory.

Experiments to Try

🔬 Experiment 1: Comment out the copy constructor. Does the program still compile? What happens when you run it?

What happens: The program compiles (C++ provides a default shallow copy constructor), but the behavior is dangerous.

Problem: Both myPlaylist and copiedPlaylist point to the same songs array. Adding a song to copiedPlaylist also affects myPlaylist.

Crash risk: When copiedPlaylist is destroyed, it calls delete[] songs;. When myPlaylist is destroyed, it tries to delete the same memory again, causing a crash or undefined behavior.

🔬 Experiment 2: Add a print statement inside the copy constructor that shows the memory addresses. Are they different?

Add this to the copy constructor:

cout << "Original songs at: " << (void*)other.songs << endl;
cout << "Copied songs at: " << (void*)songs << endl;

What you'll see: Two different memory addresses, proving that each object has its own independent array.

Without deep copy: Both addresses would be the same (both pointing to the same array).

🔬 Experiment 3: What happens if you forget delete[] songs; in the destructor?

What happens: Memory leak. The dynamically allocated array is never freed.

How to detect: Use Valgrind or similar tools. They'll report "X bytes in Y blocks are definitely lost".

Why it matters: In a long-running program, memory leaks accumulate and eventually exhaust available memory, causing crashes.

🔬 Experiment 4: Try creating multiple copies in a chain: Playlist p3 = copiedPlaylist;. Does deep copying work recursively?

What happens: Yes! Each copy creates a completely independent object with its own array.

Try this:

Playlist p3 = copiedPlaylist;
p3.addSong("New Song");
// p3 has the new song, but myPlaylist and copiedPlaylist don't

Destructors called: Three times (once for each object), each freeing its own independent array.

🔬 Experiment 5: What if capacity is different between the original and copy? Should the copy constructor allocate based on capacity or count?

Current implementation: Allocates based on capacity (copies the full array size, even if not all slots are used).

Alternative approach: Allocate only count elements (save memory):

Playlist(const Playlist& other) : count(other.count), capacity(other.count) {
    songs = new string[capacity];
    for (int i = 0; i < count; i++) {
        songs[i] = other.songs[i];
    }
}

Trade-off: Saves memory but reduces capacity. If you plan to add more songs, keeping the original capacity is better.

Example 3: Using Static Members to Track Objects

Problem Statement

Create a Student class that automatically assigns unique student ID numbers to each new student. Use a static member to track the total count and generate IDs.

Concept Review

A static member variable is shared across all objects of the class. When one object modifies it, all objects see the change. This makes static members perfect for counters, shared configuration, or ID generation.

Experiments to Try

🔬 Experiment 1: Remove the initialization of static members (int Student::totalStudents = 0;). Does the code compile?

What happens: Linker error (not a compiler error!).

Error message: "undefined reference to Student::totalStudents"

Why: Static members must be defined outside the class. The declaration in the class is just a declaration; the definition (with initialization) must appear in a .cpp file or before main() in a single-file program.

🔬 Experiment 2: Try to access name from the static function getTotalStudents(). What error do you get?

Try adding: cout << name; inside getTotalStudents()

Error: "invalid use of member 'name' in static member function"

Why: Static functions don't have a this pointer. They're not tied to any specific object, so they can't access non-static members (which are specific to each object).

What they CAN access: Only other static members (totalStudents, nextID, other static functions).

🔬 Experiment 3: Create 100 students in a loop. Does each get a unique ID?

Try this:

for (int i = 0; i < 10; i++) {
    Student s("Student_" + to_string(i), 3.0);
    s.display();
}

What happens: Each student gets a unique ID (100001, 100002, 100003, ..., 100010).

Why it works: nextID is static (shared), so incrementing it in one constructor affects all future constructions.

🔬 Experiment 4: What happens to totalStudents when objects are destroyed? Does it go negative?

What happens: totalStudents correctly decreases when objects are destroyed (destructor calls totalStudents--;).

Check the output: When s4 goes out of scope, you see "Student Pieter Botha (ID 100004) removed" and the count drops from 4 to 3.

Final count: When main() ends, the remaining 3 students are destroyed, bringing totalStudents to 0.

🔬 Experiment 5: Try initializing the static variable inside the class: static int totalStudents = 0; in the class definition. What happens?

What happens: Compilation error.

Error message: "ISO C++ forbids in-class initialization of non-const static member"

Exception: You CAN initialize static const integral types in-class:

static const int MAX_STUDENTS = 1000;  // OK

For non-const statics: Always initialize outside the class.

Problem Statement

The following Rectangle class has several bugs related to const correctness. The code compiles on some compilers with warnings, but violates C++ const rules. Identify all the bugs and explain how to fix them.

Identify the Bugs

Try to find all 4 bugs before revealing the answer.

Bug #1: Modifying Member in const Function (Line 13-14)

Location: getArea() function

Problem:

double getArea() const {
    callCount++;  // BUG: Modifying member variable in const function
    return width * height;
}

Why it's wrong: A const member function promises not to modify the object. Incrementing callCount violates this promise.

Fix Option 1: Remove const from getArea() (but then it can't be called on const objects).

Fix Option 2: Make callCount mutable:

mutable int callCount;  // Can be modified even in const functions

Bug #2: Non-const Getter (Line 23)

Location: getWidth() function

Problem:

double getWidth() {  // BUG: Missing const
    return width;
}

Why it's wrong: Getters should be const because they don't modify the object. Without const, you can't call getWidth() on a const Rectangle&.

Fix:

double getWidth() const {
    return width;
}

Where it breaks: Line 32 calls other.getWidth() where other is a const Rectangle&. This fails if getWidth() isn't const.

Bug #3: Calling Non-const Function on const Reference (Line 37)

Location: analyzeRectangle() function

Problem:

void analyzeRectangle(const Rectangle& rect) {
    rect.display();
    rect.setWidth(10.0);  // BUG: Calling mutator on const reference
}

Why it's wrong: rect is a const Rectangle&, meaning you can't modify it. setWidth() is a mutator (non-const function).

Fix: Remove the setWidth() call or remove const from the parameter:

void analyzeRectangle(Rectangle& rect) {  // Not const
    rect.display();
    rect.setWidth(10.0);  // Now OK
}

Bug #4: Attempting to Modify const Object (Line 41)

Location: main() function

Problem:

const Rectangle r2(7.0, 4.0);
analyzeRectangle(r2);  // BUG: Passing const object to function that modifies it

Why it's wrong: r2 is declared const, so it cannot be modified. But analyzeRectangle() calls setWidth() on it.

Fix Option 1: Remove const from r2.

Fix Option 2: Don't call analyzeRectangle() on const objects.

Summary of All Fixes

class Rectangle {
private:
    double width;
    double height;
    mutable int callCount;  // FIX: Make mutable

public:
    Rectangle(double w, double h) : width(w), height(h), callCount(0) {}

    double getArea() const {
        callCount++;  // OK now (callCount is mutable)
        return width * height;
    }

    void setWidth(double w) {
        width = w;
    }

    double getWidth() const {  // FIX: Add const
        return width;
    }

    void display() const {
        cout << "Width: " << width << ", Height: " << height << endl;
        cout << "Area: " << getArea() << endl;
    }

    void printInfo(const Rectangle& other) const {
        cout << "Comparing with rectangle of width " << other.getWidth() << endl;
    }
};

void analyzeRectangle(Rectangle& rect) {  // FIX: Remove const (or don't call setWidth)
    rect.display();
    rect.setWidth(10.0);
}

int main() {
    Rectangle r1(5.0, 3.0);
    r1.display();

    Rectangle r2(7.0, 4.0);  // FIX: Remove const
    analyzeRectangle(r2);

    return 0;
}
