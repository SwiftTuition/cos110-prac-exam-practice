Unit 3: Introduction to Classes & Constructors

Good day, good people!

Welcome to Unit 3, where we start building our own custom data types using classes. Up until now, you've been using built-in types like int, double, and string. But what if you want to create a Student type that bundles together a name, ID number, and GPA? That's where classes come in.

In this unit, we'll cover how to design classes, create objects from those classes, and use constructors to initialize them properly. We'll also look at important modifiers like const, inline, and static that give you fine control over how your classes behave.

Prerequisites: You should be comfortable with pointers, dynamic memory allocation (new and delete), and basic function overloading from Units 1 and 2.

1. Class Basics: From Structs to Classes

What's the Difference Between struct and class?

You've probably seen struct before in C or COS 132. A struct lets you bundle related data together:

struct Student {
    string name;
    int studentID;
    double gpa;
};

In C++, a class works almost identically to a struct, with one key difference: default access control.

  • struct: Members are public by default (anyone can access them)
  • class: Members are private by default (only the class itself can access them)

Here's the same Student as a class:

class Student {
    string name;        // private by default
    int studentID;      // private by default
    double gpa;         // private by default
};

But wait! If everything's private, how do we use the class? We need to specify public sections:

class Student {
private:
    string name;
    int studentID;
    double gpa;

public:
    void setName(string n) {
        name = n;
    }

    string getName() {
        return name;
    }
};

Why Make Things Private?

This is called encapsulation. The idea is simple: hide the internal details (data) and only expose what others need (functions). This protects your data from being changed in ways you don't expect.

Swift Note: Think of a class like a locked box. Private members are inside the box (only the class can see them). Public members are buttons and displays on the outside (everyone can use them). This prevents bugs where someone changes gpa = -5.0 directly—instead, they must use your setter function, where you can validate the value first.

Access Specifiers

There are three access levels in C++:

  • private: Only accessible within the class itself (default for classes)
  • public: Accessible from anywhere
  • protected: Accessible within the class and derived classes (we'll cover this in Unit 7 on inheritance)
Important: Trying to access private members from outside the class will cause a compilation error. The compiler will tell you something like "member is private" or "cannot access private member."

2. Constructors: Initializing Objects Properly

What Is a Constructor?

A constructor is a special member function that runs automatically when you create an object. Its job is to initialize the object's member variables.

Constructors have two key characteristics:

  • Same name as the class
  • No return type (not even void)

Default Constructor

A default constructor takes no parameters. If you don't write any constructor, C++ creates one for you automatically (but it doesn't initialize your variables!).

class Student {
private:
    string name;
    int studentID;
    double gpa;

public:
    // Default constructor
    Student() {
        name = "";
        studentID = 0;
        gpa = 0.0;
    }
};

Now when you create a Student object, it starts with known values instead of garbage:

Student s;  // Calls default constructor automatically
// s.name = "", s.studentID = 0, s.gpa = 0.0

Parameterized Constructor

A parameterized constructor accepts arguments so you can initialize the object with specific values:

class Student {
private:
    string name;
    int studentID;
    double gpa;

public:
    // Parameterized constructor
    Student(string n, int id, double g) {
        name = n;
        studentID = id;
        gpa = g;
    }
};

Usage:

Student s1("Zanele Nkosi", 12345, 3.8);
// s1.name = "Zanele Nkosi", s1.studentID = 12345, s1.gpa = 3.8
Important: If you define any constructor (even a parameterized one), C++ will not create a default constructor for you automatically. If you want both, you must write both.

Constructor Initialization Lists

There's a better way to initialize member variables using an initialization list:

Student(string n, int id, double g) : name(n), studentID(id), gpa(g) {
    // Body can be empty or contain additional logic
}

This syntax uses a colon (:) followed by member initializations. Why is this better?

  • More efficient (direct initialization instead of assignment)
  • Required for const members and references
  • Required for members that are objects without default constructors
  • Avoids ambiguity (no need for this->name = name)
Best Practice: Use initialization lists instead of assignment in the constructor body. It's cleaner, more efficient, and prevents certain errors.

3. Copy Constructors: Deep vs Shallow Copy

What Is a Copy Constructor?

A copy constructor creates a new object as a copy of an existing object. It's called when:

  • You initialize a new object from an existing one: Student s2 = s1;
  • You pass an object by value to a function
  • You return an object by value from a function

The syntax uses a const reference to the same class type:

class Student {
public:
    // Copy constructor
    Student(const Student& other) {
        // Copy member variables from 'other' to this object
    }
};

Shallow Copy vs Deep Copy

If you don't write a copy constructor, C++ creates one for you. This default copy constructor does a shallow copy: it copies member variables directly.

This works fine for simple types (int, double, etc.), but causes problems with pointers:

Object 1:               Object 2 (shallow copy):
+---------+             +---------+
| ptr  ----\            | ptr  ----\
+---------+ \           +---------+ |
             \________________________/
                        |
                        v
                  [Shared data]

Problem: Both objects point to the SAME memory!
Deleting one object breaks the other.

A deep copy creates a separate copy of the dynamically allocated memory:

Object 1:               Object 2 (deep copy):
+---------+             +---------+
| ptr  ----|           | ptr  ----|
+---------+ |           +---------+ |
            v                       v
      [Data copy 1]           [Data copy 2]

Each object has its own independent memory.
Swift Note: If your class has any pointer members allocated with new, you must write a custom copy constructor that performs a deep copy. Otherwise, you'll get crashes when one object deletes memory that another object is still using.

Implementing a Deep Copy Constructor

class IntArray {
private:
    int* data;
    int size;

public:
    // Parameterized constructor
    IntArray(int s) : size(s) {
        data = new int[size];
    }

    // Copy constructor (deep copy)
    IntArray(const IntArray& other) : size(other.size) {
        data = new int[size];  // Allocate new memory
        for (int i = 0; i < size; i++) {
            data[i] = other.data[i];  // Copy values
        }
    }

    // Destructor
    ~IntArray() {
        delete[] data;
    }
};
Important: The "Rule of Three" states: If you need a custom destructor, you almost always need a custom copy constructor and assignment operator too. All three manage the same resource (dynamic memory).

4. const Member Functions: Accessors and Mutators

What Does const Mean for Member Functions?

When you mark a member function as const, you're promising that the function will not modify any member variables of the object.

class Student {
private:
    string name;
    double gpa;

public:
    // Accessor (const) - doesn't modify anything
    double getGPA() const {
        return gpa;
    }

    // Mutator (non-const) - modifies data
    void setGPA(double g) {
        gpa = g;
    }
};

The const keyword goes after the parameter list and before the function body.

Why Use const Member Functions?

There are two main reasons:

  1. Documentation: It tells other programmers (and yourself!) that this function is read-only
  2. const Correctness: const objects can only call const member functions
void printStudent(const Student& s) {
    cout << s.getGPA();  // OK - getGPA() is const
    s.setGPA(4.0);       // ERROR - setGPA() is not const
}
Note: When you pass an object as const& (to avoid copying), you can only call const member functions on it. This prevents accidental modifications.

Common Mistake: Forgetting const

A function that should be const but isn't will prevent you from using it with const references:

class Student {
public:
    string getName() {  // FORGOT const!
        return name;
    }
};

void printName(const Student& s) {
    cout << s.getName();  // ERROR: getName() is not const
}

Fix: Add const to getName():

string getName() const {
    return name;
}
Best Practice: Mark all accessor functions (getters) as const. Only mutator functions (setters) should be non-const.
⚡ Swift Quiz
Quick Check: If you have a const Student s; object, can you call a non-const member function on it?
Answer: No. A const object can only call const member functions. This ensures the object cannot be modified. Attempting to call a non-const function will result in a compilation error.

5. inline Functions: When and Why

What Is an inline Function?

The inline keyword is a suggestion to the compiler to replace function calls with the actual function code (called "inlining"). This can make small functions faster by avoiding the overhead of a function call.

class Student {
private:
    int studentID;

public:
    inline int getID() const {
        return studentID;
    }
};

For very simple functions (like the getter above), the compiler might inline them automatically, even without the keyword.

Member Functions Defined Inside the Class

When you define a member function inside the class declaration (in the header file), it's implicitly inline:

// Student.h
class Student {
private:
    int studentID;

public:
    int getID() const {  // Implicitly inline
        return studentID;
    }
};

This is convenient for short functions, but it has a trade-off: it puts implementation details in the header file, which breaks the separation of interface and implementation.

When to Use inline

  • ✅ Very short functions (1-2 lines)
  • ✅ Frequently called functions (getters/setters)
  • ❌ Long or complex functions
  • ❌ Functions with loops or recursion
Important: inline is just a suggestion. The compiler can ignore it. Modern compilers are smart enough to inline functions automatically when beneficial.
Note: EO1 2025 Question 1 asks: "Inline member functions work against the principle of separating interface and implementation." This is true because defining functions in the header exposes implementation details.

6. static Members: Shared Across All Objects

What Is a static Member Variable?

A static member variable belongs to the class itself, not to any individual object. All objects of the class share the same static variable.

Common use case: counting how many objects have been created.

class Student {
private:
    static int count;  // Shared by all Student objects
    string name;

public:
    Student(string n) : name(n) {
        count++;  // Increment shared counter
    }

    static int getCount() {
        return count;
    }
};

Initializing static Members

You must initialize static member variables outside the class, typically in a .cpp file:

// Student.cpp
int Student::count = 0;  // Initialize static variable
Important: You cannot initialize static members inside the class declaration (like static int count = 0; in the header). This will cause a compilation error. The only exception is static const integral types.

static Member Functions

A static member function can be called without an object. It can only access static members (not regular member variables).

class Student {
private:
    static int count;

public:
    static int getCount() {  // static function
        return count;  // Can access static members
        // return name;  // ERROR: Can't access non-static members
    }
};

Calling a static function:

int total = Student::getCount();  // Use :: operator, no object needed
Best Practice: Use static member variables for data that should be shared across all objects (like counters, configuration settings, or shared resources).

7. Destructors and the this Pointer

What Is a Destructor?

A destructor is a special member function that runs automatically when an object is destroyed. Its job is to clean up resources (especially dynamically allocated memory).

Destructor characteristics:

  • Same name as the class with a tilde (~) prefix
  • No parameters
  • No return type
  • Cannot be overloaded (only one destructor per class)
class IntArray {
private:
    int* data;
    int size;

public:
    IntArray(int s) : size(s) {
        data = new int[size];
    }

    ~IntArray() {  // Destructor
        delete[] data;  // Free the memory
        data = NULL;    // Good practice
    }
};

When Is the Destructor Called?

The destructor is called automatically when:

  • A local object goes out of scope
  • A dynamically allocated object is deleted with delete
  • The program terminates (for global/static objects)
Swift Note: If you allocate memory with new in a constructor, you must free it with delete in the destructor. Otherwise, you have a memory leak. Every new must have a matching delete.

The this Pointer

Inside any non-static member function, you have access to a special pointer called this. It points to the current object (the one that called the function).

class Student {
private:
    string name;

public:
    void setName(string name) {
        this->name = name;  // Disambiguate: this->name is member, name is parameter
    }

    Student* getThis() {
        return this;  // Return pointer to current object
    }
};

When to Use this

  • To resolve naming conflicts (parameter vs member variable)
  • To return the current object (return *this; for chaining)
  • To pass the current object to another function

Example with initialization list (no need for this):

Student(string name) : name(name) {
    // Initialization list handles the conflict automatically
}
Important: this is a pointer to the current object. To access members, use this->member. To get the object itself (not a pointer), use *this.

8. Common Mistakes to Avoid

Mistake 1: Ambiguous Variable Names in Constructors

This code has a problem:

class Student {
private:
    int id;

public:
    Student(int id) {
        id = id;  // BUG: Assigns parameter to itself!
    }
};

The parameter id shadows the member variable id. The assignment does nothing useful.

Fix 1: Use this pointer:

Student(int id) {
    this->id = id;  // Clear: this->id is member, id is parameter
}

Fix 2: Use initialization list (better):

Student(int id) : id(id) {
    // Initialization list handles it correctly
}

Mistake 2: Shallow Copy with Pointers

Forgetting to write a copy constructor when you have pointer members:

class IntArray {
private:
    int* data;
    int size;

public:
    IntArray(int s) : size(s) {
        data = new int[size];
    }

    // Missing copy constructor!
    // Default shallow copy will be used

    ~IntArray() {
        delete[] data;
    }
};

int main() {
    IntArray arr1(5);
    IntArray arr2 = arr1;  // Shallow copy!
    // Both arr1 and arr2 point to same memory
    // When arr2 is destroyed, it deletes the memory
    // When arr1 is destroyed, it tries to delete already-freed memory = CRASH
}

Fix: Write a deep copy constructor (see Section 3).

Mistake 3: Modifying Member Variables in const Functions

class Counter {
private:
    int count;

public:
    void increment() const {  // Marked const
        count++;  // ERROR: Cannot modify member in const function
    }
};

Fix: Remove const if the function modifies members:

void increment() {  // Not const
    count++;
}

Mistake 4: Initializing static Members in the Header

// Student.h
class Student {
private:
    static int count = 0;  // ERROR: Cannot initialize here
};

Fix: Initialize in the .cpp file:

// Student.cpp
int Student::count = 0;

Mistake 5: Forgetting to Delete Dynamically Allocated Memory

class Student {
private:
    int* grades;

public:
    Student(int numGrades) {
        grades = new int[numGrades];
    }

    // Missing destructor - memory leak!
};

Fix: Add a destructor:

~Student() {
    delete[] grades;
}

Summary

In this unit, you learned the fundamentals of creating and using classes in C++:

  • Classes vs structs: Classes have private members by default; structs have public members by default
  • Access specifiers: public, private, and protected control visibility
  • Constructors: Default (no parameters), parameterized (with parameters), and copy constructors (create from existing object)
  • Initialization lists: Preferred way to initialize member variables in constructors
  • Deep vs shallow copy: When you have pointers, you must write a custom copy constructor to allocate separate memory
  • const member functions: Mark functions const if they don't modify the object (accessors/getters)
  • inline functions: Hint to compiler to replace function calls with code (for small functions)
  • static members: Shared across all objects; initialized outside the class; static functions can't access non-static members
  • Destructors: Clean up resources (especially dynamic memory) when objects are destroyed
  • this pointer: Points to the current object; used to disambiguate names or return the object itself
Key Concept: If your class has any pointer members allocated with new, you need the "Big Three": destructor, copy constructor, and assignment operator (we'll cover assignment in Unit 4).
