Q1 Arrow Operator Syntax

Which of the following is equivalent to (*ptr).data?

  1. ptr.data
  2. ptr->data
  3. ptr*data
  4. &ptr.data

Answer: B - ptr->data

Explanation: The arrow operator (->) is syntactic sugar that combines pointer dereferencing and member access. ptr->data is exactly equivalent to (*ptr).data.

Why other options are wrong:

  • A (ptr.data): This tries to access a member of the pointer itself, not the object it points to. Compilation error.
  • C (ptr*data): Invalid syntax. This would be interpreted as multiplication.
  • D (&ptr.data): This takes the address of ptr.data, which is wrong because ptr is already a pointer.

Q2 The this Pointer

What does the this pointer point to inside a member function?

  1. The class definition
  2. The first object of the class
  3. The current object that called the function
  4. The base class if using inheritance

Answer: C - The current object that called the function

Explanation: Inside every non-static member function, this is a pointer to the object that invoked the function. When you call obj1.method(), inside method(), this points to obj1.

Why other options are wrong:

  • A: The class is a blueprint, not an object. this points to an instance, not the class itself.
  • B: this doesn't specifically point to the first object. It points to whichever object called the member function.
  • D: this points to the current object's type, not the base class. Even in derived classes, this has the derived type.

Q3 Copy Constructor Signature

Which is the correct signature for a copy constructor?

  1. ClassName(ClassName other)
  2. ClassName(ClassName& other)
  3. ClassName(const ClassName& other)
  4. ClassName(ClassName* other)

Answer: C - ClassName(const ClassName& other)

Explanation: The copy constructor must take a const reference to another object of the same class. The const prevents modification of the source object, and the & (reference) is required to avoid infinite recursion.

Why other options are wrong:

  • A: Pass-by-value would require copying the argument, which calls the copy constructor, which needs to copy the argument... infinite recursion!
  • B: Missing const. While this compiles, it prevents copying from const objects and temporaries. Not standard practice.
  • D: Takes a pointer instead of reference. This is not a copy constructor signature. A copy constructor specifically takes a reference.

Q4 When is the Copy Constructor Called?

In which of the following situations is the copy constructor called?

MyClass obj1;
MyClass obj2 = obj1;  // Statement 1
MyClass obj3;
obj3 = obj1;           // Statement 2
  1. Both statements
  2. Statement 1 only
  3. Statement 2 only
  4. Neither statement

Answer: B - Statement 1 only

Explanation: Statement 1 (MyClass obj2 = obj1;) is initialization, which calls the copy constructor because obj2 doesn't exist yet and is being created from obj1.

Statement 2 first creates obj3 with the default constructor, then assigns obj1 to it using the assignment operator, not the copy constructor.

Key distinction: Copy constructor creates a new object. Assignment operator copies to an existing object.

Q5 Shallow vs Deep Copy

What is the problem with a shallow copy when a class has pointer members?

  1. It copies the pointer value, so both objects point to the same memory
  2. It doesn't copy any data at all
  3. It only copies primitive types
  4. It causes a compilation error

Answer: A - It copies the pointer value, so both objects point to the same memory

Explanation: A shallow copy copies the pointer's address (the memory location it points to), not the data itself. This means both the original and copy share the same dynamically allocated memory. When one object modifies the data or is destroyed and frees the memory, the other object's pointer becomes dangling.

Why other options are wrong:

  • B: Shallow copy does copy data - it copies the pointer address. The problem is it doesn't copy what the pointer points to.
  • C: Shallow copy copies all member variables, including pointers. The issue is how it copies pointers (address only).
  • D: Shallow copy compiles fine. It's the default behavior. The problem is runtime bugs (crashes, data corruption).

Q6 Destructor Syntax

Which statement about destructors is FALSE?

  1. Destructors have the same name as the class with a ~ prefix
  2. Destructors can take parameters
  3. Destructors have no return type
  4. Destructors are called automatically when objects go out of scope

Answer: B - Destructors can take parameters (FALSE)

Explanation: Destructors CANNOT take any parameters and cannot be overloaded. You can only have one destructor per class with the signature ~ClassName().

Why other statements are true:

  • A: True - The destructor name is ~ClassName, where ClassName is the class name.
  • C: True - Destructors don't have a return type, not even void.
  • D: True - Destructors are called automatically when local objects go out of scope or when dynamically allocated objects are deleted.

Q7 Delete vs Delete[]

What is the correct way to delete an array allocated with int* arr = new int[10];?

  1. delete arr;
  2. delete[] arr;
  3. free(arr);
  4. delete arr[10];

Answer: B - delete[] arr;

Explanation: Arrays allocated with new[] must be freed with delete[]. The [] tells the compiler this is an array, so it properly destructs all elements and frees all memory.

Why other options are wrong:

  • A (delete arr;): This is undefined behavior. Using delete (without []) on an array only destroys the first element and may leak the rest of the array.
  • C (free(arr);): free() is for C-style memory allocated with malloc(). Using free() on memory allocated with new is undefined behavior.
  • D (delete arr[10];): This tries to delete the 11th element (index 10), not the array. Syntax error.

Q8 Assignment Operator Return Type

What should the assignment operator return?

  1. void
  2. ClassName (by value)
  3. ClassName& (by reference)
  4. ClassName* (pointer)

Answer: C - ClassName& (by reference)

Explanation: The assignment operator should return a reference to the current object (return *this;). This enables chaining: a = b = c; works because b = c returns a reference to b, which is then assigned to a.

Why other options are wrong:

  • A (void): While this compiles, you can't chain assignments. Standard practice is to return a reference.
  • B (by value): This creates an unnecessary copy of the object. Inefficient and not standard.
  • D (pointer): Incorrect. The assignment operator should return a reference, not a pointer. Returning this directly (which is a pointer) doesn't match the expected ClassName& signature.

Q9 Self-Assignment Check

Why is it important to check for self-assignment in the assignment operator?

  1. To improve performance by avoiding unnecessary work
  2. To prevent deleting the object's own data before copying from it
  3. Both A and B
  4. It's not important - the compiler handles it automatically

Answer: C - Both A and B

Explanation: Checking for self-assignment (if (this == &other)) is important for two reasons:

  1. Correctness: Without the check, the assignment operator deletes its own memory (thinking it's "old" data), then tries to copy from that freed memory. This causes undefined behavior.
  2. Performance: Even if the implementation doesn't cause corruption, self-assignment wastes time copying an object to itself.

Example of what goes wrong without check:

obj = obj;  // Self-assignment
// Without check:
delete[] data;  // Deletes obj's data (same as other's data!)
data = new int[size];
// Now copying from deleted memory!

Q10 The Big Three Rule

If a class needs a custom destructor, what else does it likely need?

  1. Only a copy constructor
  2. Only an assignment operator
  3. Both a copy constructor and an assignment operator
  4. Nothing else - destructor is enough

Answer: C - Both a copy constructor and an assignment operator

Explanation: This is the "Rule of Three" (Big Three): If you need one of these three, you usually need all three:

  1. Destructor: To free resources
  2. Copy constructor: To properly copy resources (deep copy)
  3. Assignment operator: To properly assign resources (deep copy)

If a class needs a custom destructor (usually because it has dynamically allocated memory or other resources), the default shallow copy behavior of copy constructor and assignment operator will cause problems (double deletion, dangling pointers).

Example: A class with int* data needs custom destructor to delete[] data;, custom copy constructor to allocate new memory, and custom assignment operator to handle copying and cleanup properly.

Q11 Code Tracing - Copy Constructor

What is the output of the following code?

class Counter {
    int* count;
public:
    Counter(int c) {
        count = new int(c);
        cout << "Created: " << *count << endl;
    }

    Counter(const Counter& other) {
        count = new int(*other.count);
        cout << "Copied: " << *count << endl;
    }

    ~Counter() {
        cout << "Destroyed: " << *count << endl;
        delete count;
    }
};

int main() {
    Counter c1(5);
    Counter c2 = c1;
    return 0;
}

Output:

Created: 5
Copied: 5
Destroyed: 5
Destroyed: 5

Line-by-Line Trace:

  1. Line: Counter c1(5); → Calls constructor with c = 5. Allocates count, sets to 5. Prints "Created: 5".
  2. Line: Counter c2 = c1; → Calls copy constructor. Allocates new memory for c2.count, copies value 5 from c1.count. Prints "Copied: 5". Now two independent Counter objects exist.
  3. Exit main: Objects destroyed in reverse order of creation (LIFO).
  4. c2 destroyed: Destructor prints "Destroyed: 5", frees c2.count.
  5. c1 destroyed: Destructor prints "Destroyed: 5", frees c1.count.

Key Point: The copy constructor does deep copy (count = new int(*other.count);), so both objects have independent memory. No double-delete issues.

Q12 Code Tracing - Assignment

What is the output?

class Box {
    int value;
public:
    Box(int v) : value(v) {
        cout << "Construct " << value << endl;
    }

    Box& operator=(const Box& other) {
        cout << "Assign from " << other.value << endl;
        value = other.value;
        return *this;
    }

    ~Box() {
        cout << "Destruct " << value << endl;
    }
};

int main() {
    Box b1(10);
    Box b2(20);
    b2 = b1;
    return 0;
}

Output:

Construct 10
Construct 20
Assign from 10
Destruct 10
Destruct 10

Line-by-Line Trace:

  1. Box b1(10); → Constructor called with v = 10. Prints "Construct 10". Variables: b1.value = 10
  2. Box b2(20); → Constructor called with v = 20. Prints "Construct 20". Variables: b1.value = 10, b2.value = 20
  3. b2 = b1; → Assignment operator called. Prints "Assign from 10". b2.value becomes 10. Variables: b1.value = 10, b2.value = 10
  4. Exit main (b2 destroyed first): Destructor prints "Destruct 10"
  5. b1 destroyed: Destructor prints "Destruct 10"

Key Point: Assignment operator is called (not copy constructor) because b2 already exists. After assignment, both objects have value 10.

Q13 Memory Leak Detection

Which version of the code has a memory leak?

Version A:

class Data {
    int* ptr;
public:
    Data() { ptr = new int(0); }
    ~Data() { delete ptr; }
};

Version B:

class Data {
    int* ptr;
public:
    Data() { ptr = new int(0); }
    Data(const Data& other) {
        ptr = new int(*other.ptr);
    }
    ~Data() { delete ptr; }
};
  1. Version A only
  2. Version B only
  3. Both versions
  4. Neither version

Answer: C - Both versions

Explanation:

Version A: Has a memory leak because it lacks a custom copy constructor. The default copy constructor does shallow copy, so if you do Data d2 = d1;, both objects point to the same memory. When one is destroyed, it deletes the memory. The other's destructor tries to delete already-freed memory (double delete).

Version B: Fixed the copy constructor but lacks a custom assignment operator. If you do d2 = d1; (assignment), the default assignment operator does shallow copy. Old memory in d2 is never freed (leak), and both objects point to the same new memory (double delete when destroyed).

Correct solution: Need both copy constructor AND assignment operator (plus destructor). That's the Big Three!

// Correct version
class Data {
    int* ptr;
public:
    Data() { ptr = new int(0); }

    Data(const Data& other) {
        ptr = new int(*other.ptr);  // Deep copy
    }

    Data& operator=(const Data& other) {
        if (this == &other) return *this;
        delete ptr;  // Free old memory
        ptr = new int(*other.ptr);  // Deep copy
        return *this;
    }

    ~Data() { delete ptr; }
};

Q14 Method Chaining

To enable method chaining (e.g., obj.method1().method2()), what must method1 return?

  1. void
  2. ClassName (by value)
  3. ClassName& (reference to object)
  4. ClassName* (pointer to object)

Answer: C - ClassName& (reference to object)

Explanation: For method chaining, the method must return a reference to the current object using return *this;. This allows calling another method on the returned reference.

class Builder {
public:
    Builder& setName(string n) {
        name = n;
        return *this;  // Return reference to current object
    }

    Builder& setAge(int a) {
        age = a;
        return *this;
    }
};

// Usage:
Builder b;
b.setName("Alice").setAge(25);  // Method chaining!

Why other options don't work:

  • A (void): Can't call methods on void. obj.method1().method2() won't compile.
  • B (by value): Returns a copy of the object. Changes made by method2() affect the copy, not the original.
  • D (pointer): Would require obj.method1()->method2() (arrow syntax). Not standard chaining pattern.

Q15 Find the Bug

This assignment operator has a bug. What's wrong?

MyClass& operator=(const MyClass& other) {
    if (this == &other) return *this;

    size = other.size;
    data = new int[size];
    for (int i = 0; i < size; i++) {
        data[i] = other.data[i];
    }

    return *this;
}
  1. Missing delete[] data; before allocating new memory
  2. Should use delete instead of delete[]
  3. Self-assignment check is wrong
  4. Return type should be void

Answer: A - Missing delete[] data; before allocating new memory

Bug Location: Between the self-assignment check and data = new int[size];

What's wrong: The code allocates new memory without freeing the old memory first. When you do obj1 = obj2;, obj1 already has a data array. If we don't delete it, it's leaked - we lose the pointer to the old memory when we overwrite it with the new allocation.

Correct code:

MyClass& operator=(const MyClass& other) {
    if (this == &other) return *this;

    delete[] data;  // ← Fix: Delete old memory first!

    size = other.size;
    data = new int[size];
    for (int i = 0; i < size; i++) {
        data[i] = other.data[i];
    }

    return *this;
}

Why this matters: Every assignment without the fix leaks memory. In a program with many assignments, you'll eventually run out of memory.

Q16 True or False

True or False: The copy constructor is called when you pass an object by value to a function.

Answer: True

Explanation: When you pass an object by value, C++ needs to create a copy of the argument to pass to the function. This copying is done by the copy constructor.

void processData(MyClass obj) {  // Pass by value
    // ...
}

MyClass original;
processData(original);  // Copy constructor called!

This is one of three situations where the copy constructor is called:

  1. Initialization: MyClass obj2 = obj1;
  2. Pass by value: function(obj);
  3. Return by value: return obj; (though compilers often optimize this away)

Performance implication: This is why passing large objects by reference (const MyClass& obj) is preferred - avoids the copy.

Q17 Understanding this

Inside a member function, what is the type of this?

  1. ClassName
  2. ClassName&
  3. ClassName*
  4. const ClassName*

Answer: C - ClassName* (or D in const member functions)

Explanation: this is a pointer to the current object. In non-const member functions, its type is ClassName*. In const member functions, it's const ClassName*.

Usage:

  • this is the pointer itself
  • *this is the object (dereferencing the pointer)
  • this->member accesses a member via the pointer
class Example {
    int value;
public:
    void setValue(int value) {
        this->value = value;  // this is Example*
    }

    Example& getRef() {
        return *this;  // Dereference to get Example&
    }
};

Note: Both C and D can be correct depending on whether the member function is const or not, but C is the answer for regular (non-const) member functions.

Q18 2D Array Deletion

How do you properly delete a 2D array allocated like this?

int** matrix = new int*[rows];
for (int i = 0; i < rows; i++) {
    matrix[i] = new int[cols];
}
  1. delete[] matrix;
  2. delete matrix;
  3. Delete each row, then the array of pointers
  4. free(matrix);

Answer: C - Delete each row, then the array of pointers

Correct deletion code:

// Delete in reverse order of allocation
for (int i = 0; i < rows; i++) {
    delete[] matrix[i];  // Delete each row
}
delete[] matrix;  // Delete array of pointers

Explanation: With 2D arrays, you have two levels of allocation:

  1. Array of row pointers: new int*[rows]
  2. Each row: new int[cols] for each row

You must delete in reverse order: first delete each row (level 2), then delete the pointer array (level 1).

Why other options are wrong:

  • A: Only deletes the array of pointers, not the rows. Leaks all row memory.
  • B: Wrong deletion operator and only deletes first pointer. Leaks everything.
  • D: free() is for malloc(). Using it with new is undefined behavior.

Q19 When Default Works

For which class can you safely use the default copy constructor and assignment operator?

// Class A
class A {
    int x;
    double y;
};

// Class B
class B {
    int* ptr;
};

// Class C
class C {
    string name;
    int id;
};

// Class D
class D {
    int* data;
    int size;
};
  1. Classes A and C only
  2. All classes
  3. Class A only
  4. None of them

Answer: A - Classes A and C only

Explanation:

Class A (Safe): Only has primitive types (int, double). Default memberwise copy works fine. No dynamic memory.

Class B (NOT Safe): Has a raw pointer (int* ptr). If this pointer points to dynamically allocated memory, default copy would do shallow copy. Need custom Big Three.

Class C (Safe): Uses string which manages its own memory. When you copy a string, it does its own deep copy internally. No raw pointers, so default copy is safe.

Class D (NOT Safe): Has raw pointer int* data with size, strongly suggesting dynamic allocation. Needs custom Big Three for deep copying.

Rule: Default copy is safe when you have:

  • Only primitive types (int, double, char, etc.)
  • Only objects that manage their own memory (string, vector, etc.)

NOT safe when you have:

  • Raw pointers to dynamically allocated memory
  • Resources that need manual management (files, sockets, etc.)

Q20 Constructor vs Copy Constructor

What's the difference between these two lines?

MyClass obj1 = obj2;  // Line 1
MyClass obj1(obj2);   // Line 2
  1. Line 1 calls assignment operator, Line 2 calls copy constructor
  2. Both call copy constructor
  3. Line 1 calls copy constructor, Line 2 calls parameterized constructor
  4. They're completely different and unrelated

Answer: B - Both call copy constructor

Explanation: Both lines are initialization syntax, and both call the copy constructor. There's no difference in behavior.

  • MyClass obj1 = obj2; - Copy initialization (looks like assignment but isn't!)
  • MyClass obj1(obj2); - Direct initialization

Both create a new object obj1 from existing object obj2 using the copy constructor.

Common misconception: Line 1 LOOKS like assignment because of the =, but it's initialization. The assignment operator is only called when assigning to an EXISTING object:

MyClass obj1;      // Default constructor
obj1 = obj2;       // NOW assignment operator is called

Key distinction: If the object doesn't exist yet, it's initialization (copy constructor). If it already exists, it's assignment (assignment operator).
