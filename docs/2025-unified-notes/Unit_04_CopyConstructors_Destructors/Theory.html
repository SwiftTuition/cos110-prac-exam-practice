1. The Arrow Operator (->)

When you have a pointer to an object, accessing members can be clumsy. You need to dereference the pointer first, then use the dot operator:

Hero* hero = new Hero("Aragorn", 100);
cout << (*hero).name << endl;      // Awkward!
(*hero).takeDamage(20);            // Hard to read

The arrow operator (->) is a shortcut that combines dereferencing and member access into one step:

Hero* hero = new Hero("Aragorn", 100);
cout << hero->name << endl;        // Clean!
hero->takeDamage(20);              // Easy to read

hero->name is exactly the same as (*hero).name, but shorter and clearer.

Swift Note: The arrow operator doesn't do anything new. It's just syntactic sugar that makes pointer code easier to read. Use it whenever you access members through a pointer.

When to Use the Arrow Operator

Use -> when:

  • You have a pointer to an object
  • You want to access a member (data or function)

Use . (dot) when:

  • You have the object itself (not a pointer)
Hero gandalf("Gandalf", 200);     // Object (not pointer)
gandalf.castSpell();               // Use dot operator

Hero* legolas = new Hero("Legolas", 150);  // Pointer to object
legolas->shootArrow();             // Use arrow operator

delete legolas;
⚡ Swift Quiz
Quick Check: If you have Warrior* knight = new Warrior();, which is correct: knight.attack() or knight->attack()?
Answer: knight->attack() is correct. knight is a pointer, so we use the arrow operator. Using knight.attack() would give a compilation error because knight is a pointer type, not an object.

2. The this Pointer

Inside every member function, there's a special pointer called this. It points to the object that called the function.

Think of it this way: when you call hero1.takeDamage(20), inside the takeDamage function, this points to hero1. When you call hero2.takeDamage(30), this points to hero2.

Use Case 1: Disambiguation

The most common use of this is when parameter names match member variable names:

class Hero {
private:
    string name;
    int health;

public:
    Hero(string name, int health) {
        // Without 'this', which 'name' is which?
        // name = name;  // ❌ Assigns parameter to itself!

        // With 'this', it's clear:
        this->name = name;        // this->name is the member
        this->health = health;    // health parameter goes into member
    }
};

this->name means "the name member of the current object". name (without this->) refers to the parameter.

Important: Without this, the statement name = name; assigns the parameter to itself, leaving the member variable unchanged. This is a common bug!

Use Case 2: Returning the Current Object

Sometimes you want a function to return a reference to the current object. This allows chaining:

class Counter {
private:
    int count;

public:
    Counter() : count(0) {}

    Counter& increment() {
        count++;
        return *this;  // Return reference to current object
    }

    int getValue() { return count; }
};

// Now you can chain calls:
Counter c;
c.increment().increment().increment();  // count is now 3

return *this; returns a reference to the current object. Notice the * dereferences the this pointer.

🔬 Experiment 1: Remove all this-> from the constructor. What happens?

What happens: The code still compiles, but the member variables don't get initialized correctly. You'll see garbage values or default initialization.

Why: Without this->, the statement name = name; assigns the parameter name to itself. The member variable name is never touched. This is a silent bug!

The lesson: When parameter names match member names, always use this-> to be explicit about which one you mean.

What happens: Yes, it still works! The code prints correctly.

The lesson: You only need this-> when there's ambiguity. But some programmers use it everywhere for clarity.

⚡ Swift Quiz
Quick Check: What does return *this; do in a member function?
Answer: return *this; returns a reference to the current object. The this pointer points to the object, and *this dereferences it to get the object itself. This allows function chaining.

3. Copy Constructors and the Shallow Copy Problem

When you create a new object from an existing object, C++ calls a special constructor called the copy constructor:

Hero aragorn("Aragorn", 100);
Hero aragornCopy = aragorn;  // Copy constructor is called

If you don't write a copy constructor, C++ provides a default one. The default copy constructor does a memberwise copy: it copies each member variable from the source object to the new object.

This works fine for simple data types (int, double, etc.), but causes serious problems with pointers.

The Problem: Shallow Copy

Suppose you have a class that uses dynamic memory:

class Warrior {
private:
    string name;
    int* scores;   // Pointer to dynamically allocated array
    int numScores;

public:
    Warrior(string n, int num) {
        name = n;
        numScores = num;
        scores = new int[numScores];  // Allocate array on heap

        // Initialize to zeros
        for (int i = 0; i < numScores; i++) {
            scores[i] = 0;
        }
    }
};

If you copy this object using the default copy constructor, here's what happens:

BEFORE COPY:
john (original)
  name: "John"
  numScores: 3
  scores: 0x1000 ──┐
                   │
                   v
              [10][20][30]  ← Array on heap at address 0x1000


AFTER SHALLOW COPY (default copy constructor):
john (original)           bob (copy)
  name: "John"              name: "John"
  numScores: 3              numScores: 3
  scores: 0x1000 ──┐        scores: 0x1000 ──┐
                   │                          │
                   └──────────────────────────┘
                              │
                              v
                         [10][20][30]  ← SAME array!

Both objects point to the SAME array in memory!

This is called a shallow copy: the pointer value (memory address) is copied, but not the data it points to. Both objects now share the same array.

Why this is dangerous:
  • If john modifies scores[0], bob's scores[0] also changes!
  • When john is destroyed and deletes the array, bob's pointer becomes a dangling pointer pointing to freed memory
  • When bob is destroyed, it tries to delete the same array again, causing a double delete crash

The Solution: Deep Copy

A deep copy allocates new memory and copies the actual data, not just the pointer:

AFTER DEEP COPY (custom copy constructor):
john (original)                   bob (copy)
  name: "John"                      name: "John"
  numScores: 3                      numScores: 3
  scores: 0x1000 ──┐                scores: 0x2000 ──┐
                   │                                  │
                   v                                  v
              [10][20][30]                      [10][20][30]
              (john's array)                    (bob's array)

Each object has its own independent array!

To do a deep copy, you write your own copy constructor.

4. Writing a Copy Constructor

A copy constructor is a special constructor that takes a reference to another object of the same class:

class Warrior {
private:
    string name;
    int* scores;
    int numScores;

public:
    // Regular constructor
    Warrior(string n, int num) {
        name = n;
        numScores = num;
        scores = new int[numScores];
        for (int i = 0; i < numScores; i++) {
            scores[i] = 0;
        }
    }

    // Copy constructor
    Warrior(const Warrior& other) {
        name = other.name;
        numScores = other.numScores;

        // Allocate NEW memory for this object
        scores = new int[numScores];

        // Copy values from other's array
        for (int i = 0; i < numScores; i++) {
            scores[i] = other.scores[i];
        }
    }
};

Copy Constructor Syntax Rules

  1. Pass by reference: The parameter MUST be const ClassName&
    • If you pass by value, you'd need to copy the parameter, which calls the copy constructor, which needs to copy the parameter... infinite recursion!
  2. Use const: The const prevents you from accidentally modifying the source object
  3. Deep copy pointers: Allocate new memory and copy the data, don't copy the pointer address
Best Practice: If your class has pointer members that point to dynamically allocated memory, you MUST write a custom copy constructor to do deep copying.

5. Destructors: Cleaning Up Memory

A destructor is a special member function that runs automatically when an object is destroyed. This happens when:

  • A local object goes out of scope
  • A dynamically allocated object is deleted with delete
  • The program ends

The destructor's job is to clean up resources, especially dynamically allocated memory.

Destructor Syntax

class Warrior {
private:
    string name;
    int* scores;
    int numScores;

public:
    // Constructor
    Warrior(string n, int num) {
        name = n;
        numScores = num;
        scores = new int[numScores];
    }

    // Destructor
    ~Warrior() {
        delete[] scores;  // Free the dynamically allocated memory
        cout << name << " was destroyed." << endl;
    }
};

Destructor Rules

  1. Name: Same as class name with a ~ prefix
  2. No return type: Not even void
  3. No parameters: Destructors never take parameters
  4. Only one: You can only have one destructor per class (no overloading)
  5. Automatic: Called automatically, you rarely call it manually
Critical Rule: If your constructor uses new, your destructor MUST use delete (or delete[] for arrays). Otherwise, you have a memory leak!

Array Deletion

Use the correct deletion operator:

  • delete ptr; for single objects allocated with new
  • delete[] ptr; for arrays allocated with new[]
int* single = new int;           // Single int
delete single;                    // Use delete

int* array = new int[10];         // Array of ints
delete[] array;                   // Use delete[]

Using the wrong one causes undefined behavior (crashes or memory leaks).

What happens: The code runs and prints the same output, but you have a memory leak!

Why: Without a destructor, the dynamically allocated arrays are never freed. Each time an Array object is destroyed, the memory it allocated remains in use but is inaccessible. In a long-running program, this eventually exhausts available memory.

🔬 Experiment 2: Change delete[] data; to delete data; (remove the []). What's wrong?

What happens: Undefined behavior! The program might crash, or it might seem to work but leak memory.

Why: delete data; only deletes the first element of the array. The rest of the array is leaked. Worse, using delete instead of delete[] on an array is undefined behavior.

The lesson: Match your deletion to your allocation: new → delete, new[] → delete[].

⚡ Swift Quiz
Quick Check: Can you call a destructor explicitly like obj.~ClassName();?
Answer: Technically yes, but you should almost never do it. Destructors are meant to be called automatically when objects go out of scope. Calling them manually can cause double-deletion bugs when the object is automatically destroyed later.

6. The Assignment Operator

The assignment operator (=) is used to copy values from one existing object to another existing object:

Warrior john("John", 5);
Warrior bob("Bob", 3);

bob = john;  // Assignment operator is called

This is different from the copy constructor, which creates a new object:

Warrior john("John", 5);
Warrior bob = john;  // Copy constructor (bob doesn't exist yet)

Like the copy constructor, the default assignment operator does a shallow copy. For classes with pointers, you need to write a custom assignment operator that does deep copying.

The Self-Assignment Problem

One unique challenge with the assignment operator is self-assignment:

Warrior john("John", 5);
john = john;  // Assigning object to itself!

This might seem silly, but it can happen in real code:

warriors[i] = warriors[j];  // What if i == j?

If you don't check for self-assignment, you'll delete your own data before trying to copy it!

Writing the Assignment Operator

class Warrior {
private:
    string name;
    int* scores;
    int numScores;

public:
    // Assignment operator
    Warrior& operator=(const Warrior& other) {
        // 1. Check for self-assignment
        if (this == &other) {
            return *this;
        }

        // 2. Delete old memory
        delete[] scores;

        // 3. Copy simple members
        name = other.name;
        numScores = other.numScores;

        // 4. Deep copy pointers
        scores = new int[numScores];
        for (int i = 0; i < numScores; i++) {
            scores[i] = other.scores[i];
        }

        // 5. Return *this for chaining
        return *this;
    }
};

Assignment Operator Rules

  1. Self-assignment check: Always check if (this == &other) first
  2. Delete old data: Free the current object's dynamic memory before allocating new
  3. Deep copy: Allocate new memory and copy values
  4. Return *this: Allows chaining like a = b = c;
  5. Return type: Must be ClassName& (reference to current object)
Critical Bug: Forgetting the self-assignment check causes this sequence:
  1. Delete this->scores (which is the same as other.scores!)
  2. Try to copy from other.scores (which was just deleted!)
  3. Crash or garbage data

Why: Without the check, delete[] numbers; frees the memory that other.numbers points to (since this and other are the same object). Then the code tries to copy from freed memory!

What happens: The code still works, but you have a memory leak!

⚡ Swift Quiz
Quick Check: What's the difference between Warrior b = a; and Warrior b; b = a;?
Answer:
  • Warrior b = a; calls the copy constructor because b doesn't exist yet and is being initialized.
  • Warrior b; b = a; calls the default constructor first to create b, then calls the assignment operator to copy a's values into b.

7. The Big Three Rule

If your class needs one of these three special functions, it usually needs all three:

  1. Destructor: To free dynamic memory
  2. Copy constructor: To do deep copying
  3. Assignment operator: To do deep copying during assignment

This is called the Rule of Three (or Big Three).

Swift Note: The Big Three work together:
  • The destructor cleans up memory when objects are destroyed
  • The copy constructor creates independent copies when new objects are initialized
  • The assignment operator creates independent copies when existing objects are assigned
All three are needed to prevent shallow copy bugs and memory leaks.

When Do You Need the Big Three?

You need to implement all three when your class:

  • Has pointer members
  • Allocates memory dynamically (uses new)
  • Manages any resource (files, network connections, etc.)

You DON'T need them if:

  • Your class only has simple data types (int, double, etc.)
  • Your class only has objects that manage their own memory (like string)

Example: Class That Needs Big Three

class DynamicArray {
private:
    int* data;    // Pointer - needs Big Three!
    int size;

public:
    DynamicArray(int s) {
        size = s;
        data = new int[size];
    }

    // Copy constructor
    DynamicArray(const DynamicArray& other) {
        size = other.size;
        data = new int[size];
        for (int i = 0; i < size; i++) {
            data[i] = other.data[i];
        }
    }

    // Assignment operator
    DynamicArray& operator=(const DynamicArray& other) {
        if (this == &other) return *this;
        delete[] data;
        size = other.size;
        data = new int[size];
        for (int i = 0; i < size; i++) {
            data[i] = other.data[i];
        }
        return *this;
    }

    // Destructor
    ~DynamicArray() {
        delete[] data;
    }
};

Example: Class That DOESN'T Need Big Three

class Student {
private:
    string name;   // string manages its own memory
    int id;        // Simple type, no pointers
    double gpa;    // Simple type, no pointers

public:
    Student(string n, int i, double g) : name(n), id(i), gpa(g) {}

    // No need for Big Three!
    // Default versions work fine
};

8. Common Mistakes

Mistake 1: Shallow Copy When Deep Copy Needed

// ❌ WRONG - Shallow copy
class Inventory {
    int* items;
    int size;
public:
    Inventory(const Inventory& other) {
        size = other.size;
        items = other.items;  // Both point to same array!
    }
};
// ✅ CORRECT - Deep copy
class Inventory {
    int* items;
    int size;
public:
    Inventory(const Inventory& other) {
        size = other.size;
        items = new int[size];  // Allocate new memory
        for (int i = 0; i < size; i++) {
            items[i] = other.items[i];  // Copy values
        }
    }
};

Mistake 2: Missing Self-Assignment Check

// ❌ WRONG - No self-assignment check
Widget& operator=(const Widget& other) {
    delete[] data;  // If other == this, we just deleted our own data!
    size = other.size;
    data = new int[size];
    // Now copying from deleted memory!
    for (int i = 0; i < size; i++) {
        data[i] = other.data[i];
    }
    return *this;
}
// ✅ CORRECT - With self-assignment check
Widget& operator=(const Widget& other) {
    if (this == &other) return *this;  // Check first!

    delete[] data;
    size = other.size;
    data = new int[size];
    for (int i = 0; i < size; i++) {
        data[i] = other.data[i];
    }
    return *this;
}

Mistake 3: Forgetting const in Copy Constructor

// ❌ WRONG - Missing const
Warrior(Warrior& other) {  // Should be const!
    // ...
}
// ✅ CORRECT - With const
Warrior(const Warrior& other) {
    // ...
}

Without const, you can't copy from const objects or temporary objects.

Mistake 4: Wrong Delete Operator

// ❌ WRONG
~Container() {
    delete data;  // Should be delete[]!
}

// ✅ CORRECT
~Container() {
    delete[] data;  // Match new[] with delete[]
}

Mistake 5: Passing Copy Constructor by Value

// ❌ WRONG - Infinite recursion!
Warrior(Warrior other) {  // Missing &
    // To pass 'other' by value, C++ needs to copy it
    // Copying calls this copy constructor
    // Which needs to pass by value
    // Which calls the copy constructor...
}
// ✅ CORRECT - Pass by reference
Warrior(const Warrior& other) {
    // ...
}

Summary

Here are the key concepts from Unit 4:

Arrow Operator (->)

  • Shortcut for (*ptr).member
  • Use with pointers to objects
  • Makes pointer code cleaner and easier to read

The this Pointer

  • Points to the current object inside member functions
  • Use this-> to disambiguate when parameter names match member names
  • Use return *this; to enable function chaining

Copy Constructor

  • Signature: ClassName(const ClassName& other)
  • Called when creating a new object from an existing one
  • MUST pass by reference to avoid infinite recursion
  • Do deep copy for pointer members

Destructor

  • Signature: ~ClassName()
  • Called automatically when object is destroyed
  • Use delete[] for arrays, delete for single objects
  • No return type, no parameters

Assignment Operator

  • Signature: ClassName& operator=(const ClassName& other)
  • Called when assigning existing object to existing object
  • MUST check for self-assignment
  • Delete old memory, do deep copy, return *this

The Big Three Rule

  • If you need one, you need all three
  • Needed when class has pointers or manages resources
  • Not needed for classes with only simple types or self-managing objects
Best Practice Checklist:
  • ✓ Write copy constructor for classes with pointer members
  • ✓ Write destructor to free dynamic memory
  • ✓ Write assignment operator with self-assignment check
  • ✓ Do deep copy, not shallow copy
  • ✓ Match new[] with delete[]
  • ✓ Pass copy constructor parameter by const reference
  • ✓ Return *this from assignment operator
