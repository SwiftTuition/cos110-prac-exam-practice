Problem 1: Student Record Manager

Easy

Task:

Create a StudentRecord class that stores a student's name and an array of test scores dynamically. Implement the Big Three (copy constructor, destructor, assignment operator) to ensure proper memory management.

Requirements:

  • Store student name (string) and test scores (dynamic int array)
  • Copy constructor should create a deep copy of scores
  • Destructor should free the scores array
  • Assignment operator should handle self-assignment and deep copy

Class Interface:

class StudentRecord {
private:
    string name;
    int* scores;
    int numScores;
public:
    StudentRecord(string studentName, int num);
    StudentRecord(const StudentRecord& other);  // Copy constructor
    StudentRecord& operator=(const StudentRecord& other);  // Assignment
    ~StudentRecord();  // Destructor
    void setScore(int index, int score);
    void display() const;
};

  • Create a student with 3 test scores
  • Copy the student record (copy constructor)

  1. Copy Constructor: Allocates a new array and copies each score individually. This ensures that mpho and lesedi have independent score arrays.

Problem 2: Matrix Class

Intermediate

Task:

Create a Matrix class that stores a 2D array of integers dynamically. The matrix dimensions (rows and columns) can vary. Implement the Big Three and add a method for displaying the matrix.

Requirements:

  • Store a 2D dynamic array (pointer to pointer)
  • Deep copy should copy all elements
  • Handle different matrix sizes in assignment
  • Properly free all allocated memory

Class Interface:

class Matrix {
private:
    int** data;
    int rows;
    int cols;
public:
    Matrix(int r, int c);
    Matrix(const Matrix& other);
    Matrix& operator=(const Matrix& other);
    ~Matrix();
    void set(int row, int col, int value);
    void display() const;
};

Test Cases:

  • Create a 3x3 matrix and fill it with values
  • Copy the matrix and verify independent modification
  • Assign a 2x2 matrix to the 3x3 matrix
  • Verify no memory leaks

Explanation:

  1. 2D Array Allocation: We allocate an array of pointers (data = new int*[rows]), then allocate each row (data[i] = new int[cols]). This creates a true 2D dynamic array.
  2. Deep Copy: Both copy constructor and assignment operator allocate completely new arrays and copy all elements.
  3. Proper Deletion: The destructor (and assignment operator) must delete each row before deleting the array of pointers. Forgetting this causes memory leaks.
  4. Size Changes: The assignment operator handles changing matrix sizes by deleting the old matrix (whatever size it was) and allocating a new one with the source's dimensions.
Time Complexity: O(rows × cols) for copy constructor and assignment operator.
Space Complexity: O(rows × cols) for storing the matrix.
Key Point: With 2D arrays, you must delete in reverse order of allocation: delete rows first, then the pointer array.

Problem 3: Debug the Inventory System

Debugging Challenge

Task:

The following Inventory class has bugs in its Big Three implementation. Find all the bugs and explain how to fix them.

#include <iostream>
#include <string>
using namespace std;

class Inventory {
private:
    string* items;
    int numItems;

public:
    Inventory(int n) {
        numItems = n;
        items = new string[numItems];
        for (int i = 0; i < numItems; i++) {
            items[i] = "Empty";
        }
    }

    Inventory(Inventory& other) {
        numItems = other.numItems;
        items = other.items;
    }

    Inventory& operator=(const Inventory& other) {
        numItems = other.numItems;
        items = new string[numItems];
        for (int i = 0; i < numItems; i++) {
            items[i] = other.items[i];
        }
        return *this;
    }

    ~Inventory() {
        delete items;
    }

    void setItem(int index, string item) {
        if (index >= 0 && index < numItems) {
            items[index] = item;
        }
    }

    void display() {
        for (int i = 0; i < numItems; i++) {
            cout << items[i] << " ";
        }
        cout << endl;
    }
};

int main() {
    Inventory inv1(3);
    inv1.setItem(0, "Sword");
    inv1.setItem(1, "Shield");
    inv1.setItem(2, "Potion");

    Inventory inv2 = inv1;
    inv2.setItem(0, "Axe");

    inv1.display();
    inv2.display();

    Inventory inv3(2);
    inv3 = inv1;
    inv3.display();

    return 0;
}

Your Task: Identify at least 4 bugs in the code above.

Bugs Found:

Bug 1: Shallow Copy in Copy Constructor
Location: Line 22: items = other.items;
Problem: This copies the pointer address, not the data. Both objects point to the same array.
Fix: Allocate new memory and copy values: 
items = new string[numItems];
for (int i = 0; i < numItems; i++) {
    items[i] = other.items[i];
}
Bug 2: Missing const in Copy Constructor
Location: Line 19: Inventory(Inventory& other)
Problem: Should be const Inventory& other. Without const, you can't copy from const objects.
Fix: Inventory(const Inventory& other)
Bug 3: Missing Self-Assignment Check
Location: Assignment operator (line 25)
Problem: No check for if (this == &other). Also missing deletion of old memory.
Fix: Add at start: 
if (this == &other) return *this;
delete[] items;  // Delete old memory
Bug 4: Wrong Delete in Destructor
Location: Line 36: delete items;
Problem: Should be delete[] items; because items is an array.
Fix: delete[] items;

Corrected Code:

// Copy constructor (FIXED)
Inventory(const Inventory& other) {  // Added const
    numItems = other.numItems;

    // Deep copy!
    items = new string[numItems];
    for (int i = 0; i < numItems; i++) {
        items[i] = other.items[i];
    }
}

// Assignment operator (FIXED)
Inventory& operator=(const Inventory& other) {
    if (this == &other) return *this;  // Self-assignment check

    delete[] items;  // Delete old memory

    numItems = other.numItems;
    items = new string[numItems];
    for (int i = 0; i < numItems; i++) {
        items[i] = other.items[i];
    }
    return *this;
}

// Destructor (FIXED)
~Inventory() {
    delete[] items;  // Use delete[] for arrays
}
Key Lessons:
  • Always deep copy pointers in copy constructor
  • Copy constructor parameter must be const ClassName&
  • Assignment operator must check self-assignment and delete old memory
  • Match allocation type with deletion: new[] with delete[]

Problem 4: Clash Royale Deck Manager

Challenge

Swift plays Clash Royale - a real-time strategy mobile game where players build decks of 8 cards and battle opponents. Each card has a name and elixir cost (resource needed to play it). Decks need to be copied for testing strategies and assigned to different player profiles.

Task:

Create a ClashDeck class that manages a collection of cards. The class should support:

  • Dynamic card storage (array of Card structs)
  • Method chaining for adding cards (return *this)
  • Deep copying for deck testing (copy constructor)
  • Profile switching (assignment operator)
  • Proper cleanup when decks are destroyed

Card Structure:

struct Card {
    string name;
    int elixirCost;
};

Requirements:

  1. Store an array of Cards dynamically (max 8 cards)
  2. Implement addCard() that returns ClashDeck& for chaining
  3. Implement copy constructor for deep copying
  4. Implement assignment operator with self-assignment check
  5. Implement destructor to free memory
  6. Add displayDeck() to show all cards

  • Copy the deck and verify independence
  • Assign one deck to another
  • Test self-assignment

Explanation:

  1. Method Chaining: addCard() returns ClashDeck& and ends with return *this;. This allows chaining: deck.addCard(...).addCard(...).addCard(...).
  2. Deep Copy: Copy constructor allocates a new Card array and copies each card. This allows testing strategies without affecting the original deck.
  3. Assignment for Profile Switching: Assignment operator allows copying a deck configuration to a different profile. It checks self-assignment, deletes old memory, and creates a new copy.
  4. Capacity Tracking: We track both numCards (current count) and capacity (max size) to prevent overflow.
Time Complexity: O(n) for copy constructor and assignment operator, where n is the number of cards.
Space Complexity: O(n) for storing the deck.
Design Pattern: This demonstrates the Fluent Interface pattern (method chaining) combined with proper resource management (Big Three).
Real-World Application: This pattern is used in many APIs:
  • jQuery: $('.element').addClass('active').fadeIn().slideDown()
  • cout: cout << "Hello" << " " << "World" << endl;
  • SQL builders: query.select("*").from("users").where("age > 18")
