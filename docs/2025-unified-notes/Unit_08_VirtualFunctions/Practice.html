Problem 3: Find and Fix the Bug (Debugging)

Task

The following code compiles and runs, but doesn't produce the expected polymorphic behavior. Find the bug and fix it.

Buggy Code

#include <iostream>
using namespace std;

class Shape {
public:
    void draw() {
        cout << "Drawing a generic shape" << endl;
    }
};

class Circle : public Shape {
public:
    void draw() {
        cout << "Drawing a circle" << endl;
    }
};

class Square : public Shape {
public:
    void draw() {
        cout << "Drawing a square" << endl;
    }
};

int main() {
    Shape* shapes[2];
    shapes[0] = new Circle();
    shapes[1] = new Square();

    for (int i = 0; i < 2; i++) {
        shapes[i]->draw();
    }

    for (int i = 0; i < 2; i++) {
        delete shapes[i];
    }

    return 0;
}

Current (Wrong) Output

Drawing a generic shape
Drawing a generic shape

Expected Output

Drawing a circle
Drawing a square

Question

What's wrong? Why does it print "Drawing a generic shape" twice instead of calling the derived class versions?

The Bug

The draw() function in the Shape class is not virtual. Without the virtual keyword, static binding is used - the compiler looks at the pointer type (Shape*) and always calls Shape::draw().

  1. Line 5: Changed void draw() to virtual void draw()
  2. Added virtual destructor: virtual ~Shape() {} to prevent memory leaks

Why This Fixes It

With virtual, the compiler uses dynamic binding. At runtime, when shapes[i]->draw() is called, the program checks what shapes[i] actually points to (Circle or Square) and calls the correct version.

Common Mistake: Forgetting to make functions virtual in the base class is one of the most common bugs in polymorphic code. Without virtual, you don't get polymorphism - you just get static binding based on pointer type.

Problem 4: Predict the Output (Challenge)

Task

Predict the output of this complex code involving virtual and non-virtual functions. This tests your understanding of when polymorphism works and when it doesn't.

Code to Analyze

#include <iostream>
using namespace std;

class Base {
public:
    virtual void func1() {
        cout << "Base::func1" << endl;
    }

    void func2() {
        cout << "Base::func2" << endl;
    }

    virtual ~Base() {}
};

class Derived : public Base {
public:
    void func1() {
        cout << "Derived::func1" << endl;
    }

    void func2() {
        cout << "Derived::func2" << endl;
    }
};

int main() {
    Base* ptr = new Derived();

    ptr->func1();
    ptr->func2();

    delete ptr;
    return 0;
}

Question

What will this program print? Try to predict before revealing the answer.

Correct Output

Derived::func1
Base::func2

Line-by-Line Analysis

  1. Base* ptr = new Derived();
    Creates a Derived object, but ptr is of type Base*.
  2. ptr->func1();
    func1() is virtual in Base.
    Dynamic binding: Check actual object type → It's Derived → Call Derived::func1()
    Prints: "Derived::func1"
  3. ptr->func2();
    func2() is NOT virtual in Base.
    Static binding: Compiler looks at pointer type → It's Base* → Call Base::func2()
    Prints: "Base::func2"

Key Insight

The Rule:
  • Virtual functions: Use dynamic binding (actual object type determines which version)
  • Non-virtual functions: Use static binding (pointer/reference type determines which version)
