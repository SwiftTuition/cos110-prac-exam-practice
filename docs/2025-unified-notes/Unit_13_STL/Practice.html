What's Wrong? Vector Iterator Invalidation

Problem:

The following code is supposed to remove all even numbers from a vector while iterating through it. However, it has a bug that causes undefined behavior. Can you spot what's wrong? 

#include <iostream>
#include <vector>

using namespace std;

int main() {
    vector<int> numbers;
    numbers.push_back(1);
    numbers.push_back(2);
    numbers.push_back(3);
    numbers.push_back(4);
    numbers.push_back(5);
    numbers.push_back(6);

    // Remove all even numbers
    vector<int>::iterator it;
    for (it = numbers.begin(); it != numbers.end(); ++it) {
        if (*it % 2 == 0) {
            numbers.erase(it);  // Problem is here!
        }
    }

    // Display remaining numbers
    cout << "Remaining numbers: ";
    for (it = numbers.begin(); it != numbers.end(); ++it) {
        cout << *it << " ";
    }
    cout << endl;

    return 0;
}

Your task: Identify the bug and explain why it causes problems. Then provide a corrected version.

The Bug

Line 19 is the problem: numbers.erase(it);

Why it's wrong: When you call erase() on a vector, it invalidates all iterators at and after the erased position. After erasing, the iterator it no longer points to a valid location. When the loop does ++it, it's incrementing an invalid iterator - this is undefined behavior!

What happens: The program might crash, might skip elements, or might appear to work sometimes. Undefined behavior is unpredictable.

Understanding the Fix

  • Line 22: Use a while loop instead of for because we need control over when to increment.
  • Line 26: erase() returns an iterator to the element after the erased one. We assign this to it.
  • Line 28: Only increment it if we didn't erase. If we erased, it already points to the next element.
  • Why this works: By using the return value of erase(), we get a valid iterator to the next element, avoiding the invalidation problem.
General Rule: Never increment an iterator after calling erase() on it. Always use the returned iterator or adjust your loop structure accordingly.
Alternative approach: You could also iterate backwards, or build a new vector with only the elements you want to keep. The backwards approach works because erasing doesn't invalidate iterators before the erased position.
