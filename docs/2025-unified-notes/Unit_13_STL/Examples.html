6Lines 42-47: insert() returns a pair. The second member is a bool: true if insertion happened, false if element already existed. This lets us know if the insertion succeeded.

7Lines 50-52: Use erase() to remove an element by value. After removing "Rock", we have 5 genres left.

Key Takeaways:
  • Sets automatically remove duplicates - perfect for "unique items" scenarios
  • Sets keep elements sorted (strings alphabetically, numbers numerically)
  • count() on sets returns 0 or 1 (can't have duplicates)
  • insert() returns a pair<iterator, bool> - the bool tells you if insertion succeeded
  • erase() can take a value or an iterator

🐛 Find the Bug: Misusing Stack Operations

Problem: The following program tries to process a stack of exam scores, but it has a bug that prevents it from compiling. Can you find what's wrong?

🐛
Buggy Code - This Won't Compile!
#include <iostream>
#include <stack>

using namespace std;

int main() {
    stack<int> examScores;

    // Push exam scores onto stack
    examScores.push(85);
    examScores.push(92);
    examScores.push(78);
    examScores.push(95);

    cout << "Processing exam scores..." << endl;

    // Process all scores
    while (!examScores.empty()) {
        // Get and remove the top score
        int score = examScores.pop();
        cout << "Score: " << score << endl;
    }

    return 0;
}

Your task: Find the bug and understand why it doesn't work. Then click the reveal button to see the explanation and fixed code.

🔍 The Bug

Line 20 is the problem: 

int score = examScores.pop();  // COMPILE ERROR!

Why it doesn't work: The pop() function in STL's stack does NOT return a value! It has return type void. This is a deliberate design decision in the STL.

Why is pop() void? For exception safety. If pop() both removed AND returned the value, what happens if the copy constructor throws an exception? The element would be removed from the stack but the caller wouldn't receive it - data loss!

The correct approach: Use top() to get the value, then pop() to remove it:

📖 Understanding the Fix

1Line 20: Call top() to GET the value at the top of the stack. This returns a reference to the element without removing it.

2Line 23: Call pop() to REMOVE the top element. This returns nothing (void), so we can't assign it to a variable.

3Why two steps? This separation ensures exception safety. If copying the value fails, the element is still on the stack. If we had a combined "pop and return" operation, a copy failure would lose the data.

4LIFO order: Stack is Last-In-First-Out. We pushed 85, 92, 78, 95 in that order. So we process them in reverse: 95, 78, 92, 85.

Common Mistake - Don't Do This: 
// WRONG - pop() doesn't return anything!
int value = myStack.pop();

// ALSO WRONG - using pop() result in cout
cout << myStack.pop();  // Compile error!

// CORRECT - two-step process
int value = myStack.top();
myStack.pop();
Remember: This same pattern applies to queue! Use front() to get the value, then pop() to remove it. Never try to use pop()'s return value - it doesn't have one!
