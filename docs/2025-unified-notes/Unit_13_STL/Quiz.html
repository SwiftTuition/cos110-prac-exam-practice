Section A: Multiple Choice
10 questions · 1 mark each · 10 marks total
Q1
[1 mark]
Which STL container provides the fastest access to elements by index?
A) list
B) vector
C) set
D) map
Correct Answer: B) vector

Explanation:

Vector provides O(1) random access to elements by index using the [] operator or at() function. This is because vectors store elements contiguously in memory, so accessing v[100] is just a pointer offset calculation.

Why other options are wrong:

  • A) list: Requires O(n) time to access by index because you must traverse nodes from beginning.
  • C) set: Doesn't support index access at all (elements are ordered by value, not position).
  • D) map: Doesn't support index access (uses keys, not indices).
Q2
[1 mark]
What is the return type of the pop() function in STL's stack?
A) The element being removed
B) A boolean indicating success
C) void (returns nothing)
D) An iterator to the next element
Correct Answer: C) void (returns nothing)

Explanation:

The pop() function in STL's stack (and queue) returns void. This is a deliberate design decision for exception safety. If pop() both removed and returned the element, and the copy constructor threw an exception, the element would be lost from the container but not received by the caller.

Correct usage:

// Get value first
int value = myStack.top();
// Then remove it
myStack.pop();

This two-step process ensures that if copying fails, the element remains on the stack.

Q3
[1 mark]
Which iterator category does a list provide?
A) Forward iterator
B) Bidirectional iterator
C) Random access iterator
D) Input iterator
Correct Answer: B) Bidirectional iterator

Explanation:

A list (doubly linked list) provides bidirectional iterators. This means you can:

  • Move forward with ++it
  • Move backward with --it
  • Access elements with *it

What you CANNOT do:

  • Jump to arbitrary positions with it + 5 (requires random access)
  • Use array notation like it[5] (requires random access)
  • Calculate distance in O(1) time with it2 - it1 (requires random access)

Only vector and deque provide random access iterators.

Q4
[1 mark]
In a map<int, string>, what does it->first represent when it is an iterator?
A) The value (string)
B) The key (int)
C) A pointer to the pair
D) The beginning of the map
Correct Answer: B) The key (int)

Explanation:

Map iterators point to pair objects. Each pair has two members:

  • first - The key (in this case, int)
  • second - The value (in this case, string)

Example:

map<int, string> students;
students[12345] = "Themba";

map<int, string>::iterator it = students.begin();
cout << it->first;  // Prints: 12345 (the key)
cout << it->second; // Prints: Themba (the value)
Q5
[1 mark]
What happens if you insert a duplicate element into a set?
A) The set stores both copies
B) The insertion is ignored (element already exists)
C) A compile error occurs
D) The old element is replaced
Correct Answer: B) The insertion is ignored (element already exists)

Explanation:

Sets only store unique elements. If you try to insert an element that already exists, the insert() operation does nothing.

How to check if insertion happened:

set<int> numbers;
numbers.insert(10);

pair<set<int>::iterator, bool> result = numbers.insert(10);
if (result.second) {
    cout << "Inserted successfully";
} else {
    cout << "Element already exists"; // This will print
}

The insert() function returns a pair where second is true if insertion happened, false if element already existed.

Q6
[1 mark]
Which algorithm requires random access iterators and will NOT work with a list?
A) find()
B) count()
C) sort()
D) reverse()
Correct Answer: C) sort()

Explanation:

The std::sort() algorithm requires random access iterators because it needs to jump around in the container efficiently. Lists only provide bidirectional iterators.

Example:

list<int> myList = {5, 2, 8, 1};
// sort(myList.begin(), myList.end()); // COMPILE ERROR!

// List has its own member function:
myList.sort(); // This works!

Why other options work with lists:

  • find() - Only needs forward iterator (sequential search)
  • count() - Only needs forward iterator (sequential traversal)
  • reverse() - Works with bidirectional iterators
Q7
[1 mark]
What is the default inner container for stack<int>?
A) vector
B) list
C) deque
D) array
Correct Answer: C) deque

Explanation:

By default, stack uses deque as its underlying container. This is mentioned in EO3 2018 Question 1.2.

Example:

stack<int> s1;                    // Uses deque by default
stack<int, vector<int> > s2;     // Explicitly use vector
stack<int, list<int> > s3;       // Explicitly use list

Note: In C++98, you need a space between the closing >> to avoid the parsing ambiguity: vector<int> > not vector<int>>.

Q8
[1 mark]
What does container.end() return?
A) An iterator to the last element
B) An iterator one past the last element
C) A null pointer
D) The size of the container
Correct Answer: B) An iterator one past the last element

Explanation:

The end() function returns an iterator pointing to the position one past the last element. This is called a "sentinel" or "past-the-end" iterator.

Important: You should NEVER dereference end()! It doesn't point to a valid element.

Correct usage:

vector<int> v = {1, 2, 3};
vector<int>::iterator it;
for (it = v.begin(); it != v.end(); ++it) { // Compare to end()
    cout << *it; // Dereference to get value
}
// *v.end(); // UNDEFINED BEHAVIOR - DON'T DO THIS!

The half-open range [begin, end) is standard in STL - includes first, excludes end.

Q9
[1 mark]
Which operation is O(1) for a list but O(n) for a vector?
A) Access element by index
B) Insert at the front
C) Access last element
D) Get size
Correct Answer: B) Insert at the front

Explanation:

Inserting at the front has different time complexities:

  • List: O(1) - Just create new node and update head pointer
  • Vector: O(n) - Must shift all existing elements one position to make room

Example:

list<int> l;
l.push_front(10); // O(1) - efficient!

vector<int> v;
// No push_front() for vector!
// Would need: v.insert(v.begin(), 10); // O(n) - slow!

Why other options are wrong:

  • A: Vector is O(1), list is O(n)
  • C: Both are O(1) using back()
  • D: Both are O(1) using size()
Q10
[1 mark]
What does binary_search() return?
A) An iterator to the found element
B) The index of the found element
C) A boolean (true if found, false otherwise)
D) The number of matching elements
Correct Answer: C) A boolean (true if found, false otherwise)

Explanation:

The binary_search() algorithm returns a bool: true if the element is found, false otherwise. It does NOT return an iterator or index.

Important requirement: The range must be sorted!

Example:

vector<int> v = {1, 3, 5, 7, 9}; // Must be sorted!
if (binary_search(v.begin(), v.end(), 5)) {
    cout << "Found!";
} else {
    cout << "Not found";
}

If you need the iterator: Use lower_bound() or find() instead.

Section B: True or False
5 questions · 2 marks each · 10 marks total · Justify your answer
Q11
[2 marks]
True or False: Vectors always use less memory than lists for the same number of elements.

Justify your answer in no more than two sentences.

Answer: TRUE

Justification:

Vectors store elements contiguously, requiring only space for the elements themselves plus overhead for size/capacity. Lists require additional memory for two pointers (next and prev) per node, making them less memory-efficient.

Memory breakdown:

  • Vector: n × sizeof(element) + small overhead
  • List: n × (sizeof(element) + 2 × sizeof(pointer))

For an int (4 bytes) on a 64-bit system (8-byte pointers): vector uses ~4 bytes per element, list uses ~20 bytes per element!

Q12
[2 marks]
True or False: Map keys must be unique, but values can be duplicated.

Justify your answer in no more than two sentences.

Answer: TRUE

Justification:

A map stores unique key-value pairs where each key can only appear once, but multiple keys can map to the same value. If you insert a key that already exists, it overwrites the old value.

Example:

map<int, string> m;
m[1] = "Alice";
m[2] = "Alice";  // Duplicate VALUE is fine
m[1] = "Bob";    // Overwrites - keys must be unique!
Q13
[2 marks]
True or False: You can use sort() algorithm directly on any STL container.

Justify your answer in no more than two sentences.

Answer: FALSE

Justification:

The std::sort() algorithm requires random access iterators, which only vector and deque provide. Containers like list must use their own member function list.sort() instead.

Why this matters:

Sorting requires jumping around in the collection for efficiency (e.g., quicksort pivoting). Lists can only move sequentially, so they need a different sorting algorithm optimized for linked structures (typically mergesort).

Q14
[2 marks]
True or False: Accessing map[key] when the key doesn't exist will throw an exception.

Justify your answer in no more than two sentences.

Answer: FALSE

Justification:

The [] operator will create a new entry with the default value for that type if the key doesn't exist. To avoid this behavior, use find() or at() (which does throw an exception).

Example:

map<int, string> m;
cout << m[999]; // Creates entry 999 → "" (empty string)
cout << m.size(); // Prints 1 (entry was created!)

// Safe way:
if (m.find(999) != m.end()) {
    cout << m[999]; // Only access if exists
}
Q15
[2 marks]
True or False: Iterators remain valid after calling erase() on a vector.

Justify your answer in no more than two sentences.

Answer: FALSE

Justification:

Calling erase() on a vector invalidates all iterators at and after the erased position because elements are shifted. You must use the iterator returned by erase() to continue safely.

Correct pattern:

vector<int>::iterator it = v.begin();
while (it != v.end()) {
    if (*it % 2 == 0) {
        it = v.erase(it); // Use return value!
    } else {
        ++it;
    }
}
Section C: Code Tracing
5 questions · 3-4 marks each · 18 marks total
Q16
[4 marks]
What is the output of the following code? Show your working. 
stack<char> s;
for (char c = 'w'; c <= 'z'; c++) {
    s.push(c);
}

char x = s.top();
s.pop();
char y = 'a';

while (!s.empty()) {
    cout << s.top() << endl;
    s.pop();
    if (!s.empty()) {
        s.pop();
        s.push(y++);
    }
}
cout << x << endl;
cout << y << endl;

Similar to EO3 2018 Question 1.1

Output:
y
a
b
z
c

Step-by-step trace:

  1. After loop: Stack contains (bottom to top): w, x, y, z
  2. Line 6-7: x = 'z' (top), then pop. Stack: w, x, y
  3. Initialize: y = 'a'
  4. Iteration 1:
    • Print top: y
    • Pop (removes 'y'). Stack: w, x
    • Not empty, so pop (removes 'x'), push(y++ = 'a'). Stack: w, a
    • y is now 'b'
  5. Iteration 2:
    • Print top: a
    • Pop (removes 'a'). Stack: w
    • Not empty, so pop (removes 'w'), push(y++ = 'b'). Stack: b
    • y is now 'c'
  6. Iteration 3:
    • Print top: b
    • Pop (removes 'b'). Stack: empty
    • Stack is empty, so don't enter if
  7. After loop: Print x = 'z', then y = 'c'
Q17
[3 marks]
What is the output of the following code? 
vector<int> v;
v.push_back(10);
v.push_back(20);
v.push_back(30);

v.pop_back();
v.push_back(40);

for (int i = 0; i < v.size(); i++) {
    cout << v[i] << " ";
}
cout << endl;
Output: 10 20 40

Explanation:

  1. After lines 2-4: Vector contains [10, 20, 30]
  2. Line 6 (pop_back()): Removes 30. Vector: [10, 20]
  3. Line 7 (push_back(40)): Adds 40. Vector: [10, 20, 40]
  4. Loop prints all elements: 10 20 40
Q18
[4 marks]
What is the output of the following code? 
map<string, int> ages;
ages["Alice"] = 20;
ages["Bob"] = 25;
ages["Charlie"] = 20;

ages["Alice"] = 21;

map<string, int>::iterator it;
for (it = ages.begin(); it != ages.end(); ++it) {
    cout << it->first << ": " << it->second << endl;
}
Output:
Alice: 21
Bob: 25
Charlie: 20

Explanation:

  1. Line 2-4: Insert three entries
  2. Line 6: Overwrites Alice's age from 20 to 21 (keys are unique)
  3. Iteration: Map automatically sorts by key (alphabetically for strings)
  4. Order: Alice, Bob, Charlie (alphabetical)
  5. Values: 21, 25, 20 (note: Alice was updated)

Key point: Maps sort by KEY, not by value or insertion order!

Q19
[3 marks]
What is the output of the following code? 
set<int> numbers;
numbers.insert(5);
numbers.insert(2);
numbers.insert(8);
numbers.insert(2);
numbers.insert(1);

set<int>::iterator it;
for (it = numbers.begin(); it != numbers.end(); ++it) {

cout << endl;
Output: 1 2 5 8

Explanation:

  1. Line 2: Insert 5
  2. Line 3: Insert 2
  3. Line 4: Insert 8
  4. Line 5: Try to insert 2 (duplicate - ignored!)
  5. Line 6: Insert 1
  6. Final set: {1, 2, 5, 8} (sorted, no duplicates)

  • Sets keep elements sorted (1, 2, 5, 8 not 5, 2, 8, 1)

Q20
[4 marks]
What is the output of the following code? 
queue<int> q;
q.push(10);
q.push(20);
q.push(30);

cout << q.front() << endl;
q.pop();

q.push(40);
cout << q.front() << endl;

while (!q.empty()) {
    cout << q.front() << " ";
    q.pop();
}
cout << endl;
Output:
10
20
20 30 40

Step-by-step trace:

  1. After pushes (lines 2-4): Queue: [10, 20, 30] (front → back)
  2. Line 6: Print front: 10
  3. Line 7: Pop front. Queue: [20, 30]
  4. Line 9: Push 40 at back. Queue: [20, 30, 40]
  5. Line 10: Print front: 20
  6. While loop: Print and pop all: 20, 30, 40

Key point: Queue is FIFO (First In, First Out). Elements are removed from the front and added to the back.

Section D: Matching

Q21
[5 marks]
Match each use case with the most appropriate STL container:

Use Cases:

  1. Need frequent random access by index
  2. Need to store unique student numbers
  3. Need to map employee IDs to names
  4. Need to process tasks in the order they arrive
  5. Need frequent insertion/deletion at both ends

Containers:

  • A) vector
  • B) list
  • C) deque
  • D) set
  • E) map
  • F) stack
  • G) queue
Answers:
  1. A) vector - Random access by index is O(1) for vectors
  2. D) set - Sets automatically store unique elements
  3. E) map - Maps store key-value pairs (ID → name)
  4. G) queue - FIFO processing matches task queue behavior
  5. C) deque - Efficient at both front and back

Detailed explanations:

  • 1 → vector: Vectors store elements contiguously, allowing O(1) random access via [] operator.
  • 2 → set: Sets enforce uniqueness automatically - trying to insert a duplicate student number would be ignored.
  • 3 → map: Perfect for ID-to-name lookups with O(log n) access time.
  • 4 → queue: First task in, first task processed (FIFO).
  • 5 → deque: "Double-ended queue" - efficient push/pop at both front and back, unlike vector (only efficient at back).
Q22
[5 marks]
Match each iterator category with its capabilities:

Iterator Categories:

  1. Forward Iterator
  2. Bidirectional Iterator
  3. Random Access Iterator

Capabilities:

  • A) Can use ++ only
  • B) Can use ++ and --
  • C) Can use ++, --, and []
  • D) Can jump to arbitrary positions with + and -
  • E) Required for std::sort()
Answers:
  1. Forward Iterator: A only
  2. Bidirectional Iterator: A, B
  3. Random Access Iterator: A, B, C, D, E (all capabilities)

Breakdown:

  • Forward (A): Can only move forward (++), read/write with *
  • Bidirectional (A, B): All forward capabilities PLUS backward movement (--)
  • Random Access (A, B, C, D, E): All bidirectional capabilities PLUS:
    • Array notation: it[n]
    • Arithmetic: it + 5, it - 3
    • Distance: it2 - it1
    • Required for sort()

Container examples:

  • Forward: (most containers provide at least this)
  • Bidirectional: list, set, map
  • Random Access: vector, deque

Q24
[4 marks]
Write a function that uses an STL stack<int> to reverse a vector<int>. Your function should take a vector by reference and modify it in-place. (Similar to EO3 2018 Q4.1a)

Function signature: void reverseVector(vector<int>& v)

Solution:
void reverseVector(vector<int>& v) {
    stack<int> s;

    // Push all elements onto stack
    for (int i = 0; i < v.size(); i++) {
        s.push(v[i]);
    }

    // Pop elements back into vector (reversed order)
    for (int i = 0; i < v.size(); i++) {
        v[i] = s.top();
        s.pop();
    }
}

How it works:

  1. Create a stack to temporarily store elements
  2. Push all vector elements onto stack (LIFO property)
  3. Pop elements from stack back into vector
  4. Since stack is LIFO, elements come out in reverse order

Example:

  • Input: [1, 2, 3, 4]
  • After push loop: Stack (bottom→top): 1, 2, 3, 4
  • After pop loop: Vector: [4, 3, 2, 1]
Q25
[3 marks]
Explain why the pop() function in stack and queue returns void instead of returning the removed element.
Answer:

Reason: Exception safety

If pop() both removed and returned the element, there's a risk of data loss. Here's why:

  1. pop() would need to make a copy of the element to return it
  2. If the copy constructor throws an exception during this copy, the element has already been removed from the container
  3. The caller never receives the element (exception interrupted the return)
  4. The element is lost - it's no longer in the container and wasn't received by the caller

Two-step solution prevents this:

// Step 1: Get the value (if this fails, element stays in stack)
T value = s.top();
// Step 2: Remove it (void return, can't fail to return)
s.pop();

This separation guarantees that if getting the value fails, the element remains in the container.

Q26
[4 marks]
Given a map<string, int> grades containing student names and marks, write code to:
  1. Find and print the highest mark
  2. Find and print the name of the student with the highest mark

You may assume the map is not empty.

Solution:
int maxMark = 0;
string topStudent = "";

map<string, int>::iterator it;
for (it = grades.begin(); it != grades.end(); ++it) {
    if (it->second > maxMark) {
        maxMark = it->second;      // Update highest mark
        topStudent = it->first;    // Update student name
    }
}

cout << "Highest mark: " << maxMark << endl;
cout << "Top student: " << topStudent << endl;

Explanation:

  • Line 1-2: Initialize tracking variables
  • Line 5-10: Iterate through map, comparing each mark (it->second) to current max
  • Line 7-8: When we find a higher mark, update both the mark and the name
  • Key point: We track BOTH the max value and its corresponding key

Note: We can't use max_element() directly on a map because we need to compare values, not keys. Manual iteration is required.

Q27
[4 marks]
Write code to remove all duplicate elements from a vector<int> v using an STL set. The resulting vector should contain only unique elements.
Solution:
set<int> uniqueElements;

// Insert all vector elements into set (duplicates auto-removed)
for (int i = 0; i < v.size(); i++) {
    uniqueElements.insert(v[i]);
}

// Clear vector and copy unique elements back
v.clear();
set<int>::iterator it;
for (it = uniqueElements.begin(); it != uniqueElements.end(); ++it) {
    v.push_back(*it);
}

How it works:

  1. Create a set to store unique elements
  2. Insert all vector elements into set - duplicates are automatically ignored
  3. Clear the original vector
  4. Copy elements from set back to vector - now only unique elements
  5. Bonus: Elements are now sorted (set maintains sorted order)

Example:

  • Input: [3, 1, 4, 1, 5, 9, 2, 6, 5]
  • After set insert: set contains {1, 2, 3, 4, 5, 6, 9}
  • Final vector: [1, 2, 3, 4, 5, 6, 9] (unique and sorted)
Q28
[4 marks]
When should you choose a list over a vector? Give two specific scenarios with justification.
Answer:

Scenario 1: Frequent insertion/deletion in the middle

Justification: List allows O(1) insertion/deletion once you have an iterator to the position. Vector requires O(n) time because all subsequent elements must be shifted.

Example: Managing a playlist where users frequently add/remove songs at arbitrary positions.

Scenario 2: Iterator stability during modifications

Justification: When you insert or delete elements in a list, iterators to other elements remain valid. In a vector, insertions/deletions can invalidate all iterators due to reallocation or shifting.

Example: Processing a task list where you might remove tasks while iterating, and other iterators need to remain valid.

When NOT to use list:

  • Need random access by index (O(n) for list vs O(1) for vector)
  • Concerned about memory overhead (list uses ~3x more memory per element)
  • Cache locality matters (vector has better cache performance)
