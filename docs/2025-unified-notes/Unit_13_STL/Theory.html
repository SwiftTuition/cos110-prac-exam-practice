Unit 13: Standard Template Library (STL)

Welcome to Unit 13! This week (Week 15), we're exploring the Standard Template Library - a collection of pre-built data structures and algorithms that make C++ programming way more efficient. Think of it like having a toolbox where someone already built the hammer, screwdriver, and wrench for you. You just need to learn how to use them.

Prerequisites: This unit builds on Unit 9 (Templates). The entire STL is built using templates, so you need to understand how template classes work. If you're fuzzy on templates, go back and review that unit first!

1. Introduction to the STL

Before the STL existed, programmers had to write their own dynamic arrays, linked lists, and search algorithms for every single project. Imagine building a linked list from scratch every time you needed one. That's tedious and error-prone.

The Standard Template Library solves this by giving us three core components:

  • Containers: Data structures that store collections of objects (like vector, list, map)
  • Iterators: Smart pointers that let us access elements in containers in a uniform way
  • Algorithms: Functions that perform operations on containers (like sort, find, count)

The genius of the STL is that these components are decoupled. Algorithms don't know about specific containers - they just know how to use iterators. This means you can use the same sort algorithm on a vector, a deque, or any other compatible container without changing the algorithm's code.

Swift Note: The STL is like the ultimate reusable code library. Instead of reinventing the wheel every time, we use battle-tested, optimized data structures. This is what separates beginner programmers from professionals - knowing when to use what already exists.

1.1 Why Use the STL?

  • Save time: Don't rebuild data structures from scratch
  • Fewer bugs: STL code is heavily tested and optimized
  • Industry standard: Every C++ developer uses the STL
  • Performance: STL implementations are highly optimized

Experiment 1: What happens if you try to access numbers[10] when the vector only has 3 elements after pop_back()?

What happens: Accessing numbers[10] is undefined behavior. The program might crash, might give you garbage values, or might seem to work (but still be wrong).

Why: The [] operator does NOT check if the index is valid. It just accesses memory at that location. If you go beyond the vector's size, you're accessing memory you shouldn't.

Safe alternative: Use the .at() function instead, which throws an exception if the index is out of bounds:

try {
    cout << numbers.at(10);  // Throws exception
} catch (out_of_range& e) {
    cout << "Error: " << e.what() << endl;
}

2. Iterators - The Great Unifier

An iterator is an object that acts like a pointer. It provides a way to access elements in a container sequentially, regardless of how the container is implemented internally.

2.1 Why Do We Need Iterators?

Think about it: a vector stores elements contiguously in memory (like an array), while a list stores elements in separate nodes connected by pointers. How do we write code that works for both?

Iterators solve this problem. They give us a uniform interface:

  • *it - Get the element the iterator points to (dereference)
  • ++it - Move to the next element
  • it == other - Check if two iterators point to the same place

2.2 The begin() and end() Functions

Every container provides two essential functions:

  • container.begin() - Returns an iterator pointing to the first element
  • container.end() - Returns an iterator pointing one past the last element
Important: The end() iterator is a sentinel - it marks the end, but doesn't point to a valid element. Never dereference end()! It's like NULL for linked lists.

The standard iterator loop pattern looks like this: 

vector<int>::iterator it;
for (it = container.begin(); it != container.end(); ++it) {
    cout << *it << " ";  // Dereference to get the value
}

2.3 C++98 vs C++11: The auto Keyword

In C++98, iterator declarations are verbose: 

// C++98 way - have to spell out the full type
vector<int>::iterator p = container.begin();

In C++11 and later, you can use the auto keyword to let the compiler figure out the type: 

// C++11 way - compiler deduces the type automatically
auto p = container.begin();  // Much cleaner!
How auto works: The compiler looks at the right side of the = and figures out what type container.begin() returns. It then makes p that exact type. This is called type inference.

For this course, we're sticking to C++98, so you'll need to write out the full iterator type. But it's good to know about auto for when you see modern C++ code!

2.4 Const Iterators

Sometimes you want to read data from a container but not modify it. That's what const iterators are for:

  • container::iterator - Read and write access
  • container::const_iterator - Read-only access

2.5 Iterator Categories

Not all iterators have the same capabilities. The STL classifies iterators into categories based on what operations they support:

  • Forward Iterators: Can move forward with ++. Can read/write with *.
  • Bidirectional Iterators: Everything forward can do, PLUS can move backward with --.
  • Random Access Iterators: Everything bidirectional can do, PLUS can jump to any position with +, -, and [].
Container capabilities:
• vector and deque: Random access iterators
• list: Bidirectional iterators only
• set and map: Bidirectional iterators only

2.6 Reverse Iterators

Sometimes you need to iterate backward through a container. That's what reverse iterators are for:

  • container.rbegin() - Points to the last element
  • container.rend() - Points to before the first element
  • When you ++ a reverse iterator, it moves backward through the container

⚡ Swift Quiz #1
Quick Check: If you have a list<int> and an iterator it pointing to an element, can you do it + 5 to jump 5 elements ahead?
Answer: No! You cannot do it + 5 on a list iterator.

Why: A list is a linked list, and its iterators are only bidirectional, not random access. To move 5 elements ahead, you'd have to do ++it five times manually. The + operator only works with random access iterators (like those from vector or deque).

If you need to jump around frequently, use a vector instead of a list!

3. The Vector Container

A vector is essentially a dynamic array - an array that can grow and shrink as needed. Unlike regular arrays, you don't need to know the size in advance.

3.1 Key Vector Operations

  • push_back(value) - Add element to the end
  • pop_back() - Remove last element
  • size() - Get number of elements
  • [index] - Access element (no bounds checking!)
  • at(index) - Access element (throws exception if out of bounds)
  • clear() - Remove all elements
  • empty() - Check if vector is empty

3.3 Capacity vs Size

Vectors have two related but different concepts:

  • Size: How many elements are currently in the vector (size())
  • Capacity: How much space is allocated (capacity())

When a vector runs out of space, it allocates a larger block of memory (usually double), copies all elements, and deletes the old block. This is why adding elements to a vector is generally fast, but occasionally slow (when reallocation happens).

Experiment 2: What happens to capacity as we add more elements? Does it increase by 1 each time?

What happens: Capacity doesn't increase by 1 - it typically doubles each time it needs to grow (though the exact growth factor is implementation-defined).

Why: If capacity grew by 1 each time, we'd need to reallocate and copy all elements for every single push_back. That would be O(n²) total time. By doubling, we amortize the cost - most push_back operations are O(1), and only occasional ones are O(n).

Amortized analysis: If you add n elements, you'll do roughly log₂(n) reallocations, not n reallocations. This makes vector very efficient!

⚡ Swift Quiz #2
Quick Check: You have a vector<int> v with 5 elements. What's the difference between v[10] and v.at(10)?
Answer:
  • v[10] - Undefined behavior. No bounds checking. Might crash, might return garbage, might seem to work (but is still wrong).
  • v.at(10) - Throws out_of_range exception. Safe because it checks if index is valid before accessing.

Rule of thumb: Use [] when you're certain the index is valid (like in a loop with i < v.size()). Use .at() when you need safety (like user input).

4. The List Container

A list is the STL's implementation of a doubly linked list. Remember Unit 10? Same concept, but pre-built and optimized for you!

4.1 When to Use List vs Vector

Use vector when:

  • You need fast random access (accessing elements by index)
  • You mostly add/remove at the end
  • You want cache-friendly memory layout (better performance)

Use list when:

  • You frequently insert/delete in the middle
  • You don't need random access
  • You want iterators that stay valid even after insertions/deletions

4.2 Key List Operations

  • push_back(value) - Add to end
  • push_front(value) - Add to beginning (vector doesn't have this!)
  • pop_back() - Remove from end
  • pop_front() - Remove from beginning
  • insert(iterator, value) - Insert before the iterator position
  • erase(iterator) - Remove element at iterator position

Quick Check: You need to store 1000 student records and frequently access them by index (like students[500]). Should you use a vector or a list?

Only use list if you're frequently inserting/deleting in the middle AND you don't need random access. For most use cases, vector is the better choice.

5. The Map Container

A map stores key-value pairs where each key is unique. Keys are automatically sorted. Think of it like a dictionary: you look up a word (key) to get its definition (value).

5.1 Key Map Operations

  • map[key] = value - Insert or update a key-value pair
  • map[key] - Access value by key (creates entry if key doesn't exist!)
  • map.find(key) - Returns iterator to element, or end() if not found
  • map.erase(key) - Remove key-value pair
  • map.count(key) - Returns 1 if key exists, 0 otherwise

5.2 Iterating Through a Map

Map iterators point to pair objects. Each pair has two members:

  • it->first - The key
  • it->second - The value

Important Map Behavior: Using map[key] when the key doesn't exist will create that key with a default value (0 for int, "" for string, etc.). If you want to check existence without creating, use find() or count()!

Experiment 3: What happens if you access students[99999999] (a student number that doesn't exist)?

What happens: The map will create a new entry with key 99999999 and value "" (empty string, the default for string type).

Why: The [] operator is designed to always give you a reference to a value. If the key doesn't exist, it creates it with the default value for that type.

To avoid this: Use find() to check if a key exists:

map<int, string>::iterator found = students.find(99999999);
if (found != students.end()) {
    cout << found->second;  // Only access if it exists
} else {
    cout << "Student not found!";
}

6. The Set Container

A set stores unique elements in sorted order. It's like a mathematical set - no duplicates allowed!

6.1 Key Set Operations

  • insert(value) - Add element (ignored if already exists)
  • erase(value) - Remove element
  • find(value) - Returns iterator to element, or end() if not found
  • count(value) - Returns 1 if element exists, 0 otherwise
  • size() - Number of elements

Quick Check: If you insert the same element into a set 10 times, how many elements will be in the set?
Answer: Just 1 element!

If you need to store duplicates, use multiset instead (allows duplicate keys).

7. STL Algorithms

The STL provides a library of algorithms that work on containers using iterators. These algorithms are in the <algorithm> header.

7.1 Common Algorithms

  • sort(begin, end) - Sort elements in range
  • find(begin, end, value) - Find element, returns iterator
  • count(begin, end, value) - Count occurrences
  • min_element(begin, end) - Find minimum
  • max_element(begin, end) - Find maximum
  • reverse(begin, end) - Reverse order
  • binary_search(begin, end, value) - Search in sorted range
Important: Most algorithms work with iterators, not containers directly. You pass container.begin() and container.end() to define the range.

7.2 Why Algorithms Need Specific Iterator Types

Not all algorithms work with all containers! Here's why:

  • sort() needs random access iterators (works with vector/deque, NOT list)
  • find() only needs forward iterators (works with any container)
// This works - vector has random access iterators
vector<int> v = {5, 2, 8, 1};
sort(v.begin(), v.end());

// This DOES NOT compile - list only has bidirectional iterators
list<int> l = {5, 2, 8, 1};
// sort(l.begin(), l.end());  // COMPILE ERROR!

// List has its own sort member function instead:
l.sort();  // This works!

Experiment 4: What happens if you try binary_search() on an unsorted vector?

What happens: binary_search() will give you wrong results. It might say an element exists when it doesn't, or say it doesn't exist when it does.

Why: Binary search assumes the data is sorted. It works by repeatedly dividing the search space in half. If the data isn't sorted, the assumptions it makes are invalid.

Solution: Always sort() your container before using binary_search()!

8. Container Adapters: Stack and Queue

Container adapters are special containers that provide a restricted interface to other containers. Think of them as wrappers.

8.1 Stack (LIFO - Last In, First Out)

A stack is like a stack of plates - you can only add or remove from the top.

  • push(value) - Add to top
  • pop() - Remove from top (doesn't return value!)
  • top() - Look at top element
  • empty() - Check if stack is empty
  • size() - Number of elements
Inner Container: By default, stack uses deque internally. You can specify a different container: stack<int, vector<int> > s; (note the space before the closing >> - required in C++98!)

8.2 Queue (FIFO - First In, First Out)

A queue is like a line at a store - first person in line gets served first.

  • push(value) - Add to back
  • pop() - Remove from front (doesn't return value!)
  • front() - Look at front element
  • back() - Look at back element
  • empty() - Check if queue is empty

9. When to Use STL vs Custom Implementation

9.1 Use STL When:

  • You need a standard data structure (vector, list, map, etc.)
  • Performance is important (STL is highly optimized)
  • You want to write less code and have fewer bugs
  • You're working with a team (everyone knows STL)

9.2 Write Custom Code When:

  • You need a specialized data structure not in STL
  • You're learning
  • You have very specific performance requirements the STL doesn't meet
  • You need full control over memory management
Remember: Earlier, we've built linked lists, stacks, and queues from scratch in previous units. The STL gives us these for free! Understanding how they work under the hood (Unit 10, 11) makes you appreciate the STL and helps you choose the right container.

Summary

You've now explored the Standard Template Library! Here's what we covered:

  • Three Components: Containers (store data), Iterators (access data), Algorithms (process data)
  • Containers:
    • vector - Dynamic array, random access, fast at end
    • list - Doubly linked list, efficient insertion/deletion anywhere
    • deque - Double-ended queue, fast at both ends
    • map - Key-value pairs, unique keys, sorted by key
    • set - Unique elements, sorted
    • stack - LIFO adapter
    • queue - FIFO adapter
  • Iterators: Uniform interface, categories (forward/bidirectional/random access), const vs mutable
  • Algorithms: sort, find, count, min_element, max_element, etc.
