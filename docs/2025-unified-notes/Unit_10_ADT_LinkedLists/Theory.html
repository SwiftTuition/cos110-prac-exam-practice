Welcome to Linked Lists

You're about to learn one of the most important data structures in computer science. Linked lists solve a fundamental problem: how do you store data when you don't know how much space you'll need?

Prerequisites

Before starting this unit, you should understand:

  • Pointers (Unit 1) - Memory addresses, dereferencing, the -> operator
  • Dynamic memory (Unit 1) - new and delete operators
  • Destructors (Unit 4) - Cleaning up allocated memory

If any of these concepts feel shaky, review those units first. Linked lists build directly on pointers and dynamic memory.

1. The Problem with Arrays

Arrays are useful, but they have one big limitation: fixed size. 

int numbers[5];  // Can only hold 5 integers

// What if you need 6? You're stuck.
// What if you only use 2? You wasted space for 3.

Why Arrays Are Limited

When you create an array, C++ sets aside a block of memory. All elements must sit next to each other: 

Array in memory (5 integers):

[10][20][30][40][50]
 ↑   All elements must be next to each other

Memory Address: 1000, 1004, 1008, 1012, 1016
  • Size is fixed: Once created, you can't easily resize it
  • Insertion is expensive: Adding to the middle means shifting everything
  • Deletion is expensive: Removing from the middle leaves gaps or requires shifting
// To insert 25 between 20 and 30, you must shift:
[10][20][30][40][50]
         ↓
[10][20][__][30][40][50]  // Shift 30, 40, 50 to the right
         ↓
[10][20][25][30][40][50]  // Insert 25

// This takes time proportional to array size - expensive!
Swift Note: Linked lists solve this by not storing elements next to each other in memory. Instead, each element stores the address of the next element.

2. Understanding "How Long Does It Take?"

Before we get into linked lists, let's talk about how we measure how fast an operation is. We use something called Big-O notation.

What Does O(1) Mean?

O(1) means "constant time" - the operation takes the same amount of time no matter how much data you have. 

// Accessing an array element is O(1)
int value = numbers[3];  // Same speed for array of 10 or 10,000 elements

What Does O(n) Mean?

O(n) means "linear time" - the time grows with the amount of data. If you double the data, you double the time. 

// Printing all elements is O(n)
for (int i = 0; i < size; i++) {
    cout << numbers[i] << " ";
}
// 10 elements = 10 operations, 100 elements = 100 operations
Note: We'll use O(1) and O(n) throughout this unit to describe how fast operations are. O(1) = fast (constant), O(n) = slower as data grows (linear).

3. Nodes: The Building Blocks

A linked list is made of nodes. Think of a node like a container with two parts:

  • Data: The actual value you want to store (int, string, etc.)
  • Pointer to next node: The memory address of the next node in the list

Here's how we write a node in C++:

struct Node {
    int data;      // The value stored in this node
    Node* next;    // Pointer to the next node
};

Let's break this down:

  • int data - Holds the value (like 10, 20, 30)
  • Node* next - Holds the memory address of the next node (or NULL if there's no next node)
A single node:

+--------+--------+
|  data  |  next  |
+--------+--------+
|   42   |   *----|---> (points to next node)
+--------+--------+

Creating Nodes with Dynamic Memory

We create nodes on the heap using new. This lets us create nodes as we need them: 

Node* first = new Node;  // Create a node on the heap
first->data = 10;        // Set its data to 10
first->next = NULL;      // No next node yet (end of list)

The arrow operator -> is used when you have a pointer to a struct/class. It accesses the members. first->data is the same as (*first).data.

Important: Every new must have a matching delete, or you'll have a memory leak. We'll see how destructors handle this later.

4. Singly Linked Lists

A singly linked list is a sequence of nodes where each node points to the next node. The list keeps a head pointer to the first node. 

Singly Linked List:

head
 |
 v
[10|*]--->[20|*]--->[30|X]

Node 1    Node 2    Node 3

* = pointer to next node
X = NULL (end of list)

Basic Structure

Here's how we set up a linked list class: 

class LinkedList {
private:
    struct Node {
        int data;
        Node* next;
    };

    Node* head;  // Points to first node

public:
    LinkedList() {
        head = NULL;  // Empty list
    }
};

What each part does:

  • Node struct - Defines what a node looks like (data + next pointer)
  • head pointer - Keeps track of the first node in the list
  • Constructor sets head = NULL - an empty list has no nodes

Traversing the List (Visiting Every Node)

To visit every node, start at head and follow the next pointers until you reach NULL: 

void print() {
    Node* current = head;  // Start at the beginning

    while (current != NULL) {
        cout << current->data << " ";
        current = current->next;  // Move to next node
    }
    cout << endl;
}

How this works line by line:

  1. Node* current = head - Create a pointer starting at the first node
  2. while (current != NULL) - Keep going until we reach the end
  3. cout << current->data - Print the current node's data
  4. current = current->next - Move to the next node
Important: Always check current != NULL BEFORE accessing current->data. If you dereference a NULL pointer, your program will crash (segmentation fault).

Insertion at the Front (O(1) - Fast!)

Adding to the front is fast because you only update two pointers: 

void insertFront(int value) {
    Node* newNode = new Node;     // 1. Create new node
    newNode->data = value;        // 2. Set its data
    newNode->next = head;         // 3. Point it to old first node
    head = newNode;               // 4. Make it the new first node
}
Inserting 5 at the front:

Before:
head
 |
 v
[10|*]--->[20|X]

After:
head
 |
 v
[5|*]--->[10|*]--->[20|X]
 New      Old first

This takes O(1) time because you only update two pointers, no matter how big the list is.

5. Deletion from Singly Linked Lists

Deletion requires finding the node to delete AND the node before it (so you can update its next pointer to skip over the deleted node).

Deleting the First Node

Deleting the first node is straightforward: 

void deleteFirst() {
    if (head == NULL) return;  // Empty list - nothing to delete

    Node* temp = head;      // Save old head
    head = head->next;      // Move head to second node
    delete temp;            // Free the old head
}

What each line does:

  1. if (head == NULL) return - Check if list is empty first
  2. Node* temp = head - Save the node we're about to delete
  3. head = head->next - Move head to the second node (or NULL if only one node)
  4. delete temp - Free the memory of the old first node
Deleting first node:

Before:
head
 |
 v
[10|*]--->[20|*]--->[30|X]
 temp

After:
      head
       |
       v
[DELETED] [20|*]--->[30|X]

Deleting a Middle Node

You need TWO pointers: one for the node to delete, one for the node before it: 

void deleteValue(int value) {
    if (head == NULL) return;  // Empty list

    // Special case: deleting head
    if (head->data == value) {
        Node* temp = head;
        head = head->next;
        delete temp;
        return;
    }

    // Find the node BEFORE the one to delete
    Node* current = head;
    while (current->next != NULL && current->next->data != value) {
        current = current->next;
    }

    // If we found it
    if (current->next != NULL) {
        Node* temp = current->next;       // Node to delete
        current->next = temp->next;       // Bypass it
        delete temp;                      // Free memory
    }
}

How this works:

  1. Check if the head node has the value - special case
  2. Use current to find the node BEFORE the one we want to delete
  3. Check current->next->data to see if the NEXT node matches
  4. Save current->next in temp
  5. Skip over it: current->next = temp->next
  6. Free the memory: delete temp
Important: Deleting a node before saving its next pointer leads to accessing freed memory (use-after-free). Always save what you need BEFORE calling delete.

6. Doubly Linked Lists

A doubly linked list has pointers in both directions: each node has a next pointer AND a prev pointer. 

Doubly Linked List:

head
 |
 v
[X|10|*]<--->[*|20|*]<--->[*|30|X]

* = pointer
X = NULL

Each node points forward AND backward

Node Structure

Here's how a doubly linked node looks: 

struct Node {
    int data;
    Node* next;    // Points to next node
    Node* prev;    // Points to previous node
};

What's different:

  • next - Points to the node after this one (same as singly linked)
  • prev - Points to the node before this one (new!)

Why Use Doubly Linked Lists?

Advantages:

  • Go both ways: You can move forward or backward through the list
  • Easier deletion: No need to find the previous node - you already have prev
  • Easier insertion: Can insert before or after a given node easily

Disadvantages:

  • More memory: Each node needs two pointers instead of one
  • More work: Must update two pointers (next and prev) during insertion/deletion

Insertion in a Doubly Linked List

Inserting after a given node requires updating FOUR pointers: 

void insertAfter(Node* node, int value) {
    if (node == NULL) return;  // Can't insert after NULL

    Node* newNode = new Node;
    newNode->data = value;

    newNode->next = node->next;  // 1. New node points forward
    newNode->prev = node;        // 2. New node points backward

    if (node->next != NULL) {
        node->next->prev = newNode;  // 3. Next node points back to new
    }

    node->next = newNode;        // 4. Current node points forward to new
}

How this works:

  1. Set new node's next to point to what comes after
  2. Set new node's prev to point to the current node
  3. If there's a next node, update its prev to point back to new node
  4. Update current node's next to point to new node
Inserting 25 after 20:

Before:
[*|20|*]<--->[*|30|X]

After:
[*|20|*]<--->[*|25|*]<--->[*|30|X]
             New node

Four pointers updated!

7. Circular Linked Lists

A circular linked list has no NULL pointers - the last node points back to the first node, forming a circle. 

Circular Linked List:

tail
 |
 v
[10|*]--->[20|*]--->[30|*]
 ^                      |
 |______________________|

The last node points back to the first!

What's Different?

Instead of a head pointer, circular lists often use a tail pointer. Why?

  • Easy access to both ends: tail points to the last node, and tail->next points to the first node
  • O(1) insertion at both ends: You can insert at the front or back in constant time

Traversing a Circular List

You can't check for NULL because there is no NULL. Instead, check if you've returned to the starting node: 

void print() {
    if (tail == NULL) return;  // Empty list

    Node* current = tail->next;  // Start at "first" node

    do {
        cout << current->data << " ";
        current = current->next;
    } while (current != tail->next);  // Stop when back to start

    cout << endl;
}

Why use do-while?

A regular while loop checks the condition BEFORE running the body. Since current == tail->next at the start, a while loop would skip the first node! A do-while runs the body FIRST, then checks.

Important: Always use do-while for circular lists, not while. A while loop would skip the first node.

Insertion at the Front (O(1))

void insertFront(int value) {
    Node* newNode = new Node;
    newNode->data = value;

    if (tail == NULL) {
        tail = newNode;
        tail->next = tail;  // Points to itself
    } else {
        newNode->next = tail->next;  // New node points to old first
        tail->next = newNode;        // Tail points to new first
    }
}

How this works:

  1. Create new node
  2. If list is empty, make it point to itself
  3. Otherwise, insert it between tail and first node

When to Use Circular Lists

  • Round-robin scheduling: Operating systems cycle through processes
  • Game turns: Players take turns in a loop
  • Music playlists: Loop back to the first song after the last
Swift Note: Think of anime episode lists that auto-play - when you finish the last episode, some streaming services loop back to episode 1. That's a circular linked list!

    current = current->next;
    count++;

⚡ Swift Quiz
Quick Check: Why can't you use while (current != NULL) to go through a circular linked list?
Answer: Because current will NEVER be NULL in a circular list - every node points to another node (the last points back to the first). You'd loop forever!

8. Common Mistakes and Edge Cases

Mistake 1: Wrong NULL Check Order

This crashes if current is NULL: 

// WRONG - crashes if current is NULL
while (current->next != NULL) {
    cout << current->data << " ";
    current = current->next;
}

// CORRECT - check current first
while (current != NULL) {
    cout << current->data << " ";
    current = current->next;
}

Why? If current is NULL, trying to access current->next dereferences a NULL pointer (segmentation fault).

Mistake 2: Use-After-Free in Deletion

// WRONG - accesses freed memory
Node* current = head;
while (current != NULL) {
    delete current;
    current = current->next;  // current is deleted! Crash!
}

// CORRECT - save next before deleting
Node* current = head;
while (current != NULL) {
    Node* temp = current->next;  // Save next
    delete current;              // Delete current
    current = temp;              // Move to saved next
}

Mistake 3: Forgetting to Update Both Pointers in Doubly Linked Lists

// WRONG - only updates next pointers
void insertAfter(Node* node, int value) {
    Node* newNode = new Node;
    newNode->data = value;
    newNode->next = node->next;
    node->next = newNode;
    // Forgot to update prev pointers!
}

// CORRECT - updates all four pointers
void insertAfter(Node* node, int value) {
    Node* newNode = new Node;
    newNode->data = value;

    newNode->next = node->next;
    newNode->prev = node;

    if (node->next != NULL) {
        node->next->prev = newNode;
    }

    node->next = newNode;
}

Edge Cases to Always Test

  • Empty list: What if head is NULL?
  • Single node: Does your code handle a list with only one node?
  • Deleting the only node: Does head become NULL?
  • Inserting into an empty list: Does head get updated correctly?
Important: Always test edge cases! Most bugs in linked list code come from forgetting to handle empty lists or single-node lists.

~LinkedList() {

        current = temp;              // Move to saved next
    }
}

The pattern: Always save what you need BEFORE calling delete!

9. Real-World Example: Swift's Student Tracker

Swift tracks students using a linked list. Each student node contains their name and points to the next student. When a new student signs up, Swift adds them to the front of the list (O(1) insertion). 

struct StudentNode {
    string name;
    int grade;
    StudentNode* next;
};

class StudentTracker {
private:
    StudentNode* head;

public:
    StudentTracker() { head = NULL; }

    void addStudent(string name, int grade) {
        StudentNode* newStudent = new StudentNode;
        newStudent->name = name;
        newStudent->grade = grade;
        newStudent->next = head;
        head = newStudent;
    }

    void printAllStudents() {
        StudentNode* current = head;
        while (current != NULL) {
            cout << current->name << " (Grade " << current->grade << ")" << endl;
            current = current->next;
        }
    }
};

Why a linked list?

  • Swift doesn't know how many students will sign up (dynamic size)
  • Adding new students at the front is fast (O(1))
  • Can easily remove students who leave
Swift Note: In the real world, linked lists are used when you need dynamic size and frequent insertions/deletions. Arrays are better when you need random access (like accessing element 100 directly).

10. How Long Do Operations Take?

Here's a summary of how fast each operation is for different linked list types:

Operation Singly (head only) Doubly (head & tail) Circular (tail only)
Insert at front O(1) O(1) O(1)
Insert at back O(n) O(1) O(1)
Delete from front O(1) O(1) O(1)
Delete from back O(n) O(1) O(n)
Search for value O(n) O(n) O(n)
Access by index O(n) O(n) O(n)
Remember: Linked lists are great at insertion/deletion at the ends (especially with tail pointers), but not good at random access. Arrays are the opposite - great for random access, not good for insertion/deletion.

Summary

You've learned the three types of linked lists and how they solve the fixed-size problem of arrays:

  • Singly Linked Lists: Each node points to the next. Simple, uses less memory, but can only go forward.
  • Doubly Linked Lists: Each node points forward and backward. Uses more memory, but you can go both ways and deletion is easier.
  • Circular Linked Lists: Last node points back to the first. No NULL pointers, great for round-robin scenarios like playlists.

Important patterns to remember:

  • Always check current != NULL before dereferencing
  • Save next before deleting a node
  • Update ALL pointers in doubly linked lists (four pointers per insertion/deletion)
  • Use do-while for circular lists
  • Test edge cases: empty list, single node, boundary operations
