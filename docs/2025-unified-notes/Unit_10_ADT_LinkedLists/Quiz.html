Question 1: Time Complexity (Multiple Choice)

What is the time complexity of searching for a specific value in a singly linked list with n nodes?

  1. O(1) - constant time
  2. O(log n) - logarithmic time
  3. O(n) - linear time
  4. O(n²) - quadratic time

Answer: C - O(n)

Detailed Explanation:

Searching for a value in a singly linked list requires traversing the list from the head node until we find the target value or reach the end (NULL). In the worst case, the value is at the last node or doesn't exist in the list, meaning we must visit all n nodes.

Why other options are wrong:

  • Option A (O(1)): Incorrect. O(1) would mean we can access the value immediately without traversal, like accessing an array element by index. Linked lists don't support random access - we must traverse from the head.
  • Option B (O(log n)): Incorrect. O(log n) complexity is typical for binary search on sorted arrays or balanced binary search trees. Linked lists cannot use binary search effectively because we can't jump to the middle element directly.
  • Option D (O(n²)): Incorrect. O(n²) would involve nested loops through the list. A simple search only requires one pass through the list, making it O(n), not O(n²).

Key Point: Unlike arrays (O(1) access by index), linked lists require sequential traversal. This is the fundamental trade-off: linked lists excel at insertion/deletion but are slower for searching.

Question 2: Code Tracing

What is the output of the following code?

#include <iostream>
using namespace std;

struct Node {
    int data;
    Node* next;
};

void mystery(Node* head) {
    if (head == NULL || head->next == NULL) {
        return;
    }

    Node* current = head;
    while (current->next->next != NULL) {
        current = current->next;
    }

    cout << current->next->data << endl;
    delete current->next;
    current->next = NULL;
}

int main() {
    Node* head = new Node;
    head->data = 5;
    head->next = new Node;
    head->next->data = 10;
    head->next->next = new Node;
    head->next->next->data = 15;
    head->next->next->next = new Node;
    head->next->next->next->data = 20;
    head->next->next->next->next = NULL;

    mystery(head);
    mystery(head);

    return 0;
}

Output:

20
15

Detailed Line-by-Line Trace:

Initial list: 5 → 10 → 15 → 20 → NULL

First call to mystery(head):

  1. Check if head == NULL or head->next == NULL: No, we have at least 2 nodes.
  2. current = head: current points to node with data 5
  3. while (current->next->next != NULL): Loop until current is at second-to-last node
    • Iteration 1: current->next->next points to 15 (not NULL), so current moves to 10
    • Iteration 2: current->next->next points to 20 (not NULL), so current moves to 15
    • Iteration 3: current->next->next is NULL, loop exits
  4. current now points to node 15
  5. cout << current->next->data: Prints 20 (the last node)
  6. delete current->next: Deletes the node with 20
  7. current->next = NULL: Node 15 now points to NULL

List after first call: 5 → 10 → 15 → NULL

Second call to mystery(head):

  1. Check if head == NULL or head->next == NULL: No, we have 3 nodes
  2. current = head: current points to node with data 5
  3. while (current->next->next != NULL):
    • Iteration 1: current->next->next points to 15 (not NULL), so current moves to 10
    • Iteration 2: current->next->next is NULL, loop exits
  4. current now points to node 10
  5. cout << current->next->data: Prints 15
  6. delete current->next: Deletes the node with 15
  7. current->next = NULL: Node 10 now points to NULL

Final list: 5 → 10 → NULL

What does the mystery function do? It deletes the last node from the list and prints its value before deletion. This is a "delete last" operation.

Why the condition current->next->next != NULL? We need to stop at the second-to-last node so we can update its next pointer to NULL after deleting the last node.

Question 3: True or False

Statement: In a doubly linked list, inserting a new node at the front requires updating exactly four pointers: the new node's prev, the new node's next, the old head's prev, and the head pointer itself.

Answer: TRUE (with conditions)

Detailed Explanation:

When inserting at the front of a non-empty doubly linked list, we indeed update four pointers:

  1. newNode->prev = NULL - new node's prev points to nothing
  2. newNode->next = head - new node's next points to old head
  3. head->prev = newNode - old head's prev points back to new node
  4. head = newNode - update head pointer to new node

However, there's an edge case:

If the list is empty (head == NULL), we only update TWO pointers:

  1. newNode->prev = NULL
  2. newNode->next = NULL
  3. head = newNode

We can't update head->prev because there is no old head!

Implementation tip: Always check if head != NULL before accessing head->prev to avoid segmentation faults.

The correct insert-front code:

void insertFront(Node*& head, int value) {
    Node* newNode = new Node;
    newNode->data = value;
    newNode->prev = NULL;
    newNode->next = head;

    if (head != NULL) {  // Critical check!
        head->prev = newNode;
    }

    head = newNode;
}

Question 4: Find the Bug

The following function is supposed to print all values in a circular linked list, but it has a bug. Identify the bug and explain how to fix it. 

void printCircular(Node* tail) {
    if (tail == NULL) {
        return;
    }

    Node* current = tail->next;

    while (current != tail) {
        cout << current->data << " ";
        current = current->next;
    }

    cout << endl;
}

The Bug:

The function never prints the tail node's data! The loop stops when current == tail, which means we exit before printing the tail's value.

Why this happens:

We start at tail->next (the head) and loop while current != tail. This means we print all nodes from head to the second-to-last node, but never the tail itself.

The Fix:

Use a do-while loop instead of a while loop:

void printCircular(Node* tail) {
    if (tail == NULL) {
        return;
    }

    Node* current = tail->next;  // Start at head

    do {
        cout << current->data << " ";
        current = current->next;
    } while (current != tail->next);  // Loop until back at head

    cout << endl;
}

Alternative Fix:

Keep the while loop but print the tail after the loop:

void printCircular(Node* tail) {
    if (tail == NULL) {
        return;
    }

    Node* current = tail->next;

    while (current != tail) {
        cout << current->data << " ";
        current = current->next;
    }

    cout << tail->data << " ";  // Print the tail node
    cout << endl;
}

Key Lesson: Circular linked lists are tricky because there's no NULL to mark the end. Always ensure you visit ALL nodes, including where you started!

do-while vs while for circular lists: The do-while is generally preferred for circular lists because it guarantees we process at least one node before checking the termination condition.

Question 5: Implementation (Short Answer)

Write a function that deletes a node from the middle of a singly linked list, given a pointer to the node to be deleted. You may NOT use a pointer to the head of the list.

Constraint: You cannot access any node before the given node.

Function signature:

void deleteNode(Node* nodeToDelete);

Hint: Since you can't access the previous node, you'll need to use a trick involving copying data.

Solution:

void deleteNode(Node* nodeToDelete) {
    if (nodeToDelete == NULL || nodeToDelete->next == NULL) {
        return;  // Can't delete if null or last node
    }

    // Copy data from next node to current node
    nodeToDelete->data = nodeToDelete->next->data;

    // Delete the next node instead
    Node* temp = nodeToDelete->next;
    nodeToDelete->next = temp->next;
    delete temp;
}

Detailed Explanation:

Since we can't access the previous node to update its next pointer, we use a clever trick:

  1. Copy the next node's data into the current node: This makes the current node "become" the next node in terms of data.
  2. Delete the next node instead: We update current node's next to skip the next node, then delete it.

Example:

Before: 1 → 2 → 3 → 4 → NULL (delete node 2)

  1. Copy 3's data into 2: 1 → 3 → 3 → 4 → NULL
  2. Delete the second 3: 1 → 3 → 4 → NULL

Limitations:

  • Cannot delete the last node (no next node to copy from)
  • If the node stores complex data (objects with pointers), copying might cause issues
  • This is a "trick" solution - in practice, you'd usually have access to the head

Time Complexity: O(1) - constant time deletion!

Space Complexity: O(1) - no extra space needed

Question 6: Comparison (Short Answer)

When determining if there are elements in a doubly linked list, which function between empty() and size() is better to use in terms of efficiency? Give reasons for your answer.

Context: Assume empty() checks if head == NULL, and size() counts all nodes by traversing the list.

Answer: empty() is better.

Detailed Explanation:

Why empty() is more efficient:

  • Time Complexity: O(1) - constant time
    • Simply checks if head == NULL
    • This is a single comparison operation
    • No traversal required

Why size() is less efficient:

  • Time Complexity: O(n) - linear time
    • Must traverse the entire list to count nodes
    • For a list with 1000 nodes, this means 1000 operations
    • Wasteful when you only need to know "is it empty?"

Code Comparison:

// Efficient - O(1)
bool empty() {
    return head == NULL;  // Single check
}

// Inefficient for checking emptiness - O(n)
int size() {
    int count = 0;
    Node* current = head;
    while (current != NULL) {  // Traverses entire list
        count++;
        current = current->next;
    }
    return count;
}

// Usage:
if (empty()) {  // ✅ Good - O(1)
    cout << "List is empty" << endl;
}

if (size() == 0) {  // ❌ Bad - O(n) just to check emptiness
    cout << "List is empty" << endl;
}

Best Practice: Use the most specific function for your needs:

  • Need to check if empty? Use empty()
  • Need the exact count? Use size()
  • Don't use size() == 0 when empty() will do!

Optimization: Some implementations maintain a separate count variable that's updated during insertions/deletions. This makes size() O(1) as well, but requires careful maintenance.

Question 7: Memory Leak Detection

The following destructor for a singly linked list has a critical bug that causes a memory leak. Identify the bug and explain why it causes a leak. 

struct Node {
    int data;
    Node* next;
};

class List {
private:
    Node* head;

public:
    ~List() {
        Node* current = head;
        while (current != NULL) {
            delete current;
            current = current->next;
        }
    }
};

The Bug:

The code deletes current and then tries to access current->next. This is a use-after-free error that causes undefined behavior.

Why this causes a memory leak (or crash):

  1. Line: delete current;
    • The memory pointed to by current is freed
    • The current pointer still holds the address, but the memory is no longer valid
  2. Line: current = current->next;
    • We try to access next field of the deleted memory
    • This is undefined behavior - might work, might crash, might give garbage
    • If it gives garbage, we might skip nodes, causing a memory leak

The Fix:

Save the next pointer BEFORE deleting the current node:

~List() {
    Node* current = head;

    while (current != NULL) {
        Node* temp = current->next;  // Save next BEFORE deleting
        delete current;               // Safe to delete now
        current = temp;               // Move to saved next
    }
}

Step-by-Step Trace (Fixed Version):

List: [1] → [2] → [3] → NULL

  1. current = [1], temp = [2], delete [1], current = [2]
  2. current = [2], temp = [3], delete [2], current = [3]
  3. current = [3], temp = NULL, delete [3], current = NULL
  4. current == NULL, loop exits. All nodes deleted! ✅

General Rule: When deleting nodes in a linked list, always follow this pattern:

while (current != NULL) {
    Node* next = current->next;  // 1. Save next
    delete current;              // 2. Delete current
    current = next;              // 3. Move to saved next
}

Memory Management Principle: Never access an object after delete! Once you call delete ptr, any access to ptr->anything is undefined behavior.

Question 8: Recursive Implementation (Challenge)

Provide a recursive implementation of the printReverse() function that prints a singly linked list in reverse order without using any STL containers or auxiliary data structures.

Function signature:

void printReverse(Node* head);

Node structure:

struct Node {
    int data;
    Node* next;
};

Example: If list is 1 → 2 → 3 → NULL, output should be: 3 2 1

Solution:

void printReverse(Node* head) {
    // Base case: empty list
    if (head == NULL) {
        return;
    }

    // Recursive case: print rest of list first
    printReverse(head->next);

    // Then print current node
    cout << head->data << " ";
}

How it works:

The key insight is that recursion uses the call stack to reverse the order:

  1. Recursive calls go deep first: We call printReverse(head->next) before printing, so we reach the end of the list before printing anything.
  2. Print on the way back: As the recursive calls return, we print each node. This happens in reverse order!

Step-by-Step Trace:

List: 1 → 2 → 3 → NULL

printReverse(1)
  → printReverse(2)
    → printReverse(3)
      → printReverse(NULL)  // Base case, returns immediately
      ← prints "3"
    ← prints "2"
  ← prints "1"

Output: 3 2 1

Call Stack Visualization:

| printReverse(NULL) |  ← Returns (base case)
| printReverse(3)    |  ← Prints 3, then returns
| printReverse(2)    |  ← Prints 2, then returns
| printReverse(1)    |  ← Prints 1, then returns

Time Complexity: O(n) - we visit each node once

Space Complexity: O(n) - recursion depth equals list length (uses call stack)

Recursion Pattern: This is a classic "process after recursive call" pattern:

void function(Node* node) {
    if (base_case) return;
    function(node->next);  // Recurse first
    process(node);         // Process after
}

Comparison with iterative approach: An iterative solution would require a stack or making two passes (one to reverse pointers, one to print). The recursive solution is more elegant but uses O(n) stack space.
