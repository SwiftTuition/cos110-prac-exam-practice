Problem 1: Book Class (Basic)

Difficulty: Easy

Estimated Time: 20-30 minutes

The Problem

Create a Book class that stores information about a book: title, author, and page count. Split the implementation across three files with proper include guards, and create a makefile to build the project.

This is a straightforward problem to get you comfortable with the three-file pattern. Focus on getting the structure right: header declarations, implementation definitions, and client code.

Detailed Requirements

File 1: book.h

  • Include guards using BOOK_H
  • Include <string> for the std::string type
  • Class definition with three private member variables: title (string), author (string), pages (int)
  • Public constructor that takes title, author, and page count as parameters
  • Public getters for all three member variables (all should be const)
  • Public display() method that prints the book info (should be const)

File 2: book.cpp

  • Include "book.h" at the top
  • Include <iostream> for output in display()
  • Implement constructor: initialize all three member variables from parameters
  • Implement getters: simple return statements
  • Implement display(): print in format "Title" by Author (X pages)
  • Remember to use Book:: scope resolution operator before each function name

File 3: main.cpp

  • Include "book.h"
  • Create at least two Book objects with different data
  • Call display() on each book
  • Test at least one getter function

File 4: Makefile

  • Variables: CXX = g++, CXXFLAGS = -std=c++98 -Wall
  • Target program depends on main.o and book.o
  • Target main.o depends on main.cpp and book.h
  • Target book.o depends on book.cpp and book.h
  • Target clean removes all .o files and the executable
Hint: If you get stuck, review the Temperature example from the Examples page. The structure is very similar.

Complete Solution

File 1: book.h

// book.h - Header file for Book class
#ifndef BOOK_H
#define BOOK_H

#include <string>

class Book {
private:
    std::string title;
    std::string author;
    int pages;
public:
    Book(const std::string& t, const std::string& a, int p);
    std::string getTitle() const;
    std::string getAuthor() const;
    int getPages() const;
    void display() const;
};

#endif

File 2: book.cpp

// book.cpp - Implementation file for Book class
#include "book.h"
#include <iostream>

Book::Book(const std::string& t, const std::string& a, int p) {
    title = t;
    author = a;
    pages = p;
}

std::string Book::getTitle() const {
    return title;
}

std::string Book::getAuthor() const {
    return author;
}

int Book::getPages() const {
    return pages;
}

void Book::display() const {
    std::cout << "\"" << title << "\" by " << author;
    std::cout << " (" << pages << " pages)" << std::endl;
}

File 3: main.cpp

// main.cpp - Application file
#include "book.h"
#include <iostream>

int main() {
    Book b1("1984", "George Orwell", 328);
    Book b2("The Hobbit", "J.R.R. Tolkien", 310);
    Book b3("Dune", "Frank Herbert", 688);

    std::cout << "My Reading List:" << std::endl;
    b1.display();
    b2.display();
    b3.display();

    std::cout << "\nThe longest book has " << b3.getPages() << " pages." << std::endl;

    return 0;
}

File 4: Makefile

CXX = g++
CXXFLAGS = -std=c++98 -Wall

program: main.o book.o
    $(CXX) $(CXXFLAGS) main.o book.o -o program

main.o: main.cpp book.h
    $(CXX) $(CXXFLAGS) -c main.cpp

book.o: book.cpp book.h
    $(CXX) $(CXXFLAGS) -c book.cpp

clean:
    rm -f *.o program

Explanation

Include Guards:

The #ifndef BOOK_H, #define BOOK_H, and #endif prevent the header from being included multiple times. If BOOK_H is already defined (meaning this header was already included), the preprocessor skips everything between #ifndef and #endif.

Const Correctness:

All getters and display() are marked const because they don't modify the Book object. This is good practice - it tells the compiler and other programmers that these functions are read-only.

Makefile Dependencies:

Notice that main.o depends on book.h because main.cpp includes it. If you change book.h (add a new method, for example), both main.cpp and book.cpp need to be recompiled, but if you only change book.cpp, only that file gets recompiled.

Problem 2: Episode Tracker with Namespace (Intermediate)

Difficulty: Intermediate

Estimated Time: 45-60 minutes

The Problem

Create an anime episode tracker that keeps track of which episodes you've watched. Use dynamic memory to store the watched status of each episode, and wrap everything in a namespace to practice namespace organization.

This problem adds complexity: you'll need dynamic memory management, which means implementing the Big Three (copy constructor, assignment operator, destructor). You'll also use a namespace for the first time.

Detailed Requirements

Namespace: AnimeTracker

All code should be inside the AnimeTracker namespace.

Class: Series

  • Private members:
    • name (string) - name of the anime series
    • watched (bool*) - dynamic array of watched status
    • totalEpisodes (int) - total number of episodes
  • Public methods:
    • Constructor: takes series name and episode count, allocates array, initializes all to false
    • Copy constructor: deep copy of the watched array
    • Destructor: deallocates the watched array
    • Assignment operator: handles self-assignment, deep copy
    • markWatched(int episode): marks episode as watched (episode numbers start at 1)
    • displayProgress(): prints "Series Name: Watched X/Y episodes"

Files to Create:

  • series.h: Header with namespace and class declaration
  • series.cpp: Implementation (all functions inside namespace block)
  • main.cpp: Test code using the Series class
  • Makefile: Build automation
Important: Make sure you handle dynamic memory correctly. If you forget delete[] in the destructor or assignment operator, you'll have memory leaks. If you do a shallow copy instead of deep copy, you'll have double-delete bugs.
Hint: In the assignment operator, remember to check for self-assignment first: if (this == &other) return *this;. Also remember to delete the old array before allocating a new one.

Complete Solution

File 1: series.h

// series.h - Header for anime episode tracker
#ifndef SERIES_H
#define SERIES_H

#include <string>

namespace AnimeTracker {
    class Series {
    private:
        std::string name;
        bool* watched;
        int totalEpisodes;
    public:
        Series(const std::string& n, int total);
        Series(const Series& other);
        ~Series();
        Series& operator=(const Series& other);

        void markWatched(int episode);
        void displayProgress() const;
        int getWatchedCount() const;
    };
}

#endif

File 2: series.cpp

// series.cpp - Implementation
#include "series.h"
#include <iostream>

namespace AnimeTracker {
    // Constructor: allocate array and initialize to false
    Series::Series(const std::string& n, int total) {
        name = n;
        totalEpisodes = total;
        watched = new bool[totalEpisodes];
        for (int i = 0; i < totalEpisodes; i++) {
            watched[i] = false;
        }
    }

    // Copy constructor: deep copy of the array
    Series::Series(const Series& other) {
        name = other.name;
        totalEpisodes = other.totalEpisodes;
        watched = new bool[totalEpisodes];
        for (int i = 0; i < totalEpisodes; i++) {
            watched[i] = other.watched[i];
        }
    }

    // Destructor: free the dynamic array
    Series::~Series() {
        delete[] watched;
    }

    // Assignment operator: check self-assignment, then deep copy
    Series& Series::operator=(const Series& other) {
        if (this == &other) {
            return *this;
        }

        // Delete old array
        delete[] watched;

        // Copy data
        name = other.name;
        totalEpisodes = other.totalEpisodes;

        // Allocate new array and copy
        watched = new bool[totalEpisodes];
        for (int i = 0; i < totalEpisodes; i++) {
            watched[i] = other.watched[i];
        }

        return *this;
    }

    // Mark an episode as watched (1-indexed)
    void Series::markWatched(int episode) {
        if (episode >= 1 && episode <= totalEpisodes) {
            watched[episode - 1] = true;
        }
    }

    // Display watch progress
    void Series::displayProgress() const {
        int count = getWatchedCount();
        std::cout << name << ": Watched " << count << "/" << totalEpisodes << " episodes" << std::endl;
    }

    // Helper: count watched episodes
    int Series::getWatchedCount() const {
        int count = 0;
        for (int i = 0; i < totalEpisodes; i++) {
            if (watched[i]) {
                count++;
            }
        }
        return count;
    }
}

File 3: main.cpp

// main.cpp - Test the Series class
#include "series.h"
#include <iostream>

using AnimeTracker::Series;

int main() {
    Series deathNote("Death Note", 37);
    Series codeGeass("Code Geass", 50);

    deathNote.markWatched(1);
    deathNote.markWatched(2);
    deathNote.markWatched(3);
    deathNote.markWatched(4);
    deathNote.markWatched(5);

    codeGeass.markWatched(1);
    codeGeass.markWatched(2);

    std::cout << "Watch Progress:" << std::endl;
    deathNote.displayProgress();
    codeGeass.displayProgress();

    // Test copy constructor
    Series backup = deathNote;
    std::cout << "\nBackup copy:" << std::endl;
    backup.displayProgress();

    return 0;
}

File 4: Makefile

CXX = g++
CXXFLAGS = -std=c++98 -Wall

program: main.o series.o
    $(CXX) $(CXXFLAGS) main.o series.o -o program

main.o: main.cpp series.h
    $(CXX) $(CXXFLAGS) -c main.cpp

series.o: series.cpp series.h
    $(CXX) $(CXXFLAGS) -c series.cpp

clean:
    rm -f *.o program

Explanation

Namespace Usage:

In the header, we wrap the class definition in namespace AnimeTracker { ... }. In the implementation file, we also wrap everything in the namespace block. In main.cpp, we can either use the fully qualified name (AnimeTracker::Series) or bring it into scope with using AnimeTracker::Series;.

Deep Copy in Copy Constructor:

We allocate a new array (watched = new bool[totalEpisodes]) and copy each element individually. This is a deep copy. If we just did watched = other.watched, both objects would share the same array (shallow copy), and when one is destroyed, it would delete the array, leaving the other with a dangling pointer.

Assignment Operator:

The assignment operator must: (1) check for self-assignment, (2) delete the old array to avoid memory leaks, (3) allocate a new array and copy the data, and (4) return *this to allow chained assignments like a = b = c.

Problem 3: What's Wrong? (Debug Challenge)

Difficulty: Intermediate

Estimated Time: 30-40 minutes

The Problem

A student tried to create a Rectangle class but made several mistakes related to separate compilation, include guards, and scope resolution. Your job is to find ALL the bugs and fix them.

This tests your understanding of everything in this unit. Don't just look for one error - there are multiple bugs in these files.

The Buggy Code

File 1: rectangle.h

using namespace std;

class Rectangle {
    int width;
    int height;
public:
    Rectangle(int w, int h);
    int area();
    int perimeter();
};

File 2: rectangle.cpp

#include "rectangle.h"

Rectangle::Rectangle(int w, int h) {
    width = w;
    height = h;
}

int area() {
    return width * height;
}

int Rectangle::perimeter() {
    return 2 * (width + height);
}

File 3: main.cpp

#include <iostream>
#include "rectangle.cpp"

int main() {
    Rectangle r(10, 5);
    cout << "Area: " << r.area() << endl;
    cout << "Perimeter: " << r.perimeter() << endl;
    return 0;
}
Hint: Think about: include guards, namespace usage in headers, scope resolution operators, what files to include, const correctness, and access specifiers.

All Bugs Found

Bug #1: Missing Include Guards

Problem: rectangle.h has no include guards. If this header gets included multiple times (directly or indirectly), the compiler will see the Rectangle class definition more than once and error out with "redefinition of class Rectangle".

Fix: Add include guards:

#ifndef RECTANGLE_H
#define RECTANGLE_H

// ... class definition ...

#endif

Bug #2: Using Directive in Header File

Problem: using namespace std; in the header file forces this directive on every file that includes rectangle.h. This can cause name collisions.

Fix: Remove using namespace std; from the header. If you need std types in the header (like std::string), use the fully qualified name.

Bug #3: Member Variables Not Explicitly Private

Problem: While class members default to private, it's better to be explicit for clarity.

Fix: Add private: label before member variables.

Bug #4: Missing Scope Resolution Operator

Problem: In rectangle.cpp, the function area() is missing Rectangle:: prefix. The compiler thinks you're defining a standalone function called area(), not the member function Rectangle::area().

Fix:

int Rectangle::area() {  // Not just int area()
    return width * height;
}

Bug #5: Including .cpp File

Problem: main.cpp includes "rectangle.cpp" instead of "rectangle.h". This will cause multiple definition errors during linking because the functions in rectangle.cpp will be defined twice: once when rectangle.cpp is compiled directly, and once when it's included in main.cpp.

Fix:

#include "rectangle.h"  // Not "rectangle.cpp"

Bug #6: Missing std:: in main.cpp

Problem: cout and endl are used without std:: prefix and there's no using declaration.

Fix: Either use std::cout and std::endl, or add using std::cout; and using std::endl; at the top of main.cpp.

Bug #7: Missing Const Correctness

Problem: area() and perimeter() don't modify the Rectangle object, so they should be marked const.

Fix:

// In header:
int area() const;
int perimeter() const;

// In implementation:
int Rectangle::area() const {
    return width * height;
}

int Rectangle::perimeter() const {
    return 2 * (width + height);
}

Fixed Code

    int perimeter() const;

#endif

Problem 4: Student Record System (Challenge)

Difficulty: Hard

Estimated Time: 90-120 minutes

The Problem

Create a complete student record management system with two related classes: Student and Course. This is a big project that combines everything you've learned: namespaces, dynamic memory, operator overloading, proper file organization, and makefiles.

This problem is meant to challenge you. If you can complete this, you've mastered separate compilation and are ready for real-world C++ projects.

Detailed Requirements

Namespace: UniversitySystem

Both classes should be in the UniversitySystem namespace.

Class 1: Student

  • Private members:
    • name (string)
    • studentNumber (string)
    • mark (double)
  • Public methods:
    • Default constructor: sets name to "Unknown", studentNumber to "u00000000", mark to 0.0
    • Parameterized constructor: takes name, student number, and mark
    • Getters for all three members (all const)
    • setMark(double m): updates the mark
    • hasPassed() const: returns true if mark >= 50
    • Friend function: operator<< for easy output

Class 2: Course

  • Private members:
    • courseName (string)
    • students (Student*) - dynamic array
    • capacity (int) - maximum number of students
    • count (int) - current number of students
  • Public methods:
    • Constructor: takes course name and capacity, allocates array
    • Copy constructor: deep copy
    • Destructor: deallocates array
    • Assignment operator: deep copy with self-assignment check
    • addStudent(const Student& s): adds student if space available
    • displayAll() const: prints all students using << operator
    • getPassPercentage() const: returns percentage of students who passed

Files to Create:

  • student.h and student.cpp
  • course.h and course.cpp
  • main.cpp: create a course, add 4-5 students, display info
  • Makefile: proper dependencies for all files
Approach: Build this incrementally. Start with Student class, test it. Then add Course class. Finally add operator overloading and the more complex methods. Don't try to write everything at once.

File 4: course.cpp

// course.cpp
#include "course.h"
#include <iostream>

namespace UniversitySystem {
    Course::Course(const std::string& name, int cap) {
        courseName = name;
        capacity = cap;
        count = 0;
        students = new Student[capacity];
    }

    Course::Course(const Course& other) {
        courseName = other.courseName;
        capacity = other.capacity;
        count = other.count;
        students = new Student[capacity];
        for (int i = 0; i < count; i++) {
            students[i] = other.students[i];
        }
    }

    Course::~Course() {
        delete[] students;
    }

    Course& Course::operator=(const Course& other) {
        if (this == &other) {
            return *this;
        }

        delete[] students;

        courseName = other.courseName;
        capacity = other.capacity;
        count = other.count;
        students = new Student[capacity];
        for (int i = 0; i < count; i++) {
            students[i] = other.students[i];
        }

        return *this;
    }

    void Course::addStudent(const Student& s) {
        if (count < capacity) {
            students[count] = s;
            count++;
        } else {
            std::cout << "Course full! Cannot add more students." << std::endl;
        }
    }

    void Course::displayAll() const {
        std::cout << "Course: " << courseName << std::endl;
        std::cout << "Students enrolled: " << count << "/" << capacity << std::endl;
        std::cout << "------------------------" << std::endl;
        for (int i = 0; i < count; i++) {
            std::cout << students[i] << std::endl;
        }
    }

    double Course::getPassPercentage() const {
        if (count == 0) {
            return 0.0;
        }

        int passCount = 0;
        for (int i = 0; i < count; i++) {
            if (students[i].hasPassed()) {
                passCount++;
            }
        }

        return (passCount * 100.0) / count;
    }

    int Course::getStudentCount() const {
        return count;
    }
}

Key Points in the Solution

1. Namespace Organization:

Both classes are in the UniversitySystem namespace. In headers, we wrap the class definition. In implementation files, we wrap all function definitions.

2. Course Depends on Student:

Notice that course.h includes student.h because Course has a Student* member. In the makefile, course.o depends on both course.h and student.h.

3. Deep Copy in Course:

The Course copy constructor and assignment operator both do deep copies of the Student array. This is critical - if you did a shallow copy, both Course objects would share the same array.

4. Operator Overloading:

The << operator for Student is a friend function, so it can access private members. It returns ostream& to allow chaining: cout << s1 << s2;
