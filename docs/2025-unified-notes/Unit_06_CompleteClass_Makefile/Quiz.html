1
What is the main purpose of an include guard in a header file?
A) To make the code run faster
B) To prevent the header file from being included more than once
C) To hide private members from other files
D) To create a namespace for the class

Answer

✓ Correct Answer: B) To prevent the header file from being included more than once

Include guards stop a header file from being included multiple times in the same file. Without them, you'd get errors about classes being defined twice.

#ifndef RECTANGLE_H #define RECTANGLE_H // Class definition #endif

• A is wrong - include guards don't affect speed, just prevent duplicate definitions

• C is wrong - private members are hidden by the 'private' keyword, not include guards

• D is wrong - namespaces are created with the 'namespace' keyword, not include guards

2
In a three-file structure (header, implementation, application), where should you write the actual code for member functions?
A) In the header file (.h)
B) In the implementation file (.cpp)
C) In the application file (main.cpp)
D) In a separate .txt file

Answer

✓ Correct Answer: B) In the implementation file (.cpp)

The implementation file is where you write the actual code that makes your member functions work. The header just has the declarations (what functions exist), but the .cpp file has the definitions (what they actually do).

// Rectangle.cpp (implementation file) void Rectangle::setWidth(int w) { width = w; // Actual code here }

• A is wrong - headers only have declarations, not the full function code

• C is wrong - main.cpp is where you use the class, not where you write its member functions

• D is wrong - C++ code goes in .cpp files, not .txt files

3
What does the scope resolution operator (::) do in C++?
A) It creates a pointer to a class
B) It tells the compiler which class a member function belongs to
C) It makes a variable global
D) It ends a line of code

Answer

✓ Correct Answer: B) It tells the compiler which class a member function belongs to

The :: operator connects a function name to its class. When you write Rectangle::setWidth(), you're saying "this setWidth function belongs to the Rectangle class".

void Rectangle::setWidth(int w) { // Rectangle:: tells us this is Rectangle's setWidth width = w; }

• A is wrong - pointers use * and &, not ::

• C is wrong - global variables don't need ::, they're just declared outside functions

• D is wrong - semicolons (;) end lines, not ::

4
Which files do you need to compile to create a working program?
A) Only the header files (.h)
B) Only main.cpp
C) All .cpp files (implementation and application files)
D) Only the implementation files (.cpp)

Answer

✓ Correct Answer: C) All .cpp files (implementation and application files)

You need to compile every .cpp file in your project. Header files (.h) get included automatically when you #include them, but all .cpp files must be compiled.

g++ main.cpp Rectangle.cpp -o program // Both .cpp files get compiled

• A is wrong - header files don't get compiled directly, they get included into .cpp files

• B is wrong - main.cpp needs the other .cpp files to link with

• D is wrong - you also need to compile the application file (usually main.cpp)

5
What is the correct format for an include guard?
A) #guard FILENAME_H
B) #ifndef FILENAME_H #define FILENAME_H ... #endif
C) #include FILENAME_H
D) namespace FILENAME_H

Answer

✓ Correct Answer: B) #ifndef FILENAME_H #define FILENAME_H ... #endif

Include guards use three parts: #ifndef checks if the name isn't defined yet, #define defines it, and #endif closes the guard. Everything goes between #define and #endif.

#ifndef RECTANGLE_H // If not defined #define RECTANGLE_H // Define it now // All class code here #endif // End of guard

• A is wrong - there's no #guard command in C++

• C is wrong - #include is for bringing in other files, not for guards

• D is wrong - namespaces are different from include guards

6
In a makefile, what does a target represent?
A) A file that needs to be created or updated
B) A variable that stores a value
C) A comment in the makefile
D) An error message

Answer

✓ Correct Answer: A) A file that needs to be created or updated

A target is what you want to build. It's usually a file like "program" or "Rectangle.o". The makefile checks if the target needs updating by looking at when its dependencies were last changed.

program: main.o Rectangle.o g++ main.o Rectangle.o -o program # "program" is the target here

• B is wrong - variables in makefiles use different syntax (like CC = g++)

• C is wrong - comments start with #

• D is wrong - makefiles don't have special error message syntax

7
What happens during the compilation stage?
A) .cpp files are turned into object files (.o)
B) Object files are combined into an executable
C) #include directives are processed
D) The program runs

Answer

✓ Correct Answer: A) .cpp files are turned into object files (.o)

Compilation takes your C++ code and turns it into machine code stored in object files. Each .cpp file gets its own .o file. This happens after preprocessing but before linking.

g++ -c Rectangle.cpp -o Rectangle.o // Creates object file from source code

• B is wrong - that's linking, not compilation

• C is wrong - that's preprocessing, which happens before compilation

• D is wrong - the program runs after everything is built, not during compilation

8
What happens during the linking stage?
A) Header files are copied into .cpp files
B) Object files are combined into one executable program
C) Syntax errors are checked
D) Variables are initialized

Answer

✓ Correct Answer: B) Object files are combined into one executable program

The linker takes all the .o object files and connects them together into one program. It makes sure all function calls find their actual function code.

g++ main.o Rectangle.o -o program // Links object files into final program

• A is wrong - that's what the preprocessor does with #include

• C is wrong - syntax errors are caught during compilation, not linking

• D is wrong - variables are initialized when the program runs

9
How do you create a namespace in C++?
A) namespace MySpace { ... }
B) #namespace MySpace
C) class namespace MySpace
D) using MySpace;

Answer

✓ Correct Answer: A) namespace MySpace { ... }

You create a namespace by writing the keyword 'namespace' followed by a name, then putting all your code inside curly braces.

namespace Geometry { class Rectangle { // Class code }; }

• B is wrong - namespace isn't a preprocessor directive, so no # is needed

• C is wrong - classes and namespaces are separate things

• D is wrong - that's how you use a namespace, not how you create one

10
What's the difference between "using namespace std;" and "using std::cout;"?
A) They do exactly the same thing
B) The first brings in everything from std, the second only brings in cout
C) The first is faster than the second
D) The second creates a new namespace called cout

Answer

✓ Correct Answer: B) The first brings in everything from std, the second only brings in cout

"using namespace std;" is like opening all the drawers in a desk - you get access to everything. "using std::cout;" opens just one drawer - you only get cout.

using namespace std; // Now can use cout, cin, string, etc using std::cout; // Only cout, still need std::cin

• A is wrong - they give you access to different amounts of stuff

• C is wrong - they compile to the same speed, it's just about what names you can use

• D is wrong - it doesn't create a namespace, it just lets you use cout without std::

11
If you have a class Rectangle in namespace Geometry, how do you create an object of that class without a using directive?
A) Rectangle myRect;
B) Geometry::Rectangle myRect;
C) Geometry.Rectangle myRect;
D) namespace Geometry Rectangle myRect;

Answer

✓ Correct Answer: B) Geometry::Rectangle myRect;

You need to specify which namespace the class comes from using the scope resolution operator (::). It's like giving the full address: "Geometry namespace, Rectangle class".

namespace Geometry { class Rectangle { /* ... */ }; } Geometry::Rectangle myRect; // Full name needed

• A is wrong - compiler doesn't know where to find Rectangle without the namespace

• C is wrong - C++ uses :: not . for namespaces

• D is wrong - that's not valid C++ syntax

12
In a makefile, what does the clean target usually do?
A) Compiles all source files
B) Removes object files and executables
C) Runs the program
D) Checks for syntax errors

Answer

✓ Correct Answer: B) Removes object files and executables

The clean target deletes all the files that were created during building (like .o files and the program itself). It's like cleaning up your workspace so you can start fresh.

clean: rm -f *.o program # Removes all .o files and the program

• A is wrong - that's what the default target does

• C is wrong - you run the program by typing its name, not with make clean

• D is wrong - the compiler checks for syntax errors, not make clean

13
What should you put in a header file?
A) Only the class declaration with function bodies
B) The class declaration without function bodies
C) The main() function
D) Only private members

Answer

✓ Correct Answer: B) The class declaration without function bodies

Header files are like a menu - they list what's available but don't give all the details. You declare your class and list all member functions, but save the actual code for the .cpp file.

// Rectangle.h class Rectangle { private: int width, height; public: void setWidth(int w); // Declaration only };

• A is wrong - function bodies go in the .cpp file, not the header

• C is wrong - main() goes in your application file (like main.cpp)

• D is wrong - headers have both private and public members

14
What error will you get if you forget to write Rectangle:: before a function name in the implementation file?
A) Syntax error
B) Linking error - function definition not found
C) Runtime error
D) No error, it will work fine

Answer

✓ Correct Answer: B) Linking error - function definition not found

Without Rectangle::, the compiler thinks you're creating a regular function, not a member function of Rectangle. When it tries to link, it can't find the Rectangle member functions you promised in the header.

// Wrong: void setWidth(int w) { ... } // Regular function // Right: void Rectangle::setWidth(int w) { ... } // Member function

• A is wrong - the syntax is valid, just not what you meant

• C is wrong - the program won't even build, so can't run

• D is wrong - you'll definitely get an error

15
What's the purpose of splitting a program into multiple files?
A) To make the program run faster
B) To organize code and allow reusing classes in different programs
C) To use less memory
D) To hide code from other programmers

Answer

✓ Correct Answer: B) To organize code and allow reusing classes in different programs

When you put a class in its own files, you can use it in many different programs just by including the header. It also keeps your code organized - each class in its own set of files.

// Program 1: #include "Rectangle.h" // Use Rectangle // Program 2: #include "Rectangle.h" // Same class, different program

• A is wrong - file organization doesn't affect speed

• C is wrong - memory usage is about what the program does, not how many files

• D is wrong - the code is still readable in separate files

16
Which statement is true about dependencies in a makefile?
A) Dependencies are files that must exist before the target can be built
B) Dependencies are error messages
C) Dependencies are optional and can be ignored
D) Dependencies are comments

Answer

✓ Correct Answer: A) Dependencies are files that must exist before the target can be built

Dependencies tell make what files are needed to build the target. If Rectangle.o needs Rectangle.cpp and Rectangle.h, those are its dependencies. Make checks if any dependencies changed to know if it needs to rebuild.

Rectangle.o: Rectangle.cpp Rectangle.h # Rectangle.cpp and Rectangle.h are dependencies

• B is wrong - dependencies are input files, not errors

• C is wrong - dependencies are critical for make to work correctly

• D is wrong - comments use # in makefiles

17
What will happen if you #include "Rectangle.cpp" instead of "Rectangle.h"?
A) Nothing, it works the same way
B) You'll get multiple definition errors when linking
C) The program will run slower
D) It won't compile at all

Answer

✓ Correct Answer: B) You'll get multiple definition errors when linking

When you include a .cpp file, you're copying all its function definitions into your file. Then when you compile Rectangle.cpp separately, you get two copies of every function. The linker doesn't know which one to use.

// Wrong: #include "Rectangle.cpp" // Copies all function code // Right: #include "Rectangle.h" // Only copies declarations

• A is wrong - you'll definitely get errors

• C is wrong - the program won't even build

• D is wrong - it might compile, but linking will fail

18
When should you use a namespace?
A) Only when writing very large programs
B) When you want to group related code together or avoid name conflicts
C) Never, they're not useful
D) Only for classes, not functions

Answer

✓ Correct Answer: B) When you want to group related code together or avoid name conflicts

Namespaces help you organize code (like putting all geometry classes together) and prevent problems when two things have the same name (like if you and another programmer both create a Rectangle class).

namespace Geometry { class Rectangle { /* ... */ }; class Circle { /* ... */ }; } // All geometry stuff grouped together

• A is wrong - namespaces are useful in programs of any size

• C is wrong - namespaces are very useful for organization

• D is wrong - namespaces can contain classes, functions, variables, etc.

19
What does the -c flag do when compiling?
A) It creates a complete executable program
B) It compiles to an object file without linking
C) It checks for errors only
D) It cleans up old files

Answer

✓ Correct Answer: B) It compiles to an object file without linking

The -c flag tells g++ to stop after creating the .o file. Don't link yet - we'll do that later. This is useful when you want to compile files separately.

g++ -c Rectangle.cpp -o Rectangle.o // Creates Rectangle.o, doesn't try to make a program yet

• A is wrong - that's what happens when you don't use -c

• C is wrong - it still creates the .o file, not just checking

• D is wrong - cleaning is done with make clean or rm commands

20
Where should you include the header file in your class's implementation file?
A) At the very end of the file
B) In the middle, between function definitions
C) At the top of the file, usually first thing
D) You don't need to include it

Answer

✓ Correct Answer: C) At the top of the file, usually first thing

The implementation file needs the header file right at the start so the compiler knows about the class declaration before you start writing member functions.

// Rectangle.cpp #include "Rectangle.h" // First thing void Rectangle::setWidth(int w) { // Now compiler knows about Rectangle class }

• A is wrong - you need the declarations before using them

• B is wrong - includes go at the top by convention and necessity

• D is wrong - without it, compiler doesn't know about your class

21
What does "separate compilation" mean?
A) Compiling on different computers
B) Compiling each .cpp file independently, then linking them together
C) Compiling classes separately from functions
D) Using two different compilers

Answer

✓ Correct Answer: B) Compiling each .cpp file independently, then linking them together

Separate compilation means each .cpp file gets compiled on its own to create a .o file. Then all the .o files get linked together at the end. This saves time - if you change one file, you only recompile that one.

g++ -c main.cpp -o main.o // Compile separately g++ -c Rectangle.cpp -o Rectangle.o g++ main.o Rectangle.o -o program // Link together

• A is wrong - it's about compiling files separately, not using different computers

• C is wrong - classes and functions aren't compiled separately, files are

• D is wrong - you use the same compiler for all files

22
What is the "std" namespace used for?
A) For storing user-defined classes
B) For all the standard C++ library features like cout, cin, string, etc.
C) For storing integers only
D) For preventing errors

Answer

✓ Correct Answer: B) For all the standard C++ library features like cout, cin, string, etc.

The std namespace contains everything from the C++ standard library. That's why we write std::cout or use "using namespace std;" - all those tools are stored in the std namespace.

std::cout << "Hello"; // cout is in std namespace std::string name; // string is in std namespace std::vector nums; // vector is in std namespace

• A is wrong - user classes usually go in custom namespaces or the global namespace

• C is wrong - std has many types, not just integers

• D is wrong - namespaces help organize code, not prevent errors directly

23
In a makefile, what does the TAB character before commands indicate?
A) It's optional for formatting
B) It's required - tells make this is a command to run
C) It's a comment
D) It means the line should be skipped

Answer

✓ Correct Answer: B) It's required - tells make this is a command to run

The TAB character is critical in makefiles. It tells make "this line is a command to execute". If you use spaces instead of TAB, make will give you an error.

program: main.o Rectangle.o g++ main.o Rectangle.o -o program # Must use TAB, not spaces!

• A is wrong - TAB is absolutely required, not optional

• C is wrong - comments use # in makefiles

• D is wrong - TAB means "run this command"

24
What happens if you forget the #endif in an include guard?
A) Nothing, it's optional
B) Compiler error - unterminated conditional directive
C) The program runs slower
D) It only affects debug mode

Answer

✓ Correct Answer: B) Compiler error - unterminated conditional directive

#ifndef starts a conditional block that must be closed with #endif. Without #endif, the compiler doesn't know where the conditional section ends and will give you an error.

#ifndef RECTANGLE_H #define RECTANGLE_H // Class definition #endif // Must have this!

• A is wrong - #endif is required to close the #ifndef

• C is wrong - it won't even compile

• D is wrong - preprocessor directives work the same in all modes

25
Why might you want to use "using std::cout;" instead of "using namespace std;"?
A) It makes the program run faster
B) To avoid bringing in lots of names you don't need and might conflict with your code
C) It uses less memory
D) It's required by C++98

Answer

✓ Correct Answer: B) To avoid bringing in lots of names you don't need and might conflict with your code

"using namespace std;" brings in hundreds of names. If you have a variable called "count", it might conflict with std::count. Only bringing in what you need (like just cout) is safer.

using std::cout; // Only cout using std::cin; // Only cin // Safer than "using namespace std;"

• A is wrong - both compile to the same speed

• C is wrong - memory usage is the same

• D is wrong - both are allowed in C++98

26
What's the relationship between a header file and its implementation file?
A) They're completely unrelated
B) The header declares what exists, the implementation defines how it works
C) They both contain exactly the same code
D) The implementation file includes the header file, but not the other way around

Answer

✓ Correct Answer: B) The header declares what exists, the implementation defines how it works

The header file is like a promise - "these functions exist". The implementation file is where you keep that promise - "here's what those functions actually do".

// Rectangle.h - Declaration (the promise) void setWidth(int w); // Rectangle.cpp - Definition (keeping the promise) void Rectangle::setWidth(int w) { width = w; }

• A is wrong - they work together as a pair

• C is wrong - they have different content (declarations vs definitions)

• D is wrong - that's true but doesn't explain their relationship

27
When would you get a linking error?
A) When you have a syntax error
B) When you declare a function but never define it
C) When you forget a semicolon
D) When you use the wrong variable type

Answer

✓ Correct Answer: B) When you declare a function but never define it

Linking errors happen when the linker can't find something. If your header promises a function exists but you never write the actual code for it in the .cpp file, the linker will complain.

// Rectangle.h void setWidth(int w); // Promise made // Rectangle.cpp // Oops! Never wrote setWidth() - linking error!

• A is wrong - syntax errors are caught during compilation

• C is wrong - semicolon errors are syntax errors, caught at compile time

• D is wrong - type errors are caught during compilation

28
What's the advantage of using a makefile instead of typing the compile command every time?
A) Makefiles make the program run faster
B) Makefiles automatically recompile only the files that changed, saving time
C) Makefiles prevent all errors
D) Makefiles make the executable file smaller

Answer

✓ Correct Answer: B) Makefiles automatically recompile only the files that changed, saving time

Make is smart - it checks when files were last changed. If Rectangle.cpp hasn't changed since you last compiled it, make skips it and only recompiles what actually needs updating. This saves tons of time in big projects.

make # make: 'Rectangle.o' is up to date. # Only recompiles what changed!

• A is wrong - makefiles are about building, not runtime speed

• C is wrong - makefiles help with building but don't prevent errors in your code

• D is wrong - the final executable size is the same
