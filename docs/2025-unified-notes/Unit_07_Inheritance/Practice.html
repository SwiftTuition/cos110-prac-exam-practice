Problem 1: Book and Textbook (Easy)

Problem Statement

Create a Book base class with title and author. Then create a Textbook derived class that adds subject and grade level. Implement constructors that properly chain to the base class.

Requirements:

  • Book class with title and author (protected members)
  • Constructor for Book that initializes both members
  • displayInfo() function in Book that prints title and author
  • Textbook class that inherits from Book
  • Adds subject and gradeLevel (private members)
  • Constructor that calls the Book constructor
  • Redefined displayInfo() that shows all four pieces of information

Test cases:

  • Create a Textbook object: Textbook calculus("Calculus", "James Stewart", "Mathematics", 12);
  • Call displayInfo() and verify it shows all information

Solution Explanation

Key Points:
  • Use protected for Book members so Textbook can access them
  • Call the base constructor via initializer list: : Book(t, a)
  • Redefine displayInfo() with the exact same signature
  • Can call base version with Book::displayInfo() if needed

Why This Works

The Textbook constructor calls Book(t, a) in its initializer list. This ensures that title and author are initialized before the Textbook constructor body runs. The displayInfo() function in Textbook calls Book::displayInfo() to avoid duplicating code, then adds the textbook-specific information.

Problem 2: Electric Vehicle with Copy Constructor (Intermediate)

Problem Statement

Create a Vehicle base class and an ElectricVehicle derived class. Implement both regular constructors and copy constructors that properly handle inheritance.

Requirements:

  • Vehicle class with make, model, and year (protected)
  • Regular constructor for Vehicle
  • Copy constructor for Vehicle that prints "Copying vehicle: [make]"
  • ElectricVehicle inherits from Vehicle
  • Adds batteryCapacity (in kWh) and range (in km) as private members
  • Regular constructor that calls base constructor
  • Copy constructor that calls base copy constructor
  • displayInfo() function showing all vehicle information
  • Test the copy constructor by creating a copy of an electric vehicle

Test cases:

  • Create an ElectricVehicle: ElectricVehicle tesla("Tesla", "Model 3", 2023, 75.0, 500);
  • Create a copy: ElectricVehicle teslaCopy = tesla;
  • Verify both constructor messages and that the copy has identical values

Solution Explanation

Key Points:
  • Copy constructor signature: ElectricVehicle(const ElectricVehicle& other)
  • Must call base copy constructor: : Vehicle(other)
  • The base copy constructor handles copying make, model, and year
  • Derived copy constructor only copies its own members

Why This Works

When the copy constructor is called with ElectricVehicle teslaCopy = tesla;, the ElectricVehicle copy constructor calls Vehicle(other). The compiler knows to use the Vehicle copy constructor (not the regular constructor) because other is a reference to an ElectricVehicle, which is also a Vehicle. This properly copies all base class members before the derived class constructor copies its own members.

Notice the destructor order: derived first, then base. This is automatic and happens in reverse order of construction.

Bug #1: Cat constructor doesn't call Pet constructor

The Cat constructor doesn't call the Pet constructor, so petName and age are never initialized. The compiler tries to call Pet() default constructor, but it doesn't exist.

Fix: Cat(string n, string b) : Pet(n), breed(b), lives(9) { }

Bug #2: Accessing private base class members

Cat::makeSound() and Cat::displayInfo() try to access petName and age directly, but they're private in Pet.

Fix: Change private: to protected: in the Pet class, OR use getter functions.

Bug #3: Using assignment instead of initializer list in Pet

The Pet constructor uses assignment in the body instead of the initializer list.

Fix: Pet(string n) : petName(n), age(0) { }

Problem 4: Banking System (Challenge)

Problem Statement

Create a complete banking system with an Account base class and two derived classes: SavingsAccount and CheckingAccount. This requires implementing constructors, copy constructors, destructors, and multiple member functions.

Requirements:

Account base class:

  • accountNumber (string), ownerName (string), balance (double) - all protected
  • Constructor that initializes all three
  • Copy constructor
  • Destructor that prints "Closing account [accountNumber]"
  • deposit(double amount) - adds to balance
  • withdraw(double amount) - returns true if successful, false if insufficient funds
  • displayInfo() - shows account number, owner, and balance

SavingsAccount derived class:

  • Adds interestRate (double, private)
  • Constructor, copy constructor, destructor
  • addInterest() - adds interest to balance
  • Redefine displayInfo() to include interest rate
  • Redefine withdraw() to require minimum balance of R100

CheckingAccount derived class:

  • Adds overdraftLimit (double, private)
  • Constructor, copy constructor, destructor
  • Redefine withdraw() to allow overdraft up to the limit
  • Redefine displayInfo() to include overdraft limit

Test cases:

  • Create a SavingsAccount with R5000 initial balance and 5.5% interest
  • Add interest and display info
  • Try to withdraw R4950 (should fail - would leave less than R100)
  • Create a CheckingAccount with R1000 balance and R500 overdraft
  • Withdraw R1200 (should succeed)
  • Display final balance

Solution Explanation

Key Points:
  • This is production-quality code with proper encapsulation
  • Each derived class calls base constructors appropriately
  • Function redefinition changes behavior while maintaining signatures
  • Protected members allow derived classes to access balance directly
  • Destructors are called in reverse order (derived → base)

Why This Works

This solution demonstrates several advanced inheritance concepts:

  • Virtual functions: The virtual keyword on withdraw() and displayInfo() enables polymorphism (covered in later units)
  • Function redefinition: Each account type provides its own withdrawal rules
  • Calling base version: Account::displayInfo() in derived classes avoids code duplication
  • Protected members: Allow derived classes to modify balance directly
  • Proper encapsulation: Account-specific logic stays in each class

Notice how the savings account enforces a minimum balance while the checking account allows overdrafts. This is the power of inheritance - shared functionality with specialized behavior.
