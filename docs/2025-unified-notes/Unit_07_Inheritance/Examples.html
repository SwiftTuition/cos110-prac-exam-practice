Example 1: Basic Inheritance - Shape and Circle

Problem

Create a Shape base class that stores a color, and a Circle derived class that adds a radius and calculates area. This demonstrates the fundamentals of inheritance.

Approach

We'll create a base class with protected members so derived classes can access them. The Circle class will inherit from Shape and add circle-specific functionality.

Step 1: Design the base class

The Shape class has a color member and a constructor to initialize it. We make color protected so Circle can access it.

Step 2: Design the derived class

Circle inherits from Shape using class Circle : public Shape. It adds a radius member and provides functions to calculate area and display information.

Step 3: Call the base constructor

In the Circle constructor, we use the initializer list to call the Shape constructor and pass it the color: Circle(string c, double r) : Shape(c), radius(r) { }

Example 2: My Hero Academia - Hero Quirks

Context: In My Hero Academia, an anime where heroes have special powers called "quirks," different heroes inherit common traits but have unique quirk abilities. Let's model this system using inheritance.

Problem

Create a Hero base class with common hero attributes (name, power level), and derived classes for specific heroes with unique quirks. Demonstrate function redefinition and constructor chaining.

Approach

The base Hero class provides a generic useQuirk() function. Derived classes like ExplosionHero and IceHero redefine this function to show their specific quirk abilities.

Step 1: Base class with protected members

Hero has name and powerLevel as protected members. This allows derived classes to access them while keeping them hidden from main().

Step 2: Generic quirk function

The base class useQuirk() function is generic and will be redefined by each derived hero type.

Step 3: Derived classes redefine useQuirk()

Each hero type provides its own specific implementation of useQuirk() with the exact same signature (name and parameters).

Example 3: Attack on Titan - Military Hierarchy

Context: In Attack on Titan, an anime where soldiers are organized into different military branches, we can model the Scout Regiment hierarchy with inheritance.

Problem

Create a military system where Soldier is the base class, and specialized units like ScoutRegiment and GarrisonRegiment inherit from it. Demonstrate copy constructors in inheritance and function redefinition for specialized duties.

Approach

This is more advanced because we'll implement copy constructors that properly handle inheritance. We'll also show how each regiment type has different duties.

Step 1: Base Soldier class with copy constructor

Soldier has name, rank, and kill count. We implement a copy constructor that creates a proper copy.

Step 2: Derived classes with specialized members

ScoutRegiment adds titansKilled and expeditionCount. GarrisonRegiment adds wallDefenseScore.

Step 3: Copy constructor in derived class

The derived class copy constructor must call the base class copy constructor: ScoutRegiment(const ScoutRegiment& other) : Soldier(other)

Try to identify all the bugs before revealing the solution. Think about:

  • How do constructors work in inheritance?
  • What can derived classes access from base classes?
  • How should member variables be initialized?

Bug #1: Constructor doesn't call base constructor

Location: Dog constructor
Problem: The Dog constructor doesn't call the Animal constructor, so name and age are never initialized.
Fix: Dog(string n, int a, string b) : Animal(n, a), breed(b) { }

Bug #2: Accessing private base class members

Location: Dog::makeSound() and Dog::displayInfo()
Problem: Trying to access name and age directly, but they're private in Animal.
Fix: Either change name and age to protected in Animal, or add public getter functions.

Bug #3: Initializing members in constructor body

Location: Animal constructor
Problem: Using assignment in the constructor body instead of the initializer list is less efficient.
Fix: Animal(string n, int a) : name(n), age(a) { }

Bug #4: breed member not initialized in initializer list

Location: Dog constructor
Problem: breed should be initialized in the initializer list.
Fix: Include it in the fixed version from Bug #1.

Corrected Code

class Animal {
public:
    Animal(string n, int a) : name(n), age(a) { }  // Bug #3 fixed

    void makeSound() {
        cout << name << " makes a sound" << endl;
    }

    string getName() const { return name; }  // Add getter
    int getAge() const { return age; }       // Add getter

protected:  // Bug #2 fixed: changed to protected
    string name;
    int age;
};

class Dog : public Animal {
public:
    Dog(string n, int a, string b)
        : Animal(n, a), breed(b) { }  // Bug #1 and #4 fixed

    void makeSound() {
        cout << name << " barks!" << endl;  // Now accessible
    }

    void displayInfo() {
        cout << "Name: " << name << endl;
        cout << "Age: " << age << endl;
        cout << "Breed: " << breed << endl;
    }

private:
    string breed;
};
