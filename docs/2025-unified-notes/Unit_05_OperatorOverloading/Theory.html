Welcome to Operator Overloading

In this unit, we're going to make your custom classes behave like built-in types. Imagine being able to write money1 + money2 instead of money1.add(money2), or cout << student instead of student.print(). That's the power of operator overloading.

This isn't just syntactic sugar (though it does make code sweeter). It makes your code more intuitive, easier to read, and less error-prone. When you see a + b, you immediately know what's happening. When you see a.performAdditionOperationWith(b), your brain has to work harder.

Prerequisites

Before you start this unit, make sure you're comfortable with:

  • Classes and objects (defining member variables and functions)
  • Constructors (especially copy constructors)
  • Destructors and the assignment operator
  • References and the this pointer
  • Dynamic memory allocation (new and delete)

If any of these topics feel shaky, go back to Unit 4 and strengthen your foundation. Operator overloading builds directly on these concepts.

1. What is Operator Overloading?

Operators like +, -, *, and == are actually functions with special syntax. When you write 5 + 3, the compiler calls a function (something like add(5, 3) under the hood). Operator overloading lets you define what these operators do when applied to your custom classes.

Why Do We Need This?

Suppose you're building a class to represent money amounts. Without operator overloading: 

Money price(10, 50);  // $10.50
Money tax(0, 84);     // $0.84
Money total = price.add(tax);  // Functional, but awkward

With operator overloading: 

Money price(10, 50);  // $10.50
Money tax(0, 84);     // $0.84
Money total = price + tax;  // Natural and intuitive!

The second version reads like math. Your code becomes self-documenting. Anyone looking at price + tax immediately understands what's happening.

How Does It Work?

To overload an operator, you define a special function named operator followed by the symbol. For example, to overload +, you write a function called operator+. 

// Basic syntax for overloading +
ReturnType operator+(const ClassName& left, const ClassName& right) {
    // Your implementation here
    return result;
}
Key Concept: You're not creating a new operator or changing how existing operators work for built-in types. You're teaching the compiler what + means when applied to your class.

Important Rules

  • At least one operand must be a class type - You can't redefine 2 + 2
  • No new operators - You can't create ** or <>
  • Arity cannot change - Binary operators stay binary, unary stay unary
  • Precedence and associativity are fixed - * always comes before +
Common Mistake: Trying to change how operators work for built-in types. This code is illegal: 
int operator+(int a, int b) {  // ILLEGAL!
    return a - b;  // Can't change how integers add
}
⚡ Swift Quiz
Quick Check: If you define operator+ for a Fraction class, can you write both f1 + f2 and f1 + 5?
Answer: It depends on how you implement it. f1 + f2 will work if you overload for two Fractions. For f1 + 5 to work, the compiler needs a way to convert 5 to a Fraction (via a constructor) or you need to overload for Fraction + int specifically.

2. Three Ways to Overload: Friend, Member, and Non-Member

There are three approaches to operator overloading, each with different trade-offs. Understanding when to use each is critical.

Approach 1: Non-Member Functions

These are regular functions defined outside the class. They take both operands as parameters. 

class Money {
public:
    int getDollars() const { return dollars; }
    int getCents() const { return cents; }
private:
    int dollars, cents;
};

// Non-member operator function
Money operator+(const Money& m1, const Money& m2) {
    int total = (m1.getDollars() * 100 + m1.getCents()) +
                (m2.getDollars() * 100 + m2.getCents());
    return Money(total / 100, total % 100);
}

Pros: Symmetric - both operands are treated equally. Supports automatic type conversion on both sides.

Cons: Must use public getters (can't access private members). Less efficient.

Approach 2: Member Functions

Defined inside the class. The left operand becomes the calling object (this), and the right operand is the parameter. 

class Money {
public:
    // Member operator function
    Money operator+(const Money& other) const {
        int total = (dollars * 100 + cents) +
                    (other.dollars * 100 + other.cents);
        return Money(total / 100, total % 100);
    }
private:
    int dollars, cents;
};

When you write m1 + m2, the compiler calls m1.operator+(m2).

Pros: Direct access to private members. More efficient.

Cons: Asymmetric - left and right operands treated differently. Type conversion only works on the right operand.

The Asymmetry Problem: With member functions, m1 + 5 might work (if there's a constructor to convert 5 to Money), but 5 + m1 will NOT work. Why? Because 5.operator+(m1) doesn't make sense - 5 is an int, not a Money object.

Approach 3: Friend Functions (Best of Both Worlds)

Friend functions are non-members that are granted access to private members. You declare them as friend inside the class, but define them outside. 

class Money {
public:
    // Friend declaration (note the 'friend' keyword)
    friend Money operator+(const Money& m1, const Money& m2);
private:
    int dollars, cents;
};

// Definition (NO 'friend' keyword here, NO 'Money::' scope)
Money operator+(const Money& m1, const Money& m2) {
    // Can access private members because it's a friend!
    int total = (m1.dollars * 100 + m1.cents) +
                (m2.dollars * 100 + m2.cents);
    return Money(total / 100, total % 100);
}

Pros: Symmetric (both m1 + m2 and 5 + m1 can work). Efficient (direct access to private members).

Cons: Slightly breaks encapsulation (grants external access to private data).

Swift Note: For most binary operators (+, -, *, ==), friend functions are the preferred approach. They combine efficiency with symmetric type conversion.

Decision Table

Operator          | Recommended Approach     | Why?
------------------|--------------------------|---------------------------
+, -, *, /        | Friend function          | Symmetric conversion
==, !=, <, >      | Friend function          | Symmetric conversion
<<, >>            | Friend function (MUST!)  | Left operand is stream
=, [], (), ->     | Member function (MUST!)  | C++ requires it
++, --, - (unary) | Member function          | Operates on one object
+=, -=, *=, /=    | Member function          | Modifies left operand
⚡ Swift Quiz
Quick Check: Why must operator<< and operator>> be friend functions and not member functions?
Answer: Because the left operand is a stream object (ostream or istream), not your class object. For cout << myObject, you need operator<<(cout, myObject), not myObject.operator<<(cout). Since we can't add members to ostream, we must use a non-member (friend) function.

3. Stream Operators (<< and >>)

Overloading << and >> is one of the most useful applications of operator overloading. It lets you write cout << myObject instead of myObject.print().

Why They Must Be Friend Functions

For cout << myObject, the call is operator<<(cout, myObject). The left operand is cout (an ostream object), not your object. You can't add member functions to ostream (it's from the standard library), so you must use a non-member function.

The Return Type: Why References?

To enable chaining like cout << obj1 << obj2, the operator must return the stream. But we return it by reference to avoid making unnecessary copies. 

// Return type is ostream& (reference to ostream)
ostream& operator<<(ostream& os, const Money& m) {
    os << "$" << m.dollars << "." << (m.cents < 10 ? "0" : "") << m.cents;
    return os;  // Return the stream for chaining
}

When you write cout << m1 << m2, here's what happens:

  1. operator<<(cout, m1) is called, prints m1, returns cout
  2. The result (cout) is used for the next operation: operator<<(cout, m2)
  3. operator<<(cout, m2) is called, prints m2, returns cout

Input Operator (>>)

The input operator is similar, but the object parameter is NOT const (because we're modifying it with input). 

// Note: 'Money& m' is NOT const because we're modifying it
istream& operator>>(istream& is, Money& m) {
    cout << "Enter dollars: ";
    is >> m.dollars;
    cout << "Enter cents: ";
    is >> m.cents;
    return is;  // Return stream for chaining
}
Common Mistake: Forgetting to return the stream. This code won't compile: 
void operator<<(ostream& os, const Money& m) {  // WRONG return type!
    os << "$" << m.dollars;
    // No return statement
}
// Error: cout << m1 << m2 won't work because (cout << m1) returns void

Complete Example

class Money {
public:
    Money(int d = 0, int c = 0) : dollars(d), cents(c) {}

    // Friend declarations
    friend ostream& operator<<(ostream& os, const Money& m);
    friend istream& operator>>(istream& is, Money& m);

private:
    int dollars;
    int cents;
};

// Output operator
ostream& operator<<(ostream& os, const Money& m) {
    os << "$" << m.dollars << "." << (m.cents < 10 ? "0" : "") << m.cents;
    return os;
}

// Input operator
istream& operator>>(istream& is, Money& m) {
    char dollarSign;
    is >> dollarSign;  // Read '$'
    is >> m.dollars;   // Read dollars
    is.ignore();       // Skip '.'
    is >> m.cents;     // Read cents
    return is;
}
⚡ Swift Quiz
Quick Check: Why is the Money parameter const in operator<< but NOT const in operator>>?
Answer: In operator<<, we're only reading the object to print it - we don't modify it, so it's const. In operator>>, we're reading input INTO the object, modifying its values, so it cannot be const.

4. Increment and Decrement Operators (++ and --)

These operators are tricky because they come in two forms: prefix (++x) and postfix (x++). They behave differently:

  • Prefix (++x): Increment first, then return the new value
  • Postfix (x++): Return the old value, then increment

How C++ Distinguishes Them

C++ uses a clever trick: the postfix version has a dummy int parameter that's never used. It's just a signal to the compiler. 

class Counter {
public:
    Counter(int v = 0) : value(v) {}

    // Prefix ++: increments and returns new value by reference
    Counter& operator++() {
        value++;
        return *this;  // Return the modified object
    }

    // Postfix ++: returns old value, then increments
    // The 'int' parameter is never used - it's just for disambiguation
    const Counter operator++(int) {
        Counter old = *this;  // Save current state
        value++;              // Increment
        return old;           // Return saved (old) state
    }

private:
    int value;
};

Understanding the Return Types

Notice the different return types:

  • Prefix: Returns Counter& (reference) - allows chaining like ++(++c)
  • Postfix: Returns const Counter (value) - prevents nonsense like (c++)++
Example execution:

Counter c(5);

++c:                    c++:
1. value becomes 6      1. Save old value (5)
2. Return reference     2. value becomes 6
   to c (now 6)         3. Return old value (5)

After ++c: c = 6        After c++: c = 6
Result: 6               Result: 5 (but c is now 6)
Swift Note: Postfix is less efficient because it creates a copy of the old state. When you have a choice, prefer prefix (++i instead of i++), especially in loops.

Why Postfix Returns const

The const on the postfix return prevents this nonsensical code: 

Counter c(5);
(c++)++;  // What should this mean?!

// Without const, this would:
// 1. c++ returns temporary copy (value 5)
// 2. ++ on temporary (makes temporary 6)
// 3. Temporary is destroyed
// 4. c is still 6 (not 7 as you might expect)
// This is confusing, so we prevent it with const
⚡ Swift Quiz
Quick Check: If c has value 10, what are the values of c and result after Counter result = c++;?
Answer: result = 10 (the old value before increment), and c = 11 (incremented after returning). Postfix returns the old value but still increments the original.

5. The Subscript Operator ([])

The subscript operator lets your class act like an array. It's perfect for classes that represent collections or containers.

Why It Must Be a Member

C++ requires operator[] to be a non-static member function. It operates directly on the object's internal data.

Return by Reference

To allow assignment (myArray[0] = 42), the operator must return a reference. This makes the result an l-value (something that can appear on the left side of =). 

class IntArray {
public:
    IntArray(int size) : size(size) {
        data = new int[size];
    }

    ~IntArray() {
        delete[] data;
    }

    // Return by reference allows: arr[i] = value
    int& operator[](int index) {
        if (index < 0 || index >= size) {
            cout << "Index out of bounds!" << endl;
            exit(1);
        }
        return data[index];  // Return reference to element
    }

private:
    int* data;
    int size;
};

Using the Subscript Operator

IntArray arr(5);

arr[0] = 10;  // Works because operator[] returns int&
arr[1] = 20;
int x = arr[0];  // Also works - reading the reference

cout << arr[0];  // Prints 10

Const Overload

For const objects, you need a const version that returns const int&: 

class IntArray {
public:
    // Non-const version: allows modification
    int& operator[](int index) {
        return data[index];
    }

    // Const version: read-only
    const int& operator[](int index) const {
        return data[index];
    }
};

When you have a const IntArray, the const version is called. This prevents modification while still allowing efficient access (returns reference, not a copy).

Common Mistake: Returning by value instead of reference: 
int operator[](int index) {  // WRONG: returns copy
    return data[index];
}

// This won't work:
arr[0] = 42;  // ERROR: Can't assign to a temporary copy!
⚡ Swift Quiz
Quick Check: Why does operator[] need to return a reference instead of a value?
Answer: Returning a reference allows the result to be an l-value, which means it can appear on the left side of an assignment. Without a reference, arr[0] = 42 would try to assign to a temporary copy, which is illegal.

6. Common Mistakes to Avoid

Mistake #1: Wrong Parameter Order for <<

// WRONG
ostream& operator<<(const Money& m, ostream& os) {  // Backwards!
    os << m.dollars;
    return os;
}

// Calling cout << money would translate to operator<<(money, cout)
// But you'd have to write: money << cout  (backwards and confusing!)

// CORRECT
ostream& operator<<(ostream& os, const Money& m) {
    os << m.dollars;
    return os;
}

Mistake #2: Modifying Through const Reference

// WRONG
Money operator+(const Money& m1, const Money& m2) {
    m1.dollars++;  // ERROR: m1 is const!
    return m1;
}

// CORRECT: Don't modify parameters, create new object
Money operator+(const Money& m1, const Money& m2) {
    int total = (m1.dollars * 100 + m1.cents) +
                (m2.dollars * 100 + m2.cents);
    return Money(total / 100, total % 100);
}

Mistake #3: Using friend Keyword in Definition

class Money {
public:
    friend Money operator+(const Money& m1, const Money& m2);
};

// WRONG - Don't use 'friend' in definition
friend Money operator+(const Money& m1, const Money& m2) {
    // ...
}

// CORRECT - 'friend' only in declaration
Money operator+(const Money& m1, const Money& m2) {
    // ...
}

Mistake #4: Assignment Operator Doesn't Return *this

// WRONG
void operator=(const Money& other) {
    dollars = other.dollars;
    cents = other.cents;
    // No return!
}

// This breaks chaining: a = b = c;

// CORRECT
Money& operator=(const Money& other) {
    if (this != &other) {  // Self-assignment check
        dollars = other.dollars;
        cents = other.cents;
    }
    return *this;  // Enable chaining
}
Critical Rule: Operators that modify the left operand (=, +=, etc.) should:
  • Be implemented as member functions
  • Return *this by reference
  • Check for self-assignment (for =)

7. Summary

Key Concepts:
  • Operator overloading defines what operators do for your classes
  • Makes code more intuitive: m1 + m2 instead of m1.add(m2)
  • Cannot change arity, precedence, or associativity
  • Cannot create new operators or redefine for built-in types
Swift Note: Decision Guide
  • Friend functions: Binary operators (+, -, ==), stream operators (<<, >>)
  • Member functions: Assignment (=), subscript ([]), increment (++), compound assignment (+=)
Return Type Guidelines:
  • +, -, *, / → Return new object by value
  • <<, >> → Return stream by reference (ostream&, istream&)
  • =, +=, -= → Return *this by reference
  • Prefix ++, -- → Return *this by reference
  • Postfix ++, -- → Return old value by value (const)
  • [] → Return element by reference
