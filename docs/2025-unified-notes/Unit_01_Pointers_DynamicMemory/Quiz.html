Question 1

Which of the following correctly declares a pointer to an integer?

  1. int ptr*;
  2. int *ptr;
  3. *int ptr;
  4. pointer int ptr;

✅ Answer: B

Correct: int *ptr;

Explanation: The asterisk (*) goes before the variable name to declare a pointer. int *ptr; means "ptr is a pointer to an int". The asterisk can be next to the type (int* ptr) or the variable (int *ptr) - both are syntactically correct, though int *ptr is preferred to avoid confusion when declaring multiple variables.

Why other options are wrong:

  • A: int ptr*; - Syntax error. The asterisk must come before the variable name, not after.
  • C: *int ptr; - Syntax error. You can't put * before the type.
  • D: pointer int ptr; - Not valid C++ syntax. There's no pointer keyword.
Question 2

What is the output of this code?

int main() {
    int x = 10;
    int *ptr = &x;
    *ptr = 20;
    cout << x << " " << *ptr << endl;
    return 0;
}

✅ Answer

Output: 20 20

Line-by-Line Trace:

  1. int x = 10; - Variable x is created with value 10
  2. int *ptr = &x; - Pointer ptr stores the address of x
  3. *ptr = 20; - Dereference ptr and write 20 to that address. Since ptr points to x, this changes x to 20
  4. cout << x << " " << *ptr << endl; - Print the value of x (which is now 20) and the value at the address stored in ptr (also 20, because it points to x)

Why this output? Because ptr points to x, modifying *ptr modifies x directly. Both x and *ptr refer to the same memory location, so they have the same value.

Question 3

True or False: In C++98, you can declare an array with a variable size like int arr[n]; where n is determined at runtime.

Justify your answer.

✅ Answer: False

Justification:

In C++98, array sizes must be compile-time constants. You cannot use a variable whose value is determined at runtime to declare the size of an array. For example: 

int n;
cin >> n;
int arr[n];  // ❌ ERROR in C++98: array size must be constant

If you need an array whose size is determined at runtime, you must use dynamic memory allocation: 

int n;
cin >> n;
int *arr = new int[n];  // ✅ Correct: dynamic allocation
// ... use array ...
delete [] arr;

Important Note: Some compilers (like GCC) support Variable Length Arrays (VLAs) as a C99 extension, so int arr[n]; might compile on certain systems. However, VLAs are NOT part of the C++98 standard and should not be used in COS 110.

Question 4

What happens if you dereference a NULL pointer?

  1. The program returns 0
  2. The program accesses memory address 0
  3. Undefined behavior (usually a crash)
  4. The compiler prevents compilation

✅ Answer: C

Correct: Undefined behavior (usually a crash)

Detailed Explanation:

Dereferencing a NULL pointer (e.g., *ptr where ptr == NULL) is undefined behavior in C++. On most systems, this causes a segmentation fault (segfault) or access violation, which crashes the program immediately.

This happens because NULL is typically defined as 0, and memory address 0 is protected by the operating system. Trying to read or write to address 0 is caught by the OS, which terminates your program.

Example:

int *ptr = NULL;
*ptr = 10;  // ☠️ CRASH: dereferencing NULL pointer

Why other options are wrong:

  • A: The program doesn't return 0 - it crashes before reaching any return statement
  • B: While technically you're trying to access address 0, this is protected and causes a crash, not successful access
  • D: The compiler usually cannot detect NULL dereferences at compile time (it's a runtime error). The code compiles successfully but fails when executed

Best Practice: Always check pointers before dereferencing:

if (ptr != NULL) {
    *ptr = 10;  // Safe: only dereference if not NULL
}
Question 5

What is the output of this code?

int main() {
    int arr[] = {10, 20, 30};
    int *ptr = arr;
    cout << *ptr << " ";
    ptr++;
    cout << *ptr << " ";
    ptr = ptr + 1;
    cout << *ptr << endl;
    return 0;
}

✅ Answer

Output: 10 20 30

Line-by-Line Trace:

  1. int arr[] = {10, 20, 30}; - Creates array with 3 elements at indices 0, 1, 2
  2. int *ptr = arr; - ptr points to the first element of the array (address of arr[0])
  3. cout << *ptr; - Dereferences ptr, printing the value at arr[0]: 10
  4. ptr++; - Increments the pointer. Now ptr points to arr[1]. (Pointer arithmetic: adding 1 to an int* moves it forward by sizeof(int) bytes)
  5. cout << *ptr; - Dereferences ptr, printing the value at arr[1]: 20
  6. ptr = ptr + 1; - Adds 1 to the pointer. Now ptr points to arr[2]
  7. cout << *ptr; - Dereferences ptr, printing the value at arr[2]: 30

Key Concept: Pointer Arithmetic

When you add to a pointer, it moves by multiples of the size of the type it points to. For int*, adding 1 moves forward by sizeof(int) bytes (typically 4 bytes). This is why ptr++ moves from arr[0] to arr[1], not to some random memory location.

Array notation arr[i] is actually shorthand for *(arr + i) - pointer arithmetic and dereferencing!

Question 6

This code has a bug. Identify it and explain how to fix it.

int main() {
    int size = 5;
    int *arr = new int[size];

    for (int i = 0; i < size; i++) {
        arr[i] = i * 10;
    }

    delete arr;

    return 0;
}

🐛 Bug Location

Line 9: delete arr;

What's Wrong

The array was allocated with new int[size] (array allocation), so it MUST be freed with delete[] arr (array deallocation). Using plain delete without brackets is undefined behavior - it typically only frees the first element and leaks the remaining 4 integers.

How to Fix

delete [] arr;  // Use delete[] for arrays
arr = NULL;     // Best practice: set to NULL after deleting

The Rule

Match your allocation with your deallocation:

  • new → delete (single object)
  • new[] → delete[] (array)

Mismatching causes undefined behavior and memory leaks.

Question 7

Which statement about pointers is FALSE?

  1. A pointer stores the memory address of a variable
  2. The & operator returns the address of a variable
  3. The * operator dereferences a pointer
  4. Pointers can only point to variables of type int

✅ Answer: D

False statement: Pointers can only point to variables of type int

Why this is false:

Pointers can point to variables of ANY type. You can have double*, char*, string*, or pointers to any class or struct. Each pointer type matches the type of data it points to: 

int *intPtr;        // Points to int
double *doublePtr;  // Points to double
char *charPtr;      // Points to char

Why other options are true:

  • A: True - A pointer is a variable that stores a memory address
  • B: True - &x gives you the address of variable x
  • C: True - *ptr accesses the value at the address stored in ptr
Question 8

Johan writes the following function. What is the output when main() runs?

void update(int val) {
    val = val + 10;
}

int main() {
    int score = 50;
    update(score);
    cout << score << endl;
    return 0;
}

✅ Answer

Output: 50

Why?

The function update receives val by value, which means it gets a copy of score. When we modify val inside the function, we're only changing the copy, not the original score variable in main().

Execution Trace:

  1. int score = 50; - Create variable score with value 50
  2. update(score); - Pass the value 50 to the function. Inside update, val is a separate variable initialized to 50
  3. val = val + 10; - val becomes 60, but score in main() is unchanged
  4. Function ends, val is destroyed
  5. cout << score; - Print score, which is still 50

How to fix it: Use a pointer parameter to modify the original variable:

void update(int *valPtr) {
    *valPtr = *valPtr + 10;
}

int main() {
    int score = 50;
    update(&score);  // Pass address
    cout << score << endl;  // Output: 60
    return 0;
}

Now the function receives the address of score and can modify the original variable through the pointer.

Question 9

Which of the following code snippets will cause a memory leak?

  1. int *ptr = new int(5);
delete ptr;
ptr = NULL;
  2. int *ptr = new int(5);
ptr = NULL;
  3. int x = 5;
int *ptr = &x;
  4. int *ptr = new int(5);
delete ptr;
delete ptr;

✅ Answer: B

Causes memory leak:

int *ptr = new int(5);
ptr = NULL;

Why this leaks:

When we do new int(5), we allocate memory on the heap and ptr stores its address. If we then do ptr = NULL; without first calling delete ptr;, we lose the address of that allocated memory. The integer is still allocated in the heap, but we have no way to access or free it - it's leaked.

Visualization:

After new:   ptr → [5]  (allocated integer on heap)
After NULL:  ptr → NULL
             [5]  (orphaned! still allocated but inaccessible)

Why other options don't leak:

  • A: No leak - memory is properly freed with delete before setting to NULL
  • C: No leak - ptr points to a stack variable x, not heap memory. No new means no need to delete
  • D: No leak (but has a different problem - double delete, which is undefined behavior and usually crashes). The memory is freed on the first delete

Correct pattern:

int *ptr = new int(5);
delete ptr;      // Free memory first
ptr = NULL;      // Then set to NULL
Question 10

True or False: After calling delete on a pointer, the pointer's value automatically becomes NULL.

Justify your answer.

✅ Answer: False

Justification:

After calling delete on a pointer, the pointer still contains the old memory address - it doesn't automatically become NULL. This creates a dangling pointer - a pointer that points to memory that has been freed.

Example:

int *ptr = new int(42);
cout << ptr << endl;   // Prints address, e.g., 0x55a2b3c4d5e6
delete ptr;
cout << ptr << endl;   // STILL prints 0x55a2b3c4d5e6 (dangling!)
// ptr is NOT automatically NULL

The memory at that address has been freed (returned to the OS), but ptr still holds the old address. Accessing *ptr now is undefined behavior - you're accessing freed memory.

Why this matters:

Dangling pointers are dangerous because dereferencing them might appear to work (if the memory hasn't been reused yet) or might crash randomly. This makes bugs hard to find.

Best Practice: Always set pointers to NULL after deleting:

delete ptr;
ptr = NULL;  // Now it's safe - dereferencing NULL crashes immediately

if (ptr != NULL) {
    *ptr = 10;  // Safe: only dereference if not NULL
}

Setting to NULL makes the pointer "safe" to check. Dereferencing NULL crashes immediately and predictably, making bugs obvious.

Question 12

What does the expression &x return?

  1. The value stored in variable x
  2. The memory address of variable x
  3. A copy of variable x
  4. A reference to variable x

✅ Answer: B

Correct: The memory address of variable x

Explanation:

The & operator is the "address-of" operator. When applied to a variable, it returns the memory address where that variable is stored. This is how you get a pointer to a variable: 

int x = 42;
int *ptr = &x;  // ptr now stores the address of x
cout << &x;     // Prints something like: 0x7ffd5e3c4a2c

Why other options are wrong:

  • A: To get the value of x, you just use x, not &x
  • C: &x doesn't create a copy - it returns an address
  • D: While references exist in C++, &x in this context returns an address (pointer), not a reference. References are declared differently (int &ref = x;)

The two meanings of &:

  • &x - Address-of operator: "give me the address of x"
  • int &ref = x; - Reference declaration: "ref is another name for x"

These are different uses of the same symbol.

Question 13

Nandipha writes this code but it crashes. What's wrong and how should it be fixed?

int main() {
    int *ptr;
    *ptr = 100;
    cout << *ptr << endl;
    return 0;
}

🐛 Bug Location

Line 2-3: Uninitialized pointer being dereferenced

What's Wrong

The pointer ptr is declared but not initialized, so it contains a random garbage address. On line 3, we dereference this pointer with *ptr = 100, attempting to write to whatever random address is in ptr. This is undefined behavior and usually causes a crash (segmentation fault).

Why it crashes:

The garbage address in ptr likely points to memory that doesn't belong to your program. When you try to write to it, the operating system detects the illegal access and terminates your program.

How to Fix - Option 1: Point to Existing Variable

int main() {
    int value;       // Create a variable
    int *ptr = &value;  // Point to it
    *ptr = 100;      // Now safe: we own this memory
    cout << *ptr << endl;
    return 0;
}

How to Fix - Option 2: Dynamically Allocate

int main() {
    int *ptr = new int;  // Allocate memory
    *ptr = 100;          // Now safe: we allocated this memory
    cout << *ptr << endl;
    delete ptr;          // Don't forget to free it!
    ptr = NULL;
    return 0;
}

The Rule

Never dereference an uninitialized pointer. Before using *ptr, ensure ptr points to valid memory by either:

  • Pointing it to an existing variable with &
  • Allocating memory with new
  • Setting it to NULL (and checking before dereferencing)
Question 14

If arr is an array of integers, what does arr by itself (without brackets) represent?

  1. The first element of the array
  2. The size of the array
  3. A pointer to the first element of the array
  4. The sum of all elements in the array

✅ Answer: C

Correct: A pointer to the first element of the array

Explanation:

In C++, an array name (without brackets) automatically "decays" to a pointer to its first element. This means arr is equivalent to &arr[0].

Example:

int arr[] = {10, 20, 30};
int *ptr = arr;  // arr decays to pointer to first element

cout << arr << endl;      // Prints address (e.g., 0x7ffd...)
cout << &arr[0] << endl;  // Prints same address
cout << *arr << endl;     // Prints 10 (first element)

This is why:

  • You can assign an array to a pointer: int *ptr = arr;
  • Array notation arr[i] is actually *(arr + i) - pointer arithmetic!
  • You can pass arrays to functions that expect pointers

Important: While arr acts like a pointer, it's NOT exactly the same:

  • sizeof(arr) gives the total size of the array, not the size of a pointer
  • You can't reassign arr to point elsewhere (it's a constant pointer)
Question 15

Tebogo writes the following code. What is the output?

int main() {
    int x = 5;
    int y = 10;
    int *p1 = &x;
    int *p2 = &y;

    *p1 = *p2;

    cout << x << " " << y << endl;
    return 0;
}

✅ Answer

Output: 10 10

Line-by-Line Trace:

  1. int x = 5; - x is 5
  2. int y = 10; - y is 10
  3. int *p1 = &x; - p1 points to x
  4. int *p2 = &y; - p2 points to y
  5. *p1 = *p2; - Dereference both pointers:
    • *p2 reads the value at y (which is 10)
    • *p1 = ... writes that value to the location p1 points to (which is x)
    • Result: x becomes 10, y stays 10
  6. cout << x << " " << y; - Print both: 10 10

Key Concept:

The statement *p1 = *p2; copies the value from one location to another. It does NOT make p1 point to the same place as p2. If Tebogo wanted to make p1 point to y, the code would be: 

p1 = p2;  // Now both pointers point to y (no dereferencing)

Compare:

  • *p1 = *p2; - Copy the value: x = y; (x becomes 10)
  • p1 = p2; - Copy the address: both pointers now point to y
Question 16

True or False: Dynamic memory allocated with new is automatically freed when the pointer goes out of scope.

Justify your answer.

✅ Answer: False

Justification:

Dynamic memory allocated with new lives on the heap and persists until you explicitly free it with delete. When a pointer goes out of scope, only the pointer variable itself is destroyed, not the memory it points to.

Example of a memory leak:

void doSomething() {
    int *ptr = new int(42);
    // Do some work
    // Oops! Forgot to delete
}  // ptr goes out of scope and is destroyed

// The integer on the heap is now leaked - allocated but inaccessible

What happens:

  1. new int(42) allocates memory on the heap
  2. ptr (a local variable on the stack) stores the address
  3. Function ends: ptr is destroyed (it's a stack variable)
  4. The heap memory is still allocated but we lost the address - memory leak!

Correct pattern:

void doSomething() {
    int *ptr = new int(42);
    // Do some work
    delete ptr;  // MUST explicitly free heap memory
    ptr = NULL;
}  // Now safe: heap memory was freed before ptr went out of scope

Key Difference: Stack vs Heap

  • Stack variables: Automatically cleaned up when they go out of scope
  • Heap memory: Must be explicitly freed with delete - never automatic

This is why you must be careful with dynamic memory - forgetting delete causes leaks!

Question 17

This code compiles but has undefined behavior. What's the problem?

int main() {
    int *ptr = new int(25);
    delete ptr;
    *ptr = 50;
    cout << *ptr << endl;
    return 0;
}

🐛 Bug Location

Line 4: *ptr = 50;

What's Wrong

After delete ptr; on line 3, the memory has been freed and returned to the operating system. However, ptr still contains the old address - it's now a dangling pointer. On line 4, we dereference this dangling pointer and try to write to freed memory, which is undefined behavior.

Why it's dangerous:

  • The memory might have been reused for something else - we'd corrupt random data
  • The OS might have reclaimed the memory - we'd crash with a segfault
  • It might appear to work (the memory hasn't been reused yet) - silent bug that's hard to find

Execution timeline:

Line 2: Allocate  → ptr points to valid heap memory containing 25
Line 3: Delete    → Memory freed, but ptr still holds old address (dangling!)
Line 4: Dereference → ☠️ Accessing freed memory - UNDEFINED BEHAVIOR
Line 5: Print     → Might print garbage, might crash, might print 50

How to Fix

Option 1: Don't use the pointer after deleting

int main() {
    int *ptr = new int(25);
    cout << *ptr << endl;  // Use it BEFORE deleting
    delete ptr;
    ptr = NULL;            // Set to NULL after deleting
    // Don't use ptr anymore
    return 0;
}

Option 2: Allocate new memory if you need to continue using it

int main() {
    int *ptr = new int(25);
    delete ptr;
    ptr = new int(50);  // Allocate new memory
    cout << *ptr << endl;
    delete ptr;
    ptr = NULL;
    return 0;
}

Best Practice: Set pointers to NULL after deleting to make dangling pointers detectable:

delete ptr;
ptr = NULL;

if (ptr != NULL) {
    *ptr = 50;  // This check prevents the bug
}
Question 18

What is the correct way to dynamically allocate an array of 10 doubles?

  1. double *arr = new double(10);
  2. double *arr = new double[10];
  3. double arr[] = new double[10];
  4. double *arr = malloc(10 * sizeof(double));

✅ Answer: B

Correct: double *arr = new double[10];

Explanation:

To allocate a dynamic array, use new type[size]. The square brackets indicate array allocation. This allocates memory for 10 consecutive doubles on the heap and returns a pointer to the first element.

Why other options are wrong:

  • A: new double(10); allocates a single double initialized to 10, not an array of 10 doubles. Parentheses are for initialization, not array size.
  • C: double arr[] = new double[10]; - Syntax error. You can't use array notation [] on the left side with dynamic allocation. Must use pointer notation.
  • D: malloc(10 * sizeof(double)); - While this works in C, it's not the C++ way. In C++, use new, not malloc. Additionally, malloc returns void* which would need casting.

Complete example:

double *arr = new double[10];  // Allocate array of 10 doubles

for (int i = 0; i < 10; i++) {
    arr[i] = i * 1.5;  // Use like regular array
}

delete [] arr;  // MUST use delete[] with square brackets
arr = NULL;

Remember: new[] requires delete[] (with brackets)!

Question 19

What is the output of this code?

int main() {
    int *p1 = new int(7);
    int *p2 = p1;

    *p2 = 14;

    cout << *p1 << " " << *p2 << endl;

    delete p1;
    p1 = NULL;
    p2 = NULL;

    return 0;
}

✅ Answer

Output: 14 14

Line-by-Line Trace:

  1. int *p1 = new int(7); - Allocate integer on heap with value 7, p1 points to it
  2. int *p2 = p1; - Copy the address from p1 to p2. Now BOTH pointers point to the SAME integer on the heap
  3. *p2 = 14; - Write 14 to the location p2 points to. Since p1 and p2 point to the same place, the change is visible through both pointers
  4. cout << *p1 << " " << *p2; - Both print 14 because they point to the same memory location
  5. delete p1; - Free the memory (only one delete needed since there's only one allocation)
  6. p1 = NULL; p2 = NULL; - Set both pointers to NULL for safety

Memory Visualization:

After line 2:
  p1 → [7]  ← p2  (both point to same location)

After line 4:
  p1 → [14] ← p2  (both see the change)

After line 7:
  p1 → NULL
  p2 → NULL
  [deleted]  (heap memory freed)

Important Notes:

  • When you assign one pointer to another (p2 = p1;), you're copying the address, not allocating new memory
  • Both pointers share the same heap object, so modifying through one affects the other
  • You only delete once because there's only one allocation - don't do delete p2; after delete p1; (that would be a double-delete error)
Question 20

Chantelle wants to pass an array to a function that will modify its elements. Which function signature should she use?

  1. void modify(int arr[], int size);
  2. void modify(int *arr, int size);
  3. void modify(int arr, int size);
  4. Both A and B are correct

✅ Answer: D

Correct: Both A and B are correct

Explanation:

In C++, int arr[] and int *arr are exactly equivalent when used as function parameters. Both indicate that the function receives a pointer to the first element of an array.

Example:

// These two signatures are identical:
void modify1(int arr[], int size) {
    arr[0] = 100;  // Modifies original array
}

void modify2(int *arr, int size) {
    arr[0] = 100;  // Also modifies original array
}

int main() {
    int numbers[] = {1, 2, 3, 4, 5};
    modify1(numbers, 5);  // Works
    modify2(numbers, 5);  // Also works - same effect
    return 0;
}

Why they're the same:

When you pass an array to a function, it "decays" to a pointer to its first element. The function doesn't receive a copy of the array - it receives the address where the array starts. Both arr[] and *arr syntax express this.

Why option C is wrong:

void modify(int arr, int size); declares arr as a regular integer, not an array or pointer. This would cause a compilation error when trying to pass an array.

Style note:

  • int arr[] - Makes it clear you expect an array
  • int *arr - More technically accurate (it IS a pointer)

Both are used in practice. Choose based on readability for your context.

Question 21

This code has a subtle bug. Identify and fix it.

int main() {
    int size = 5;
    int *arr = new int[size];

    for (int i = 0; i <= size; i++) {
        arr[i] = i * 2;
    }

    delete [] arr;
    return 0;
}

🐛 Bug Location

Line 5: for (int i = 0; i <= size; i++)

What's Wrong

The loop condition i <= size is incorrect. For an array of size 5, valid indices are 0, 1, 2, 3, 4 (from 0 to size-1). The loop runs from 0 to 5 (inclusive), so on the last iteration when i = 5, we access arr[5], which is out of bounds - one past the end of the array.

Why it's a problem:

Accessing arr[5] when the array only has 5 elements (indices 0-4) is undefined behavior. You're writing to memory that doesn't belong to your array. This might:

  • Corrupt other variables in your program
  • Cause a crash (segmentation fault)
  • Appear to work (if the memory happens to be accessible) - silent bug!

Execution trace (incorrect):

i = 0: arr[0] = 0   ✅ Valid
i = 1: arr[1] = 2   ✅ Valid
i = 2: arr[2] = 4   ✅ Valid
i = 3: arr[3] = 6   ✅ Valid
i = 4: arr[4] = 8   ✅ Valid
i = 5: arr[5] = 10  ❌ OUT OF BOUNDS!

How to Fix

Change i <= size to i < size:

for (int i = 0; i < size; i++) {  // Use < not <=
    arr[i] = i * 2;
}

Now the loop runs from 0 to 4 (when i=5, the condition is false), accessing only valid indices.

The Pattern

For arrays of size n:

  • Valid indices: 0 to n-1
  • Loop condition: i < n (NOT i <= n)
  • Total iterations: exactly n times

Common mistake: Confusing "less than" with "less than or equal to" when size is the loop bound!

Question 22

Andile claims: "If I delete a pointer twice, it will free the memory twice, which ensures it's completely gone." True or False?

Justify your answer.

✅ Answer: False

Justification:

Deleting a pointer twice is a serious error called a double delete, and it causes undefined behavior - usually a crash. The memory is fully freed after the first delete. Attempting to delete it again is illegal.

Why double delete is wrong:

  1. First delete: Memory is freed and returned to the operating system
  2. Second delete: You're trying to free memory that's already been freed (or worse, might have been reallocated for something else). This corrupts the memory management system

Example that crashes:

int *ptr = new int(42);
delete ptr;  // First delete: memory freed ✅
delete ptr;  // Second delete: CRASH ☠️ - undefined behavior

What happens:

The exact behavior is undefined (depends on your system), but typical outcomes are:

  • Immediate crash: The memory allocator detects corruption and aborts
  • Silent corruption: The allocator's internal data structures are corrupted, causing random crashes later
  • Appears to work: Rare, but if memory happened to be in a certain state, the error might not be immediately visible

How to prevent double delete:

int *ptr = new int(42);
delete ptr;
ptr = NULL;  // Set to NULL after deleting

// Later in code:
if (ptr != NULL) {
    delete ptr;  // Safe: won't delete if already NULL
}
// Or:
delete ptr;  // Also safe: deleting NULL does nothing (it's defined behavior)

Key facts:

  • Deleting NULL is safe and does nothing
  • Deleting a non-NULL pointer twice is undefined behavior
  • Always set pointers to NULL after deleting to prevent double-delete bugs
Question 23

What is the output of this code?

int main() {
    int x = 100;
    int *ptr = &x;

    cout << ptr << " " << *ptr << endl;

    return 0;
}

✅ Answer

Output: An address followed by 100

Example output: 0x7ffd5e3c4a2c 100

Explanation:

  • ptr (without the *) prints the address stored in the pointer. This is a hexadecimal memory address like 0x7ffd5e3c4a2c. The exact address will vary each time you run the program.
  • *ptr (with the *) dereferences the pointer and prints the value at that address, which is 100 (the value of x).

Understanding the output:

ptr:  0x7ffd5e3c4a2c  ← Memory address (varies each run)
*ptr: 100              ← Value at that address (always 100)

The difference:

  • ptr - "WHERE is x in memory?" (the address)
  • *ptr - "WHAT value is stored there?" (the value)

Note: The actual address printed will be different each time because the operating system assigns memory dynamically. What matters is that *ptr always prints 100 regardless of where x is located.

Question 24

What is the purpose of setting a pointer to NULL after calling delete?

  1. To free the memory a second time
  2. To prevent memory leaks
  3. To make the pointer safe to check and prevent dangling pointer bugs
  4. It's not necessary - just good style

✅ Answer: C

Correct: To make the pointer safe to check and prevent dangling pointer bugs

Explanation:

After delete ptr;, the memory is freed but ptr still contains the old address - it's a dangling pointer. Setting it to NULL (ptr = NULL;) makes the pointer "safe":

  1. Checkable: You can test if (ptr != NULL) to see if it's safe to use
  2. Safe to delete again: Calling delete on a NULL pointer does nothing (defined behavior)
  3. Immediate crash if dereferenced: Dereferencing NULL crashes immediately and predictably, unlike dereferencing a dangling pointer which causes random bugs

Example showing the benefit:

int *ptr = new int(42);
delete ptr;
ptr = NULL;  // Make it safe

// Later in code:
if (ptr != NULL) {
    *ptr = 10;  // This check prevents the bug
} else {
    cout << "Pointer is NULL, can't use it" << endl;
}

Without setting to NULL:

int *ptr = new int(42);
delete ptr;
// Didn't set to NULL - ptr still has old address (dangling!)

if (ptr != NULL) {
    *ptr = 10;  // ☠️ BUG: condition is true (ptr != NULL),
                // but dereferencing accesses freed memory!
}

Why other options are wrong:

  • A: Setting to NULL doesn't free memory - delete already did that
  • B: Setting to NULL doesn't prevent memory leaks. Leaks happen when you FORGET to delete, not from setting to NULL
  • D: It's not just style - it actively prevents bugs by making dangling pointers detectable

Best Practice Pattern:

delete ptr;
ptr = NULL;  // ALWAYS do this together
Question 25

Consider this code that manages a dynamic array. How many memory-related errors does it contain?

int main() {
    int *arr = new int[5];

    for (int i = 0; i < 5; i++) {
        arr[i] = i;
    }

    int *backup = arr;
    arr = new int[3];

    for (int i = 0; i < 3; i++) {
        arr[i] = backup[i];
    }

    delete [] arr;

    return 0;
}
  1. No errors
  2. 1 error
  3. 2 errors
  4. 3 errors

✅ Answer: C (2 errors)

Error #1: Memory Leak (Line 8-9)

Location:

int *backup = arr;
arr = new int[3];

What's wrong:

When we do arr = new int[3];, we're reassigning arr to point to a new array. The original array of 5 integers still exists on the heap, and backup points to it, but we never delete it. This is a memory leak - 5 integers allocated but never freed.

Memory state after line 9:

backup → [0][1][2][3][4]  (original array - leaked!)
arr → [garbage][garbage][garbage]  (new array)

Error #2: No Cleanup for backup (Line 15-16)

What's wrong:

We delete arr (the 3-element array), but we never delete backup (the 5-element array). The original 5-element array is never freed - confirmed memory leak.

What should happen:

delete [] arr;   // Free the 3-element array
arr = NULL;
delete [] backup;  // Also need to free the original 5-element array
backup = NULL;

Complete Fixed Version

int main() {
    int *arr = new int[5];

    for (int i = 0; i < 5; i++) {
        arr[i] = i;
    }

    // Option 1: Delete old array before allocating new one
    int *backup = arr;
    arr = new int[3];

    for (int i = 0; i < 3; i++) {
        arr[i] = backup[i];
    }

    delete [] backup;  // Clean up original array
    backup = NULL;

    delete [] arr;     // Clean up new array
    arr = NULL;

    return 0;
}

Alternative Better Design

If you need to resize an array, delete the old one before allocating new:

int main() {
    int *arr = new int[5];

    for (int i = 0; i < 5; i++) {
        arr[i] = i;
    }

    // Create temporary copy
    int *temp = new int[3];
    for (int i = 0; i < 3; i++) {
        temp[i] = arr[i];
    }

    // Delete old array BEFORE reassigning pointer
    delete [] arr;

    // Now reassign
    arr = temp;

    // Clean up
    delete [] arr;
    arr = NULL;

    return 0;
}

Key Lessons

  • Never reassign pointers without freeing the old memory first (unless you save the old pointer and free it later)
  • Every new[] needs exactly one delete[]
  • Track all your allocations - if you have multiple pointers to heap memory, make sure you delete through all of them
  • In C++11+: Use std::vector instead of manual arrays to avoid these issues entirely!
