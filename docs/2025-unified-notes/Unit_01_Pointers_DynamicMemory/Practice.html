Problem 1 - Easy

Swap Two Values Using Pointers

Your Task

Write a function called swap that takes two integer pointers and swaps the values they point to. After calling swap(&a, &b), the value of a should be what b was, and vice versa.

Function Signature

void swap(int *ptr1, int *ptr2);

Test Cases

Your function should pass these tests:

  • Input: a = 5, b = 10 → Output: a = 10, b = 5
  • Input: x = 100, y = 200 → Output: x = 200, y = 100
  • Input: m = -7, n = 42 → Output: m = 42, n = -7

✅ Solution

void swap(int *ptr1, int *ptr2) {
    int temp = *ptr1;   // Store value at ptr1 in temporary variable
    *ptr1 = *ptr2;      // Copy value at ptr2 to location of ptr1
    *ptr2 = temp;       // Copy temp (original ptr1 value) to location of ptr2
}

Explanation

This function uses the classic three-way swap algorithm:

  1. Save the first value: temp = *ptr1 stores the value that ptr1 points to. Without this, we'd lose it when we overwrite *ptr1.
  2. Copy second to first: *ptr1 = *ptr2 writes the value from ptr2's location into ptr1's location. Now both pointers point to the same value.
  3. Copy saved value to second: *ptr2 = temp writes the original first value (saved in temp) into ptr2's location. The swap is complete.

Why This Works

Because ptr1 and ptr2 are pointers (addresses), when we dereference them with *, we're accessing the actual variables in main(), not copies. Changes made through the pointers affect the original variables.

If the function signature were void swap(int val1, int val2) instead, the function would receive copies of the values, and swapping the copies wouldn't affect the originals.

Time Complexity

O(1) - Constant time. We perform exactly 3 operations regardless of input size.

Swift Note: The temporary variable is essential. If you try *ptr1 = *ptr2; then *ptr2 = *ptr1;, you'll just copy the same value to both locations - no swap happens because you lost the original *ptr1 value!
Problem 2 - Intermediate

Dynamic Student Record Manager

The Scenario

Henk runs a tutoring center in Pretoria. Students enroll throughout the year, so he needs a program that can dynamically allocate an array for student IDs based on how many students enroll, then properly clean up the memory when done.

Your Task

Complete the program below to:

  1. Ask the user how many students are enrolling
  2. Dynamically allocate an array to store that many student IDs
  3. Read the student IDs from the user
  4. Display all the IDs
  5. Properly deallocate the memory
⚠️ Requirements: You must use dynamic memory allocation (new[] and delete[]). Setting the pointer to NULL after deletion is required.

Example Run

  Student 2: 23456

✅ Solution

#include 
using namespace std;

int main() {
    int numStudents;

    cout << "How many students are enrolling? ";
    cin >> numStudents;

    // Dynamically allocate array for student IDs
    int *studentIDs = new int[numStudents];

    // Read student IDs from user
    for (int i = 0; i < numStudents; i++) {
        cout << "Enter ID for student " << (i + 1) << ": ";
        cin >> studentIDs[i];
    }

    // Display all student IDs
    cout << "\nStudent IDs:" << endl;
    for (int i = 0; i < numStudents; i++) {
        cout << "  Student " << (i + 1) << ": "
             << studentIDs[i] << endl;
    }

    // Properly deallocate memory
    delete [] studentIDs;
    studentIDs = NULL;

    cout << "\nAll records archived." << endl;

    return 0;
}

Step-by-Step Explanation

Step 1: Dynamic Allocation

int *studentIDs = new int[numStudents];

This allocates a block of memory on the heap large enough for numStudents integers. The variable numStudents is determined at runtime (from user input), which is why we need dynamic allocation - regular arrays require compile-time constants for their size.

The pointer studentIDs stores the address of the first element. Even though it's a pointer, we can use array notation [] to access elements.

Step 2: Reading Values

for (int i = 0; i < numStudents; i++) {
    cout << "Enter ID for student " << (i + 1) << ": ";
    cin >> studentIDs[i];
}

We loop from 0 to numStudents - 1 (the valid indices) and read each ID directly into the array. The expression studentIDs[i] is equivalent to *(studentIDs + i) - it calculates the address of the i-th element and accesses it.

Note that we display (i + 1) to the user (1-indexed) but use i for array access (0-indexed). This makes the output more natural for humans.

Step 3: Displaying Values

for (int i = 0; i < numStudents; i++) {
    cout << "  Student " << (i + 1) << ": " << studentIDs[i] << endl;
}

Similar loop structure, but this time we're reading from the array instead of writing to it. Again, we use 1-indexed labels for the user but 0-indexed access for the array.

Step 4: Deallocation

delete [] studentIDs;
studentIDs = NULL;

Two essential steps:

  1. delete [] studentIDs; - The brackets are essential because we allocated an array with new[]. This tells C++ to free ALL elements of the array, not just the first one. Using delete studentIDs; (without brackets) would be undefined behavior and likely cause a memory leak.
  2. studentIDs = NULL; - After freeing the memory, we set the pointer to NULL. This prevents it from being a dangling pointer. If we accidentally tried to access *studentIDs after this, we'd get an immediate crash (dereferencing NULL) rather than silent corruption from accessing freed memory.

Why Dynamic Memory Here?

We don't know numStudents until runtime - the user tells us. In C++98, you can't do: 

int studentIDs[numStudents];  // ❌ ERROR in C++98: array size must be constant

Dynamic allocation with new[] is the only way to create arrays with runtime-determined sizes.

Common Mistakes to Avoid

  • Wrong delete operator: Using delete studentIDs; instead of delete [] studentIDs; - causes undefined behavior
  • Forgetting to delete: Not calling delete[] at all - causes a memory leak
  • Accessing after delete: Using studentIDs[i] after the delete[] - accesses freed memory (undefined behavior)
  • Not setting to NULL: Leaves a dangling pointer that might appear to work but is dangerous

Time Complexity

O(n) where n = numStudents. Both the input loop and display loop iterate exactly n times. Allocation and deallocation are O(n) internally (the system must initialize/free n integers).

Best Practice: In production code, you'd want to add validation (what if numStudents is negative or zero?). You might also check if allocation succeeded (though in modern systems, if new fails, it throws an exception rather than returning NULL).

🐛 The Bugs

Bug #1: Wrong Delete Operator (Line 27)

Code: delete durations;

Problem: durations was allocated with new int[numSongs] (array allocation), so it MUST be freed with delete[] durations; (array deallocation). Using plain delete on an array is undefined behavior - it typically only frees the first element and leaks the rest.

Fix: delete [] durations;

Bug #2: Memory Leak (Line 27-28)

Code:

delete durations;
durations = temp;

Problem: When we reassign durations = temp;, we lose the pointer to the 3-element array. Even if we had used delete[] correctly, there's a logical error: we're replacing an array of 3 songs with a single song! The original design seems flawed - we should be expanding the array, not replacing it.

Bug #3: Incomplete Cleanup

Problem: After reassigning durations = temp;, both durations and temp point to the same memory location. When main() ends, neither pointer is deleted, so the single integer allocated for newSong is leaked.

Additionally, we never set any pointer to NULL after deletion.

Bug #4: Conceptual Error

Problem: The program claims to "add" a song, but actually replaces the entire playlist with just the new song. After line 28, the original 3 songs are gone (and leaked), and we only have the new song.

✅ Corrected Version #1: Just Delete Everything Properly

If the intent really is to replace the playlist:

#include 
using namespace std;

int main() {
    cout << "=== Playlist Manager ===" << endl;

    int numSongs = 3;
    int *durations = new int[numSongs];

    durations[0] = 180;
    durations[1] = 210;
    durations[2] = 195;

    cout << "Current playlist:" << endl;
    for (int i = 0; i < numSongs; i++) {
        cout << "  Song " << (i+1) << ": "
             << durations[i] << " seconds" << endl;
    }

    int newSong = 240;
    cout << "\nAdding new song (" << newSong << " seconds)..." << endl;

    // Delete the old array BEFORE reassigning
    delete [] durations;  // FIX: Use delete[] for arrays
    durations = NULL;

    // Create new single-song playlist
    int *temp = new int;
    *temp = newSong;
    durations = temp;  // Now safe to reassign

    cout << "New song added: " << *durations << " seconds" << endl;
    cout << "Playlist updated!" << endl;

    // Clean up the new allocation
    delete durations;
    durations = NULL;

    return 0;
}

✅ Corrected Version #2: Actually Add to the Playlist (Better Design)

If the intent is to expand the array to include the new song:

#include 
using namespace std;

int main() {
    cout << "=== Playlist Manager ===" << endl;

    int numSongs = 3;
    int *durations = new int[numSongs];

    durations[0] = 180;
    durations[1] = 210;
    durations[2] = 195;

    cout << "Current playlist:" << endl;
    for (int i = 0; i < numSongs; i++) {
        cout << "  Song " << (i+1) << ": "
             << durations[i] << " seconds" << endl;
    }

    int newSong = 240;
    cout << "\nAdding new song (" << newSong << " seconds)..." << endl;

    // Create new larger array
    int newSize = numSongs + 1;
    int *newDurations = new int[newSize];

    // Copy old songs
    for (int i = 0; i < numSongs; i++) {
        newDurations[i] = durations[i];
    }

    // Add new song
    newDurations[numSongs] = newSong;

    // Delete old array
    delete [] durations;

    // Point to new array
    durations = newDurations;
    numSongs = newSize;

    cout << "\nUpdated playlist:" << endl;
    for (int i = 0; i < numSongs; i++) {
        cout << "  Song " << (i+1) << ": "
             << durations[i] << " seconds" << endl;
    }

    // Clean up
    delete [] durations;
    durations = NULL;

    return 0;
}

Key Lessons

  • Match allocation with deallocation: new → delete, new[] → delete[]
  • Never reassign pointers without freeing first (unless you save the old pointer elsewhere)
  • Every allocation needs exactly one deallocation
  • Set pointers to NULL after deletion to avoid dangling pointers
  • To resize arrays, you must allocate new, copy, then delete old - arrays can't be resized in place
Real-World Note: In later units, you'll learn about data structures like linked lists and vectors that handle dynamic resizing automatically. Manual array resizing (Version #2) is inefficient for frequent additions - each addition requires O(n) copying!
Problem 4 - Challenge

Dynamic Grade Table

The Scenario

Wesley, a teacher in Cape Town, needs to store grades for multiple students across multiple assignments. The number of students and assignments varies each semester, so he needs a 2D dynamic array that can be sized at runtime.

Your Task

Create a 2D dynamic array (a "table" or "matrix") to store grades. The dimensions should be determined by user input. Your program should:

  1. Ask for the number of students and number of assignments
  2. Dynamically allocate a 2D array (grades[students][assignments])
  3. Fill the array with sample grades (you can use a pattern like row * 10 + col)
  4. Display the grade table
  5. Properly deallocate ALL memory (this is the challenging part!)
Hint: A 2D dynamic array is actually an array of pointers, where each pointer points to an array (a row). You'll need to:
  • Allocate an array of int* pointers (one per student)
  • For each pointer, allocate an array of int (one per assignment)
  • When deallocating, delete each row's array first, then delete the array of pointers

How many students? 3
How many assignments? 4

Grade Table:
Student 1:  50  51  52  53
Student 2:  60  61  62  63
Student 3:  70  71  72  73

All memory freed.

✅ Solution

#include 
using namespace std;

int main() {
    int numStudents, numAssignments;

    cout << "How many students? ";
    cin >> numStudents;
    cout << "How many assignments? ";
    cin >> numAssignments;

    // Allocate array of pointers (one pointer per student)
    int **grades = new int*[numStudents];

    // For each student, allocate an array for their assignment grades
    for (int i = 0; i < numStudents; i++) {
        grades[i] = new int[numAssignments];
    }

    // Fill the array with sample grades
    for (int i = 0; i < numStudents; i++) {
        for (int j = 0; j < numAssignments; j++) {
            grades[i][j] = 50 + (i * 10) + j;
        }
    }

    // Display the grade table
    cout << "\nGrade Table:" << endl;
    for (int i = 0; i < numStudents; i++) {
        cout << "Student " << (i + 1) << ": ";
        for (int j = 0; j < numAssignments; j++) {
            cout << " " << grades[i][j];
        }
        cout << endl;
    }

    // Deallocate memory - MUST delete rows before deleting array of pointers
    for (int i = 0; i < numStudents; i++) {
        delete [] grades[i];  // Delete each row
        grades[i] = NULL;
    }
    delete [] grades;  // Delete the array of pointers
    grades = NULL;

    cout << "\nAll memory freed." << endl;

    return 0;
}

Understanding 2D Dynamic Arrays

A 2D dynamic array is more complex than a 1D array. Here's what's happening:

Step 1: Allocate Array of Pointers

int **grades = new int*[numStudents];

Breaking this down:

  • int* is a "pointer to int"
  • int** is a "pointer to pointer to int"
  • new int*[numStudents] creates an array of int* pointers
  • grades stores the address of this array of pointers

At this point, we have an array of pointers, but each pointer is uninitialized (points to garbage). We haven't allocated any actual grade storage yet.

Memory visualization after this step:

grades → [ptr][ptr][ptr]  (array of 3 pointers, if numStudents = 3)
          ???  ???  ???   (each pointer contains garbage)

Step 2: Allocate Each Row

for (int i = 0; i < numStudents; i++) {
    grades[i] = new int[numAssignments];
}

For each student (each element of the grades array), we allocate an array of integers to hold that student's assignment grades. Now each pointer in the grades array points to its own separate array.

Memory visualization after this step (3 students, 4 assignments):

grades → [ptr][ptr][ptr]
           |    |    |
           ↓    ↓    ↓
         [int][int][int][int]  ← Student 1's grades
         [int][int][int][int]  ← Student 2's grades
         [int][int][int][int]  ← Student 3's grades

Now we can access any grade with grades[i][j]:

  • grades[i] gives us the pointer to student i's array
  • grades[i][j] accesses the j-th element of that array (assignment j's grade)

Step 3: Fill and Display

for (int i = 0; i < numStudents; i++) {
    for (int j = 0; j < numAssignments; j++) {
        grades[i][j] = 50 + (i * 10) + j;
    }
}

We use nested loops to access every element. The formula 50 + (i * 10) + j creates a pattern:

  • Student 0: grades 50, 51, 52, 53...
  • Student 1: grades 60, 61, 62, 63...
  • Student 2: grades 70, 71, 72, 73...

Step 4: Deallocation (MOST IMPORTANT)

// Delete each row first
for (int i = 0; i < numStudents; i++) {
    delete [] grades[i];
    grades[i] = NULL;
}
// Then delete the array of pointers
delete [] grades;
grades = NULL;

⚠️ ORDER MATTERS!

You MUST delete the rows before deleting the array of pointers. Here's why:

  • If you delete grades first, you lose access to all the row pointers (grades[0], grades[1], etc.)
  • Without those pointers, you can't delete the rows, so they leak
  • You must "unwind" the allocation in reverse order: delete what you allocated last, first

Correct order:

  1. Delete each row with delete [] grades[i] (we allocated these with new int[])
  2. Set each row pointer to NULL
  3. Delete the array of pointers with delete [] grades (we allocated this with new int*[])
  4. Set grades to NULL

Why This Pattern?

C++ doesn't have true multi-dimensional dynamic arrays. Instead, we simulate them with "arrays of arrays" - a pointer to pointers. This gives us:

  • Flexibility: Each row can theoretically have a different length (jagged arrays)
  • Runtime sizing: We don't need compile-time constants
  • But: We must manually manage memory for each dimension

Time and Space Complexity

  • Allocation: O(numStudents) for the pointer array + O(numStudents × numAssignments) for the rows = O(n × m)
  • Deallocation: O(numStudents × numAssignments) - must free each element's memory
  • Space: O(n × m) for the actual data + O(n) for the array of pointers
Pro Tip: In real code, you'd often wrap this in a class with a destructor that handles cleanup automatically. That's coming in Unit 4 when you learn about the Big Three (destructor, copy constructor, assignment operator)!
Common Mistake: Forgetting to delete the rows, or deleting in the wrong order. This causes memory leaks that are hard to detect. Tools like Valgrind (on Linux) can help find these leaks during development.
