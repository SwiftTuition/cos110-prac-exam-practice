Welcome to Pointers & Dynamic Memory

This unit covers one of the most important concepts in C++: pointers and dynamic memory management. Pointers give you direct control over your computer's memory, allowing you to write efficient programs and build complex data structures.

By the end of this unit, you'll understand how to work with memory addresses, create variables at runtime, and manage memory properly to avoid leaks and crashes.

Swift Note: Pointers can feel abstract at first, but we'll break everything down step-by-step with plenty of interactive examples you can run and modify. Take your time and experiment with the code!

COS 132 Refresher: Arrays Basics

Before we dive into pointers, let's refresh one important concept from COS 132: arrays. Understanding arrays will make pointers much easier to grasp.

What is an Array?

An array is a collection of elements of the same type, stored in contiguous (adjacent) memory locations. You declare an array by specifying the type and size. 

// Declare an array of 5 integers
int scores[5];

// Initialize an array
int numbers[4] = {10, 20, 30, 40};

// Access elements using indices (0-based)
cout << numbers[0];  // Prints: 10
cout << numbers[3];  // Prints: 40

// Modify elements
numbers[1] = 99;
cout << numbers[1];  // Prints: 99

Arrays in Memory

Here's how an array looks in memory. Each element occupies a specific memory location with its own address.

Array: int numbers[4] = {10, 20, 30, 40}; Memory Layout: numbers[0] numbers[1] numbers[2] numbers[3] ┌────┐ ┌────┐ ┌────┐ ┌────┐ Memory: │ 10 │ │ 20 │ │ 30 │ │ 40 │ └────┘ └────┘ └────┘ └────┘ Address: 0x1000 0x1004 0x1008 0x100C └───────────────────────────────────────┘ Contiguous block in memory
⚠️ Array Limitation: In C++, the size of an array must be a constant known at compile time. You can't write int arr[n]; where n comes from user input. This is a major limitation that dynamic memory solves!

What Are Pointers?

A pointer is a variable that stores a memory address. Instead of holding a value like 42 or 3.14, a pointer holds the location in memory where that value is stored.

The Memory Address Analogy

Think of your computer's memory as a long street of houses. Each house has a unique address (like "123 Main Street"), and each house contains something inside (furniture, belongings, etc.).

  • A regular variable is like the furniture inside the house.
  • A pointer is like writing down the house's address on a piece of paper.

The address lets you find the house (and its contents) even if you're not currently there.

Memory as a Street: House at 123 Main St: House at 456 Oak Ave: ┌──────────────────┐ ┌──────────────────┐ │ int x = 100 │ │ int y = 200 │ │ Address: 0x1000 │ │ Address: 0x2000 │ └──────────────────┘ └──────────────────┘ Pointer (like a piece of paper with an address): ┌──────────────────┐ │ int *ptr │ │ Value: 0x1000 │ ──────→ Points to x │ Address: 0x3000 │ └──────────────────┘

Why Do We Need Pointers?

Pointers unlock three important capabilities:

  • Efficient function arguments: Passing a pointer (just an address) is much faster than copying a large object.
  • Dynamic memory: Pointers are the only way to create variables and arrays whose size isn't known until the program runs.
  • Advanced data structures: Linked lists, trees, and graphs connect pieces of data using pointers.
Swift Note: You've actually used pointers already! When you use call-by-reference (void func(int &x)), C++ is passing a pointer to x behind the scenes. Now we're learning to use them directly.

Pointer Syntax and Operations

Working with pointers requires three key concepts. The confusing part? Two of them use symbols you already know (& and *), but in new contexts.

1. The Address-of Operator (&)

The & operator gives you the memory address of a variable. It answers the question: "Where does this variable live in memory?" 

int score = 100;

// Get the address of score
cout << &score;  // Prints something like: 0x7ffee4b5e0a4
                 // This is the memory address where score is stored

2. Pointer Declaration (*)

When declaring a variable, the * symbol makes it a pointer. This tells the compiler: "This variable will hold an address, not a regular value." 

// Declare a pointer to an integer
int *ptr;

// Declare a pointer to a double
double *dPtr;

// The * attaches to the variable name, not the type
int *p1, *p2;   // Both are pointers
int* p3, p4;    // p3 is a pointer, p4 is a regular int (confusing!)

3. The Dereferencing Operator (*)

When * is used with an existing pointer variable, it "goes to" the address and accesses the value stored there. This is called dereferencing. 

int score = 100;
int *ptr = &score;  // ptr holds the address of score

// Dereference: access the value AT the address
cout << *ptr;       // Prints: 100 (the value of score)

// Modify the value through the pointer
*ptr = 200;
cout << score;      // Prints: 200 (score was changed!)
⚠️ Important: The * symbol has two different meanings:
  • int *ptr; → Declaration (ptr is a pointer)
  • *ptr = 50; → Dereferencing (access value at ptr's address)
The context tells you which one it is.

Putting It All Together

// 1. Create a regular variable
int num = 42;

// 2. Declare a pointer
int *p;

// 3. Store the address of num in p
p = #

// 4. Access the value through the pointer
cout << *p;  // Prints: 42

// 5. Modify through the pointer
*p = 99;
cout << num;  // Prints: 99 (num changed!)
cout << *p;   // Prints: 99

  • ptr

Pointers and Functions: Call-by-Reference Explained

One of the most important uses of pointers is passing variables to functions by reference. This lets functions modify the original variable, not just a copy.

Call-by-Value (The Default)

When you pass a variable to a function normally, C++ makes a copy. Changes to the parameter don't affect the original variable. 

void tryToDouble(int num) {
    num = num * 2;  // Only changes the COPY
}

int main() {
    int x = 10;
    tryToDouble(x);
    cout << x;  // Still prints: 10 (unchanged!)
    return 0;
}

Call-by-Reference with Pointers

By passing a pointer (the address), the function can access and modify the original variable. 

void actuallyDouble(int *numPtr) {
    *numPtr = *numPtr * 2;  // Changes the ORIGINAL
}

int main() {
    int x = 10;
    actuallyDouble(&x);  // Pass the address of x
    cout << x;  // Prints: 20 (changed!)
    return 0;
}
Swift Note: This is exactly what the & reference parameter does (void func(int &x)). It's just a cleaner syntax for the same concept!

💡 Swift Quiz: Why Does Swap Work?
Question: Why does the swap function successfully swap the values of first and second in main()?

Answer:

The swap function receives pointers (addresses) to first and second, not copies of their values. When the function dereferences these pointers (*a and *b), it's directly accessing and modifying the original variables in main().

If we had used call-by-value (void swap(int a, int b)), the function would only swap copies, leaving the originals unchanged.

Pointer Safety: NULL and Initialization

The most dangerous thing about pointers is using them before they're initialized. An uninitialized pointer contains a random memory address, and dereferencing it causes undefined behavior (usually a crash).

Always Initialize Pointers

// WRONG: Uninitialized pointer
int *ptr;
*ptr = 10;  // CRASH! ptr points to random memory

// CORRECT: Initialize to NULL
int *ptr = NULL;

// Check before using
if (ptr != NULL) {
    *ptr = 10;  // This won't execute (ptr is null)
}

// Or initialize to a valid address
int x;
int *ptr2 = &x;
*ptr2 = 10;  // Safe!

What is NULL?

NULL is a special value that represents a "null pointer" - a pointer that points to nothing. It's a safe default value that you can check before using the pointer.

⚠️ Important Rule: Never dereference a pointer that is NULL or uninitialized. Always initialize pointers and check them before use.

Dynamic Memory: Creating Variables at Runtime

So far, all our variables have been created automatically when we declare them. They live on the stack and are destroyed automatically when they go out of scope. But what if you need a variable that:

  • Outlives the function that created it?
  • Has a size that isn't known until the program runs?

That's where dynamic memory comes in. Dynamic variables live on the heap (also called the freestore), and their lifetime is controlled manually.

The new Operator

The new operator allocates memory on the heap and returns a pointer to that memory. 

// Allocate an integer on the heap
int *ptr = new int;

// You can also initialize it
int *ptr2 = new int(42);

// Use the dynamic variable through the pointer
*ptr = 100;
cout << *ptr;  // Prints: 100

The delete Operator

When you're done with a dynamic variable, you must return its memory to the system using delete. If you forget, you have a memory leak. 

int *ptr = new int(50);

// ... use ptr ...

delete ptr;        // Free the memory
ptr = NULL;        // Set to null (good practice)
Stack vs Heap: STACK (Automatic variables): ┌──────────────┐ │ int x = 10; │ ← Created when declared └──────────────┘ ← Destroyed when out of scope HEAP (Dynamic variables): ┌──────────────────────┐ │ int *p = new int(20);│ ← Created with 'new' └──────────────────────┘ ← Destroyed with 'delete' (YOU control lifetime)
⚠️ Essential Rule: Every new must have exactly one matching delete. Forgetting to delete causes memory leaks. Using a pointer after delete causes crashes.

Common Memory Errors

1. Memory Leaks

A memory leak occurs when you allocate memory with new but never release it with delete. The memory becomes "lost" - your program can't access it, but the system still considers it in use. 

void leakyFunction() {
    int *p = new int(10);
    // ... use p ...
    // Function ends WITHOUT calling delete
}  // LEAK! Memory is lost forever

// If called in a loop:
for (int i = 0; i < 1000; i++) {
    leakyFunction();  // Leaks more memory each time!
}
// Eventually the program runs out of memory and crashes

Fix: Always call delete before losing the pointer.

void goodFunction() {
    int *p = new int(10);
    // ... use p ...
    delete p;  // Clean up before function ends
}

2. Dangling Pointers

A dangling pointer points to memory that has been freed. Using it causes undefined behavior (crashes, corrupted data, etc.). 

int *p = new int(100);
delete p;      // Memory is freed

cout << *p;    // DANGER! Dangling pointer
*p = 200;      // DANGER! Writing to freed memory

Fix: Set pointers to NULL after deleting.

int *p = new int(100);
delete p;
p = NULL;      // Now it's safe

// Any attempt to use it can be checked:
if (p != NULL) {
    cout << *p;  // Won't execute
}

3. Double Deletion

Calling delete twice on the same pointer causes undefined behavior. 

int *p = new int(50);
delete p;
delete p;  // CRASH! Double deletion

// Fix: Set to NULL after first delete
int *p = new int(50);
delete p;
p = NULL;

delete p;  // Safe - deleting NULL does nothing
💡 Swift Quiz: Spot the Memory Leak
Question: Does this code have a memory leak? 
int *p = new int(5);
p = new int(10);

Answer: YES, this has a memory leak!

The first new int(5) allocates memory and p points to it. The second new int(10) allocates different memory and p now points to this new location. The original memory (containing 5) is still allocated but we've lost the pointer to it - it's leaked.

Correct approach:

int *p = new int(5);
delete p;        // Free the first allocation
p = new int(10); // Now allocate new memory

Dynamic Arrays: Arrays with Runtime Size

Remember the limitation of regular arrays? Their size must be a constant known at compile time. Dynamic arrays solve this by letting you specify the size at runtime.

Creating Dynamic Arrays

Use new type[size] where size can be a variable. This returns a pointer to the first element. 

int size;
cout << "How many elements? ";
cin >> size;

// Create a dynamic array
int *arr = new int[size];

// Use it like a normal array
for (int i = 0; i < size; i++) {
    arr[i] = i * 10;
    cout << arr[i] << " ";
}

Deleting Dynamic Arrays

This is important: when you delete a dynamic array, you must use delete [], not delete. The empty brackets tell C++ to free the entire array. 

int *arr = new int[100];

// ... use arr ...

delete [] arr;    // CORRECT: frees the entire array
arr = NULL;

// delete arr;    // WRONG! Only frees first element, leaks the rest
⚠️ Important: Mixing new/delete and new[]/delete[] causes undefined behavior. This corrupts memory and causes hard-to-debug crashes.
  • new type → delete ptr
  • new type[size] → delete [] ptr

Question: What's wrong with this code? 
double *scores = new double[50];
// ... use scores ...
delete scores;

Answer: The delete statement is wrong!

We allocated an array with new double[50], so we must delete it with delete [] scores;. Using delete scores; without the brackets only frees the first element and leaks the remaining 49 elements.

Correct version:

double *scores = new double[50];
// ... use scores ...
delete [] scores;  // The [] is essential!
scores = NULL;

The Relationship Between Pointers and Arrays

In C++, array names and pointers are closely related. When you declare an array, the array name acts like a pointer to the first element. 

int arr[5] = {10, 20, 30, 40, 50};

// Array name is like a pointer to the first element
cout << arr;     // Prints the address of arr[0]
cout << &arr[0]; // Same address

// You can use pointer syntax with arrays
cout << *arr;       // Prints 10 (first element)
cout << *(arr + 1); // Prints 20 (second element)

// And array syntax with pointers
int *ptr = arr;
cout << ptr[0];  // Prints 10
cout << ptr[2];  // Prints 30
Swift Note: While arrays and pointers are related, they're not identical. You can't reassign an array name (arr = something doesn't work), but you can reassign a pointer.

Question: What's the key difference between an array name and a pointer variable? 
int arr[5];

Answer:

  • Array name (arr): Is a constant pointer to the first element. You CANNOT reassign it (arr = something; is illegal).

int arr[5];
int x;

arr = &x;  // ERROR! Can't reassign an array name

int *ptr;
ptr = arr;  // OK! Pointer can be assigned
ptr = &x;   // OK! Pointer can be reassigned

Looking Ahead: Where Do Pointers Go From Here?

You now understand the fundamentals of pointers and dynamic memory. But where do these concepts go?

Classes and Dynamic Memory (Unit 6)

Later in the course, you'll learn about classes that manage dynamic memory. When a class contains a pointer to dynamic memory (like a dynamic array), you'll need to implement three special member functions to handle copying and cleanup properly. This is called "The Big Three":

  • Destructor: Cleans up dynamic memory when an object is destroyed
  • Copy Constructor: Makes a deep copy when creating a new object from an existing one
  • Assignment Operator: Makes a deep copy when assigning one object to another

Don't worry about these yet—another unit will cover them in detail. Just know that everything you've learned here about new, delete, and memory management will be essential!

Data Structures (Later Units)

Pointers are the building blocks for advanced data structures like:

  • Linked Lists: Nodes connected by pointers
  • Trees: Hierarchical structures with pointer connections
  • Graphs: Networks of nodes and edges

These structures only work because pointers let you connect pieces of data together dynamically.

Summary: What You've Learned

Key Concepts

  • Pointers: Variables that store memory addresses. Use & to get an address, * to dereference.
  • Dynamic Memory: Memory allocated at runtime with new, freed with delete.
  • Dynamic Arrays: Arrays created with new[], deleted with delete[], with size determined at runtime.
  • Memory Safety: Always initialize pointers, always delete what you allocate, set pointers to NULL after deleting.

Essential Rules to Memorize

  • Every new needs exactly one delete
  • Every new[] needs exactly one delete[]
  • Always initialize pointers before dereferencing
  • Set pointers to NULL after deleting
  • Never use a pointer after it's been deleted
