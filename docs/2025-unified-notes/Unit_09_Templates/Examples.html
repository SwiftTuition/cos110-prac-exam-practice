Example 1

Music Rating System with Function Templates

The Scenario

Zanele is building a music playlist manager that tracks song ratings. Users can rate songs with integers (1-5 stars), floating-point numbers (like 4.7 out of 5), or even string ratings ("Amazing", "Good", etc.). She needs a function that finds the highest rating regardless of the rating type.

The Problem We're Solving

Without templates, Zanele would need to write three separate functions: 

// For integer ratings
int findMaxRating(int a, int b) {
    return (a > b) ? a : b;
}

// For double ratings
double findMaxRating(double a, double b) {
    return (a > b) ? a : b;
}

// For string ratings (alphabetical comparison)
string findMaxRating(string a, string b) {
    return (a > b) ? a : b;
}

The logic is identical in all three. Templates let us write this once and have the compiler generate the versions we need.

How This Code Works

  1. Template declaration: template<class T> tells the compiler this is a template. T is a placeholder for any type.
  2. Generic function body: (rating1 > rating2) ? rating1 : rating2 works with any type that supports the > operator.
  3. Automatic instantiation: When we call findMaxRating(rock, pop) with int arguments, the compiler generates an int version. When we call it with double arguments, it generates a double version.
  4. Same template, multiple functions: We have both findMaxRating and findMinRating templates. Each gets instantiated for the types we use.
Swift Note: Notice how the string comparison ("Excellent" vs "Amazing") uses alphabetical order. The string class overloads the > operator to do this. Our template works with any type that has > defined!

Things to Experiment With

Experiment 1: Add a third template function called findAverage that returns (rating1 + rating2) / 2. Call it with int and double ratings. What happens if you try it with string ratings? (It won't compile - strings don't support + and /!)
Experiment 2: What happens if you call findMaxRating(5, 3.7) (mixing int and double)? Try it and read the error. The compiler can't figure out what T should be because the arguments are different types.
Experiment 3: Create three variables: int a = 5;, int b = 3;, int c = 8;. Find the maximum of all three by nesting calls: findMaxRating(a, findMaxRating(b, c)). Templates can work with complex expressions!
Experiment 4: Try calling findMaxRating with char values like 'A' and 'Z'. It should work because characters support comparison. Which one is "greater"?
Experiment 5: Add cout statements inside the template functions to print "Comparing two values". This will show you how many times each version of the template is called and which types are being compared.
Example 2

Generic Playlist Container

The Scenario

Thabo wants a simple playlist class that can store different types of items. Sometimes he stores song names (strings), sometimes track IDs (integers), and sometimes ratings (doubles). He doesn't want to write three separate playlist classes.

Why Use a Class Template?

A class template lets us create a single container class that works with any data type. Think of it like a blueprint for a box - you design the box once, then you can make boxes that hold books, boxes that hold shoes, or boxes that hold tools. Same design, different contents.

Breaking Down the Template Class

  1. Class declaration: template<class T> class Playlist { ... } creates a template class. T appears throughout the class wherever we'd normally write a specific type like int or string.
  2. Member variables: T items[20]; creates an array of type T. For Playlist<string>, this becomes string items[20]. For Playlist<int>, it becomes int items[20].
  3. Member functions: void add(T item) takes a parameter of type T. T get(int index) returns type T. The type adapts based on the specialization.
  4. Object declaration: Playlist<string> songNames; tells the compiler to create a version of Playlist where T = string. This is called template specialization.
  5. Default value: return T(); in get() creates a default value of type T. For int it's 0, for string it's "".
Swift Note: Each specialization (Playlist<string>, Playlist<int>, Playlist<double>) is a completely separate class. You can't assign one to another or mix them - they're as different as Car and Bicycle!

Things to Experiment With

Experiment 1: Add a remove(int index) function that removes an item from the playlist. You'll need to shift all items after the removed one forward by one position. Test it with different types!
Experiment 2: Create a Playlist<char> and add individual characters. Can you spell out a word in your playlist? Display it to see!
Experiment 3: What happens if you try to create Playlist<Playlist<int> > (a playlist of playlists)? Try it! Remember to add a space between the >> for C++98 compatibility.
Experiment 4: Add a clear() function that empties the playlist by setting count = 0. Test it by adding items, clearing, then adding new items.
Experiment 5: Try creating a playlist without specifying the type: Playlist myList;. What error do you get? This demonstrates why class templates need explicit type specification.
Example 3

Anime Watch History with Template Inheritance

The Scenario

Naledi tracks anime she's watched using a generic container. Now she wants to extend this container with a history feature - the ability to save a snapshot of her watch list and restore it later. Instead of rewriting the entire container, she'll use inheritance to add the new feature.

Why Template Inheritance?

Template inheritance combines two powerful features: templates (for generic code) and inheritance (for code extension). You can create a base template class with common functionality, then derive specialized template classes that add new features while keeping everything generic.

Understanding Template Inheritance Syntax

  1. Base class: template<class T> class WatchList { ... } is our generic container with basic add/display functionality.
  2. Derived class declaration: template<class T> class WatchListWithHistory : public WatchList<T>
    Notice we must specify WatchList<T> (not just WatchList) in the inheritance list. This passes the type parameter to the base class.
  3. Protected members: The base class uses protected: for items and count so the derived class can access them.
  4. Accessing inherited members: this->count and this->items[i] explicitly show we're accessing inherited members. The this-> is important in template base classes.
  5. Type propagation: When we create WatchListWithHistory<string>, both the derived and base portions use string for type T.
Swift Note: The this-> syntax makes it crystal clear to the compiler (and readers) that we're accessing inherited members. In template classes, this helps with name lookup and makes the code more explicit.

Things to Experiment With

Experiment 1: Add a clearHistory() function that sets historyCount = 0. Test saving, clearing the history, and trying to restore (you should get back an empty list).
Experiment 2: Create a WatchListWithHistory<int> to track episode numbers. Add episodes like 1, 2, 3, save history, add 4, 5, then restore. Templates work with any type!
Experiment 3: What happens if you remove this-> from this->count in the derived class? Try changing one occurrence to just count. Does it still compile? (It might, but this-> is safer for template classes.)
Experiment 4: Add a function to the base class void remove(int index) that removes an item. Then call it from main and verify it works with the derived class. Inherited functions are available in derived classes!
Experiment 5: Try calling saveHistory() twice in a row before adding new items. Then restore. What happens? The second save overwrites the first - each save replaces the previous history.

Bug 1: Missing <T> in Constructor Definition (Line 18)

Location: MusicManager::MusicManager()

What's wrong: When defining the constructor outside the class, you need MusicManager<T>:: not just MusicManager::. The class name in the scope resolution must include the template parameter.

Fix: Change to MusicManager<T>::MusicManager()

Bug 2: Missing <T> in addSong Definition (Line 24)

Location: void MusicManager::addSong(T song)

What's wrong: Same issue - need MusicManager<T>:: not MusicManager::.

Fix: Change to void MusicManager<T>::addSong(T song)

Bug 3: Missing Type in Object Declaration (Line 46)

Location: MusicManager myMusic;

What's wrong: Template classes require explicit type specification. The compiler doesn't know what type T should be. Since we're adding strings, we need to specify <string>.

Fix: Change to MusicManager<string> myMusic;

Bug 4: No Bounds Checking in getSong (Line 32)

Location: return songs[index];

What's wrong: The function doesn't check if index is valid. If someone calls getSong(10) when we only have 3 songs, we access invalid memory.

Fix: Add bounds checking: 

template<class T>
T MusicManager<T>::getSong(int index) {
    if (index >= 0 && index < count) {
        return songs[index];
    }
    return T();
}

The Corrected Code

#include <iostream>
#include <string>
using namespace std;

template<class T>
class MusicManager {
public:
    MusicManager();
    void addSong(T song);
    T getSong(int index);
    void display();

private:
    T songs[5];
    int count;
};

template<class T>
MusicManager<T>::MusicManager() {
    count = 0;
}

template<class T>
void MusicManager<T>::addSong(T song) {
    if (count < 5) {
        songs[count] = song;
        count++;
    }
}

template<class T>
T MusicManager<T>::getSong(int index) {
    if (index >= 0 && index < count) {
        return songs[index];
    }
    return T();
}

template<class T>
void MusicManager<T>::display() {
    for (int i = 0; i < count; i++) {
        cout << (i + 1) << ". " << songs[i] << endl;
    }
}

int main() {
    MusicManager<string> myMusic;

    myMusic.addSong("Jerusalema");
    myMusic.addSong("Skeleton Move");
    myMusic.addSong("Ke Star");

    cout << "My playlist:" << endl;
    myMusic.display();

    cout << "\nFirst song: " << myMusic.getSong(0) << endl;

    return 0;
}

Key Lessons

  • Always use ClassName<T>:: when defining template member functions outside the class - the template parameter is part of the class name in this context
  • Template classes require explicit type specification - you can't write MusicManager myMusic;, you must write MusicManager<string> myMusic;
  • The constructor name is special - it's MusicManager<T>::MusicManager() (not MusicManager<T>::MusicManager<T>())
  • Always validate array indices - even in templates, check bounds before accessing arrays
  • Read compiler errors from top to bottom - the first error often causes cascading errors below it
