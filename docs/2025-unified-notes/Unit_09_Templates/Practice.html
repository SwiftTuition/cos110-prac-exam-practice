Problem 1 - Basic

Generic Minimum Function

Your Task

Write a function template called findMin that takes three parameters of the same type and returns the smallest of the three values. Your template should work with any type that supports the < operator.

Function Signature

template<class T>
T findMin(T a, T b, T c);

Test Cases

Your function should pass these tests:

  • Input: findMin(5, 2, 8) → Output: 2
  • Input: findMin(3.7, 2.1, 4.5) → Output: 2.1
  • Input: findMin('z', 'a', 'm') → Output: 'a'
  • Input: findMin("zebra", "apple", "mango") → Output: "apple"

✅ Solution

template<class T>
T findMin(T a, T b, T c) {
    T minimum = a;

    if (b < minimum) {
        minimum = b;
    }

    if (c < minimum) {
        minimum = c;
    }

    return minimum;
}

Alternative Solution (Using Nested Conditionals)

template<class T>
T findMin(T a, T b, T c) {
    if (a < b && a < c) {
        return a;
    } else if (b < c) {
        return b;
    } else {
        return c;
    }
}

Alternative Solution (Using Ternary Operator)

template<class T>
T findMin(T a, T b, T c) {
    return (a < b) ? ((a < c) ? a : c) : ((b < c) ? b : c);
}

Explanation

The first solution uses a straightforward approach:

  1. Initialize minimum: Start by assuming a is the smallest value.
  2. Compare with b: If b is smaller than the current minimum, update minimum to b.
  3. Compare with c: If c is smaller than the current minimum, update minimum to c.
  4. Return result: After checking all three values, minimum holds the smallest value.

Why This Works

This is a function template, which means the compiler generates a specific version for each type we use. When we call findMin(5, 2, 8), the compiler generates an int version. When we call findMin(3.7, 2.1, 4.5), it generates a double version.

The key requirement is that type T must support the < operator. Built-in types like int, double, char, and the string class all support this operator, so our template works with all of them.

Time Complexity

O(1) - Constant time. We always perform exactly 2 comparisons regardless of input values.

Best Practice: The first solution is the clearest and easiest to understand. The ternary operator version is clever but harder to read. In production code, clarity usually wins over cleverness!
Problem 2 - Intermediate

Generic Circular Buffer

The Scenario

Lerato is building a music app that keeps track of the last 5 songs played. When a 6th song is played, the oldest one is removed. This is called a circular buffer - it wraps around when full. You need to build a generic version that works with any type.

Your Task

Complete the CircularBuffer template class with the following features:

  • Store up to 5 items of any type
  • add(T item) - adds an item, removing the oldest if full
  • display() - displays all items in order (oldest to newest)
  • isFull() - returns true if buffer holds 5 items

  Song B
  Song C
  Song D
  Song E

Buffer is full!

Adding: Song F  (Song A will be removed)

  Song C
  Song D
  Song E
  Song F

template<class T>
class CircularBuffer {
public:
    CircularBuffer() : count(0), front(0) {}

    void add(T item) {
        if (count < 5) {
            // Buffer not full yet - just add at the next position
            items[(front + count) % 5] = item;
            count++;
        } else {
            // Buffer is full - overwrite oldest item
            items[front] = item;
            front = (front + 1) % 5;  // Move front pointer forward
        }
    }

    void display() const {
        for (int i = 0; i < count; i++) {
            cout << "  " << items[(front + i) % 5] << endl;
        }
    }

    bool isFull() const {
        return count == 5;
    }

private:
    T items[5];
    int count;
    int front;
};

How the Circular Buffer Works

The Add Operation

There are two cases:

  1. Buffer not full (count < 5): We add the item at position (front + count) % 5. The modulo ensures we wrap around if needed. For example, if front = 2 and count = 3, we add at index (2 + 3) % 5 = 0. Then we increment count.
  2. Buffer is full (count == 5): We overwrite the oldest item (at index front) with the new item. Then we move front forward: front = (front + 1) % 5. This ensures front always points to the oldest item.

The Display Operation

To display items from oldest to newest, we start at front and iterate count times. For each position i, we access items[(front + i) % 5]. The modulo makes the index wrap around when it reaches 5.

Example walkthrough:

State after adding A, B, C:
  front = 0, count = 3
  [A][B][C][ ][ ]
   ^

After adding D, E:
  front = 0, count = 5
  [A][B][C][D][E]
   ^

After adding F (overwrites A):
  front = 1, count = 5
  [F][B][C][D][E]
      ^

Display shows: B, C, D, E, F (starting from front)

Why Templates Here?

The circular buffer logic is completely independent of what type of data we're storing. By using a template, we can create a CircularBuffer<string> for songs, CircularBuffer<int> for scores, or CircularBuffer<double> for temperatures - all from the same code!

Time Complexity

  • add(): O(1) - constant time insertion regardless of buffer state
  • display(): O(n) where n = count (always ≤ 5, so effectively O(1))
  • isFull(): O(1) - simple comparison
Swift Note: Circular buffers are used in real systems like audio/video streaming, network packet buffers, and logging systems. They're memory-efficient because they reuse the same fixed-size array instead of constantly allocating and deallocating memory!

The 4 Bugs

Bug 1: Missing <T> in Constructor Definition (Line 16)

Error: ScoreTracker::ScoreTracker()

Fix: ScoreTracker<T>::ScoreTracker()

When defining template class members outside the class, you must include <T> after the class name.

Bug 2: Missing <T> in getHighScore Definition (Line 27)

Error: T ScoreTracker::getHighScore()

Fix: T ScoreTracker<T>::getHighScore()

Same issue - all template member functions need the <T>.

Bug 3: Missing Type Specification in main (Line 33)

Error: ScoreTracker gameScore;

Fix: ScoreTracker<int> gameScore;

Template classes require explicit type specification. The compiler can't figure out what T should be without being told.

Bug 4: Inconsistent Constructor Initialization (Line 17 - Logic Error)

Potential Issue: highScore = T(); initializes to a default value, which for int is 0. This is fine for tracking high scores (you start at 0), but if you wanted a "no score yet" sentinel, you might want -1 or use a separate flag.

This isn't necessarily a bug, but it's worth thinking about whether T() is the right default for your use case.

Corrected Code

#include <iostream>
#include <string>
using namespace std;

template<class T>
class ScoreTracker {
public:
    ScoreTracker();
    void setHighScore(T score);
    T getHighScore();

private:
    T highScore;
};

template<class T>
ScoreTracker<T>::ScoreTracker() {
    highScore = T();
}

template<class T>
void ScoreTracker<T>::setHighScore(T score) {
    highScore = score;
}

template<class T>
T ScoreTracker<T>::getHighScore() {
    return highScore;
}

int main() {
    ScoreTracker<int> gameScore;

    gameScore.setHighScore(9500);
    cout << "High score: " << gameScore.getHighScore() << endl;

    return 0;
}

Key Takeaways

  • Template member functions must use ClassName<T>:: when defined outside the class
  • Exception: Constructor name is ClassName<T>::ClassName() (not ClassName<T>::ClassName<T>())
  • Template class objects need type specification: ClassName<Type> obj;
  • Read compiler errors from top to bottom: fixing the first error often fixes cascading errors
⚠️ Common Mistake: Forgetting the <T> is the #1 template error students make. The compiler error messages can be confusing, but they usually mention "template" or show a scope resolution issue. When you see these, check your <T> syntax!
Problem 4 - Challenge

Anime Watchlist with Favorites

The Scenario

Thandi tracks anime she wants to watch in a generic watchlist. Now she wants to extend this with a "favorites" feature - the ability to mark certain anime as favorites and view only the favorites.

Your Task

Create a derived class WatchlistWithFavorites that inherits from the provided Watchlist base class. Your derived class should add:

  • markFavorite(int index) - marks an item at the given index as a favorite
  • showFavorites() - displays only the items marked as favorites
  • A separate array to track which items are favorites (use bool array)
⚠️ Requirements: You must use template inheritance. The base class is provided - add only the derived class. Use this-> to access inherited members.

Full watchlist:
  1. Attack on Titan
  2. Death Note
  3. Demon Slayer
  4. One Piece

Marking items 0 and 2 as favorites...

Favorites only:
  Attack on Titan
  Demon Slayer

✅ Solution

template<class T>
class WatchlistWithFavorites : public Watchlist<T> {
private:
    bool isFavorite[10];

public:
    WatchlistWithFavorites() {
        for (int i = 0; i < 10; i++) {
            isFavorite[i] = false;
        }
    }

    void markFavorite(int index) {
        if (index >= 0 && index < this->count) {
            isFavorite[index] = true;
        }
    }

    void showFavorites() const {
        for (int i = 0; i < this->count; i++) {
            if (isFavorite[i]) {
                cout << "  " << this->items[i] << endl;
            }
        }
    }
};

Template Inheritance Breakdown

1. Class Declaration

template<class T>
class WatchlistWithFavorites : public Watchlist<T> {

Key points:

  • The derived class must also be a template (template<class T>)
  • In the inheritance list, we specify Watchlist<T>, not just Watchlist
  • This passes the type parameter to the base class, so if we create WatchlistWithFavorites<string>, it inherits from Watchlist<string>

2. Constructor

WatchlistWithFavorites() {
    for (int i = 0; i < 10; i++) {
        isFavorite[i] = false;
    }
}

We initialize all favorites to false. The base class constructor is called automatically before our constructor runs (it initializes count = 0).

3. Accessing Inherited Members with this->

if (index >= 0 && index < this->count) {

We use this->count and this->items[i] to access inherited members. The this-> is important for template base classes because it helps with name lookup. Without it, the compiler might not find the inherited members during the template compilation phase.

4. Implementing markFavorite

void markFavorite(int index) {
    if (index >= 0 && index < this->count) {
        isFavorite[index] = true;
    }
}

We validate the index before marking. If it's valid (between 0 and count-1), we mark that position as a favorite. This doesn't modify the base class data - we're just tracking additional information.

5. Implementing showFavorites

void showFavorites() const {
    for (int i = 0; i < this->count; i++) {
        if (isFavorite[i]) {
            cout << "  " << this->items[i] << endl;
        }
    }
}

We iterate through all items (using this->count from the base class) and display only those marked as favorites. We access this->items[i] from the base class to get each item's value.

Why This Design Works

Template inheritance lets us extend generic functionality. The base Watchlist<T> provides core functionality (adding, displaying, counting). The derived class adds specialization (favorites) without rewriting the base functionality.

This means we can create:

  • WatchlistWithFavorites<string> for anime names
  • WatchlistWithFavorites<int> for episode numbers
  • WatchlistWithFavorites<double> for ratings

All from the same template code!

Time Complexity

  • markFavorite(): O(1) - direct array access
  • showFavorites(): O(n) where n = number of items in the list
Best Practice: Always use this-> when accessing inherited members in derived template classes. It makes the code explicit and helps avoid compiler issues with dependent name lookup.
