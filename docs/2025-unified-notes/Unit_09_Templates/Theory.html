Welcome to Templates

This unit covers one of C++'s most powerful features: templates. Templates let you write code that works with any data type, without copying and pasting the same logic over and over.

By the end of this unit, you'll be able to create generic functions and classes that work with integers, doubles, strings, or even your own custom types. You'll write less code, fix fewer bugs, and build more flexible programs.

Swift Note: Templates are how the C++ Standard Library works. Every time you use vector<int> or vector<string>, you're using a class template. Now you'll learn to build these yourself!

Function Templates

The Problem: Code Duplication

You need a function to swap two variables. For integers, you write: 

void swapValues(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

Now you need to swap two doubles. So you write the same function again, just changing the type: 

void swapValues(double& a, double& b) {
    double temp = a;
    a = b;
    b = temp;
}

Then you need it for strings. Then for custom objects. The logic is identical each time, but you're stuck rewriting it. This wastes time, creates maintenance headaches, and clutters your code.

The Solution: Function Templates

A function template is a blueprint. You write the logic once, using a placeholder for the type. The compiler then generates the specific versions you need automatically. 

template<class T>
void swapValues(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}

That's it! Now you can call swapValues with any type, and the compiler creates the right version behind the scenes.

Template Instantiation Process: You write this once: ┌─────────────────────────────┐ │ template<class T> │ │ void swapValues(T& a, T& b) │ │ { /* swap logic */ } │ └─────────────────────────────┘ │ │ Compiler sees different calls ├────────────────┬────────────────┬────────────── ▼ ▼ ▼ swapValues(int&, int&) swapValues(double&, double&) swapValues(string&, string&) Compiler generates each version automatically!

Template Syntax Breakdown

Let's look at each part of the template syntax:

template<class T>
T maximum(T x, T y) {
    if (x > y) {
        return x;
    }
    return y;
}
  • template — C++ keyword that starts a template definition
  • <class T> — Declares T as a type parameter (placeholder for any type)
  • T — Used in place of int, double, etc. throughout the function
  • class T — Don't let "class" confuse you! It just means "type" here. You can also write typename T
Swift Note: The compiler only creates the code for types you actually use. If you never call swapValues with char, the char version is never generated. This saves space!

💡 Swift Quiz: Template Syntax
Quick Check: What's the difference between template<class T> and template<typename T>?
Answer: There's no difference! Both mean exactly the same thing: T is a placeholder for any data type. class is the traditional syntax from earlier C++ versions. typename was added later and is often considered clearer (since templates work with built-in types like int, not just classes). You can use either one.

What Can Templates Do?

Templates aren't magic. The type you use must support whatever operations your template performs. Here's what that means:

Example: Sorting Template

template<class T>
void bubbleSort(T arr[], int size) {
    for (int i = 0; i < size - 1; i++) {
        for (int j = 0; j < size - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                T temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

This template requires type T to support:

  • operator> (comparison)
  • operator= (assignment)

If your custom class doesn't have these operators overloaded, the template won't work with it. The compiler will give you an error when it tries to instantiate the template.

⚠️ Important: The template code must be valid for ALL types it's used with. If you write if (x > y) in your template, then every type you use must support operator>. The compiler checks this when it generates each specific version.

Class Templates

From Function Templates to Class Templates

Just like function templates let you write generic functions, class templates let you write generic classes. This is how containers like vector, stack, and queue work.

Example: A Pair Class

You want a class that stores two values. Without templates, you'd need separate classes for every combination: 

// Pair of integers
class IntPair {
    int first;
    int second;
    // ... member functions ...
};

// Pair of doubles
class DoublePair {
    double first;
    double second;
    // ... same member functions, different type ...
};

This is the same duplication problem. Class templates solve it: 

template<class T>
class Pair {
public:
    Pair(T firstVal, T secondVal);
    void setFirst(T newVal);
    void setSecond(T newVal);
    T getFirst() const;
    T getSecond() const;
private:
    T first;
    T second;
};

Now you can create pairs of any type: 

Pair<int> scores(95, 88);
Pair<double> prices(19.99, 24.99);
Pair<string> names("John", "Doe");

Key Difference: You Must Specify the Type

Unlike function templates, the compiler can't figure out the type for class templates. You must tell it explicitly using angle brackets: 

// CORRECT
Pair<int> myPair(10, 20);

// WRONG - compiler doesn't know what T should be
Pair myPair(10, 20);  // Error!
Class Template Specialization: Template Definition (one blueprint): ┌──────────────────────────┐ │ template<class T> │ │ class Pair { │ │ T first; │ │ T second; │ │ }; │ └──────────────────────────┘ │ │ You explicitly specify types ├──────────────┬──────────────┬────────────── ▼ ▼ ▼ Pair<int> Pair<double> Pair<string> (int members) (double members) (string members) Compiler creates separate classes for each type!

Quick Check: If you declare Stack<int> s1; and Stack<double> s2;, are these the same class?
Answer: No! They are two completely different classes generated by the compiler. Stack<int> has int data[100] inside, while Stack<double> has double data[100]. Defining Member Functions Outside the Class

When you define member functions outside a class template, you must follow a specific syntax. This trips up many students at first.

The Syntax

// Class definition
template<class T>
class Pair {
public:
    Pair(T firstVal, T secondVal);
    T getFirst() const;
private:
    T first;
    T second;
};

// Member function definition - OUTSIDE the class
template<class T>
Pair<T>::Pair(T firstVal, T secondVal) {
    first = firstVal;
    second = secondVal;
}

template<class T>
T Pair<T>::getFirst() const {
    return first;
}

Notice three important things:

  • You must repeat template<class T> before each member function definition
  • The class name becomes Pair<T> (not just Pair)
  • The constructor name is still just Pair (not Pair<T>)
⚠️ Common Mistake: Forgetting the <T> after the class name: 
template<class T>
void Pair::setFirst(T val) { ... }  // WRONG! Should be Pair<T>
This will give you a confusing compiler error.

Where to Put Template Code

This is one of the most confusing aspects of templates for beginners. The usual approach of separating declarations (.h files) from definitions (.cpp files) doesn't work with templates.

The Problem

The compiler needs to see the full template definition (not just the declaration) to generate code for a specific type. If the definition is in a .cpp file that's compiled separately, the linker can't find the code. 

// WRONG APPROACH - This will cause linker errors!

// Stack.h
template<class T>
class Stack {
public:
    void push(T item);  // Declaration only
    // ...
};

// Stack.cpp
#include "Stack.h"
template<class T>
void Stack<T>::push(T item) {
    // Definition
}

// main.cpp
#include "Stack.h"
int main() {
    Stack<int> s;
    s.push(10);  // Linker error: undefined reference to Stack<int>::push
}

The Solution: Put Everything in the Header

There are two common approaches:

Approach 1: Include .cpp at end of .h (Recommended)

// Stack.h
template<class T>
class Stack {
public:
    void push(T item);
    // ... declarations ...
};

#include "Stack.cpp"  // Include the definitions!

// Stack.cpp
template<class T>
void Stack<T>::push(T item) {
    // ... implementation ...
}

// main.cpp
#include "Stack.h"  // This brings in both declaration and definition
int main() {
    Stack<int> s;
    s.push(10);  // Works!
}

Approach 2: Define Everything Inline

// Stack.h
template<class T>
class Stack {
public:
    void push(T item) {
        // Definition right here in the class
    }
    // ... all definitions inline ...
};
Swift Note: This is why the C++ Standard Library header files are so large. They contain both declarations and definitions because they're templates. When you #include <vector>, you're including all the template code!

💡 Swift Quiz: Template File Organization
Quick Check: Why can't you compile a template .cpp file separately like you do with regular classes?
Answer: When the compiler processes a template .cpp file on its own, it doesn't see any specific types being used (like Stack<int> or Stack<double>). Without knowing which types to generate code for, it can't create any actual functions. Later, when the linker tries to connect main.cpp (which uses Stack<int>) to the template code, it finds nothing because no Stack<int> version was ever generated. That's why you need the full template definition visible wherever the template is used.

Templates and Inheritance

Combining Two Powerful Features

You can create template classes that inherit from other template classes. This lets you build hierarchies of generic containers and extend their functionality.

The Syntax

// Base template class
template<class T>
class Container {
protected:
    T data[100];
    int size;
public:
    Container() : size(0) {}
    void add(T item) { data[size++] = item; }
};

// Derived template class
template<class T>
class SortedContainer : public Container<T> {
public:
    void sort() {
        // Sort the inherited data array
    }
};

Key points:

  • Both base and derived must be templates
  • Use Container<T> (not just Container) in the inheritance list
  • The type parameter T is passed from derived to base
Template Inheritance: template<class T> template<class T> class Base { ... } ←───── class Derived : public Base<T> { ... } ↑ Pass T to base! When you create Derived<int>: - Derived class gets T = int - Base class ALSO gets T = int - Both specialized for the same type

Accessing Inherited Members

When accessing inherited members in a derived template class, you should use this-> to be safe: 

template<class T>
class Derived : public Base<T> {
public:
    void process() {
        // CORRECT - explicitly show it's inherited
        this->data[0] = someValue;
        this->size++;

        // Also works, but this-> is clearer
        data[0] = someValue;
    }
};
Swift Note: The this-> makes it clear to both the compiler and human readers that you're accessing an inherited member. Some compilers require it for template base classes due to how name lookup works.

Quick Check: If you write class Derived : public Base<T>, what happens if someone creates Derived<double> d;?
Answer: The compiler creates a Derived<double> class that inherits from Base<double>. Both the derived and base portions use double for the type parameter T. This means if the base class has T data[100], it becomes double data[100]. The whole inheritance chain specializes to the same type.

Common Mistakes with Templates

Here are the most frequent errors students make when learning templates, with buggy code examples. See if you can spot what's wrong!

Mistake 1: Missing Template Keyword

class T {
public:
    T maximum(T x, T y) {
        if (x > y) return x;
        return y;
    }
};

What's wrong? The code tries to create a generic function but forgets the template syntax entirely. T is being used as a regular class name, not a type parameter.

Mistake 2: Wrong Member Function Syntax

template<class T>
class Box {
public:
    T getValue() const;
private:
    T value;
};

template<class T>
T Box::getValue() const {
    return value;
}

What's wrong? When defining getValue() outside the class, it needs Box<T>:: not just Box::.

Mistake 3: Template in .cpp File

// Container.h
template<class T>
class Container {
public:
    void add(T item);
};

// Container.cpp
template<class T>
void Container<T>::add(T item) {
    // implementation
}

// main.cpp
#include "Container.h"
int main() {
    Container<int> c;
    c.add(5);
}

What's wrong? The template definition is in Container.cpp which isn't included in main.cpp. The linker won't find Container<int>::add because it was never generated.

Mistake 4: Forgetting Type in Declaration

template<class T>
class Stack {
    // ...
};

int main() {
    Stack myStack;
    myStack.push(10);
}

What's wrong? Class templates require explicit type specification. Should be Stack<int> myStack;

Mistake 5: Constructor Name with <T>

template<class T>
class Pair {
public:
    Pair(T a, T b);
};

template<class T>
Pair<T>::Pair<T>(T a, T b) {
    // implementation
}

What's wrong? The constructor name shouldn't have <T> after it. Should be Pair<T>::Pair(T a, T b).

Summary

You've now learned how to write generic, reusable code with templates. Here are the key points to remember:

Function Templates

  • Use template<class T> before the function to create a generic version
  • The compiler generates specific versions automatically based on the types you use
  • The type must support whatever operations your template performs
  • class T and typename T mean the same thing

Class Templates

  • Create generic classes like containers that work with any type
  • You must explicitly specify the type: Stack<int>, not just Stack
  • Each instantiation (Stack<int>, Stack<double>) is a separate class
  • Member functions defined outside the class need template<class T> and ClassName<T>::

Template File Organization

  • Template definitions must be in header files, not separate .cpp files
  • Common approach: include the .cpp at the end of the .h file
  • The compiler needs the full definition to generate code for each type

Templates with Inheritance

  • Template classes can inherit from other template classes
  • Use BaseClass<T> in the inheritance list to pass the type parameter
  • Use this-> to access inherited members in derived templates
  • Both base and derived specialize to the same type
