Problem 1: Write a Makefile for a Multi-File Project

Scenario:

You're helping a student named Thabo organize his grade tracking system. The project has the following files:

  • main.cpp - Contains the main function
  • Student.h - Student class declaration
  • Student.cpp - Student class implementation
  • Grade.h - Grade class declaration
  • Grade.cpp - Grade class implementation

Additional information:

  • main.cpp includes both Student.h and Grade.h
  • Student.cpp includes Student.h and Grade.h (Student has a Grade object)
  • Grade.cpp includes only Grade.h

Task:

Write a complete makefile that:

  1. Creates an executable called gradeSystem
  2. Uses variables for object files and compilation commands
  3. Compiles with the C++98 standard
  4. Includes a run target that executes the program
  5. Includes a clean target that removes all object files and the executable
  6. Has correct dependencies for all files
Hints:
  • Start by defining variables: ofiles for all .o files and gpp_o for the compile command
  • The main target (gradeSystem) should depend on all .o files
  • Each .o file depends on its .cpp source plus all headers it includes
  • Since Student.cpp includes both Student.h and Grade.h, Student.o must list both as dependencies
  • Remember to use TAB characters for indentation, not spaces
  • The -c flag tells g++ to compile without linking

Solution:

# Variables
ofiles = main.o Student.o Grade.o
gpp_o = g++ -c -std=c++98

# Main target: link all object files
gradeSystem: $(ofiles)
	g++ -std=c++98 $(ofiles) -o gradeSystem

# Compile main.cpp (depends on main.cpp, Student.h, Grade.h)
main.o: main.cpp Student.h Grade.h
	$(gpp_o) main.cpp

# Compile Student.cpp (depends on Student.cpp, Student.h, Grade.h)
Student.o: Student.cpp Student.h Grade.h
	$(gpp_o) Student.cpp

# Compile Grade.cpp (depends on Grade.cpp, Grade.h)
Grade.o: Grade.cpp Grade.h
	$(gpp_o) Grade.cpp

# Run the program
run: gradeSystem
	./gradeSystem

# Clean up compiled files
clean:
	rm -f *.o gradeSystem

Explanation:

  1. Variables: ofiles lists all object files needed for linking. gpp_o stores the compile command to avoid repetition.
  2. Main target: gradeSystem depends on all .o files. If any .o is missing or out of date, make will rebuild it before linking.
  3. Dependencies:
    • main.o depends on Student.h and Grade.h because main.cpp includes both
    • Student.o depends on Student.h and Grade.h because Student.cpp includes both
    • Grade.o depends only on Grade.h because Grade.cpp includes only that header
  4. Run target: Depends on gradeSystem to ensure it's built before execution
  5. Clean target: Removes all generated files (*.o matches all object files)
Swift Note: Getting dependencies right is crucial. If you forget to list Grade.h as a dependency for Student.o, and then you change Grade.h, make won't know to recompile Student.cpp. Your program will still link, but it will use outdated code, leading to confusing bugs.

Problem 2: Fix Errors in Overloaded Functions

Scenario:

You're tutoring Amahle, who's working on a music playlist manager. She's trying to use function overloading but keeps getting compilation errors. Your job is to identify and fix all the issues.

The buggy code:

#include 
#include 
using namespace std;

// Function to add a song
void addSong(string title);

// Another version to add song with artist
int addSong(string title);

// Add song with duration (in seconds)
void addSong(string title, int duration);

// Add song with duration using default parameter
void addSong(string title, int duration = 180);

int main() {
    addSong("Bella");
    addSong("Djadja", 180);
    return 0;
}

// Implementations
void addSong(string title) {
    cout << "Added: " << title << endl;
}

int addSong(string title) {
    cout << "Added song: " << title << endl;
    return 1;
}

void addSong(string title, int duration) {
    cout << "Added: " << title << " (" << duration << "s)" << endl;
}

Task:

Identify all the errors in this code and fix them. The program should successfully compile and support:

  • Adding a song with just a title
  • Adding a song with a title and duration
Hints:
  • Look for functions with the same signature (name + parameter types)
  • Remember: return type is NOT part of the signature
  • Check for conflicts between overloaded functions and default parameters
  • There are three distinct errors to fix

Errors Found:

Error 1: Overloading on return type only (Lines 6-9)

void addSong(string title);
int addSong(string title);  // ❌ Same signature as line 6!

Both functions have signature addSong(string). The different return types (void vs int) don't matter - the compiler can't distinguish them. You must remove one or change the parameters.

Error 2: Duplicate declaration (Lines 12-15)

void addSong(string title, int duration);
void addSong(string title, int duration = 180);  // ❌ Same signature!

Line 15 declares the same function as line 12, just with a default parameter. This creates two declarations for the same function, which is invalid. You need only one declaration with the default parameter.

Error 3: Ambiguous call (Line 18)

addSong("Bella");  // ❌ Ambiguous!

If we fix errors 1 and 2, this call becomes ambiguous. It could call:

  • addSong(string) with argument "Bella"
  • addSong(string, int) with arguments "Bella", 180 (using default)

Both match equally well, so the compiler can't choose. We need to remove the ambiguity by eliminating one overload.

Corrected Code:

#include 
#include 
using namespace std;

// Add song with optional duration (default 180 seconds)
void addSong(string title, int duration = 180);

int main() {
    addSong("Bella");           // Uses default duration
    addSong("Djadja", 200);     // Custom duration
    return 0;
}

// Implementation
void addSong(string title, int duration) {
    cout << "Added: " << title << " (" << duration << "s)" << endl;
}

Why this works:

  • Only one function declaration, so no conflicting signatures
  • Default parameter lets us call with 1 or 2 arguments
  • No ambiguity - there's only one function to call
Common Mistake: Trying to combine function overloading with default parameters in a way that creates ambiguity. When in doubt, keep it simple: use either overloading OR default parameters for a given function name, not both in a way that overlaps.

Problem 3: Add Default Parameters to Existing Functions

Scenario:

Brandon is building a tutoring session scheduler. He has a function that creates appointments, but he wants to add default parameters to make it more flexible. Currently, every call requires all four arguments, which is tedious for common cases.

Current function:

void scheduleSession(string student, string subject, int duration, string location);

Example calls (current):

scheduleSession("Sipho", "COS 110", 60, "Room 101");
scheduleSession("Lerato", "WTW 146", 60, "Room 101");  // Same duration and location!
scheduleSession("Pieter", "OBS 124", 60, "Room 101");  // Again!

Task:

Modify the function declaration to add appropriate default parameters so that:

  • The default duration is 60 minutes
  • The default location is "Room 101"
  • Student and subject must always be provided (no defaults)
  • All these calls should work: 
    scheduleSession("Sipho", "COS 110");                    // Uses both defaults
scheduleSession("Lerato", "WTW 146", 90);               // Custom duration, default location
scheduleSession("Pieter", "OBS 124", 45, "Room 202");   // All custom

Write the modified function declaration (prototype) with default parameters.

Hints:
  • Default parameters must be rightmost (trailing parameters)
  • You can't have a default for duration without also having one for location (if location comes after duration)
  • Actually, wait - think about the parameter order. Do you need to reorder them?
  • Remember: you can only omit arguments from right to left when calling

Solution:

void scheduleSession(string student, string subject, int duration = 60, string location = "Room 101");

Explanation:

  1. Parameter order: Required parameters (student, subject) come first, optional parameters (duration, location) come last.
  2. Default values: duration = 60 and location = "Room 101" provide sensible defaults.
  3. Trailing defaults: Both defaults are rightmost, so they can be omitted from right to left.

How the calls work:

Function Call Actual Arguments Used
scheduleSession("Sipho", "COS 110") student="Sipho", subject="COS 110", duration=60, location="Room 101"
scheduleSession("Lerato", "WTW 146", 90) student="Lerato", subject="WTW 146", duration=90, location="Room 101"
scheduleSession("Pieter", "OBS 124", 45, "Room 202") student="Pieter", subject="OBS 124", duration=45, location="Room 202"
Best Practice: Choose default values that represent the most common use case. In this scenario, most tutoring sessions are 60 minutes in Room 101, so those make good defaults. This reduces repetitive code and makes the most common calls shorter.
Important: The defaults only go in the declaration (usually in the .h file), NOT in the definition. The implementation would look like this: 
// scheduleSession.cpp
void scheduleSession(string student, string subject, int duration, string location) {
    cout << "Session: " << student << " - " << subject << endl;
    cout << "Duration: " << duration << " min in " << location << endl;
}

Problem 4: Debug a Makefile with Dependency Issues

Scenario:

You're helping Zanele debug her clash royale deck analyzer. She has a makefile, but weird things keep happening:

  • When she modifies Card.h, sometimes the changes don't appear in the executable
  • When she adds a new file Deck.cpp, she gets "undefined reference" errors during linking
  • The make clean command gives an error about spaces vs tabs

Project structure:

  • main.cpp - Includes Card.h and Deck.h
  • Card.h, Card.cpp - Card class (Deck.h includes Card.h)
  • Deck.h, Deck.cpp - Deck class (newly added)

Her current makefile:

# Deck Analyzer Makefile
ofiles = main.o Card.o
gpp_o = g++ -c -std=c++98

# Link object files
deckAnalyzer: $(ofiles)
	g++ -std=c++98 $(ofiles) -o deckAnalyzer

# Compile main.cpp
main.o: main.cpp
	$(gpp_o) main.cpp

# Compile Card.cpp
Card.o: Card.cpp Card.h
	$(gpp_o) Card.cpp

# Compile Deck.cpp
Deck.o: Deck.cpp Deck.h
	$(gpp_o) Deck.cpp

# Clean up
clean:
    rm -f *.o deckAnalyzer

Task:

Identify and fix ALL the bugs in this makefile. Explain what each bug causes and how to fix it.

Hints:
  • Check if all .o files that need to be linked are listed in the ofiles variable
  • Check if main.o has all its header dependencies listed
  • Since Deck.h includes Card.h, what does Deck.o depend on?
  • Look very carefully at the indentation in the clean target - are those tabs or spaces?
  • There are 4 distinct bugs to find

Bugs Found:

Bug 1: Missing Deck.o from ofiles (Line 2)

ofiles = main.o Card.o  # ❌ Missing Deck.o!

Problem: Even though there's a rule to compile Deck.cpp into Deck.o, it's never linked into the final executable because it's not in the ofiles variable.

Symptom: "undefined reference" errors when main.cpp tries to use Deck class functions.

Fix: ofiles = main.o Card.o Deck.o

Bug 2: Missing header dependencies for main.o (Line 10)

main.o: main.cpp  # ❌ Missing Card.h and Deck.h!

Problem: main.cpp includes both Card.h and Deck.h, but they're not listed as dependencies. If either header changes, make won't know to recompile main.cpp.

Symptom: Changes to Card.h or Deck.h don't trigger main.cpp recompilation, so the executable uses outdated code.

Fix: main.o: main.cpp Card.h Deck.h

Bug 3: Missing Card.h dependency for Deck.o (Line 18)

Deck.o: Deck.cpp Deck.h  # ❌ Missing Card.h!

Problem: Deck.h includes Card.h, so Deck.cpp indirectly includes Card.h. If Card.h changes, Deck.cpp needs recompilation.

Symptom: Changes to Card.h don't trigger Deck.cpp recompilation, leading to outdated code.

Fix: Deck.o: Deck.cpp Deck.h Card.h

Bug 4: Spaces instead of tab in clean target (Line 22)

clean:
    rm -f *.o deckAnalyzer  # ❌ Uses 4 spaces, not a tab!

Problem: Makefile commands MUST be indented with a tab character, not spaces.

Symptom: make clean gives error: "missing separator" or "commands commence before first target".

Fix: Replace the 4 spaces with a single tab character.

Corrected Makefile:

# Deck Analyzer Makefile
ofiles = main.o Card.o Deck.o
gpp_o = g++ -c -std=c++98

# Link object files
deckAnalyzer: $(ofiles)
	g++ -std=c++98 $(ofiles) -o deckAnalyzer

# Compile main.cpp (depends on main.cpp, Card.h, Deck.h)
main.o: main.cpp Card.h Deck.h
	$(gpp_o) main.cpp

# Compile Card.cpp (depends on Card.cpp, Card.h)
Card.o: Card.cpp Card.h
	$(gpp_o) Card.cpp

# Compile Deck.cpp (depends on Deck.cpp, Deck.h, Card.h)
Deck.o: Deck.cpp Deck.h Card.h
	$(gpp_o) Deck.cpp

# Clean up (TAB indentation!)
clean:
	rm -f *.o deckAnalyzer
Note: This example uses Clash Royale - a real-time mobile strategy game where you build a deck of 8 cards and battle opponents. Each card (like Hog Rider, Fireball, or Ice Spirit) has different properties (elixir cost, damage, hitpoints). A deck analyzer would help players optimize their card choices.
Swift Note: The hardest makefile bugs to track down are missing dependencies. The symptom is subtle: your code compiles and links, but uses outdated versions of changed files. Always ask yourself: "If I change this header file, which .cpp files need recompilation?" List all those .cpp files' corresponding .o targets as depending on that header.

Summary of fixes:

  1. Added Deck.o to ofiles variable (fixes linking errors)
  2. Added Card.h and Deck.h as dependencies for main.o (fixes stale code issue)
  3. Added Card.h as dependency for Deck.o (fixes stale code issue)
  4. Changed spaces to tab in clean target (fixes "missing separator" error)
